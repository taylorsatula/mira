# web/assets/javascript/ — browser client for the MIRA web UI: vanilla-JS modules (no bundler, no imports) communicating exclusively through `window.*` globals

Loaded as plain `<script>` tags by `web/chat/index.html` and `web/settings/index.html`. Network layer is `api-client.js`; the chat transport is the WebSocket turn protocol served by `cns/api/websocket_chat.py`.

## Rules

- **Globals, not modules.** There is no bundler and no ES-module system: every cross-module call goes through a `window.*` export declared in each file's export block (e.g. `messaging.js` exports `window.sendMessage`, `history.js` exports `window.InlineHistory`). A function without a `window.` export is private to its file — do not call it from another file, and never reach into another module's internals instead of using its exported surface.
- **Load order is enforced by the HTML, not the code.** The per-page manifests (which page loads what, in order) are owned by `web/AGENTS.md` (Wiring). A new script must be inserted at a position consistent with its dependencies (anything reading `AppState` must come after `core.js`); IIFE-style modules (`theme.js`, `sidebar.js`, `location.js`, `repulsion-feedback.js`) run at parse time and tolerate late dependencies only via optional chaining or retry loops.
- **`api-client.js` is the single backend transport.** New endpoint wrappers belong in `MiraAPIClient`'s service objects (`auth`, `chat`, `history`, `actions`, `data`, `health`), not in feature files. The two sanctioned raw-`fetch` exceptions already in the tree: `tool-config.js` calls `fetch(..., {credentials: 'include'})` directly plus its own CSRF header from `window.miraAPI._ensureCsrfToken()`; and `api-client.js` itself uses raw `fetch` without CSRF for the pre-session auth endpoints (`/v0/auth/magic-link`, `/v0/auth/verify`, `/v0/auth/signup`, WebAuthn begin steps) — a caller cannot hold a CSRF token before it has a session.
- **CSRF contract for writes.** `_httpRequest` in `api-client.js` attaches `X-CSRF-Token` to every non-GET/HEAD request whose path starts with `/v0/api` or `/v0/auth` (except `/v0/auth/csrf` itself), fetching the token lazily via `_ensureCsrfToken()`. Any raw-`fetch` write to those prefixes must replicate this or the server rejects it.
- **The WS protocol is strict: unknown frame fields are rejected server-side.** `chat.sendMessage` sends only `{type, message_id, content, include_thinking}` plus optional `image`/`image_type` or `document`/`document_type` — the old `stream` field was removed and must not be reintroduced. `message_id` must be a real UUID (`_generateId` uses `crypto.randomUUID`), because the server types it as one and echoes it back in `turn_started`.
- **Halts name their turn.** `cancelGeneration()` refuses to send a `halt` before `turn_started` has set `activeTurnId` (the server rejects an unbound halt with `NO_MATCHING_ACTIVE_TURN`); never bypass that guard by sending a bare halt.
- **Ordered-history contract (blast radius).** The server contract for `GET /v0/api/data?type=history` (keyset-cursor only, rejects `offset`/`search`, `meta.next_before`/`meta.has_more`) is owned by `cns/api/AGENTS.md` (`data.py`). `history.getHistory` in `api-client.js` reverses each page to newest-first — that reversal is the single normalization point. Every renderer in `history.js` (`renderMessageGroups`, `groupMessagesIntoSegments`, `loadInlineHistory`'s scroll anchoring) is written against the reversed, newest-first page; changing the reversal point or adding offset-style pagination anywhere breaks all of them.
- **Sanitize allowlists are per-call-site (blast radius).** There is no shared markdown renderer: `messaging.js` (`renderBlock`, `showResponse`, `loadLastSessionResponse`) and `history.js` (`createInlineHistoryPair`, `completeLastHistoryEntry`, `renderInlineSegment`) each carry their own `marked.setOptions` + `DOMPurify.sanitize` block with different `ALLOWED_TAGS`. Permitting a new HTML tag or attribute in rendered content requires editing every call site — editing one silently diverges the renderings.
- **Dangling references are intentional, not bugs to fix.** `webauthn-client.js` and `inactivity-warning.js` do not exist in this repository; `core.js` guards with `if (window.WebAuthnClient)`, and `sidebar.js`/`messaging.js`/`location.js` reference `window.inactivityWarningManager` only through optional chaining or a polling `trySubscribe`. Do not add imports or hard dependencies on either symbol.
- **`segment-timeout.js` is currently orphaned.** No HTML page loads it; the sidebar pause path in `sidebar.js` (`pause_session`/`resume_session` via `/v0/api/actions`) duplicates its actions independently. If you wire it back in, reconcile the two pause implementations rather than running both.
- **`settings.js` has two dead call paths.** `logout()` calls `this.apiClient.http.request('/v0/auth/logout')` and `downloadRawConversationData()` calls `this.apiClient.data.getRawConversationData()` — neither `http` nor `data.getRawConversationData` exists on `MiraAPIClient`, so both throw, land in their catch blocks, and continue (logout still clears the token and redirects; export shows the failure alert). Fix at the call site or add the client method; do not assume either works today.
- **Session-recovery flag round-trip.** `AppState.responseInterrupted` is set when a stream dies with `error.message === 'WebSocket closed'` and cleared by the `onConnect` handler in `core.js` after re-fetching one keyset page via `history.getHistory({limit: 50})`, locating the newest `role === 'user'` row as the turn boundary, and rendering that row plus everything after through `window.assembleTurnContent` (the same helper `loadLastSessionResponse` uses); if no user row appears in the window, recovery is skipped entirely. Changes to disconnect semantics must preserve that recovery or completed responses are lost on reconnect/tab-return.

## Files

- `api-client.js` — the entire backend transport: `MiraAPIClient` with WebSocket lifecycle (`connect`, `_handleMessage` frame dispatch, `_scheduleReconnect` exponential backoff capped at 30s, `_startKeepalive` 30s ping — it clears any existing interval first, so reconnects never stack ping timers), strict turn-protocol frame handling, offline message queue, CSRF management (`_ensureCsrfToken`, `_httpRequest`), and service wrappers `auth`/`chat`/`history`/`actions`/`data`/`health`. Zero DOM dependencies; exports `window.MiraAPIClient`. Gotcha: `connectionState === 'authenticated'` is required before `_sendMessage` actually sends — earlier sends are silently queued. Queue invariants: on reconnect-exhaustion every queued send's promise settles with a rejection (never left pending — that wedges compose in stop-mode); the burst drain (`_processMessageQueue`) and popover sends enforce the client-side in-flight guard so a live turn is never clobbered by a TURN_BUSY. `Calls: cns/api/websocket_chat.py` (WS), `auth/api.py`, `cns/api/actions.py`, `cns/api/data.py`, `cns/api/health.py`
- `core.js` — foundation module: `AppState` (UI flags, localStorage-backed `messageQueue`, `apiClient`, `responseInterrupted`, `attachedFiles`), the `elements` DOM cache (all `getElementById` lookups live here), `initializeAPIClient()` (global `onConnect`/`onDisconnect`/`onMessage` handlers incl. the tool-event normalizer and interrupted-response recovery: one `getHistory({limit: 50})` keyset page, turn boundary at the newest user row, rendered via `window.assembleTurnContent`, skipped when no user row is in the window), `initializeMira()` boot sequence, and `Functions.collapseSegment`/`Functions.openFeedbackEmail`. Everything reads `AppState`/`elements` from here.
- `messaging.js` — message lifecycle: failed-send queue (`queueMessage` through `saveQueuedMessageEdit`, localStorage-backed; queued items carry the first attachment's ≤1MB image dataUrl so a failed send re-queues with its image, and `sendSingleQueuedMessage` restores it to `AppState.attachedFiles` before sending), attachment handling (`handleFileSelect`, `downscaleImage` multi-step halving; 512px default vs 5MB preserve-resolution path), the announcement banner (backend `preferences.announcement.message` renders via `textContent` — it is plain text by contract (`config/announcement.py`), never `innerHTML`), `sendMessage` -> `handleSendMessage` (registers a per-send `messageHandler` on `eventHandlers.onMessage` and removes it after settle), the block-based streaming state machine (`streamingState`, `extractCompleteBlocks`, `renderStreamingBlocks`, `completeStreamingResponse`), thinking-token drawer (`handleThinkingToken`, `transitionThinkingToText`), and system-tag filtering (`window.filterSystemTags`, `window.filterStreamingText` — strips `<think>` blocks and all `<mira:*>` tags, and drops orphaned tag fragments split across paragraph boundaries). Consumers: `events.js` calls `window.sendMessage`; `core.js` calls `window.loadLastSessionResponse`; `repulsion-feedback.js` monkey-patches `window.sendMessage`/`window.completeStreamingResponse`.
- Every feature module below reads `AppState`/`elements` from `core.js` and the client from `AppState.apiClient` (alias `window.miraAPI`); `api-client.js` and `core.js` themselves have no such dependency.
- `ui.js` — visual layer: tool badge state machine (`updateToolIndicator`, `normalizeToolPhase`, `applyToolBadgeLabel`, timed `scheduleToolIndicatorReset`), status badges (`scheduleCompletionBadge`, `showToolbarStatusBadge`), attachment/queue popover rendering (`updateAttachmentPopover`, `updateQueueIndicator`), send-choreography animations (`runPlungerAnimation`, `animateTextDissolve`, `computeImpactDelay`), and the ASCII wave loading screen (`showLoadingScreen` with 45s slow-response fallback and `_stopLoading`). Also owns the `visibilitychange` handler that finishes stale CSS animations and force-reconnects `window.miraAPI`. Consumers: `messaging.js` (badge/animation calls), `events.js`, `domain-knowledge.js` (`ToolbarPriorityManager` label hook).
- `events.js` — all DOM event wiring: `setupEventListeners` (compose form submit with stop-mode branch to `window.cancelGeneration`, Enter-to-send vs mobile newline, paste-image ingestion via `downscaleImage`, attachment/queue popovers) and `setupDelegatedEvents` (queue-message action buttons via `data-index` delegation). Exported as `window.setupEventListeners`/`window.setupDelegatedEvents`; called only from `core.js` `initializeMira`. Gotcha: the send-button `pointerdown` preventDefault exists specifically for iOS Safari focus/keyboard-loss — do not remove it as redundant.
- `history.js` — conversation history: drawer rendering (`renderConversations`, `loadConversations` keyset pagination in `AppState.historyDrawer`), date grouping and DOM-side search/highlight (`searchHistory`, `highlightText` — there is no server-side search), calendar scan (`getConversationDaysForMonth`, bounded to 5 pages of 100), and the inline-history view (`window.InlineHistory`: `toggleInlineHistory`, `loadInlineHistory` with scroll-anchored prepend — the initial load drops the two newest messages client-side (`skipCurrentTurn`) because a keyset cursor cannot offset past the live turn, `addUserMessage`/`completeLastEntry` pending-pair protocol used by `messaging.js`). `Calls: cns/api/data.py` (history)
- `settings.js` — `SettingsManager` class: settings modal lifecycle, endpoint/streaming preference persistence (localStorage), connection test via `health.checkHealth`, calendar config via `user`/`get_calendar_config`+`store_calendar_config` actions, WebAuthn device UI (requires the absent `webauthn-client.js`, so inert as shipped — see Rules), logout (`performLogout` clears the token and redirects to `/`, main.py's redirect to `/chat`), and the two dead call paths noted in Rules. Instantiated by `core.js` (`AppState.settingsManager`, `window.settingsManager`). `Calls: auth/api.py`, `cns/api/actions.py`, `cns/api/health.py`
- `domain-knowledge.js` — `DomainKnowledgeManager`: full CRUD plus section operations (`createSection`, `updateSection`, `renameSection`, `reorderSections`, `expandSection`/`collapseSection`, `getSectionHistory`/`rollbackSection`) and sharing (`shareDomain`, `acceptShare`, `listPendingShares`), all through the `domain_knowledge` domain of `/v0/api/actions` and `data.getData('domaindocs')`. Renders the chat popover (`renderDomainPopover`, single-enabled-domain constraint is backend-enforced) and the settings page cards with drag-and-drop reorder (`_renderReorderableSectionsList`). Entry point `initDomainKnowledge(apiClient)`, called from `core.js`; exports `window.domainManager`. Enforces label format `^[a-z][a-z0-9_]*$` client-side before submit. `Calls: cns/api/actions.py`, `cns/api/data.py`
- `tool-config.js` — `ToolConfigManager`: user-specific tool configuration UI against `/v0/api/actions/tools*` (list/get/schema/PUT/DELETE/validate) and OAuth connect/disconnect via `/v0/auth/oauth/{provider}/init` and `/disconnect`. Generates forms from the server's JSON Schema (`generateFormFromSchema`, special-cases `email_tool` folder discovery and any `oauth_status` field). Only page loading it: `web/settings/index.html`. Uses raw `fetch` + `_ensureCsrfToken` (see Rules). `Calls: cns/api/tool_config.py`, `auth/api.py`
- `sidebar.js` — app sidebar (IIFE): desktop collapse persisted under `mira-sidebar-collapsed`, mobile open/close with focus trap, Escape, and edge-swipe; `isOnChatPage()` gates chat-only buttons. Wires History -> `window.InlineHistory.toggle()` (or redirects to `/chat?history=1`, which this file also consumes by auto-expanding and stripping the param), Pause/Unpause -> `window.inactivityWarningManager` or a direct `pause_session`/`resume_session` action fallback, and Collapse Segment -> `window.Functions.collapseSegment`. `Calls: cns/api/actions.py` (fallback pause path)
- `segment-timeout.js` — `SegmentTimeoutManager`: polls `get_segment_status` every 60s, renders the collapse countdown, and offers pause/resume/`collapse_segment` from its popover; publishes state via `onStatusChange` subscribers. Currently loaded by no HTML page (see Rules). `Calls: cns/api/actions.py`
- `location.js` — geolocation consent (IIFE): one-time consent modal persisted under `mira-location-consent`, permission-query gate so the browser prompt only fires from an explicit user gesture, then POSTs coordinates. Failures are deliberately silent (optional enrichment). `Calls: cns/api/location.py`
- `repulsion-feedback.js` — "Repulsed!" AI-tell detector (IIFE): a large `TELLS` regex bank scanned over each completed response via a monkey-patch of `window.completeStreamingResponse`; on match it shows the pink toolbar indicator, fires an auto-capture (`feedback`/`capture_repulsion` with empty reason), and opens a popover for the human reason. Also monkey-patches `window.sendMessage` to capture the preceding user message — therefore must load after `messaging.js`. Wrapping is idempotent per load but re-loading the page re-wraps fresh originals. `Calls: cns/api/actions.py`
- `collapse-animation.js` — standalone `collapseAnimation(element, options)` used by `Functions.collapseSegment` in `core.js`: wraps text nodes in per-character spans, locks widths against reflow, converts font, then drops with gravity; also exported for CommonJS (`module.exports`). Pure DOM/CSS, no API calls.
- `theme.js` — appearance preference (IIFE): owns `matchMedia` subscription for Auto mode and `window.miraSetTheme`/`window.miraGetTheme`; the inline pre-paint boot script in each page `<head>` does initial resolve to avoid FOUC. `<html data-theme>` is the only light-mode trigger — no `@media` interaction.
- `notification_center.js` — docstring-only TODO stub (reminder bell spec); no code, loaded by no page. Do not treat its endpoint sketch as an implemented contract.
- `marked.min.js`, `purify.min.js` — vendored libraries: marked v12.0.0 (markdown) and DOMPurify 3.0.9 (sanitizer), loaded before any renderer. Bump-together and `?v=` contract owned by `web/AGENTS.md` (Rules).

## Wiring

- **Boot chain** (chat-page manifest order, `web/AGENTS.md`): `api-client.js` defines the class -> `core.js` `initializeMira()` instantiates it into `AppState.apiClient`/`window.miraAPI`, validates the session, builds `SettingsManager`, calls `initDomainKnowledge`, then `window.setupEventListeners()`/`setupDelegatedEvents()` (events.js) and `window.loadLastSessionResponse()` (messaging.js). Reordering any of these leaves a `window.*` dependency undefined.
- **Send chain**: `events.js` submit/click -> `messaging.js` `sendMessage` (starts `handleSendMessage` immediately, then runs the plunger animation; `AppState.knockGate` couples the two so the previous response is knocked off screen in sync) -> `api-client.js` `chat.sendMessage` -> WS `message` frame. `turn_started` binds `message_id` to the server `turn_id`; `assistant_delta` chunks accumulate in `streamingState.buffer` and render as complete paragraph/code blocks; `turn_complete`/`turn_stopped`/`turn_error` resolve/reject the awaited send. The stop button (`.stop-mode`) routes to `messaging.js` `window.cancelGeneration` -> `api-client.js` `cancelGeneration()` `halt` frame.
- **Feedback scan chain**: `messaging.js` exports `window.completeStreamingResponse` -> `repulsion-feedback.js` wraps it at load time; its scan only sees DOM text after `completeStreamingResponse` runs, so moving the scan earlier sees an empty response.
- **Sidebar <-> page**: `sidebar.js` is shared by chat and settings pages; chat-only buttons no-op via `isOnChatPage()`. `?history=1` on any page redirects here and polls (100ms, 50 tries) for `window.InlineHistory.expand`.
- **Reconnect path**: WS close (non-1000) -> `_scheduleReconnect` backoff; `ui.js` `visibilitychange` short-circuits the backoff; `core.js` `onConnect` then drains `AppState.messageQueue` and recovers an interrupted response.
- **History fetch chain**: `history.js` pagination state (`AppState.historyDrawer` / `InlineHistoryState.nextBefore`) -> `api-client.js` `history.getHistory` (keyset `before`, one-day `start_date`/`end_date` window for the calendar) -> `cns/api/data.py:DataEndpoint` (contract owner: `cns/api/AGENTS.md`, Files) -> page reversed to newest-first in `history.getHistory` before any renderer sees it. There is no second normalization point.

## WebSocket turn protocol (client side of `cns/api/websocket_chat.py`)

Outbound frames the browser may send: `{type: 'auth'}` (empty — the server validates the httpOnly session cookie; non-browser clients may instead present an API token), `{type: 'message', message_id: <UUID>, content, include_thinking, [image|document + *_type]}`, `{type: 'halt', turn_id}`, `{type: 'ping'}`. Inbound frames handled by `_handleMessage`:

| Frame | Client handling |
|---|---|
| `auth_success` | state -> `authenticated`, emit `onConnect`, drain queue, start keepalive |
| `turn_started` | binds `turn_id` <-> `message_id` (`turnToMessage` map); enables `cancelGeneration` |
| `assistant_delta` | append to pending callback's `chunks` |
| `thinking` | forwarded to `onMessage`; `messaging.js` renders the thinking drawer |
| `tool` | re-emitted as normalized `tool_event` for badge updates |
| `model_error` | forwarded to `onMessage`; `messaging.js` shows a persistent invalid-tool-call notice |
| `context_reset` | forwarded to `onMessage`; `messaging.js` clears `streamingState.buffer`/render state and the response DOM so a retried attempt renders as the single response |
| `turn_complete` | frame carries flat `response` + `continuum_id` + `tools_used`/`processing_time_ms`/`emotion` (not a nested metadata object); the resolved send-promise value nests them under `metadata` and falls back to the joined `assistant_delta` text when `response` is empty |
| `proactive_message` | server-initiated heartbeat breakout message; `_handleProactiveMessage` routes to `window.handleProactiveMessage` which renders it through the standard message path (also included in history loads) |
| `turn_stopped` | frame field is `reason` (`halt`\|`disconnect`); resolves with `stopped: true` + `stop_reason` (a halt must still resolve, or the send button stays in stop-mode) |
| `turn_error` | rejects the send promise |
| `protocol_error` | `AUTH_FAILED`/`AUTH_TIMEOUT` codes clear auth and stop reconnecting; otherwise `_handleServerError` routes by the frame's optional `message_id` when present (rejecting only that send's promise) and falls back to the FIFO active callback |
| `server_shutdown` | treated as a server error |
| `pong` | keepalive no-op |

Turn routing (`_callbackForTurn`) prefers the `turn_id`->`message_id` map; FIFO over `messageCallbacks` is only the fallback for a terminal frame arriving before `turn_started`. `_rejectPendingCallbacks` on socket close is what prevents duplicated streaming handlers across reconnects.
