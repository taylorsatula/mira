# tools/implementations/ — MIRA's LLM-callable tool implementations

Every tool the main conversation, sidebar agents, and sub-agents invoke lives here as a `Tool` subclass registered with `tools/registry.py:registry`.

## Rules

- The four-piece registration flow is owned by `tools/AGENTS.md` (Rules, Rule 1). Child-specific: `simple_description` is required here — skipping it drops the tool from the `invokeother_tool` catalog and enum, leaving it unloadable at runtime unless it is in `ESSENTIAL_TOOLS`.
- The startup tool set is owned by `tools/AGENTS.md` (`ESSENTIAL_TOOLS` in `tools/repo.py`). Consequence here: a tool in neither `ESSENTIAL_TOOLS` nor config-enabled by default is always opt-in via `invokeother_tool` (`load` = this turn only, `load_for_rest_of_session` = pinned).
- Per-user credentials come from `utils/user_credentials.UserCredentialService.get_credential(credential_type, service_name)` and missing credentials must raise with user-facing setup guidance — never fall back to env vars or defaults. Users: `homeassistant_tool` (`tool_config` JSON + `api_key`/`home_assistant` token), `imagegen_tool` (`api_key`/`google_genai`), `web_tool` (`credential_name` injection in `http` op). `email_tool` is the exception: it loads via `utils/tool_config_store.load_user_tool_config("email_tool", hydrate_secrets=True)`.
- User-scoped binary artifacts follow the `.bin` + `.meta` sidecar convention: `data/users/{user_id}/artifacts/{file_id}/{random}.bin` with a `.meta` JSON sidecar (`filename`, `mime_type`), matching `utils/artifact_store.py:save_file_artifact`. `imagegen_tool._save_image`/`_load_image` hand-roll this convention; served via `cns/api/files.py` routes `/files/{file_id}` (download) and `/images/{file_id}` (inline). Artifacts persist across segment collapse — no cleanup path deletes them.
- Tool return contracts at the `cns/services/tool_loop.py` boundary: a tool returning a **list** has it passed through verbatim as provider content blocks (currently only `imagegen_tool` generate/refine, which returns image+text blocks with a 512px WebP compressed copy for replay); a dict is `json.dumps`-ed; a dict with `success: False` is additionally treated as a reported error by the circuit breaker. The special result key `_image_artifact` (`{file_id, alt_text}`) is consumed by `cns/services/orchestrator.py` to emit `![alt](/v0/api/images/{file_id})` into the user stream. Do not invent other underscore-prefixed result keys without a consumer.
- Parameters are filtered and coerced by `tools/repo.py:invoke_tool` — full contract owned by `tools/AGENTS.md` (Rules). Consequence: schema-declared params may be passed to every operation of the same tool even when that operation ignores them — each `run()` must tolerate or filter extra kwargs (see `continuum_tool._SEARCH_PARAMS`, `reminder_tool`'s `inspect.signature` filtering).
- A model-supplied timestamp with no offset is the **user's local wall time**, never UTC — the only clock the model sees is the `<current_datetime>` trinket rendered in the user's timezone. Parse with `parse_time_string(value, tz_name=get_user_preferences().timezone)`, catching `RuntimeError` → `"UTC"` when there is no user context, then `ensure_utc`. Values carrying `Z` or an explicit offset are honoured as given. Falling back to the system default zone shifts every non-UTC user's intent by their whole offset. Where an exact wall time names one specific moment (`reminder_tool._parse_date`, `punchclock_tool._parse_time_input`), it is resolved DST-strictly via `normalize_exact_local_wall_time` + `local_datetime_to_utc_iso` so ambiguous/nonexistent times raise instead of silently picking a side of the transition — keep those resolutions outside the lenient-parse fallback ladder.
- SQLite user data fields that must be encrypted at rest use the `encrypted__` column prefix (`utils/userdata_manager.py` encrypts on insert, decrypts transparently on select). Table DDL must declare the `encrypted__` columns; reading helpers must not double-decrypt already-decrypted rows (`pager_tool._decrypt_row_safely` pattern).
- Parallelism: `Tool.parallel_safe` defaults to True. Mutating tools opt out per-operation via a `_parallel_safe_operations` frozenset + `is_call_parallel_safe` override (`domaindoc_tool`, `homeassistant_tool`, `memory_tool`, `reminder_tool`) or `parallel_safe = False` (`bash_tool` — any shell command may mutate host state, so there is no enumerable safe-operation set and per-operation gating is the wrong model for a shell; `imagegen_tool`, `phoneafriend_tool`). Known ordering quirk documented in `domaindoc_tool`: the tool loop runs sequential tools before parallel ones, so a parallel + sequential pair issued in one response executes in reverse semantic order (non-corrupting for domaindoc writes).
- Disabled-by-default tools (`sidebar_tool`, `homeassistant_tool`, `weather_tool` — all `enabled: bool = Field(default=False)`) are discovered but not loaded at startup; they surface only through `invokeother_tool` when their config is enabled. `sidebar_tool` additionally stays out of the main conversation permanently — it is sidebar-agent-only, fetched by name via `tool_repo.get_tool('sidebar_tool')`, which succeeds for disabled tools.

### Credential-referencing without exposure

`web_tool.http` is the only path where the LLM names a credential (`credential_name`) instead of supplying a secret: `UserCredentialService.get_credential_metadata` supplies `allowed_domains`, `validate_domain_filters` binds the request host to them, and the value is injected into `credential_header` with `credential_prefix` server-side. Response headers are sanitized against `_SENSITIVE_RESPONSE_HEADERS` and the injected header name so the credential never echoes back. Any new tool that injects secrets into outbound requests must follow this shape — never return the value to the model.

## Files

- `contacts_tool.py` — Contact CRUD against the user SQLite `contacts` table (schema in `schemas/contacts_tool.sql`). Ops: `add_contact` (incl. batch via `contacts` JSON array), `get_contact`, `list_contacts`, `delete_contact`, `update_contact`. `_find_by_identifier` resolves UUID → exact name → starts-with → contains, returning `ambiguous`/`needs_confirmation` soft-path responses instead of guessing on partial matches. No match raises `ContactNotFoundError` (a ValueError subclass carrying the identifier — the documented raise channel; `cns/api/AGENTS.md`'s ContactsDomainHandler maps it to the 404 envelope) — never a `success: False` return, which lets callers manufacture false success on absent resources. Tool-result dicts keep `encrypted__`-prefixed keys (LLM-facing storage shape); the API boundary projects them (owned by `cns/api/AGENTS.md`).
- `continuum_tool.py` — Conversation-history search against the CNS continuum via `cns.infrastructure.continuum_repository`. Ops: `search` (hybrid vector+BM25 over segment summaries/precis or BM25 over time-bounded messages), `search_within_segment`, `expand_message` (full message + context window), `get_tool_result` (re-fetch a collapsed tool result by `tr_` breadcrumb ID). Confidence clustering filters results (`_filter_results_by_confidence`); entity boosting via `entities` param; temporal params parse through `_parse_model_wall_time` (user-local-wall-time rule above). Consumers: essential tool; search tier is the primary history-retrieval surface.
- `domaindoc_tool.py` — Section-aware domain knowledge documents (user SQLite `domaindocs`/`domaindoc_sections`/`domaindoc_versions`). Ops: overview, search, create, enable/disable, expand/collapse, pin/unpin, create/rename/delete/reorder sections, append, sed, sed_all, replace_section, plus `request_create`/`request_delete` noops that return guidance. `create` (2026-09-15) makes a doc directly: `new_label` (lowercase kebab, validated) + optional `doc_description` + first section/header/content, enabled immediately — it exists because the web UI that previously owned creation is inactive, and a `label` enum bound to existing docs cannot carry a new label, so `create` takes `new_label` instead. `tool_schema` is a `@property` rebuilding a live label catalog (own docs + accepted shares via `utils/domaindoc_shares`) at schema-read time — a `label` enum changes when docs are created, not when enabled. Nested sections: depths 0/1/2 supported — `parent` resolves at any depth (`_resolve_section_by_header`: shallowest match wins, same-depth duplicate headers rejected as ambiguous), and only depth-3 creation is rejected ("Maximum nesting depth is 2. Cannot add children to a sub-subsection."); the depth/resolution contract is owned by `cns/api/AGENTS.md` (`DomainKnowledgeDomainHandler._section_depth`/`_resolve_section_by_header` — twin implementations, same-commit change required). `_record_version` numbers versions contiguous per section and every section-scoped payload carries the as-of content in `diff_data["content"]` (restorable by the API's `rollback_section`); the version scheme is owned by `cns/api/AGENTS.md` (`DomainKnowledgeDomainHandler._record_version`); doc-level rows (`section_id` NULL) number in their own bucket and are not rollback targets. Pinned sections cannot be collapsed or deleted; delete requires the section (and all subsections) to be expanded first. Consumers: shared-doc edits invalidate trinket caches for both owner and collaborator (`invalidate_domaindoc_cache`), and section writes trigger `cns/services/domaindoc_summary_service.update_section_summary`.
- `email_tool.py` — Full IMAP/SMTP client. Ops: get_emails, get_email_content, mark_as_read/unread, delete, move, send_email, reply_to_email, create_draft, search_emails, list_folders, mark_for_later_reply, get_emails_for_later_reply. All eight mutating ops require a `reasoning` param (`_MUTATING_OPERATIONS`), logged to the user SQLite `email_action_audit` table with `encrypted__` fields — audit trail staged for future autonomy expansion (the reply-only `SIDEBAR_EMAIL_SCHEMA` template is retained but unused). Email IDs are self-contained `folder:uid` strings; later-reply state persists in `self.user_data_path/later_replies.json`. `validate_config` connects live and auto-discovers folder mappings. `from`/`subject`/`body_text` in list and read envelopes cross the `utils.untrusted_content.wrap_untrusted` boundary.
- `feedback_tool.py` — Writes user friction signals to PostgreSQL `user_feedback` (`PostgresClient("mira_service", user_id=...)`); categories feature_request/bug_report/confusion/praise/other. No-op state, pure insert. `parallel_safe = True`.
- `forage_tool.py` — Fire-and-forget speculative research: spawns a daemon thread (with `contextvars.copy_context()` to propagate user context) running `agents/implementations/forage_agent.py:ForageAgent`. Params: `query` + `context` to launch, `refine_task_id` to refine a previous result (auto-dismisses it), `dismiss_task_id` to clear, `blocking` (default false) to run synchronously — the agent executes inline on the caller's thread via `SidebarAgent.run_blocking()` (no trinket publishes; the briefing is the tool result; iteration-capped to `ForageToolConfig.max_iterations`, wall-clock to `sidebar_dispatcher.blocking_agent_timeout_seconds`). Status updates publish `UpdateTrinketEvent` targeting `working_memory/trinkets/forage_trinket.py` (background mode only; blocking mode publishes none). Requires `ToolRepository` + `WorkingMemory` constructor args.
- `heartbeat_tool.py` — Decision record for the heartbeat wake cycle (`cns/services/heartbeat_service.py`). Ops: `confirm` (writes `tick_id`/`decision`/`reason`/`wake_in_seconds` to user SQLite `heartbeat_log`; returns turn-ending guidance — keepsleeping must be followed by the literal final word `keepsleeping`, breakout continues the turn) and `status` (recent decisions + live config). `wake_in_seconds` (keepsleeping only, 60..`config.heartbeat.max_sleep_seconds`, rejected outside bounds; providing it with breakout raises) requests a long quiet sleep: the service stamps `heartbeat_wake_at` = now + value on the segment sentinel and no ticks fire until then. DDL lives in module-level `HEARTBEAT_LOG_DDL` with `ensure_heartbeat_log(db)` — the service calls that before its reads, so ordering between tool and service never matters; `ensure_heartbeat_log` also ALTERs `wake_in_seconds` into tables created before the column existed (duplicate-column error is the expected no-op). Read-only for the cycle itself: it never wakes anything. `parallel_safe=False` with `is_call_parallel_safe` allowing `status`.
- `homeassistant_tool.py` — Home Assistant REST control. Local SQLite `entity_registry` caches topology only (GC'd after 24h, `_REGISTRY_STALE_HOURS`) for fuzzy name resolution (`_resolve_entity`: direct entity_id → exact → starts-with → contains, ambiguity raises); state is always fetched live. Ops: get_state(s), find_entities, turn_on/off, toggle, call_service, list_services. Read ops are parallel-safe.
- `imagegen_tool.py` — Image generation via Google Gemini (`MODEL = "gemini-3.1-flash-image-preview"`). Chat-session lineage: `generate` opens a session, `refine` replays serialized history (`self.user_data_path/sessions/{session_id}.json`, base64 inline_data) so refinements carry all prior prompts+images; per-generation records in user SQLite `image_generations` (`encrypted__prompt`). `publish` returns the `_image_artifact` key (see Rules). Only tool returning a bare content-block list.
- `invoke_skill_tool.py` — Loads a skill's full instructions by exact name and activates them: `run(skill_name)` → `utils.skill_files.load_skill(user_id, …)` → returns the body AND publishes `{'action': 'activate', 'name', 'body'}` to `working_memory/trinkets/active_skills_trinket.py` so the body persists in the system prompt for the rest of the segment instead of scrolling away in tool-result history. Essential tool (`ESSENTIAL_TOOLS`) — the `skills_catalog` prompt section always instructs the model to call it, so it must be in every user's baseline, and turn-end ephemeral cleanup must not evict it. The tool name must stay `*_tool`-sufficed: `config/config_manager.py:AppConfig.__getattr__` only routes `*_tool` names to tool config, so any other spelling silently loses the config gate and per-user overrides. Not-found returns `success: False` listing available names (recovery guidance pattern). `parallel_safe = True` (activation is an idempotent overwrite).
- `invokeother_tool.py` — Meta-tool for on-demand loading. Builds its schema at construction from `tool_repo.list_all_tools()`, embedding a name→simple_description catalog (minus essential, gated, and config-disabled tools). `load` = ephemeral (auto-removed after the turn), `load_for_rest_of_session` = pinned via `tool_repo._pinned_tools`. Note the catalog is baked at construction; newly created tools are not reflected.
- `maps_tool.py` — OpenStreetMap geocoding/places via `utils/nominatim_client.py` (Nominatim + Overpass; no API key). Ops: geocode, reverse_geocode, place_details, places_nearby, find_place, calculate_distance (haversine). Place IDs are OSM element refs (`N`/`W`/`R` + osm_id, e.g. `N123456789`).
- `memory_tool.py` — LT_Memory management. Ops: search (hybrid + entity hub discovery + link traversal over top 5 results, `ThreadPoolExecutor` with `copy_context()`; hub discovery uses only the caller-supplied `entities` names — none means no hub pool), create_memory (queues `PendingManualMemory` to Valkey `pending_memories:{user_id}:{segment_id|presegment}`, TTL 24h, processed at segment collapse), link_memories (typed link with `bond` → `extraction_bond`), annotate_memory, touch (post-response mention boost), archive (soft-delete), merge_memories (delegates to `lt_memory.factory` consolidation handler; sources archived, links transferred, new memory stamped `last_tended_at`). Exports `CURATOR_MEMORY_SCHEMA` — full schema minus `create_memory` — consumed by `agents/implementations/memory_curator_agent.py` via `tool_schema_overrides`. `run()` enforces `_OPERATION_REQUIRED_FIELDS` — a presence gate (missing or explicit-null parameter → guided `ValueError` naming the missing fields) checked before dispatch — because the JSON schema requires only `operation` and a missing operation-specific argument would otherwise surface as a raw `TypeError` from the `_op` method's argument binding, before the tool's recovery-guidance channel can run. Memory IDs resolve by either identity form (`_resolve_memory`, classified by module-level `_memory_id_form`): a reference that parses as a complete UUID (dashed, dash-less, or `mem_`-prefixed) is an exact match against `memories.id`; anything else resolves via the `mem_XXXXXXXX` short-prefix LIKE match (`utils/tag_parser`) with a LIMIT 2 collision check — an 8-char prefix collision raises `ValueError` (ambiguous) rather than silently picking one row, so link/annotate/archive/merge/touch fail correctly and a caller holding the full UUID can always act.
- `bash_tool.py` — Guardrailed local shell executed on the machine MIRA runs on via subprocess (`bash -c`, no network transport), as the service user from `root` (default: that user's home directory, `Path.home()` at import — whatever it is named). Ops: `run` (synchronous; bounded by the parent `subprocess` timeout with the child started as its own session leader so a timeout SIGKILLs the whole process group — no GNU `timeout` binary in the composition, it is absent on stock macOS; returns exit code plus capped stdout/stderr) and `run_background` (nohup-detached; returns PID and a log path under `~/.mira_logs/`). `_validate_command(command, root, cwd)` is the guardrail entry point and raises before anything reaches the host; it runs two layers that cover what the other cannot. The **pattern layer** is regexes over the raw string, so it catches destructive literals buried in quotes or nested interpreters (`bash -c "rm -rf /"`, `python -c "os.system('rm -rf /')"`) that tokenization would hide. The **argument layer** (`_analyze_command`) tokenizes with `shlex`, splits into simple commands, resolves each verb through command runners (`sudo`/`nohup`/`timeout`/`ssh`/`sh -c`, recursing to `_MAX_NESTING`), and checks path operands against `_classify_path` — which is what catches what no regex can express: relative operands (`rm -rf .` from the root), quoted and globbed spellings of a protected path, and destructive verbs other than `rm` (`shred`, `mv`, `find -delete`, `truncate`, `dd of=`, `chmod`/`chown` in any mode syntax). `_analyze_substitutions` re-runs the argument layer over every quoted `$(...)`/backtick body as its own command line, so a destructive command hidden inside a quoted substitution is caught by the argument layer, not only by the pattern regexes. The find-narrowing carve-out requires a genuinely narrowing predicate (`_find_narrows`): a find expression whose predicate matches everything (empty predicate, `-name '*'`-style match-all, expressions reducing to no constraint) or is unparseable falls back to the guarded refusal — conservative by construction. Gotchas: `cwd` must be the *resolved* working directory and is threaded through `cd` segments, so `_run`/`_run_background` resolve `workdir` before validating; operands of destructive verbs containing `$`, backtick, or `~` are refused as `unverifiable-expansion` rather than guessed at (the model must pass literal paths); a glob whose parent is protected and whose basename matches everything (`rm -rf *` at the root) is refused, while `rm *.pyc` and `rm -rf cache/*` stay legal; `_classify_path` protects `/`, the root and every ancestor, the system tree on BOTH platform layouts (Linux FHS dirs plus macOS `/System`, `/Library`, `/Applications`, `/private`, `/Volumes`, `/cores`), user homes under either shape (`/home/<name>` and `/Users/<name>` — protecting only the Linux shape left cross-user home deletion unguarded on macOS), self-only dirs (`/tmp`, `/mnt`, `/media`, `/snap`, `/lost+found`, and the `/home` + `/Users` containers — themselves but not their contents), and `<root>/.git`; the four `git-*` patterns refuse `checkout`/`restore` wholesale, not just their discarding forms, because that breadth is the user's standing rule — do not narrow them. Redirects into `/dev/null` are explicitly allowed (the bit bucket is benign — without the carve-out the argument layer refused every `2> /dev/null` as a system-path write; regression cases Z67/Z68 pin it). Every refusal is raised by `_refuse` and appends `_ESCALATION`, which tells the model to stop work and wait for a human rather than rephrase around the gate. The guardrail is a safety net, not a sandbox: paths are not confined beyond the default cwd, and it cannot see through arbitrary obfuscation. Regression battery: `tests/protected/bash_guardrail_probe.py` (admission owned by `tests/protected/AGENTS.md`) — run it after any change to the patterns or `_analyze_command`, since it asserts both halves (destructive refused, benign allowed) and a rule that over-blocks is as broken as one that under-blocks.
  - Self-edit app-tree rule: `_load_app_tree()` computes `_APP_TREE` once at import, outside the validator (the protected battery dis-walks `_validate_command` and refuses any non-inert global, so the validator reads only that tuple). When self-edit is active (`utils/AGENTS.md`, `self_edit.py`), `_classify_app_tree_path` makes paths inside the code tree editable — the path-anchored patterns in `_APP_TREE_PATH_RULES` skip matches there — while refusing the tree root (`app-root-delete`) and every untracked top-level name from `.git/info/exclude` (`app-untracked-delete`: data, venv, .env, logs, .git — no rollback covers them). Inactive: no exemption, `/opt/mira/app` stays a system path. `_SELF_EDIT_NOTE` adds the model-facing sentence only when active.

- `phoneafriend_tool.py` — Synchronous outside-model consultation on the single `other` route (`OUTSIDE_MODEL_CONFIG = "other"`; no model choice param — both historical voices collapse onto one route). - `punchclock_tool.py` — Focus-session time tracking in user SQLite `punchclock_sessions` (state machine running/paused/completed with accumulated segments). - `reminder_tool.py` — Reminder scheduling in user SQLite `reminders` with contacts linking (`contact_uuid` from `contacts_tool`'s table; substring match, silent no-link on no match, explicit `contact_lookup_failed` on store failure). Ops: add/get/mark_completed/update/delete/snooze/batch. The extra-context param is `additional_notes` everywhere — `_add_reminder`/`_update_reminder` signature, JSON-schema property, storage column `encrypted__additional_notes`, and the actions-API create/update schema field — one term for the concept (renamed from `notes`; the actions handler passes action data through `**kwargs`, so a name split between schema and tool param is a silent drop, since `run()`'s `inspect.signature` filter discards unknown kwargs). The id-addressed ops (mark_completed/update_reminder/delete_reminder) raise `ReminderNotFoundError` (a ValueError subclass carrying the identifier and the available-active-reminders listing — the documented raise channel; `cns/api/AGENTS.md`'s ReminderDomainHandler maps it to the 404 envelope) — never a `success: False` return, which lets callers manufacture false success on absent resources. `_batch` buckets per-id outcomes into `succeeded`/`not_found`/`failed` (each failure with its reason). `category` param: `user` (default) or `internal` — internal reminders are MIRA's own proactive follow-ups, and the schema description is the contract instructing the model to bias toward creating them. Duplicate detection (`_check_duplicate_reminder`) returns the existing reminder on retries. Date parsing handles relative phrases and DST-strict exact wall times. Tool-result dicts keep `encrypted__`-prefixed keys (LLM-facing storage shape); the API boundary projects them (owned by `cns/api/AGENTS.md`).
- `selfedit_tool.py` — Applies MIRA's own code edits by restarting (contract owned by `utils/AGENTS.md`, `self_edit.py`). Ops: `request_restart` (refused with no uncommitted edits; `self_edit.schedule_restart_after_turn` restarts once the turn's lock frees) and `status` (uncommitted edits, stashes by ref and hash). Retrying or dropping a stashed edit is plain git through `bash_tool`; the outcome arrives as an activity-feed item. Not in `ESSENTIAL_TOOLS`; `enabled` defaults to `self_edit.is_active()`, so inactive installs never list it in the `invokeother_tool` catalog. Both ops refuse with the inactive reason.
- `sidebar_tool.py` — Sidebar-agent lifecycle: scratchpad write/read/clear plus `complete_task` (UPSERT into `sidebar_activity`). Registered with `enabled: False`; the `SidebarAgent` base enriches params with `thread_id`/`interface_name`/`agent_id`/`run_count` before execution — those params are not in the schema. - `sidebaragents_tool.py` — Main-conversation management of sidebar activity, reading/writing the same `sidebar_activity` and `scratchpad` tables `sidebar_tool` writes. Ops: list_activity, get_details (parses each scratchpad row into a strict `ScratchpadNoteRecord` and raises on any non-conforming row — model-authored free text is never returned raw), dismiss, resolve — dismiss/resolve use the rowcount-returning `db.update()` and raise on 0 rows (unknown thread_id is a failure, never a phantom success). Requires `WorkingMemory` constructor arg for event_bus trinket refresh via `agents/base.py:_publish_trinket_refresh`.
- `weather_tool.py` — OpenMeteo forecasts + WBGT heat-stress calculation (NIOSH/OSHA thresholds from config). Ops: get_forecast, get_heat_stress. Location is either lat/lon or a name geocoded via `utils/nominatim_client.py`. File-based response cache under `self.make_dir("cache")` keyed by coords/type/days/date/params. Disabled by default.
- `web_tool.py` — Search (Kagi primary — vault key via `clients/vault_client.get_api_key("kagi_api_key")` — DuckDuckGo fallback), fetch (trafilatura over HTTP; escalates to Playwright when extraction < `_MIN_EXTRACT_LENGTH`; LLM synthesis via `fast` route when page > 5000 chars or `focus` given), and raw `http` with SSRF protection: `_request_with_validated_redirects` validates every redirect hop with `utils/url_safety.validate_public_http_url` then connects to `validated.resolved_ip` via `http_client.pinned_request` — no DNS re-resolution, rebinding-proof. `http` supports domain allow/block filters and `credential_name` injection (see Rules). All external text in return envelopes crosses the `utils.untrusted_content.wrap_untrusted` boundary: fetch `content`/`title`, search result `title`/`snippet`, synthesis LLM input, `http` text bodies, and parsed-JSON bodies on the `json`/`full` formats (serialized with `json.dumps` before wrapping — no in-tree consumer reads them structurally).
- `whilethecatsaway_tool.py` — Fire-and-forget curiosity research: daemon thread runs `agents/implementations/whilethecatsaway_agent.py:WhileTheCatsAwayAgent`, which stores findings as LT_Memory entries. ## Wiring

- Discovery is import-driven per `tools/AGENTS.md` (Rules); this directory has no `__init__.py` — module-level `registry.register(...)` calls are the only registration path.
- Dependency injection at construction is performed by `tools/repo.py:ToolRepository.get_tool`, which inspects constructor annotations and injects `ToolRepository` (self), `WorkingMemory`, or `LLMProvider` instances. only REQUIRED constructor params (those with no default) are candidates; a required annotated param gets its dependency automatically, but an annotated param with a default is deliberately skipped — DI never injects it. `invokeother_tool` (required `tool_repo`) receives `ToolRepository`; `forage_tool`/`whilethecatsaway_tool` (required `WorkingMemory` + `ToolRepository`) receive both, `sidebaragents_tool` (required `WorkingMemory`) receives it; `phoneafriend_tool` carries a defaulted dependency param (`llm_provider: LLMProvider | None = None`) that is never injected; everything else takes none or required injected params. `invokeother_tool` reads `ESSENTIAL_TOOLS` from `tools/repo.py` at construction.
- Trinket events out (all synchronous `UpdateTrinketEvent` via the `WorkingMemory`-injected `event_bus`): `forage_tool` targets `ForageTrinket` (exists in `working_memory/trinkets/`); `sidebaragents_tool` refreshes via `agents/base.py:_publish_trinket_refresh`.
- Inbound import edges (this directory is the consumer): `continuum_tool` → `cns/infrastructure/continuum_repository.py` and `clients/embeddings_provider.py` (query embeddings); `memory_tool` → `clients/valkey_client.py`, `lt_memory/db_access.py`, `lt_memory/hybrid_search.py`, `lt_memory/models.py` (incl. `PendingManualMemory`), `lt_memory/hub_discovery.py`, and the consolidation handler from `lt_memory/factory.py`; `web_tool` → `utils/url_safety.py` (SSRF validation), `utils/http_client.py` (`pinned_request`), and the third-party `kagiapi`/`ddgs`/`trafilatura` clients; `pager_tool` → `clients/lattice_client.py` (federation writes) and `clients/llm_provider.py` (`fast` route distillation); `phoneafriend_tool` → `clients/llm_provider.py` (`OUTSIDE_MODEL_CONFIG = "other"` — the only consumer of the `other` route); `feedback_tool` → `clients/postgres_client.py` (user-scoped `PostgresClient("mira_service", user_id=...)`); `sidebaragents_tool` imports `agents/base.py:ensure_activity_schema` at module level (import-time edge into `agents/`).
- Cross-directory contracts out: `CURATOR_MEMORY_SCHEMA` → `agents/implementations/memory_curator_agent.py` (`tool_schema_overrides`); `forage_agent`/`whilethecatsaway_agent` run with tool repos restricted to `available_tools = ["continuum_tool", "memory_tool", "web_tool"]` / `["web_tool", "memory_tool", "continuum_tool"]` (enforced in `agents/implementations/forage_agent.py` and `agents/implementations/whilethecatsaway_agent.py`); `deliver_federated_message` → `cns/api/federation.py` (inbound federation can write but not read); result-envelope handling (list-of-blocks pass-through, `_image_artifact`, `success: False`) → `cns/services/tool_loop.py` + `cns/services/orchestrator.py`; `create_memory` queues → LT_Memory collapse chain (`lt_memory/AGENTS.md`, Storage flow); `domaindoc_tool` section writes → `cns/services/domaindoc_summary_service.update_section_summary`, and shared-doc edits invalidate trinket caches for both collaborators via `utils/domaindoc_shares.invalidate_domaindoc_cache`.
- Schema-in/schema-out dependency: `contacts_tool` owns the `contacts` table that `reminder_tool` links to by `contact_uuid` — same user SQLite store via each tool's `self.db` (`utils/userdata_manager.py`). A reminder referencing a deleted contact keeps its stale UUID.
