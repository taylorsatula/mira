# tools/implementations/ — one `Tool` subclass per capability the model can call

## Files

- `bash_tool.py` — guardrailed local shell, with the restart latch. Open it before changing what a command may do, or why one was refused.
- `contacts_tool.py` — contact CRUD in per-user SQLite, resolved by UUID or by name. Open it when a lookup, a duplicate, or an ambiguous-match reply is wrong.
- `continuum_tool.py` — conversation-history search over the continuum. Open it when a history search returns nothing, the wrong window, or times that look shifted.
- `domaindoc_tool.py` — section-aware knowledge documents with per-section versions, sharing, and pinning. Open it before touching the section tree or the version rows.
- `email_tool.py` — IMAP/SMTP mailbox access plus the action audit trail. Its `create_email_tool` factory is dead: no caller anywhere, and instances come from `ToolRepository.get_tool`. Open it before changing a mailbox operation, the IMAP command guards, or the reasoning requirement.
- `heartbeat_tool.py` — briefs: authoring, inspection, and the agent's outcome channel. Open it when a wake-up fires late, re-arms oddly, or never retires.
- `imagegen_tool.py` — image generation and refinement lineage, plus the artifact store `publish` serves from. Open it when a refinement loses context or a published image 404s.
- `invoke_skill_tool.py` — loads a skill body by exact name and keeps it active for the rest of the segment. Open it when a skill will not load or does not persist.
- `invokeother_tool.py` — the on-demand loading meta-tool; its two enums are the loadable-tool catalog. Open it when a tool cannot be loaded, or a loadable one is missing from the enum.
- `memory_tool.py` — long-term memory: search, queued creation, links, annotations, archive, merge. Open it before changing how a memory is found, created, or retired.
- `pager_tool.py` — virtual pager devices, local and federated messaging, device trust. Open it when delivery, a trust verdict, or an inbound federation write misbehaves.
- `reminder_tool.py` — reminders in per-user SQLite with optional contact links and the user/internal split. Open it when a date lands at the wrong instant or a reminder will not resurface.
- `sidebar_tool.py` — the sidebar-agent scratchpad, and the sign-out that closes a thread. Open it before changing what an agent may record or what closes a thread.
- `subagent_tool.py` — one tool surface over every subagent type's lifecycle: start, resume, dismiss, inspect. Open it before changing that vocabulary, its routing, or the activity surface.
- `web_tool.py` — search, fetch, and direct HTTP, with SSRF pinning and server-side credentials. Open it before changing how external text reaches the model.
- `secondarytools_notincontextrn.zip` — archive of retired tool sources; inert, on no package path, and drifting. Not source.

## Wiring

- Discovery: `ToolRepository.discover_tools` imports every module in this package and registers each top-level `Tool` subclass whose `__module__` is that module, keyed by its class `name`; no other mechanism registers a tool. Construction is a separate edge below. A subclass defined in another module, nested inside a function, or re-exported through an import is never discovered — and each module also registers its `*Config` into `tools/registry.py:registry` at import, `invokeother_tool` excepted because it takes no config. Construction, DI, availability tiers, and argument coercion are that map's. Counterpart: `tools/AGENTS.md`.
- Return envelope: a `run()` dict reaches the provider as `json.dumps`, a bare list passes through as content blocks (`imagegen_tool` is the only one), non-empty `context_files` render as separate blocks, `success: False` counts as a reported error the circuit breaker trips on, and `_image_artifact` is read by the orchestrator. Counterpart: `cns/services/AGENTS.md`.
- Shared sidebar tables: `sidebar_tool` and `subagent_tool` both write `sidebar_activity` and `scratchpad` through their own per-user `self.db`, and both call `ensure_activity_schema` before the first write — a change to either writer's row shape reaches the other's readers and the dispatcher. Counterpart: `agents/AGENTS.md`.
- Construction bypass: `cns/api/actions.py:272` (`ReminderTool()`), `cns/api/actions.py:561` (`ContactsTool()`), `cns/api/federation.py:105` (`PagerTool()`), and `cns/api/heartbeat_api.py:112` (`HeartbeatTool()`) build the instance directly, skipping `get_tool`'s DI, the config gate, and the enabled set — so a tool disabled for every user is still reachable down these routes, and an agent/API probe that calls one reads as a working tool. Counterpart: `cns/api/AGENTS.md`.
- Schemas consumed outside this directory: `HEARTBEAT_AGENT_SCHEMA`, `CURATOR_MEMORY_SCHEMA`, and the subagent dispatch protocol are imported by the agent classes. Counterpart: `agents/implementations/AGENTS.md`.
- Model-invoked subagent dispatch: `subagent_tool` resolves the type through `agents.specs.SUBAGENT_SPECS`, calls the class's `activate`/`continue_task` classmethods, and publishes a dismissal through `agents.spawn.publish_result` — so a classmethod signature or return-shape change reaches this file before any caller. Counterparts: `agents/implementations/AGENTS.md`, `agents/AGENTS.md`.
- Brief presence: `heartbeat_tool.refresh_armed_marker` writes the Postgres row the dispatcher enumerates users from. Counterpart: `agents/triggers/AGENTS.md`.
- Brief failure accounting: `heartbeat_tool.apply_run_failure` is called by `HeartbeatAgent.on_completion` with every carried brief that got no valid report, and the caller reads the `briefs` rows itself with `SELECT last_wake_at, state FROM briefs WHERE id = :id` against `BRIEFS_DDL` rather than through this tool — so renaming either column breaks the agent while every operation here keeps working, and a change to the state machine's backoff or `max_failures` terminator reaches the agent. Counterpart: `agents/implementations/AGENTS.md`.
- Domaindoc section model: header resolution and depth accounting (`_resolve_section_by_header`, `_section_depth`), depths 0 through 2, pinned-always-expanded, a collapsed parent hiding every descendant, and `_record_version`'s contiguous numbering govern `domaindoc_tool`, the API handler, and `working_memory/trinkets/domaindoc_trinket.py` alike — a change to any of them is a change to all three, or one site accepts structures another rejects. Counterparts: `cns/api/AGENTS.md`, `working_memory/trinkets/AGENTS.md`.
- Federation write seam: `pager_tool.deliver_federated_message` is the write-only entry the federation router calls. Counterpart: `cns/api/AGENTS.md`.
- Dialect error taxonomy: the tuple `web_tool._synthesize_content` degrades on (`ProviderError` from `clients/llm/dialects/base.py`, `ContextOverflowError` from `clients/llm_provider.py`, raw `httpx` transport errors) is a hand-copied projection of the provider error classes — a new subclass added to `clients/llm/dialects/base.py` is added to that tuple in the same commit, or a failed page condensation stops degrading to a truncated dump and instead propagates out of a fetch that had already succeeded.
- Credentials, wrapping, SSRF, the restart latch, skill files, and per-user SQLite plumbing are all called into, never reimplemented here. Counterpart: `utils/AGENTS.md`.
- Activated skills and subagent results both cross the trinket boundary: `invoke_skill_tool` publishes through `working_memory.publish_trinket_update(target_trinket="ActiveSkillsTrinket")`, while `subagent_tool._active_result` reads `get_trinket("SubagentResultsTrinket").active_results` back after `agents.spawn` publishes it — a rename of either trinket or of `active_results` drops the read with no hasattr guard, and the tool answers "not an active subagent result" for a task that is. Counterpart: `working_memory/trinkets/AGENTS.md`. The payload keys are the contract, not just the target class: `invoke_skill_tool.py` sends `action`/`name`/`body` to `ActiveSkillsTrinket`, and the trinkets map owns the shapes it renders.
- Reminder row projection: `reminder_tool.run(operation='get_reminders')`'s decrypted field names (`encrypted__title`, `encrypted__description`, `reminder_date`, `id`, `completed`) are rendered as-is by `working_memory/trinkets/reminder_manager.py`; the projection and that renderer move together. Counterpart: `working_memory/trinkets/AGENTS.md`.
- Import-time edge: `subagent_tool` imports `agents.base.ensure_activity_schema` at module level, so a `tools/` → `agents/` dependency exists before any call. Counterpart: `agents/AGENTS.md`.
- Guardrail witness: the battery that proves a guardrail change is `tests/protected/bash_guardrail_probe.py`; its admission rules are that map's. Counterpart: `tests/protected/AGENTS.md`.
- Memory queue: `memory_tool`'s `pending_memories:` keys are the durable seam of the collapse chain. The drain lives in `cns/services/segment_collapse_handler.py` (the collapsing segment's queue, the presegment queue, and the stranded-key rescue scan), and a key prefix survives a restart only by being listed in `clients/valkey_client.py:BOOT_FLUSH_PRESERVE_PREFIXES`. Counterpart: `cns/services/AGENTS.md`, and the flush whitelist's own contract is named in `AGENTS.md`.
- Segment-content twin: `continuum_tool._fetch_context_messages` writes its own `messages` SQL and repeats `continuum_repository.load_segment_messages`' two metadata predicates (`is_segment_boundary`, `system_notification`) rather than calling it. The repository owns the boundary predicate and this file copies it, so both move in one commit: a predicate changed on one side only makes a tool-expanded window include a boundary row the cached session dropped, and the model reads a message the client never showed it. Counterpart: `cns/infrastructure/AGENTS.md`.
- Email credential hydration: `EmailToolConfig.password` carries `json_schema_extra={"secret": True}`, which is the only thing telling `utils/tool_config_store.py:load_user_tool_config("email_tool", hydrate_secrets=True)` to pull that field from `UserCredentialService`, and `inbox_poller._try_load_config` then requires `password` among `('imap_server', 'email_address', 'password')`. A secret field's marker must exist before that hydration read: drop it from a field the poller needs and the key arrives absent, the poller reports an unconfigured user instead of a schema error, and no polling thread starts. Counterpart: `cns/services/pollers/AGENTS.md`.
- Search surfacing arm: `memory_tool._search_memories` runs its own two-worker `ThreadPoolExecutor` over `HybridSearcher.hybrid_search` and `HubDiscoveryService.discover_hub_memories` with the literals `similarity_threshold=0.5`, `min_importance=0.1`, and `top_n=limit * 2`, and `memory_tool.__init__` constructs `LTMemoryDB` and `HybridSearcher` itself; the hub service is lazy-loaded on the first search that supplies entities. Those services are built and called before this directory consumes them, so a signature, threshold, or rank-fusion change reaches this file even though it calls no `ProactiveService`. Counterpart: `lt_memory/AGENTS.md`.
- Consolidation: `memory_tool._merge_memories` is the only model-reachable caller of `consolidation_handler.execute_consolidation`, and the tool runs its own precondition first — two or more distinct, resolvable, non-archived ids — before handing the resolved UUIDs across. The handler must have created the merged row before `self._memory_db.update_last_tended([new_id])` runs here; a return before that row exists stamps `last_tended_at` on an id no read finds, which leaves the merged memory looking never tended and puts it back in `get_floor_candidates`' sampling instead of behind the fresh-tend window. Counterpart: `lt_memory/processing/AGENTS.md`.

## Rules

- A tool class that omits `simple_description` is invisible to the model while staying callable everywhere else: `invokeother_tool._build_catalog` runs once in `__init__` and bakes the surviving names into its schema enums, and `ESSENTIAL_TOOLS` in `tools/repo.py` bypasses the catalog entirely — so an agent probe or an API route that calls the tool answers normally while the model has no door to it. Adding the attribute later changes nothing until `invokeother_tool` is constructed again.
- The class `name` must end in `_tool`. `AppConfig.__getattr__` routes only `*_tool` names (and registered ones) to tool config, so any other spelling raises at the first `config.<name>` read and the per-user override and enabled gate are lost.
- Every operation must tolerate the full schema property set. `ToolRepository.invoke_tool` strips only properties the schema does not declare, then binds the rest to `run(**params)` — so a dispatch that forwards `**kwargs` straight into a narrower per-operation method raises `TypeError` for a parameter the model was entitled to send. Filter to the method's signature with `inspect.signature` (as `reminder_tool`, `heartbeat_tool`, and `bash_tool` do) or accept `**kwargs` on every operation.
- Execution order is not the model's order. `ToolLoopExecutor.execute_tools` runs every call whose `is_call_parallel_safe` returned False before it starts any parallel one, so a response that pairs an opt-out operation with a parallel one runs them reversed. The known reversal is `domaindoc_tool`'s expand-then-append, which corrupts nothing because the writes do not read collapsed state; a new pairing that assumes declaration order has to be checked against that loop rather than against the schema.
- A column added to a table whose DDL lives in `utils/userdata_manager.py` (`contacts`, `domaindocs`, `domaindoc_sections`, `domaindoc_versions`, `pager_devices`, `pager_trust`, `pager_messages`, `sidebar_activity`, `scratchpad`) needs a step in `utils/userdata_migrations.py`; a column on a table a tool creates for itself needs an idempotent `ALTER` inside that tool's own `_ensure_*`. `CREATE TABLE IF NOT EXISTS` never alters an existing user file, so a missed step leaves every deployed row one column short and every read of it fails at runtime.
- Changing a `_DESTRUCTIVE_PATTERNS` entry, `_CATASTROPHIC_PATTERNS`, or anything under `_analyze_command` changes what the shell may do, and `tests/protected/bash_guardrail_probe.py` is the witness: run it after the change, because a rule that over-blocks is as broken as one that under-blocks and neither shows up in a passing turn.
- `web_tool.http` is the only path where the model names a credential (`credential_name`). A new tool that injects a secret into an outbound request repeats the shape: bind the credential to allowed domains, validate the destination host against them, inject server-side, and never return the value to the model.

Elsewhere: this map holds no tool's operation list, parameter descriptions, or table schema — each file's module docstring is that record. The authoring walkthrough is `tools/HOW_TO_BUILD_A_TOOL.md`; why a rule reads as it does is in `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## A memory created in a turn, to the graph

The one path where this directory's write is deliberately not a write, and the reason `create_memory` can report success while a search in the same turn finds nothing.

1. `memory_tool._create_memory` builds a `PendingManualMemory` and pushes it to `pending_memories:{user}:{segment}`, or to `:presegment` when the turn has no segment yet. Nothing reaches Postgres here.
2. When that segment collapses, `cns/services/segment_collapse_handler` drains the collapsing segment's queue, the presegment queue, and — via a rescue scan — any older queue key left stranded for the user.
3. Before storing an item, the drain claims `pending_memories_done:{user}:{pending_id}` with a set-if-absent, because storing is not idempotent: the guard lives in the claim, so two overlapping drains cannot both store the same item.
4. Entity tags for the whole batch are extracted before the store loop. A failure there stores the memories untagged rather than failing them, which means entity-name recall will never surface those rows.
5. `source_segment_id` comes from the queue key's own segment suffix, so a memory swept out of a stranded queue is attributed to the segment it was spoken in, not the one collapsing now; the `:presegment` queue predates any segment and contributes no provenance at all.
