# tools/implementations/ — MIRA's LLM-callable tool implementations: one `Tool` subclass per capability

Elsewhere: registration, discovery, DI, param filtering/coercion — `tools/AGENTS.md` · signatures and full op schemas — the tool file · how a feature was built — `git log` · the authoring walkthrough — `tools/HOW_TO_BUILD_A_TOOL.md`.

## Rules

- `simple_description` is required here beyond the parent's four-piece flow: a tool without it drops out of `invokeother_tool`'s catalog and enum, so it is unloadable at runtime unless it is in `ESSENTIAL_TOOLS`.
- Per-user credentials come from `utils.user_credentials.UserCredentialService.get_credential(...)`; a missing credential raises with user-facing setup guidance — env vars and defaults are defects. Users: `imagegen_tool` (`api_key`/`google_genai`), `web_tool` (via `credential_name`, see below). `email_tool` is the exception: it loads through `utils.tool_config_store.load_user_tool_config("email_tool", hydrate_secrets=True)`.
- Return contracts at the `cns/services/tool_loop.py` boundary (counterpart: `cns/services/AGENTS.md`): a list passes through verbatim as provider content blocks (only `imagegen_tool`); a dict is `json.dumps`-ed; a dict carrying non-empty `context_files` renders as JSON plus one `<context_file path="…">` block per entry; `success: False` additionally counts as a reported error the circuit breaker trips on; `_image_artifact` is consumed by `cns/services/orchestrator.py` for the inline image. Never add another underscore-prefixed result key without its consumer.
- Tool names must stay `*_tool`-suffixed: `config/config_manager.py:AppConfig.__getattr__` routes only `*_tool` names to tool config, so any other spelling silently loses the config gate and per-user overrides.
- Every `run()` must tolerate extra kwargs: `tools/repo.py:invoke_tool` passes all schema-declared params to every operation, so an operation that ignores a param still receives it (see `continuum_tool._SEARCH_PARAMS`, `reminder_tool`'s `inspect.signature` filtering).
- A model-supplied timestamp without an offset is the user's local wall time (the only clock the model sees is the `<current_datetime>` trinket) — parse with `parse_time_string(value, tz_name=get_user_preferences().timezone)` catching `RuntimeError` → `"UTC"`, then `ensure_utc`; exact wall times are DST-strict via `normalize_exact_local_wall_time`, kept outside the lenient ladder so ambiguous/nonexistent times raise. Root `AGENTS.md` owns the doctrine; where it bites: `reminder_tool._parse_date`, `continuum_tool._parse_model_wall_time`.
- SQLite user-data fields encrypted at rest use the `encrypted__` column prefix — declare them in DDL, never double-decrypt a decrypted row (contract owned by `utils/AGENTS.md`, `userdata_manager.py`); tool-result dicts keep the `encrypted__`-prefixed storage keys LLM-facing while the API boundary projects them onto documented field names (owned by `cns/api/AGENTS.md`) — a new storage column joins a projection, never passes through.
- `parallel_safe` defaults True; mutating tools opt out per-operation (`_parallel_safe_operations` + `is_call_parallel_safe`: `domaindoc_tool`, `memory_tool`, `reminder_tool`, `heartbeat_tool`) or wholesale when no enumerable safe set exists (`bash_tool`, `imagegen_tool`, `phoneafriend_tool`). Known quirk: the tool loop runs sequential tools before parallel ones — a parallel+sequential pair in one response executes in reverse order; non-corrupting today, record new encounters here.
- Disabled-by-default tools (`sidebar_tool`) surface only through `invokeother_tool` once their config enables them. `sidebar_tool` stays out of the main conversation regardless: sidebar agents fetch it by name via `tool_repo.get_tool`, which bypasses the enabled set.
- Credential-referencing without exposure — `web_tool.http` is the only path where the LLM names a credential (`credential_name`): `get_credential_metadata` supplies `allowed_domains`, `validate_domain_filters` binds the host, the value is injected into `credential_header` server-side, and response headers are sanitized against `_SENSITIVE_RESPONSE_HEADERS` plus the injected name so the secret never echoes back. Any new tool injecting secrets into outbound requests must follow this shape — never return the value to the model.
- `domaindoc_tool`'s depth contract (depths 0–2, any-depth parent resolution, contiguous per-section versioning, `delete_section` rows not rollback targets) is twin code with `cns/api/AGENTS.md`'s `DomainKnowledgeDomainHandler` — change both in the same commit or one accepts structures the other rejects.
- The shell guardrail is two layers with disjoint catches: the pattern layer (regexes over the raw string — the only layer that sees destructive literals inside quotes or nested interpreters) and the argument layer (`_analyze_command`: `_split_lines` → shlex → simple commands → `_classify_path` — the only layer that sees relative operands, globbed or quoted spellings of protected paths, destructive verbs beyond `rm`, and every quoted `$(...)`/backtick body re-analyzed as its own command). The operator blocklist (`_compile_blocklist`) runs first in every mode — skip mode never relaxes it; redirects to `/dev/null` are the one sanctioned argument-layer carve-out.
- `skip_permissions` runs only when `BashToolConfig.dangerous_skip_permissions_enabled` is set, narrowing to the catastrophic core — cron-wipe, mount-change, `audit-log-tamper`, and `guardrail-self-edit` stay refused in every mode. `_CATASTROPHIC_VERBS ⊆ _PROHIBITED_VERBS` and the pattern-subset relation are import-time checks: a misspelling raises rather than silently relaxing a rule. Every executed skip call appends to `guardrail_bypass.log` (`_audit_bypass`) and carries `guardrail: bypassed`; refusals audit nothing.
- Persistence planting and self-editing are refused in every mode: `/etc/sudo*` operands, SSH `authorized_keys*` writes, in-place-edit clusters (`sed -i`, perl `-pi`, awk `-i inplace` — `_inplace_operands`), and anything writing, deleting, truncating, or globbing over the audit log, the guardrail's own files, `tools/`, or `config/` (`_planting_rule`, `_find_spares`, `_load_guardrail_paths`). `_classify_path` protects `/`, root and ancestors, both platform layouts' system trees, user homes under both shapes, self-only containers, and `<root>/.git`; the app-tree exemption (`_load_app_tree`, reading `.git/info/exclude` written by `deploy/python.sh`) lets MIRA edit its own code while refusing the tree root and every untracked top-level name — no git tree, no exemption.
- Every refusal comes from `_refuse` and appends `_ESCALATION` — stop and wait for a human, never rephrase around the gate; precise file edits route to the `precise-file-editing` skill (`working_memory/AGENTS.md`) instead of the shell. Safety net, not sandbox: paths are unconfined beyond the default cwd, and arbitrary obfuscation can defeat it. Witness: `tests/protected/bash_guardrail_probe.py` runs the real `_validate_command` across both halves — destructive refused AND benign allowed; run it after any pattern or `_analyze_command` change, a rule that over-blocks is as broken as one that under-blocks.

## Files

- `contacts_tool.py` — contact CRUD over the user SQLite `contacts` table. Entry: `_find_by_identifier` (UUID → exact → starts-with → contains, `ambiguous`/`needs_confirmation` soft paths). Gotcha: no match raises `ContactNotFoundError` (a ValueError carrying the identifier) — never a `success: False` on an absent resource; the API maps that raise to the 404 envelope.
- `continuum_tool.py` — conversation-history search against the CNS continuum (hybrid vector+BM25 over segments, BM25 over time-bounded messages). Entry: `search`, `search_within_segment`, `expand_message`. Gotcha: temporal params arrive as user-local wall times (`_parse_model_wall_time`).
- `domaindoc_tool.py` — section-aware knowledge documents in user SQLite. Entry: the op dispatch in `run()`, `_record_version`. Gotchas: `tool_schema` is a live-rebuilding `@property` (label enum = own docs + accepted shares at schema-read), so catalogs baked elsewhere go stale; pinned sections reject collapse and delete.
- `email_tool.py` — IMAP/SMTP client over user-configured credentials. Entry: ops in `run()`, `_MUTATING_OPERATIONS`. Gotcha: all seven mutating ops require a `reasoning` param, audited to `email_action_audit` (encrypted__ fields); `from`/`subject`/`body_text` cross the untrusted-content boundary (root rule; `utils/AGENTS.md` owns the wrapper).
- `forage_tool.py` — fire-and-forget research spawner for `ForageAgent` (daemon thread + copied context). Entry: `query`, `refine_task_id`, `dismiss_task_id`, `blocking`. Gotcha: `blocking=true` runs inline via `SidebarAgent.run_blocking()` with all trinket publishes suppressed — the result is the tool return, bounded by `sidebar_dispatcher.blocking_agent_timeout_seconds`.
- `heartbeat_tool.py` — heartbeat briefs: authoring, inspection, and the agent outcome channel. Entry: `schedule`/`report`/`list`/`cancel`, `HEARTBEAT_AGENT_SCHEMA` (grep `rg 'HEARTBEAT_AGENT_SCHEMA'` → the report-only schema consumed by `agents/implementations/heartbeat_agent.py`). Gotcha: Postgres `heartbeat_armed_users` is only the dispatcher-eligibility/device-sleep surface; brief state lives in per-user SQLite.
- `imagegen_tool.py` — Gemini image generation with chat-session lineage (serialized history replayed on `refine`). Entry: `generate`/`refine`/`publish`. Gotcha: the only tool returning a bare content-block list; `publish` returns the `_image_artifact` key; per-generation rows in user SQLite (`encrypted__prompt`).
- `invoke_skill_tool.py` — loads a skill body by exact name and activates it for the rest of the segment (publishes `{'action': 'activate', ...}` to `active_skills_trinket`). Gotcha: essential — the catalog prompt always names it, so turn-end ephemeral cleanup must never evict it.
- `invokeother_tool.py` — on-demand loading meta-tool (`load` = this turn, `load_for_rest_of_session` = pinned via `tool_repo._pinned_tools`). Gotcha: its catalog is baked at construction from `tool_repo.list_all_tools()`; tools created later are not reflected.
- `memory_tool.py` — LT_Memory management. Entry: ops in `run()`, `_resolve_memory`, `_OPERATION_REQUIRED_FIELDS`, `CURATOR_MEMORY_SCHEMA` (grep `rg 'CURATOR_MEMORY_SCHEMA'` → exported here, consumed by `agents/implementations/memory_curator_agent.py` via `tool_schema_overrides`). Gotchas: IDs resolve by either identity form with a LIMIT-2 ambiguity raise on short-prefix collisions (full UUIDs always act); `create_memory` queues to Valkey `pending_memories:*` for the collapse chain, never writes directly.
- `bash_tool.py` — guardrailed local shell executed on MIRA's own host as the service user. Entry: `_validate_command` (pure), `_analyze_command`, `_split_lines`, `_classify_path`, `run`/`run_background`/`kill_background`, the `restart_mira` param. Gotchas: results may carry `context_files` (directory AGENTS.md maps, deduped per segment via `_CONTEXT_DELIVERED`) that `tool_loop` renders as separate blocks; `restart_mira` is gated on the command exiting 0 and fires through `utils/self_restart.py` at turn-gauge zero (mechanism owned by `utils/AGENTS.md`). Guardrail invariants: Rules above.
- `pager_tool.py` — virtual pager messaging with Lattice federation; TOFU device trust (fingerprint mismatch raises `PermissionError` and marks the row conflicted). Entry: `deliver_federated_message` — the write-only entry `cns/api/federation.py` calls: inbound federation can write, never read. Messages over `max_message_length` are distilled on the `fast` route.
- `phoneafriend_tool.py` — synchronous outside-model consultation on the single `other` route (`OUTSIDE_MODEL_CONFIG`; no model-choice param). Segment-scoped thread in Valkey; `subagent_ref` resumes it and is validated against owner user and segment; the consulted model sees only what the `inquiry` carries.
- `reminder_tool.py` — reminder scheduling in user SQLite with optional `contact_uuid` link (substring match; silent no-link on no match). Entry: `add`/`batch`, `_parse_date` (DST-strict), `_check_duplicate_reminder` (60s-window duplicate returns the existing row). Gotchas: id-addressed ops raise `ReminderNotFoundError` (ValueError) — never `success: False`; the extra-context param is `additional_notes` in signature, schema, storage column, and API field — one term, or the API's `**kwargs` silently drops the split name.
- `sidebar_tool.py` — sidebar-agent scratchpad + `complete_task` lifecycle (UPSERT keyed `(interface_name, thread_id)`; the dispatcher's dedup surface). Gotcha: the `SidebarAgent` base injects `thread_id`/`interface_name`/`agent_id`/`run_count` — those must never be schema-exposed to the LLM. `_ensure_schema` also creates `sidebar_audit`, which nothing reads or writes — dead; do not build on it.
- `sidebaragents_tool.py` — main-conversation view of the sidebar activity tables `sidebar_tool` writes. Gotcha: `dismiss`/`resolve` use rowcount-returning `db.update()` and raise on 0 rows — an unknown `thread_id` is a failure, never phantom success; `get_details` parses scratchpad rows strictly and raises on any non-conforming row.
- `web_tool.py` — search (Kagi primary, DuckDuckGo fallback), fetch (trafilatura, Playwright escalation below `_MIN_EXTRACT_LENGTH`, optional `fast` synthesis), raw `http` with SSRF protection (`_request_with_validated_redirects` → `utils/url_safety.validate_public_http_url` → `http_client.pinned_request` on the resolved IP; rebinding-proof). Gotcha: every external text in return envelopes crosses the untrusted-content boundary — fetch `content`/`title`, search snippets, synthesis input, `http` bodies (JSON serialized before wrapping).
- `whilethecatsaway_tool.py` — fire-and-forget curiosity research spawning `WhileTheCatsAwayAgent`; results auto-expire in the trinket after 8 turns (no dismiss path; `working_memory/trinkets/AGENTS.md` owns the state machine). Publishes `failed`/`ThreadCrash` if the agent thread dies.
- `secondarytools_notincontextrn.zip` — archive of retired tool sources; inert (on no package path) and drifting — do not treat as source.

## Wiring

- Up into the framework: each module registers into `tools/registry.py:registry` at import and instantiates only through `tools/repo.py:ToolRepository.get_tool` (DI, per-user context) — construction, availability tiers, and coercion are owned by `tools/AGENTS.md`.
- Consumers: grep, not transcribed lists — direct fetchers `rg 'get_tool\('`; cross-package exports via the greps in the `heartbeat_tool`/`memory_tool` cards.
- Counterpart edges (a change here reaches there, same commit): return-envelope handling ↔ `cns/services/AGENTS.md` (`tool_loop.py`, `orchestrator.py`) · reminders/contacts 404-mapping and domaindoc twins ↔ `cns/api/AGENTS.md` · heartbeat schema, `CURATOR_MEMORY_SCHEMA`, and the forage/whilethecatsaway spawn contracts ↔ `agents/implementations/AGENTS.md` · result-feed trinkets ↔ `working_memory/trinkets/AGENTS.md` · the restart mechanism ↔ `utils/AGENTS.md` (`self_restart.py`) · skills loading ↔ `utils/AGENTS.md` (`skill_files.py`) · untrusted wrapping and SSRF pinning ↔ `utils/AGENTS.md` (`untrusted_content.py`, `url_safety.py`, `http_client.py`) · the guardrail's witness ↔ `tests/protected/AGENTS.md` · the heartbeat briefs store (`heartbeat_tool.py`) ↔ `agents/triggers/AGENTS.md` · `web_tool`'s `ProviderError` synthesis degrade set ↔ `clients/llm/dialects/AGENTS.md` · `continuum_tool`'s `_expand_message` SQL twins `load_segment_messages` ↔ `cns/infrastructure/AGENTS.md` · the inbox poller's config read of `email_tool`'s schema ↔ `cns/services/pollers/AGENTS.md` · the browser client's `'domaindoc_tool'` refresh literal ↔ `ui/browser/assets/javascript/AGENTS.md`.
- Import-time edge: `sidebaragents_tool.py` imports `agents/base.py:ensure_activity_schema` at module level — an edge from `tools/` into `agents/` at import; the DDL constants it guarantees are owned by `utils/AGENTS.md` (`userdata_manager.py`), the second-writer contract by `agents/AGENTS.md`.
- `create_memory`'s Valkey queue keys are the durable seam of the collapse chain — `lt_memory/AGENTS.md` owns the storage flow; the `pending_memories:` prefixes survive Valkey flushes by root-map whitelist.
