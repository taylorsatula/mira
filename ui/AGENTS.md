# ui/ — the two MIRA chat clients: the browser pages the server serves, the standalone terminal client, and the cross-client contracts binding them

Elsewhere: page controllers, the serving contract and boot file check, single-user page auth, cache-bust and theme twins — `ui/browser/AGENTS.md` · the JS modules, the one HTTP/WS transport, CSRF retry, chat-page load order, listener ownership — `ui/browser/assets/javascript/AGENTS.md` · every TUI invariant (single writer, single consumer, slash commands, endpoint store, login, update) — `ui/tui/AGENTS.md` · the full inbound frame union — `ui/tui/protocol.py` (the strict mirror) · the server side of every frame, route, and envelope — `cns/api/AGENTS.md` · session/CSRF mechanics and the token-minting routes — `auth/AGENTS.md` · the update machine-half and the breaking-release gate — `deploy/AGENTS.md` · how a feature was built — `git log` (`ui/tui/BUILD_PLAN.md`, `ui/tui/FRONTEND_PLAN.md` are historical design records; code is truth).

## Rules

- A server frame change updates both clients in the same commit — three surfaces: `cns/api/websocket_chat.py` (frame owner: `cns/api/AGENTS.md`), the browser's `ui/browser/assets/javascript/api-client.js` (`_handleFrame`/`TURN_STREAM_FRAMES`) + `messaging.js` (`handleTurnFrame`), and the TUI's strict mirror `ui/tui/protocol.py` + `ui/tui/client.py` (`_frame_to_event`); each side's full file list is its own map's. Drift is asymmetric by design: the browser logs `Unknown server frame type` and drops the frame — silent; the TUI's `extra="forbid"` mirror raises → `ProtocolError` — loud. One client updated without the other leaves the lagging client misbehaving with no shared check to catch it.
- `messaging.js:ReplyFilter` and `ui/tui/text.py:ReplyStream` are one display filter in two implementations (grep `rg 'class ReplyFilter|class ReplyStream' ui`); a semantic change lands in both the same commit: tag/think hold-back (`scanTags`/`_scan` plus trailing-fragment hold), one leading `[h:mmam]` timestamp strip per entry, interior-only blank lines, `flush()` on `tool`/`model_error` ending the provider step and dropping held text, `hasText`/`has_text` gating the `turn_complete.response` fallback. TUI-only steps: per-delta `sanitize` (Rich passes ESC through) and `breaks_before_pending`; the browser needs neither — the DOM does not interpret terminal escapes, only completed blocks render (no live pending tail), and reply-body safety rests on `renderMarkdown` (`DOMPurify.sanitize(marked.parse(...))` into `innerHTML`), never on plain-text insertion. One-side edits make the same reply render differently per client.
- TURN_BUSY and reconnect backoff are constant twins (grep `rg 'TURN_BUSY_RETRY|RECONNECT_DELAYS' ui`): `ui/browser/assets/javascript/api-client.js` `TURN_BUSY_RETRY_DELAYS_MS` [500, 1000, 2000], `TURN_BUSY_POLL_MS` 3000, `TURN_BUSY_MAX_WAIT_MS` 600000, `RECONNECT_DELAYS_MS` [2000, 4000, 8000], `RECONNECT_POLL_MS` 15000 ≡ `ui/tui/chat.py` `TURN_BUSY_RETRY_DELAYS` (0.5, 1.0, 2.0), `TURN_BUSY_POLL_SECONDS` 3.0, `TURN_BUSY_MAX_WAIT_SECONDS` 600.0, `AUTO_RECONNECT_DELAYS` (2.0, 4.0, 8.0), `AUTO_RECONNECT_POLL_SECONDS` 15.0; both measure the wait from the first bounce/loss. A cadence change on one client splits how the two retry a busy server or come back after a restart.
- History replay grouping is one vocabulary, two renderers (grep `rg 'renderHistoryRows|replay_blocks' ui`): `ui/browser/assets/javascript/history.js:renderHistoryRows` ≡ `ui/tui/history.py:replay_blocks` — a `user` row opens a pair; `assistant`+`tool` rows sharing `metadata.turn_id` form one reply (rows without a `turn_id`: a reply each); tool rows by `metadata.tool_name`/`is_error`; sentinels render only at `metadata.status === 'collapsed'` (summary from `display_title` + content). Both sides accept `is_segment_boundary` as boolean `true` or string `"true"` (`messaging.js:isSegmentSentinel`, `ui/tui/client.py:_is_sentinel`) — the server has sent both spellings. One renderer edited alone makes the same history group differently per client.
- `__init__.py` stays import-free: `python3 -m ui.tui` (the `mira` command) imports the `ui` package inside the TUI venv, built solely from `ui/tui/requirements.txt` — shared with the server only on the `pydantic`/`httpx` pins, absent its runtime stack — an import here, or a new server-tree import from `ui/tui/`, breaks the command on every install unless its transitive needs fall inside those pins. The one sanctioned server-tree import is `ui/tui/update.py` → `utils/release_identity.py` (stdlib-only by design, shared with the server — `utils/AGENTS.md`).
- Undelivered-message disposal deliberately differs: the browser queues to Retry Send (localStorage `mira-queue`, only `UNSENT_TURN_CODES` — `TURN_BUSY`, `CONNECTION_LOST`, `NOT_AUTHENTICATED`; only `TURN_BUSY` guarantees the server never took the frame: `CONNECTION_LOST` fires after the frame hit the wire with no confirmed turn, `NOT_AUTHENTICATED` on any in-flight send — a queued resend can duplicate the server-side turn, hence the reject copy "check history before resending"); the TUI returns in-flight + queued text to the input box (`ui/tui/chat.py:_restore_unsent`); a `stopped` turn queues in neither — its partial reply persists server-side. Do not port one client's disposal to the other as a consistency fix.

## Files

- `__init__.py` — package docstring only; no imports, no re-exports. `python3 -m ui.tui` resolves the `ui` package first, inside the TUI venv — the import-free rule above is load-bearing.
- `browser/` — the served client: four page controllers, assets, serving/boot file check, single-user page auth, cache-bust twin — `ui/browser/AGENTS.md`.
- `tui/` — the terminal client: strict frame mirror, turn state machine, single-writer screen, endpoint store, headless login, `mira update` — `ui/tui/AGENTS.md`.

## Wiring

- Frames, both clients ↔ `cns/api/AGENTS.md` (`cns/api/websocket_chat.py`): the server frees the per-user turn lock before queueing the terminal frame — release, then terminal, in that order — so a `TURN_BUSY` resend can win immediately on both clients; a socket drop stops the turn (`turn_stopped` reason `disconnect`) with the partial reply kept server-side.
- History rows, both clients ↔ `cns/api/AGENTS.md` (`cns/api/data.py`): keyset-only paging (`before` → `meta.next_before`/`has_more`; `offset` rejected server-side); row shape `{id, role, content, timestamp, metadata, tool_call_id, is_error}`; assistant content is a JSON-stringified content-block array — only `text` blocks are conversation (`messaging.js:messageDisplayText`, `ui/tui/history.py:_display_text`).
- Import boundary: nothing outside `ui/` imports it — the server reaches the browser client only by serving `ui/browser/` as static files (root `main.py:UI_BROWSER_DIR`, contract owned by `ui/browser/AGENTS.md`) and reaches the TUI not at all; both clients talk to the server over the wire only. The single outbound import edge is `ui/tui/update.py` → `utils/release_identity.py` (`utils/AGENTS.md`).
