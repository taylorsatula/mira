# ui/browser/assets/javascript/ — the browser chat client's modules: the one HTTP/WS transport, the client half of the turn protocol, the chat page's feature surfaces

Elsewhere: page controllers, inline scripts, script-tag inventory and cache-bust strings, single-user-mode auth, serving and the boot file check — `ui/browser/AGENTS.md` (the four page controllers under `ui/browser/`: `chat`, `settings`, `domaindocs`, `memories`) · server side of every frame, the HTTP envelope, action/data/tool-config/location route contracts — `cns/api/AGENTS.md` (`cns/api/websocket_chat.py`, `cns/api/base.py`, `cns/api/actions.py`, `cns/api/data.py`, `cns/api/tool_config.py`, `cns/api/location.py`) · CSRF/session mechanics — `auth/AGENTS.md` (`auth/session.py`) · the both-clients same-commit rule and the three twin pairings — `ui/AGENTS.md`; the TUI's side of the protocol and its strict pydantic mirror — `ui/tui/AGENTS.md` · vendor library internals — the minified files and their upstream docs · how a feature was built — `git log`.

## Rules

- Every server call goes through a `MiraAPIClient` instance: HTTP through `_httpRequest` (envelope unwrap, CSRF attach/retry, 401 → `auth.clearToken()` → logout event; the chat page's handler navigates to `/` for the single-user re-mint), frames through its socket. `location.js` and `tool-config.js` call `miraAPI._httpRequest` directly — sanctioned, same machinery; every page registers its own `onAuthChange` logout handler (grep `rg 'onAuthChange' ui/browser`). Raw `fetch`/`WebSocket` elsewhere is a defect: it skips the rotated-token retry (multi-tab writes 403 `CSRF_INVALID`) and the 401 logout, stranding the tab on a dead session.
- Inbound frames dispatch in `api-client.js:_handleFrame`: settlement, connection, `protocol_error`, and `proactive_message` frames inline, stream frames enumerated in `TURN_STREAM_FRAMES`, anything else logged (`Unknown server frame type`) and dropped — no raise, unlike the TUI's strict mirror (`ui/tui/AGENTS.md`, `ProtocolError`). A frame added in `cns/api/websocket_chat.py` lands in `_handleFrame`/`TURN_STREAM_FRAMES` in the same commit (both-clients rule owned by `ui/AGENTS.md`); a skipped browser side is a console line, never an error — the web client silently ignores the frame.
- `messaging.js:ReplyFilter` mirrors `ui/tui/text.py:ReplyStream` (twin rule owned by `ui/AGENTS.md`): tag/think hold-back (`TAG_BLOCK_RE`, `isTagFragment`), one leading `[h:mmam]` timestamp strip per entry, interior-only blank lines, `flush()` dropping held text at a provider-step end, `hasText` gating the `turn_complete.response` fallback. Same commit, both clients. Hazard: `THINK_OPEN`/`THINK_CLOSE` hold the raw tag literals on disk — edit that block through agent tool payloads and the bytes can arrive HTML-entity-mangled, after which think blocks stop matching and model reasoning renders raw; after any edit there, verify the on-disk bytes.
- One CSRF token per session; every `POST /v1/auth/csrf` rotates it (`auth/session.py:generate_csrf_token`). `_ensureCsrfToken` single-flights per tab (`_csrfFetch`); `_httpRequest` attaches `X-CSRF-Token` to non-GET/HEAD `/v1/api*` and `/v1/auth*` (except the csrf path itself) and retries exactly once on 403 `CSRF_INVALID`/`CSRF_REQUIRED`. A second concurrent token fetch in one tab rotates twice and 403s every other in-flight write; dropping the retry breaks every second tab.
- One send in flight (`_send`; overlap rejects `SEND_IN_FLIGHT`). The promise settles exactly once: `complete` | `stopped` (`halt`/`disconnect`/`stall`) | reject (`MiraTurnError`). `messaging.js:failTurn` queues to Retry Send (`AppState.messageQueue`, localStorage `mira-queue`) only for `UNSENT_TURN_CODES` (`TURN_BUSY`, `CONNECTION_LOST`, `NOT_AUTHENTICATED`; only `TURN_BUSY` guarantees the server never took the frame — `CONNECTION_LOST` fires when the frame was transmitted but no turn confirmed it, `NOT_AUTHENTICATED` on any in-flight send, so a queued resend can duplicate the server-side turn); a `stopped` turn never queues — its partial reply persists server-side; on reason `disconnect` `core.js:restoreInterruptedResponse()` re-renders it 2 s after reconnect (a stall stop keeps the partial as the displayed exchange, no restore). Conflating the two double-sends or loses the user's text. `TURN_BUSY` resends the same `message_id` frame after backoff (constants mirror `ui/tui/chat.py` `TURN_BUSY_*`).
- The response box holds one exchange, `streamingState.displayedExchange`: `messaging.js` records it at each settle (complete, stopped, failed-with-text, restore, proactive) and hands it to `InlineHistory.appendExchange` when the next send knocks it off; `history.js:withoutDisplayedExchange` keeps it out of the first fetched page while `persisted`; `loadInlineHistory` awaits `messaging.js`'s `sessionRestored` promise (resolved when the session restore settles) before its first fetch — drop the gate and the restore races the first page, duplicating or dropping the restored exchange. Break the handoff and the exchange never reaches history or renders twice.
- `ui/browser/chat/index.html` script order is the dependency order: `theme.js` in `<head>` (pre-paint, before the stylesheet link and the vendor pair), then vendor (`marked.min.js`, `purify.min.js`) → `api-client.js` → `core.js` → `ui.js` → `sidebar.js` → `messaging.js` → `history.js` → `events.js` → optional features. Top-level `const`s (`AppState`, `elements`, `streamingState`, `ASSET_VERSION`) share the scripts' global lexical scope — visible to later files, absent from `window`; cross-module calls go through `window.*` assignments. An eval-time reference to another module's binding (history.js's top-level `elements.toastScrollBtn` listener) breaks if its tag moves before the owner's; function-body references break only at call time, and `core.js:initializeMira` — the first DOMContentLoaded handler — runs after every tag has executed, so later handlers find `window.miraAPI` already built.
- Frame-listener ownership: `core.js:initializeAPIClient` installs the persistent listeners (`tool` → `ui.js:updateToolIndicator` via `TOOL_INDICATOR_STATES`, `proactive_message` → `messaging.js:handleProactiveMessage`, queue indicator on connect/disconnect, interrupted-reply restore on connect). `messaging.js:runTurn` pushes `handleTurnFrame` for exactly one send and splices it in `finally` — a leaked handler double-renders the next turn. Each popover registers its own document-level click-outside (queue/attachment in `events.js`, domain in `domain-knowledge.js`); there is no shared closer.

## Files

- `api-client.js` — the transport: WS lifecycle (connect, cookie auth, 30 s keepalive, reconnect backoff) plus the one HTTP path. Entry: `MiraAPIClient` (the constructor connects immediately — every page's `new MiraAPIClient()` opens the socket at once), `_httpRequest`, `_handleFrame`, `_sendMessage`/`chat.halt`, `auth.validateToken`/`clearToken`, `MiraHttpError`/`MiraTurnError`. Gotcha: `_handleClose` settles the in-flight send three ways — `stopped(disconnect)` once a turn started, `CONNECTION_LOST` reject if transmitted but unconfirmed, connect-wait resend if never transmitted.
- `core.js` — chat-page foundation: `AppState`, the `elements` DOM cache, client construction and the persistent listeners, startup, segment collapse. Entry: `initializeMira`, `Functions.collapseSegment`, `restoreInterruptedResponse`, `TOOL_INDICATOR_STATES`. Gotcha: `collapseSegment` races the request against the animation — `collapsed:false` means deferred behind an in-flight turn and the server's message renders, not the success HTML.
- `ui.js` — the visual layer: tool badge (`updateToolIndicator`, `toolIconSrc` over `TOOL_ICONS`), status badges, attachment/queue popovers, send animations (`runPlungerAnimation`, `animateTextDissolve`), the loading wave, `ASSET_VERSION`, `hapticFeedback`. Gotcha: `TOOL_ICONS` stems must equal the `.png` filenames in `ui/browser/assets/images/icons/toolicons/` (`reminder_tool` → `reminders`; an unknown stem falls to `default.png`).
- `messaging.js` — the turn's client half: send, Retry Send queue, attachments, `ReplyFilter`, block streaming, thinking drawer, notices, proactive messages, session restore, the `displayedExchange` record. Entry: `sendMessage`, `runTurn`/`handleTurnFrame`, `completeTurn`/`stopTurn`/`failTurn`, `ReplyFilter`, `filterReplyText`, `replyPartsFromRows`/`renderReplyParts` (the row→parts vocabulary `history.js` shares). Gotcha: only `AppState.attachedFiles[0]` is sent, then `clearAttachment()` discards the rest — the popover stages many, the frame carries one.
- `history.js` — inline paged history above the response box: keyset pager (`nextBefore`), user-pair + `turn_id` reply grouping (twin of `ui/tui/history.py`), collapsed-sentinel summaries, new-message toast. Entry: `InlineHistory`, `loadInlineHistory`, `renderHistoryRows`, `withoutDisplayedExchange`. Gotcha: leading reply rows whose user row lives one page older are carried (`InlineHistoryState.carry`) and rendered with that page — pages split on user/sentinel rows, never on counts.
- `events.js` — the chat page's DOM wiring: submit/stop, Enter vs mobile keyboard, file picker and image paste, popover open/close, queue edit/send/remove. Entry: `setupEventListeners`, `setupDelegatedEvents`. Gotcha: the send button's `pointerdown` preventDefault is load-bearing on iOS — without it the keyboard-resized viewport swallows the synthetic mid-tap click.
- `sidebar.js` — all-pages navigation: desktop collapse persisted (`mira-sidebar-collapsed`), mobile drawer/swipe/focus-trap, History button (inline toggle on the chat page, redirect elsewhere), Pause/Wrap-Up on chat. Gotcha: loads before `messaging.js`/`history.js`/`inactivity-warning.js`, so its chat-page wiring defers to DOMContentLoaded for their globals — the comment in the file marks the contract.
- `inactivity-warning.js` — the session status bar above compose: idle/warning/urgent/collapsed/paused from `continuum` `get_segment_status` polled every 30 s, pause/resume actions, `onStatusChange` subscribers. Entry: `window.inactivityWarningManager` (constructed at script load; `sidebar.js` subscribes on DOMContentLoaded; `messaging.js:sendMessage` calls `trackActivity('message_sent')` on every send — optimistic bar hide, then refresh), `init`, `togglePause`, `trackActivity`. Gotcha: `init()` paints idle before the first fetch; a failed poll keeps the last state until the next one.
- `domain-knowledge.js` — domaindoc client and chat-page popover: `DomainKnowledgeManager` over the `domain_knowledge` action domain and `domaindocs` data type; section CRUD with `parent` addressing. Entry: `initDomainKnowledge` (chat page), `DomainKnowledgeManager` (the domaindocs page constructs its own — grep `rg 'DomainKnowledgeManager'`). Gotcha: enabled state drives the chat indicator (`domain_btn`); `fetchDomains()` is the single refresh point, also called by `messaging.js` after `domaindoc_tool` runs.
- `tool-config.js` — settings-page tool config UI: `ToolConfigManager` over `/v1/api/actions/tools*` (list/get/schema/PUT/validate/DELETE → `cns/api/tool_config.py`), JSON-Schema-driven forms, email_tool folder discovery. Entry: `ToolConfigManager`, `generateFormFromSchema`, `extractFormValues`, `renderToolsPage`. Gotcha: `email_tool` save blocks until a live validation populated the folder mapping — folder fields never appear in the generated form; they come only from the validate endpoint's `discovered`.
- `location.js` — consent modal plus geolocation: POST `/v1/api/location` (server reverse-geocodes and fetches weather, `cns/api/location.py`). Entry: the IIFE's `init`, `queryLocation`, `submitLocation`. Gotcha: automatic loads query only when the browser permission is already granted (`navigator.permissions.query`), so the native prompt fires only from the consent click; consent is sticky in localStorage `mira-location-consent` (true/false/null tri-state).
- `repulsion-feedback.js` — AI-tell feedback: the `TELLS` regex bank over completed replies, automatic `feedback`/`capture_repulsion` on a hit, popover for the human reason. Entry: `window.repulsionFeedback` (`noteUserMessage`, `scanResponse`), `TELLS`, `scanResponseText`. Gotcha: a hit auto-captures immediately with empty `reason`, carrying the whole matched-tells list; the popover send writes a second, reason-bearing row — two rows per scanned response that hit is the design, not a bug.
- `theme.js` — appearance mode (auto/light/dark): `miraSetTheme`/`miraGetTheme` over localStorage `mira-theme`, matchMedia re-resolve while in Auto; the settings page's Appearance select is the one UI writing the stored mode (`ui/browser/AGENTS.md`). Gotcha: pairs with the inline pre-paint boot script in each page `<head>` (owned by `ui/browser/AGENTS.md`) — `<html data-theme="light">` is `ui/browser/assets/style.css`'s only light trigger; Auto resolves here, never in CSS.
- `collapse-animation.js` — the segment-collapse effect: wrap chars in spans, lock widths, font swap, gravity fall. Entry: `collapseAnimation` (consumed by `core.js:Functions.collapseSegment`). Gotcha: conversion is time-batched (`COLLAPSE_MAX_MS_PER_CHAR` cap) so hidden-tab 1 Hz throttling does not stretch the 5 s phases; requires `.converted`/`.falling` in `ui/browser/assets/style.css`.
- `marked.min.js` — vendored marked v12.0.0 (MIT), pinned stock build; consumed via `marked.parse` and `marked.setOptions({breaks, gfm})` in `messaging.js`, always paired with DOMPurify. No gotchas.
- `purify.min.js` — vendored DOMPurify 3.0.9, pinned stock build; behind `MARKDOWN_SANITIZE_CONFIG` (`messaging.js`) and the snippet rows (`repulsion-feedback.js`). Gotcha: its `sourceMappingURL` names a `.map` the tree does not ship — a devtools 404, harmless.

## Wiring

- Loader: consumer set is the four pages (`rg -l 'assets/javascript' ui/browser -g '*.html'`) — `ui/browser/chat/index.html` loads the full set in the Rules order; `ui/browser/settings/index.html` (theme, api-client, tool-config, sidebar); `ui/browser/domaindocs/index.html` (theme, api-client, sidebar, domain-knowledge); `ui/browser/memories/index.html` (theme, api-client, sidebar). Page controllers, script tags, and the boot file check (`main.py:UI_BROWSER_FILES`) are `ui/browser/AGENTS.md`'s.
- Server frames ↔ `cns/api/AGENTS.md` (`cns/api/websocket_chat.py`): the per-user turn lock is freed before the terminal frame (a `TURN_BUSY` resend can win immediately — mirrored in `_onTurnBusy`); a socket drop stops the turn (`stopped`/`disconnect`) with the partial reply kept; `MAX_CONTENT_LENGTH` 100_000 is enforced client-side before send because the server's rejection arrives as an unattributed `MALFORMED_FRAME`.
- History envelope: `history.getHistory` → `/v1/api/data?type=history`; `meta.has_more`/`next_before` keyset cursor (`cns/api/data.py`, routes owned by `cns/api/AGENTS.md`). Row vocabulary shared with the TUI renderer: `metadata.turn_id`, `is_segment_boundary`, sentinel `status === 'collapsed'`, `tool_name`/`is_error` — same grouping in `ui/tui/history.py` (twin rule `ui/AGENTS.md`).
- Action and data endpoints, all owned by `cns/api/AGENTS.md`: `continuum` actions (`core.js` collapse, `inactivity-warning.js` status/pause/resume), `domain_knowledge` actions + `domaindocs` data (`domain-knowledge.js`), `feedback`/`capture_repulsion` (`repulsion-feedback.js`), `user` data announcement (`messaging.js:showAnnouncement` → `preferences.announcement`); tool CRUD by `cns/api/AGENTS.md` (`cns/api/tool_config.py`); location by `cns/api/AGENTS.md` (`cns/api/location.py`).
- Twins: `ReplyFilter` ↔ `ui/tui/AGENTS.md` (`ui/tui/text.py:ReplyStream`); `TURN_BUSY` and reconnect backoff constants ↔ `ui/tui/AGENTS.md` (`ui/tui/chat.py`); the both-clients same-commit rule `ui/AGENTS.md`.
- CSRF ↔ `auth/AGENTS.md` (`auth/session.py:generate_csrf_token` — one rotated token per session; the browser retry is the client half).
- Tool-name coupling: `messaging.js` keys the domain-list refresh on the literal `'domaindoc_tool'` in `toolsUsed` — the `*_tool` naming rule is owned by `tools/implementations/AGENTS.md`; renaming the tool silently stops the refresh.
- Vendor globals `window.marked`/`window.DOMPurify` are consumed only by `messaging.js` and `repulsion-feedback.js`.

## A turn, send to settled display

`events.js` submit → `messaging.js:sendMessage`: the queue gate (`streamingState.isGenerating`), attachment read (first staged file, base64), a knock-gate promise (`AppState.knockGate`), then `runTurn` starts the wire work while the plunger animation plays alongside. `beginTurn` archives any displayed exchange, resets the stream state, and `prepareResponseContainer` waits the knock gate before hiding the old reply and setting `containerReady` — the on-screen exchange leaves only after the plunger knocks it. `api-client.js:_sendMessage` mints the `message_id` from `crypto.getRandomValues` (`randomUUID` exists only in secure contexts; a plain-http non-localhost page is not one), always sends `include_thinking: true`, and routes the attachment by MIME into `image`/`image_type` or `document`/`document_type`.

Frames then arrive on the socket; each has exactly one disposition:

| Frame | Handler | Disposition |
|---|---|---|
| `auth_success` | api-client | clears the auth timer, starts keepalive, emits `onConnect`, transmits the waiting send |
| `protocol_error` | api-client | auth codes → `clearToken` (logout event → the page's `onAuthChange` navigates); `AUTH_UNAVAILABLE` → reconnect; attributed `TURN_BUSY` → `_onTurnBusy` backoff and same-frame resend, rejecting past `TURN_BUSY_MAX_WAIT_MS`; other attributed codes → reject the send; `NO_MATCHING_ACTIVE_TURN` → warn only |
| `turn_started` | api-client + messaging | fixes `send.turnId` and `streamingState.turnId`; a halt requested pre-start fires now |
| `assistant_delta` | messaging | `ReplyFilter.feed(entry_id, …)` → `appendDisplayText`, blocked while the thinking→text transition runs |
| `thinking` | messaging | live `.thinking-stream-content`, folded into a `.thinking-drawer` at the first text token |
| `tool` | messaging + core | ends the provider step (`filter.flush()`), records completed/errored tools; `core.js` maps the event through `TOOL_INDICATOR_STATES` to the `ui.js` badge |
| `context_reset` | messaging | new `ReplyFilter` and display reset — everything streamed so far is void |
| `model_error` | messaging | flush plus a notice, removed when the turn settles |
| `turn_complete` / `turn_stopped` / `turn_error` | api-client | settle the promise once |

Settlement then drives display: `completeTurn` falls back to `response` only when `!hasText`, schedules the completion badge, records `displayedExchange`, and runs the repulsion scan; `stopTurn` shows the stall notice, or on `disconnect` arms `AppState.responseInterrupted` for `core.js` to restore from history 2 s after reconnect; `failTurn` queues the text for `UNSENT_TURN_CODES`. `endTurn` parks the settle in `pendingSettle` until `containerReady`, then releases the send button, clears turn notices, and shows proactive messages that `handleProactiveMessage` held in `deferredProactive` during the turn.

Ordering invariants: settlement precedes display settle (`pendingSettle`); the knock gate resolves before the old exchange leaves the screen; `flush()` on `tool`/`model_error` so a held-back tag fragment never renders; `displayedExchange` is recorded exactly once per turn, which is what lets `history.js` exclude it from the first page.
