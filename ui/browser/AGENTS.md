# ui/browser/ — the pages the server itself serves, in the paper shell, and the stylesheet and asset tree behind them

## Files

- `chat/index.html` — the chat page's document, and the source of the element ids `core.js:elements` captures at load and of the `data-indicator` values the toolbar modules query. Open it before renaming or dropping either. `.app` is the whole chat window and its direct children are the four regions: the dormant `artifact-pane`, `#notifications-center`, `#response_box`, and `#compose_bar`. There is no title band — the rail carries the wordmark and the client has one conversation.
- `memories/index.html` — the memories page and its inline controller. Open it before changing how memories are listed, filtered, or deleted.
- `domaindocs/index.html` — the domaindocs companion and its inline controller: live polling, inline section editing under a debounced save, conflict resolution, same-level drag reorder, the archived view. Open it before changing domaindoc editing or the poll.
- `settings/index.html` — the settings hub and its inline controller; the tab roster and each tab's loader are the controller's header comment. Open it before adding or changing a settings tab.
- `favicon.ico` — site icon served at `/favicon.ico`, linked by every page.
- `apple-touch-icon.png` — home-screen icon served at `/apple-touch-icon.png`, and the manifest's only icon.
- `manifest.json` — the PWA manifest served at `/manifest.json`; start URL `/chat`, standalone display, paper `background_color`/`theme_color`, no comments possible in it.
- `assets/style.css` — the one stylesheet for all four pages: the `:root` paper tokens and the `html[data-theme="dark"]` dusk block, the mat and rail, the chat chrome, every class the modules toggle by name, and the supporting-page primitives under `.page-main`. Open it before changing a token, a colour, or a class a module adds or removes.
- `assets/javascript/` — the modules, the one transport, the client half of the turn protocol; its own map.
- `assets/fonts/` — the three `.woff2` faces behind the `@font-face` srcs in `assets/style.css` and behind the pages' preloads. Open it before renaming a face.
- `assets/images/` — the logo, the nav and toolbar icons, and the per-tool icons the toolbar swaps. Open it before adding an icon the pages reference by path; the `TOOL_ICONS` stem-and-filename contract is the child map's.

## Wiring

- Serving: `main.py:create_app` → `page_dependencies` → `FileResponse`. Each of the four pages registers both `/name` and `/name/`, and every one carries `page_dependencies`; the three root meta files and the `/assets` mount carry none, so a gated page can still fetch its own CSS and JS. Gating an asset route bricks every page at its stylesheet. Counterpart: root `AGENTS.md` owns the route bodies, `UI_BROWSER_DIR`, and the boot check over `UI_BROWSER_FILES`.
- Page gate: route dependency `auth_api.get_current_user_for_pages` → `auth/api.py:_page_auth_failure` → `/v1/auth/local/session`. The failure is mode-dependent, so nothing in this tree may assume a redirect exists: under `multi` the gate answers with the 401 envelope and a client-side bounce to the session endpoint would land on a 404. Counterpart: `auth/AGENTS.md` owns both routes.
- Cache-bust: `ui/browser/assets/javascript/ui.js:ASSET_VERSION` ↔ the `?v=` tag every page repeats on every asset URL. One side bumped alone splits HTML-referenced and JS-injected assets into different cache generations, so a deploy pairs stale modules with fresh markup. The three font URLs are the one untagged exception on both the preload and the `@font-face` side. Counterpart: `ui/browser/assets/javascript/AGENTS.md` owns the constant.
- Theme: each page's pre-paint boot script ↔ `theme.js` ↔ `:root` in `assets/style.css`, and `theme.js`'s `window.miraGetTheme()`/`window.miraSetTheme()` setters bind `#appearance-theme` in `settings/index.html`. `:root` holds the paper values and `html[data-theme="dark"]` holds dusk, so a page whose boot script never runs renders paper; Auto resolves in `theme.js` at runtime and never in CSS. Renaming the attribute, either `window` function, or the `mira-theme` storage key is one commit across all four pages, the CSS selector, `theme.js`, and the settings page. Counterpart: `ui/browser/assets/javascript/AGENTS.md` owns the runtime half.
- Sidebar: `sidebar.js` wires the `#app-sidebar` markup by id, and that markup is duplicated in all four pages with only `active`/`aria-current` differing. A nav item, a pill, or a reorder lands in all four files in one commit; a page skipped keeps serving its old navigation with no error. `sidebar.js` hard-codes a 250px rail and shifts `document.body` through `marginLeft`, so the sheet's rail width, the body's margin, and the mat's available width are one geometry. Counterpart: `ui/browser/assets/javascript/AGENTS.md`.
- Page ids: `core.js:elements` captures `loading-screen`, `ascii-container`, `response_box` and `response_content` from `chat/index.html` once at eval time, and `ui.js` finds the toolbar buttons by `data-indicator`. An id or `data-indicator` renamed or dropped in the page leaves a module holding `null` that fails on first use, and an id added after `core.js` runs is invisible to every module. Counterpart: `ui/browser/assets/javascript/AGENTS.md` owns the capture.
- Icons: every PNG under `assets/images/` is a black-ink glyph except `logo.png`, whose wordmark is white (measured per icon, 2026-11-04). The sheet inks the logo with `--icon-brand-filter` and lightens the glyphs for dusk with `--icon-dusk-filter`; a new icon in the current style needs no rule, and an icon that ships light-inked will vanish on paper until one is added.
- Trigger rules: `settings/index.html` is the only in-tree caller of `/v1/api/triggers/rules…` and `/v1/api/triggers/conflicts`, so a rule-shape change reaches this page in the same commit. Counterpart: `cns/api/AGENTS.md`.
- Actions: the settings inline controller drives the `user`, `portrait` and `lora` action domains through `POST /v1/api/actions`, and the memories controller drives `memory` — both inside `*/index.html`, where a grep over `assets/javascript` does not reach. Renaming an action argument or the `preview_id` field fails at the call, rendering a rejected request in the page, never at load. Counterpart: `cns/api/AGENTS.md`.
- API tokens: the settings developer tab drives `/v1/auth/api-tokens`, the same route the TUI bootstrap and `deploy/vm/talktomira.sh` mint through. Counterpart: `auth/AGENTS.md`.
- CSP: the "What must change before strict can become the default" section of `auth/security_middleware.py`'s module docstring names this tree's inline scripts and handlers as strict mode's blocker. The chat page carries no inline handler; `domaindocs/index.html` carries thirty of its controller's, and the other two pages none. Counterpart: `auth/AGENTS.md`.

## Rules

- Add a page in this order: (1) create the page directory and its `index.html`, copying the head block and the rail block from an existing page — boot script, `theme.js`, `assets/style.css`, the three font preloads, the dual `theme-color` pair, cache-bust tags; (2) add the page's path to `main.py:UI_BROWSER_FILES` — skip it and the boot fails with `RuntimeError`, not the first request; (3) add the route in `main.py:create_app` with `dependencies=page_dependencies` and both `/name` and `/name/` — skip it and the page 404s; (4) copy the `#app-sidebar` block and the `api-client.js` and `sidebar.js` tags into the new page, and add its `<li>` to the `#app-sidebar` block of all four existing pages — `sidebar.js` returns early when `#app-sidebar` or `#sidebar-toggle` is missing, so a page built from the head block alone renders an inert sidebar with no error, and a page left out of the four keeps serving its old navigation. A supporting page's own script roster is part of step (1): `settings` also loads `tool-config.js` and `domaindocs` also loads `domain-knowledge.js`, and omitting either is a `ReferenceError` that ends that page's whole controller at load.
- Hide an element the way its module re-shows it. `messaging.js:showAnnouncement` and `repulsion-feedback.js:showButton` re-show by clearing inline style, so the announcement banner and the repulsion button ship `style="display:none"`; `sidebar.js` does the same for `#sidebar-pause-btn`. The queue indicator and the new-message toast are toggled by the `.hidden` class, and a `[hidden]` attribute on either survives the module's `style.display = ''` and kills the feature with no error. The inline-history container has no hidden state at all: the thread is the conversation, always rendered and paging itself.
- `#response_box` is the scroll container and is styled by id alone: `history.js` roots its `IntersectionObserver` on it and `messaging.js` writes its `scrollTop` directly, and `core.js` overwrites its whole `className` with `active` when a collapse finishes, so a class this sheet hangs the layout on is wiped. `#chat_field` stays a `<textarea>` — nothing in the tree autosizes it, and it scrolls internally between its min and max height.
- Only the four pages sit behind the gate. The icons, the manifest, and everything under `/assets` are served publicly so a gated page can still fetch its own stylesheet and scripts. A `.html` reading user data served without `page_dependencies` is readable by anyone who reaches the port; an asset moved behind the gate makes every page that references it fail to load.
- Every page controller registers a logout handler that navigates to `/` — the three inline controllers here and, by the child map's rule, the chat page's modules (grep `rg 'onAuthChange' ui/browser`). `MiraAPIClient` announces the event and stops; a page without a handler keeps a dead session and fails every later write with a 401, with no visible cause.
- Do not add inline `<script>` or inline `onclick=`-style handlers. `MIRA_CSP` stays off by default because this tree still runs both and `script-src 'self'` rejects them; the strict flip is blocked until every inline block moves into files under `assets/`. The chat page is already handler-free — the announcement-dismiss and Manage-Domains clicks that used to be `onclick` are listeners in `core.js` and `domain-knowledge.js` — while `domaindocs/index.html` keeps its controller's thirty pre-existing handlers, which a rewrite of that page would have to move rather than copy.
- Design values live in the token blocks and nowhere else: every component rule reads `var(--…)`, so dusk is the `html[data-theme="dark"]` block plus the grain and icon settings, with no per-component dark rules. A colour written into a component rule is a value dusk cannot reach. The dusk block also restates the seven `--*-ink` tokens, because the light inks sit at L 0.38-0.43 for pale paper and are unreadable on a dusk surface.
- The window is one surface, not a card on a card: `.app` is the grid, `#response_box` is its scrolling region, and `#compose_bar` is a strip docked to the window's foot carrying a top hairline rather than its own border, radius and shadow. `body[data-page="chat"] .app` names the rows because the four regions are assigned by id; a new region is a template row plus a `grid-area`. Supporting pages run the same `.app` with a single row, and their own `.page-header` inside `main.page-main` supplies the title.
- The thread keeps a reading measure and the composer does not: `#response_content` and `.inline-history-container` are capped at `min(72ch, 100%)` and centred inside `#response_box`, while `#compose_bar` spans the window. The idle prompt hangs off `#compose_bar` and is shown by `.app:has(#welcome-message)` — never `:empty` — and `#welcome-message` is now written by `history.js` when the conversation is empty, since nothing else reports emptiness.
- The artifact pane ships `hidden` with `.artifact-pane[hidden]{display:none}`. Restoring it is removing that attribute: `body[data-page="chat"] .app:has(.artifact-pane:not([hidden]))` swaps to the lane's flexible column plus a fixed 440px thread, with explicit `grid-template-areas` that keep `#compose_bar` under the thread instead of letting auto-placement drop it beneath the pane.
- A collapsed toolbar label leaves the flex flow (`display: none`), because a zero-width label still earns the parent's `gap` and pushes the glyph off centre in a chip whose width is the icon plus padding. `inactivity-warning.js` sets `.has-status-bar` on the dock so the status bar it inserts there sits clear of the dock's own hairline instead of reading as one thick rule.

Elsewhere: this map does not own the server's routing, the auth gate, or any module's behaviour — `## Wiring` routes all three. The images are binaries with no authority beyond their names, and how a page came to look the way it does is `git log`.

## The page gate, anonymous GET to interactive

The chain that makes a page reachable, and the reason no page here holds a login form.

1. An anonymous GET `/chat` reaches the route's `page_dependencies` and therefore `auth_api.get_current_user_for_pages`, which looks for a Bearer header and then a `session` cookie.
2. With neither validating, it raises `_page_auth_failure`, and the auth mode decides the outcome: under `single` a 302 to `/v1/auth/local/session`; under `multi` the standard 401 envelope, which is the whole story for that install — MIRA ships no `/login/` page, so the operator's own sign-in surface is the entry point.
3. `/v1/auth/local/session` provisions or adopts the install's original member account, mints the `session` cookie, and 303s back to `/chat`. Which account that is, and why the local fixture identity is not it, is `auth/api.py:create_local_session`'s docstring.
4. The account row exists before the cookie is minted, and the cookie rides the second GET before any page JS runs — so the `MiraAPIClient` constructed at DOMContentLoaded opens a socket that authenticates on the first try.
5. Expiry re-runs the same chain and never shows a form: a 401 clears the token, the controller's logout handler navigates to `/`, the root route redirects to `/chat`, and the gate mints again. The handlers navigate to `/` rather than to the session endpoint because the client cannot know the auth mode, and the gate is the one mode-aware seam on both the first visit and every recovery.
