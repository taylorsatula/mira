# ui/browser/ — the browser client the server itself serves: four HTML page controllers, the one shared stylesheet, the static asset tree

Elsewhere: the JS modules, the one transport, the client half of the turn protocol, loader sets and the chat-page script order — `ui/browser/assets/javascript/AGENTS.md` (per-page `<script src>` lists: the pages themselves) · every route's server side (action/data envelopes, trigger rules, tool config) and the WS frames — `cns/api/AGENTS.md` · session/CSRF mechanics, the local-session bootstrap, api-token routes — `auth/AGENTS.md` · the both-clients same-commit rule and the twin pairings — `ui/AGENTS.md` · controller source and full markup — the files · how a feature was built — `git log`.

## Rules

- Serving is fixed in root `main.py:create_app`, not in this tree: `main.py:UI_BROWSER_DIR` resolves from `main.py`'s own path, not the cwd (pages serve from any launch directory), and boot requires every `main.py:UI_BROWSER_FILES` entry to exist — a missing file raises `RuntimeError` at app construction, failing the boot, not the first request. The four pages gate behind `auth_api.get_current_user_for_pages`; `favicon.ico`, `apple-touch-icon.png`, `manifest.json`, and the `/assets` mount stay public so a gated page can still load its own JS/CSS — a newly gated asset route bricks every page at its stylesheet.
- Add-a-page recipe, in order: (1) create the page directory `ui/browser/<name>/` with its `index.html`, head block copied from an existing page (boot script, `theme.js`, `style.css`, font preloads, cache-bust tags); (2) add the path to `main.py:UI_BROWSER_FILES` — skip: boot fails `RuntimeError`; (3) add the route in `main.py:create_app` with `dependencies=page_dependencies`, both `/name` and `/name/` spellings — skip: the page 404s; (4) add the sidebar `<li>` to all four existing pages — skip: unreachable by navigation (`rg -l 'sidebar-nav-item' ui/browser` → the four pages plus `sidebar.js`/`style.css`; the markup lives only in the pages).
- Page auth has no login form anywhere: under `single` an unauthenticated page GET 302s to `/v0/auth/local/session`, which provisions the local account, mints the cookie, and bounces back to `/chat`; under `multi` the GET gets the standard 401 envelope (routes owned by `auth/AGENTS.md`, `auth/api.py:_page_auth_failure`). Every controller registers a logout handler navigating to `/` so a dead session re-runs the mint — the handler rule is the child map's (grep `rg 'onAuthChange' ui/browser`).
- `MIRA_CSP` stays off by default because these pages run inline `<script>` controllers and inline `onclick=` handlers, both rejected by `script-src 'self'`; `auth/security_middleware.py` names this tree as the strict-mode prerequisite (migrate every inline block into files under `assets/` first). Do not grow inline handler surface — a strict flip before that migration kills every controller at load. Inline `style=`/`<style>` are covered by `style-src 'unsafe-inline'`; scripts are the blocker.
- Cache-bust tags are a twin: every JS/CSS/icon URL in the pages carries `?v=<tag>`, currently `ui-20261012`, and the tag must equal `ASSET_VERSION` in `ui/browser/assets/javascript/ui.js` (its in-code comment states the sharing). Bump one side only and HTML-referenced vs JS-injected assets split cache generations — stale modules against fresh markup after a deploy. Fonts are the sanctioned exception: the four `assets/fonts/*.woff2` URLs are untagged on both the preload and `@font-face` sides, and the preload URLs must equal the `@font-face` srcs exactly or the font downloads twice.
- Light mode has one trigger: `html[data-theme="light"]` in `ui/browser/assets/style.css` (`:root` holds the dark defaults; Auto never resolves in CSS). Each page's `<head>` opens with the same pre-paint IIFE — localStorage `mira-theme` → `data-theme`, Auto via `matchMedia`, only indentation differs between pages — and `theme.js` owns the runtime setter. An attribute rename or boot-script edit lands in all four pages, the CSS selector, and `theme.js` in one commit; one page edited alone FOUCs or sticks dark.
- The sidebar `<nav id="app-sidebar">` markup is duplicated in all four pages — only `active`/`aria-current` moves; `sidebar.js` wires it by id. A nav item, pill, or reorder lands in all four files; skip one and that page's navigation goes stale.

## Files

- `chat/index.html` — the chat page's markup: sidebar, notification center (announcement banner text arrives via `data?type=user`, content from the announcement cache (`config/announcement.py`)), compose bar + file picker, toolbar indicators, attachment/queue/domain popovers, repulsion and location-consent modals, loading screen. No controller beyond the theme boot and the announcement banner's dismiss `onclick=` — behavior lives in the modules (`ui/browser/assets/javascript/AGENTS.md`). Entry: the DOM ids and `data-indicator` attributes, which `core.js`'s `elements` cache greps (`data-priority` on the toolbar buttons is dead — nothing reads it; do not build on it). Gotcha: renaming an id breaks runtime wiring with no error in this file — there is no compile step.
- `memories/index.html` — memories page + inline controller: paged list over data type `memories` (offset paging, `meta.next_offset`, page size 50), search debounced 300 ms, bulk select/delete, add-memory; action domain `memory` (`create`/`delete`/`bulk_delete`). Gotcha: all filtering, sorting, and link counts render client-side over loaded rows — the server only searches and pages; `inbound_links`/`outbound_links` arrive as arrays of `{uuid, type, …}` — both the per-group count and each link's `uuid`/`type` render.
- `domaindocs/index.html` — domaindocs companion + inline controller `DomaindocsCompanion`: 1 s polling (`POLL_DELAY_MS`), `JSON.stringify`-hash change detection, conflict modal when MIRA edits a section mid-edit (polling pauses during resolution), 3.5 s debounced saves, drag-drop reorder within one parent level, archived view via `?archived=true` (`history.replaceState`). Entry: module-level `companion`; the three header controls route through `isReady`-guarded functions (`handleSelectDomain`/`handleCreateDomain`/`handleToggleArchived`), every other inline `onclick=` calls `companion.*` directly — safe only because those sit inside `#domain-view`, hidden until a domain is selected. Gotcha: pinned sections refuse collapse, drag, and title-edit/delete — content stays editable.
- `settings/index.html` — settings hub + inline controller: six hash tabs, five over the lazy `pageLoaders` registry (`#profile`, `#credentials`, `#tools`, `#automations`, `#developer` — a dynamic section without a loader entry never loads; `#general` is static markup, its Appearance select wired in the inline controller); action domains `user` (profile, http credentials), `portrait`, `lora` — the last two preview-before-save (`preview_id` consumed on accept/decline; Redo declines first, an expired id being a server no-op); the only in-tree caller of `/v0/api/triggers/rules…` and `/v0/api/triggers/conflicts` (grep `rg 'api/triggers'`); also drives `/v0/auth/api-tokens` (shared with the TUI bootstrap and `deploy/vm/talktomira.sh`); tools tab delegates to `ToolConfigManager`. Gotcha: the UI's "User Model" is the `lora` action domain — grepping "user model" misses it.
- `favicon.ico` — site icon served at `/favicon.ico` (public); referenced by every page's `<link rel="icon">` with the cache-bust tag.
- `apple-touch-icon.png` — home-screen icon served at `/apple-touch-icon.png` (public); doubles as the manifest icon (896×919 there).
- `manifest.json` — PWA manifest served at `/manifest.json` (public): `start_url` `/chat`, standalone display, icon → `/apple-touch-icon.png`.
- `assets/style.css` — the one stylesheet for all four pages: theme tokens (`:root` dark defaults; `html[data-theme="light"]` the only light trigger), chat chrome (fixed 230 px sidebar, scrolling `#response_box`, compose bar), supporting-page primitives scoped under `.page-main`/`.modal-dialog--form`, feature classes JS toggles by name (`.hidden`, `.active`, `.converted`/`.falling`, `.mira-editing`, session-status states, `.keyboard-open`). Entry: the token names — inline `style="…"` across the pages reads `var(--…)` from here. Gotcha: supporting-page selectors are scoped so nothing leaks into chat's layout — a bare selector leaks.
- `assets/javascript/` — the modules, the one transport, the client half of the turn protocol, loader sets and chat-page script order: `ui/browser/assets/javascript/AGENTS.md`.
- `assets/fonts/` — the four `.woff2` faces behind both the `@font-face` srcs and the pages' preloads (IBM Plex Mono, Roboto, Noto Emoji, Minni — Minni is the ASCII loading screen and collapse-animation face). URLs untagged (cache-bust exception above); a rename touches `assets/style.css` and all four pages.
- `assets/images/` — `logo.png`, `icons/` nav/toolbar PNGs referenced by the pages' `<img src>` (cache-bust-tagged), `icons/toolicons/` per-tool icons; the `TOOL_ICONS` stem-must-equal-filename contract is the child map's (`ui.js`).

## Wiring

- Served by root `main.py:create_app` — routes, boot check, public/gated split (Rules above); gate, bootstrap, and token routes are `auth/AGENTS.md`'s (`auth/api.py:get_current_user_for_pages`, `/v0/auth/local/session`, `/v0/auth/api-tokens`, which the settings developer tab drives).
- Controller endpoints, route contracts owned by `cns/api/AGENTS.md`: action domains `user`/`portrait`/`lora` (settings), `memory` (memories page), data types `memories`/`domaindocs`/`user`; the trigger-rules edge is bilateral — `cns/api/AGENTS.md`'s `trigger_rules.py` card names this settings page as consumer. All calls ride the child map's one transport (`MiraAPIClient`).
- Cache-bust tag ↔ `ui/browser/assets/javascript/ui.js:ASSET_VERSION` (child map); theme boot scripts ↔ `theme.js` and the `data-theme` selector here (the child map's `theme.js` card carries the reciprocal).
- CSP strict-mode prerequisite ↔ `auth/AGENTS.md` (`auth/security_middleware.py` — the migration list names this tree).
- Sidebar behavior ↔ `ui/browser/assets/javascript/AGENTS.md` (`sidebar.js` wires the duplicated markup by id); frame and both-clients rules ↔ `ui/AGENTS.md`.

## The page gate, anonymous GET to interactive

An anonymous GET `/chat` never renders on the first response. The route dependency `auth_api.get_current_user_for_pages` finds no Bearer header and no `session` cookie and raises `_page_auth_failure`, which is mode-dependent: under `single` it is a 302 to `/v0/auth/local/session`; under `multi` it is the standard 401 JSON envelope, and that is the whole story for that install — MIRA ships no `/login/` page, so the operator's own sign-in surface is the entry point and the browser shows the envelope.

The 302 target is the only identity surface under `single` (`auth/api.py:create_local_session`): it provisions `user@localhost` — adopting an existing row verbatim on an upgraded install — mints the `session` cookie, and 303s back to `/chat`. Ordering: the account row exists before the cookie is minted, and the cookie rides the second GET before any page JS runs, so the `MiraAPIClient` constructed at DOMContentLoaded opens a socket that authenticates on the first try (transport mechanics owned by the child map).

Session expiry runs the same chain: a 401 clears the token client-side, the controller's logout handler navigates to `/`, the root route redirects to `/chat`, and the gate re-runs the mint — the user sees a reload, never a login form. The pages navigate to `/` rather than to the session endpoint because the client cannot know the auth mode; the gate is the mode-aware seam on both the first visit and every recovery.

Under `multi` no redirect exists to follow: `create_local_session` itself refuses with 404 outside `single`, so a client-side redirect added for convenience would route multi installs into a 404.
