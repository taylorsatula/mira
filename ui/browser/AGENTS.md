# ui/browser/ — browser chat client: four static HTML pages plus `/assets`, served by `main.py` for single-user mode

No build step, no bundler, no service worker: the files on disk are what the browser loads.

## Rules

- Serving contract (`main.py:create_app`): pages are served from `UI_BROWSER_DIR`, resolved from `main.py`'s own location, never the process cwd. Every path in `main.py:UI_BROWSER_FILES` must exist or `create_app` raises `RuntimeError` before the server binds. Routes: `/` → 307 `/chat`; `/chat`, `/memories`, `/domaindocs`, `/settings` (each also with a trailing slash) carry `Depends(auth_api.get_current_user_for_pages)`; `/favicon.ico`, `/apple-touch-icon.png`, `/manifest.json` and the `/assets` `StaticFiles` mount are public (no user data). A file that is neither in `UI_BROWSER_FILES` nor under `assets/` is never served — a new page needs its route (with `dependencies=page_dependencies`), its `UI_BROWSER_FILES` entry, and a `sidebar-nav-item` link in every page's sidebar markup.
- Single-user mode only. Auth is the HttpOnly `session` cookie: an unauthenticated page request 302s to `GET /v0/auth/local/session`, which provisions `user@localhost`, sets the cookie and 303s back to `/chat` (owned by `auth/AGENTS.md`). There is no login page; every page's logout handler navigates to `/`, which re-mints the session. Under `MIRA_AUTH_MODE=multi` page requests get the 401 envelope — the browser client has no multi-mode sign-in surface.
- `MIRA_CSP=strict` breaks these pages: they run inline `<script>` blocks (the theme bootstrap in every `<head>`, the settings/memories/domaindocs page controllers) and inline `on*=` handlers (`domaindocs/index.html` throughout, two in `chat/index.html`). Strict-readiness steps are owned by `auth/security_middleware.py`'s docstring. New behavior goes in `assets/javascript/`, not inline.
- Every asset URL is root-absolute (`/assets/...`, `/favicon.ico`): pages answer at both `/chat` and `/chat/`, so a relative URL resolves differently per form.
- Cache-bust tag: every page URL for a script, stylesheet, icon or image carries `?v=ui-20261012`, and `assets/javascript/ui.js:ASSET_VERSION` holds the same tag for URLs built in JS. Changing any asset means replacing the tag everywhere (`grep -rn ui-20261012 ui/browser`); a partial bump serves stale JS against new markup. Font URLs carry no tag: each page's `<link rel="preload">` href must equal the `@font-face src` in `assets/style.css` byte-for-byte or the font downloads twice.
- Theme twin: the inline pre-paint bootstrap in all four `<head>`s resolves `localStorage['mira-theme']` the way `assets/javascript/theme.js:resolve` does — change all five together or the page flashes the wrong theme before `theme.js` corrects it.
- Script load order and the client internals are owned by `ui/browser/assets/javascript/AGENTS.md`; the cross-client twin rules by `ui/AGENTS.md`.

## Files

- `chat/index.html` — the chat page: the only page loading the full module chain (order owned by the javascript map). Carries every DOM id `core.js:elements` caches, the location-consent modal, the repulsion popover, and the announcement banner (inline `onclick` dismiss).
- `settings/index.html` — inline `DOMContentLoaded` controller; loads `api-client.js`, `tool-config.js`, `sidebar.js`. Hash tabs `#profile` `#general` `#credentials` `#tools` `#automations` `#developer`, each loaded lazily through the `pageLoaders` map. Calls: `user` (`get_profile`, `update_profile`, `list/store/delete_http_credential`), `portrait` and `lora` (`get`/`refine`/`accept`/`decline`) actions; `GET/POST /v0/api/triggers/rules`, `PUT/DELETE /v0/api/triggers/rules/{id}`, `GET /v0/api/triggers/conflicts` (the Automations trigger and field selects are built from the response's `data.triggers`); `GET/POST /v0/auth/api-tokens`, `DELETE /v0/auth/api-tokens/{id}` (a new token is shown once, cleared after 60 s).
- `memories/index.html` — inline controller over `data?type=memories` (offset paging from `data.meta.has_more`/`next_offset`, server-side `search`); sort and filters apply only to rows already loaded. Calls `memory` `create`/`delete`/`bulk_delete`.
- `domaindocs/index.html` — inline `DomaindocsCompanion` over `DomainKnowledgeManager` (`assets/javascript/domain-knowledge.js`): polls `domain_knowledge get` every 1 s, re-renders only after 5 s without typing, opens the conflict modal when the server changes a section being edited, saves 3.5 s after the last keystroke, `?archived=true` lists archived docs. Inline handlers reach the global `companion`.
- `favicon.ico`, `apple-touch-icon.png`, `manifest.json` — root files with explicit routes; each listed in `UI_BROWSER_FILES`. `manifest.json` `start_url` is `/chat`.
- `assets/style.css` — the one stylesheet: dark tokens on `:root`, light overrides on `html[data-theme="light"]` (no `prefers-color-scheme` media query — `theme.js` resolves Auto), the four `@font-face` rules.
- `assets/fonts/` — IBM Plex Mono, Roboto, Noto Emoji, Minni (`.woff2`), preloaded by every page.
- `assets/images/` — `logo.png`, UI icons in `icons/`, per-tool badge icons in `icons/toolicons/` (the stem set is mirrored by `ui.js:TOOL_ICONS`; add-one recipe in the javascript map).
- `assets/javascript/` — every client module; map `ui/browser/assets/javascript/AGENTS.md`.
