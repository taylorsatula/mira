# ui/tui/ — the terminal chat client: streamed turns over native scrollback, plus the install's maintenance commands

## Files

- `__init__.py` — package docstring only; no imports and no re-exports. Open it before adding an import or a re-export to the package.
- `__main__.py` — the `mira` command's CLI. Open it before adding a subcommand, a flag, or an exit code.
- `app.py` — startup resolution and the first-run guidance. Open it before changing a startup failure or what a new operator is told.
- `chat.py` — the turn, queue, and connection state machine, and the single reader of the inbox. Open it before changing what happens to a message, a turn, or a lost connection.
- `client.py` — all I/O: WS auth and frame pump, REST history pager, action POSTs, surfaced as typed events on the inbox. Open it before touching the wire, a timeout, or an error code.
- `commands.py` — the slash-command registry and the classification of one submission. Open it before adding a command or changing what counts as one.
- `endpoints.py` — the 0600 endpoint store: named endpoints, the active pointer, fail-fast loading. Open it before changing the config file's format or a load failure.
- `history.py` — history rows to scrollback blocks. Open it before changing how a replayed conversation groups or what it shows.
- `login.py` — the headless `--login` token bootstrap. Open it before the auth routes it mirrors change, or when a mint fails.
- `migrate.py` — `mira status`/`migrate`/`restore`/`backup`: the server-venv runner and the service stop and start around it. Open it before changing service management or the status report.
- `protocol.py` — the strict pydantic mirror of every frame and of the REST history envelope. Open it before any server frame or history shape changes.
- `screen.py` — prompt_toolkit, the pinned bar, and the terminal. Open it before changing layout, a key, or anything that writes to the tty.
- `text.py` — escape sanitizing and the streaming reply filter. Open it before changing what a reply shows, live or replayed.
- `transcript.py` — the look of every scrollback element, open boxes included. Open it before adding an element or changing a box's shape.
- `update.py` — `mira update`'s decision half, handing the machine work to the release's own `deploy/update.sh`. Open it before changing release resolution, the nightly path, or the venv-rebuild path.
- `requirements.txt` — the client's own pin set, one commented line of justification per pin. Open it before adding or moving a dependency.
- `BUILD_PLAN.md` — historical build record of the first client. Open it only for how a component came to be shaped this way; the code wins.
- `FRONTEND_PLAN.md` — historical rebuild record of the Rich + prompt_toolkit client; same rule.

## Wiring

- Startup: `EndpointStore.load` → `app.run` → `MiraClient.connect` → `ChatSession.run` → `history.replay_blocks` → `Screen.run` alongside `MiraClient.run` → the inbox loop. The connect completes before any UI exists, and replay completes before the pump starts: a bar drawn first turns an auth failure into an unrecoverable half-screen, and a pump started first hands frames to a handler whose history is not loaded.
- Reconnect: `ChatSession._reconnect` → `MiraClient.close` → `ChatSession._join_pump` → `ChatSession._connect` → `MiraClient.connect`. The join must precede the connect, because the old pump's `finally` clears `MiraClient._conn`; a connect that installs the new socket first has it wiped moments later, and every send then raises `NOT_CONNECTED`.
- Frame mirror: any inbound frame change lands in `protocol.py` and `client.py:_frame_to_event` in the same commit as the server change; an unknown frame field raises `ProtocolError` (`UNPARSEABLE_FRAME`). The REST history envelope is a separate path: `protocol.parse_history_response` builds it inside `client._fetch_history_page`, whose schema failure raises `ClientError("HISTORY_BAD_ENVELOPE")` — no `ProtocolError` is produced and `_frame_to_event` is not on the path. Drift is asymmetric on purpose: the mirror raises where the browser client drops the frame silently, so a lagging TUI is loud. Counterpart: `cns/api/AGENTS.md`.
- Display, retry, and grouping twins: `text.py:ReplyStream` is one display filter with two implementations, `chat.py`'s busy-retry and reconnect cadences are one set of constants in two clients, and `history.py:replay_blocks` groups rows with the same vocabulary as `ui/browser/assets/javascript/history.js:renderHistoryRows`. All three pairings and their same-commit rule are owned by `ui/AGENTS.md`. Counterpart: `ui/AGENTS.md`.
- Endpoint store: `endpoints.py` owns the on-disk format that `mcp/talkto_mira.ts` reads (`active`, `endpoints[].base_url`, `endpoints[].api_key`). A format change updates that reader in the same commit, or the TUI keeps working while every `talkto_mira` call dies on an unreadable store. Counterpart: `mcp/AGENTS.md`.
- Auth chain: `login.py` replays session → CSRF → API-token against the live routes, scripted a second time by `deploy/vm/talktomira.sh`. A route change updates both scripters in the same commit. Counterparts: `auth/AGENTS.md`, `deploy/vm/AGENTS.md`.
- Update handoff: `update.py` resolves the release and downloads its asset, then runs the release tree's own `deploy/update.sh` with the shared `MIRA_APP_DIR`/`MIRA_TUI_VENV`/`NIGHTLY*` environment. The client owns resolution, the script owns everything that touches the install, and the script's exit code is returned unchanged. Counterpart: `deploy/AGENTS.md`.
- Release identity: `update.py` imports `utils/release_identity.py` — this directory's one sanctioned server-tree import, and the only one the TUI venv's pins can satisfy. Counterpart: `utils/AGENTS.md`.
- Runner child: `migrate.runner_command` builds the argv and env for `scripts/migrate.py` on the install's server venv (`python3 -P -m scripts.migrate …`), and its `pg_bindir` comes from sourcing `deploy/lib/output.sh` and `deploy/lib/services.sh`; `_database_status` reads that runner's `status --json` payload by key (`ledger_head`, `tree_head`, `pending`, `repeatable_due`, `fingerprint_drift`, `adopted_with_drift_override`, `refusals`). A key or shell function renamed on the runner side leaves `mira status` raising or searching an empty PATH, not reporting a runner error. Counterparts: `scripts/AGENTS.md`, `deploy/lib/AGENTS.md`.
- Migrate twins: `migrate.py` re-implements two rules of the release tree — the non-canonical-root database refusal, and `OFFICIAL_SUBJECT_RE` mirroring `deploy/lib/custom_export.sh:MIRA_OFFICIAL_SUBJECT_ERE` — and its service stop/start arms mirror `stop_mira_service`/`start_mira_service` in `deploy/update.sh`. Change both together: a divergence makes the two disagree about which commits are official, or stops one side from refusing a throwaway root. Counterpart: `deploy/AGENTS.md`.

## Rules

- Only `Screen.emit` writes to the tty while the app runs, inside a print step that never leaves raw mode. A hand `print` from `chat.py`, `transcript.py`, or anywhere else re-cooks the terminal (ECHO back on), and every key typed during it echoes into append-only scrollback where no later erase reaches it.
- An emit that happens while a turn is open goes through `ChatSession._in_box` or `ChatSession._meta`, and every terminal handler closes the box with `transcript.mira_close()`. A plain emit mid-turn puts a row between the box's rows and breaks its `╵` gutter; a turn that ends without `mira_close()` leaves the box's bottom border missing.
- A message is in exactly one place at a time — the input box, the live region, or scrollback — and `turn_started` is the only transition into scrollback. Every other exit path takes it back: `ChatSession._restore_unsent`/`Screen.restore_input` on a delivery failure, `_print_remaining` at turn end. A path that leaves the text in none of the three loses it silently.
- Any path where a message cannot be delivered returns it, with its queued siblings, to the input box through `ChatSession._restore_unsent` and `Screen.restore_input`; `Screen.consume_input` is the compare-and-clear that stops a duplicate Enter from sending the same text twice. A new path that drops instead loses the text with no error anywhere.
- Every model- or user-supplied string is sanitized before it reaches Rich or a prompt_toolkit fragment: Rich passes ESC straight to the terminal, and `Screen.run` wraps the app in `patch_stdout(raw=True)`, which writes fragment text unescaped. `transcript.py` builds `Text` from plain strings, never from markup, and sanitizes with `text.sanitize`; a new scrollback element is written there and sanitizes there. The live region is the path where box text arrives unsanitized — `Screen._build_container`'s `outbox_fragments` `_clip`s `live.sending` and `live.queued` — so one ESC pasted into the input and queued moves the cursor or clears the screen from the bar, not the scrollback.
- Unbounded waits in this directory are named, not counted: the idle `await self._inbox.get()` in `ChatSession.run`, and inside the screen `await self._app.run_async(...)` in `Screen.run` plus the `self._finished.wait()` in `Screen.emit` while the app is closing (both live as long as the app does). Every other await at a socket, queue, or timer boundary carries a timeout — the constants at the top of `client.py` and `chat.py`, the inline `timeout=1.0` CPR waits in `screen.py`. `migrate.py` has no awaits at all: its runner child and its service controls are `subprocess.run` calls with no timeout, because a migration step may run long and the controls return rather than block (`sudo -n` fails instead of prompting). A new unbounded await on a path quit can reach makes cancellation unreachable.
- Adding a slash command is one `commands.COMMANDS` entry — `name`, `summary`, `kind`, `action`, renderer — and nothing in `ChatSession`: a `continuum` kind posts `client.post_action("continuum", action, {})` and passes the envelope's `data` to the command's renderer, while a `quit` kind carries `action=""` and `render=None`. Skipping the renderer crashes the notice on success; naming an action the server does not have turns every use into an alert. A renderer must tolerate payload drift, because the server adds a `meta` dict the client never asked for.
- Settings have no terminal UI by design: the 0600 store plus `--config-debug` is the interface. Interactive configuration would be a second writer of a format `mcp/talkto_mira.ts` also reads.

Elsewhere: this map owns the client's own structure, not the server contracts it mirrors and not what a maintenance command changes on the install. How a component came to be shaped this way is `BUILD_PLAN.md`/`FRONTEND_PLAN.md`; `git log` is the record of what changed. Every other destination this directory reaches is an edge — see `## Wiring` above.

## One turn from Enter to the closed box

The path that decides most of the Rules above, crossing `screen.py`, `commands.py`, `chat.py`, `client.py`, `text.py`, and `transcript.py`:

1. Enter posts `Submit` from a key binding in `screen.py` with `put_nowait`; the screen never calls the client, it only posts intents.
2. `ChatSession._handle` dispatches. `commands.parse` classifies first: a registered word runs one REST action or quits, an unregistered word becomes a notice naming it and the text stays in the box to fix, and anything not word-shaped is a message.
3. `Screen.consume_input(raw)` clears the box only if it still starts with that text — the guard against a duplicate Enter. The message then enters `_outbox`, and `_send_next` moves it into `_InFlight`, where it shows in the live region as `sending` and nowhere else.
4. `client.send_message` mints a message id and writes the frame; a send failure puts the text back in the box.
5. `turn_started` with that id is the moment the text moves to scrollback: one emit prints `transcript.you` and clears the live region together, so the message is never in two places and never in none.
6. Deltas go through `_Turn.stream.feed`, which commits only whole lines and holds back anything that could still turn into a tag or a partial leading timestamp. Committed lines print as `mira_rows` — the label on the first row, the gutter on the rest — and the uncommitted tail stays in the live region.
7. A tool event or a `model_error` flushes the stream before printing, so a row never lands inside a paragraph still pending in the live region.
8. Exactly one terminal frame ends the turn. `turn_complete` renders its own `response` only when the stream never displayed text; `_end_reply` closes the box, prints proactives held during the turn, then either returns the queue to the box (a Ctrl+C halt) or sends the next message.
9. A `TURN_BUSY` protocol error attributed to that message id is not a failure: a retry timer re-sends from the first bounce, and only exhausting the wait window returns the text to the box.
