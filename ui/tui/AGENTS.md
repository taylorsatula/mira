# ui/tui/ — the standalone streaming WebSocket terminal chat client

Elsewhere: the server side of every frame — `cns/api/AGENTS.md` · the browser twins and the cross-client same-commit rule — `ui/AGENTS.md` · the full frame union — `protocol.py`, the strict mirror · design-record history — `git log`; the PLAN files are historical, code is truth.

## Rules

- `protocol.py` mirrors the server frames and the `cns/api/data.py` history envelope with strict `extra="forbid"` models; a server frame change lands here and in `client.py:_frame_to_event` in the same commit, or the client raises `ProtocolError`/`UNPARSEABLE_FRAME` on the new frame. The both-clients same-commit rule and the three twin pairings (ReplyFilter, backoff constants, history row grouping) are owned by `ui/AGENTS.md`. The release-update notice is NOT a frame: it rides REST (`fetch_available_update` → `GET /v1/api/update_status`).
- One terminal writer: while the app runs, only `screen.py:Screen.emit` writes to the tty, inside a print step that never leaves raw mode — a hand `print` for chat output re-cooks the tty and every key typed during it echoes twice. No hand-counted cursor movement: the renderer measures and erases the bar. Resizes run an answer-epoch discipline (`Screen.run`'s `_handle_resize`/`_gated_redraw`/`_report_cursor` instance shadows): pre-resize cursor answers are discarded, repaints gate on a post-resize answer, and terminals that never answer CPR degrade after one bounded wait.
- One consumer: `chat.py:ChatSession.run` is the only reader of the inbox; `MiraClient` and `Screen` only post (`put`/`put_nowait`). A second reader steals items. `ChatSession._update_loop` is a third producer, still posting. Handlers run strictly in order; `_live` is derived on read, never kept in step by hand.
- A message lives in exactly one place — input box, live region, or scrollback — and reaches scrollback only in `_on_turn_started` (the server accepted it). Every undeliverable path (`_restore_unsent`: send failure, attributed `protocol_error`, connect failure/cancel, lost connection, user halt with queued follow-ups) returns the message, with queued siblings, to the box via `Screen.restore_input`; `Screen.consume_input` is the compare-and-clear that ignores a duplicate Enter.
- Display safety: every model or user string passes `text.py:sanitize` (Rich passes ESC through to the terminal), and `transcript.py` builds `Text` from plain strings, never markup. A new scrollback element goes in `transcript.py` and sanitizes there.
- Box discipline: everything emitted mid-turn goes through `ChatSession._in_box` (MIRA's content; first row sets `_Turn.opened`) or `_meta` (notices inside the open box); a plain emit mid-turn breaks the `╵` gutter. Every turn end closes via `transcript.mira_close()` (`_end_reply`, `_lost_connection`, `_print_remaining`); a user halt adds a `stopped` row so an empty halted turn still leaves a labelled box.
- `turn_complete.response` renders only when `ReplyStream.has_text` is false (`_on_turn_complete`) — otherwise the streamed lines already showed it; `flush`/`finish` never reveal held-back tag fragments (an unclosed `<mira:…>` is metadata, not text); a reply held back entirely falls through to `response`.
- Tag-literal hazard: literal think/mira tag strings written through agent tool payloads get HTML-entity-mangled on disk — build them by concatenation (`text.py` does) and verify on-disk bytes by execution.
- Bounded waits: the constants sit at the top of `client.py` (`WS_OPEN_TIMEOUT`, `SEND_TIMEOUT`, `CLOSE_TIMEOUT`, `HTTP_PAGE_TIMEOUT`, `UPDATE_STATUS_TIMEOUT`, `ACTIONS_TIMEOUT`, `MAX_FRAME_BYTES`) and `chat.py` (`EMIT_TIMEOUT`, `PUMP_JOIN_TIMEOUT`, `TURN_BUSY_*`, `AUTO_RECONNECT_*`, `QUIT_DOUBLE_TAP_SECONDS`) and `migrate.py` (`START_WAIT_SECONDS`); the idle `await self._inbox.get()` in `ChatSession.run` is the one sanctioned unbounded await.
- `mira migrate`/`mira restore` manage the install's service around the database work — `migrate.py`'s `_stop_mira_service`/`_start_mira_service` (launchd and systemd arms, port 1993 as the stop's ground truth; a supervisorless install gets the honest message instead of an arm): `restore` stops a running service first (M-4a: a restore under a live server was ~54 s of connection errors, live-witnessed on the Mac gauntlet) and starts it again after success, leaving it stopped with the start command after failure (the park doctrine); a successful `migrate`/`restore` that ran while the service was parked starts it — never `--plan`, `--dry-run`, or the Vault-free subcommands; the boot gate re-verifies and stays the arbiter. The arms are the twin of `deploy/update.sh`'s `stop_mira_service`/`start_mira_service` — change both together; and only ever under the canonical root, or a throwaway root's commands touch the host install's service.
- Slash commands are a pure registry: `commands.py` holds `Command` (name, summary, kind `quit|continuum`, action, renderer), `COMMANDS`, `parse`, `help_list`; only word-shaped `/word` text is a command attempt — an unregistered word is an error notice naming it, any other leading-slash text stays a message. `ChatSession` owns policy (dispatch inline in `_on_submit`); adding a command is one registry entry plus its renderer.
- `ui/__init__.py` stays import-free: `python3 -m ui.tui` imports the `ui` package inside the TUI venv, which carries none of the server's dependencies — a server import there breaks the `mira` command on every install. The one sanctioned server-tree import is `update.py`'s stdlib-only `utils/release_identity.py`.
- Settings have no UI by design: the 0600 store (`endpoints.py`) plus `--config-debug` is the interface; do not add interactive configuration. The store's format has a second consumer — `mcp/talkto_mira.ts` (twin owned by `mcp/AGENTS.md`) — a format change updates both in the same commit.

## Files

- `__init__.py` — docstring only, no re-exports; `-m ui.tui` resolves through the `ui` package first.
- `__main__.py` — the CLI: the `update` (`UPDATE_FLAGS` = `--nightly`, `--rebuild-venvs`, `--adopt-drifted`; an unknown flag exits 1; the update exit set is 0/1/3) and `status` subcommands dispatch before argparse (no store load, no client start); `--config PATH`, `--config-debug` (store layout, never the api_key), `--login [--endpoint|--base-url] [--chat]`; default runs the chat app; exit 1 on store-load failure.
- `app.py` — connect-before-UI resolution: failures print `_connect_guidance` keyed on `ClientError.code` and exit 1 (a half-drawn bar is unrecoverable); owns `INBOX_MAX` and the first-run guidance text.
- `chat.py` — the turn/queue/reconnect state machine. Entry: `_handle` (dispatch), `_on_submit`, `_on_interrupt`, `_load_history`, `_update_loop`, `_end_reply`. Gotchas: Ctrl+C is conditional on the box (a draft never halts a turn; empty box halts/cancels/arms quit double-tap); a mid-turn Ctrl+Enter (`SubmitNow`) halts the turn and sends the queue at its end (`_interrupting_for_send` — a Ctrl+C halt clears it and restores the queue to the box instead); an attributed `TURN_BUSY` keeps the message and retries — the server frees its per-user lock before the terminal frame (`cns/api/AGENTS.md`), so a resend can win immediately; Ctrl+T flips `_show_thinking` (a second per-turn `ReplyStream` shown as `transcript.thinking_lines`, flushed/discarded at reply-stream boundaries, forward-looking only); REST command results mid-turn flush pending paragraphs first (the `_on_model_error` discipline).
- `screen.py` — prompt_toolkit ownership: the pinned bar (live region, rule, input box, rule), `emit`/`set_live`/`consume_input`/`restore_input`/`close`, the intent union `Submit`/`SubmitNow`/`Interrupt`/`Quit`/`ToggleThinking`, the `TERMINAL_TITLE` set once in `_mark_running`. Gotchas: Enter submits, Ctrl+Enter submits interrupting (a `SubmitNow` — no-op where the terminal cannot send Ctrl+Enter as its own key; it arrives as Enter), Alt+Enter/Ctrl+J newline, Up/Down jump to box-text start/end; wrapped lines don't reflow on a later resize; widths are terminal cells (`cell_len`), never `len`.
- `text.py` — pure, stdlib-only: `sanitize`, `ReplyStream` (streaming think/mira-tag filter holding back tag fragments, interior-only blank lines, the leading `[5:47pm]` stamp; `breaks_before_pending` lets the live view show a held-back paragraph break ahead of the tail), `display_lines`. Gotcha: `feed` sanitizes per delta — an escape split across deltas can leak its printable tail, never ESC.
- `transcript.py` — the look of every scrollback element (`mira_rows`/`mira_close`/`mira_box`, `mira_lines`/`thinking_lines` with inline markdown, `tool_line`/`tool_error`, `notice`/`alert`, `segment_summary`, `banner`, `tools_running`). Gotcha: `tools_running` is the one element reading the clock at render (its timer needs the bar's periodic redraw); spacing lives here only.
- `history.py` — REST rows → scrollback blocks (`replay_blocks`): assistant + tool rows sharing `metadata.turn_id` form one MIRA box; collapsed sentinels render as the dim `segment_summary` block; in `session_plus_summary` mode the newest one sits above the replay and is the only block when no active segment has messages. History cannot recover the reasoning view or a halted turn's `stopped` row.
- `client.py` — WS auth + frame pump, the `ClientEvent` union, `ClientError` (sole exception), `fetch_history` (keyset pager; mode from the endpoint store), `fetch_available_update`, `post_action`. Gotchas: `run()` posts `Disconnected` on any unannounced close; `connect()` resets lifecycle flags and raises the frame limit to `MAX_FRAME_BYTES` (server `tool` frames carry untruncated results — the websockets 1 MiB default closes mid-turn with 1009).
- `protocol.py` — the strict pydantic mirror of all WS frames plus the REST history models; `parse_inbound_frame`/`dump_outbound_frame` are the only frame entry points.
- `commands.py` — the slash-command registry (see Rules); `parse` returns `CommandHit`/`UnknownCommand`/`PlainMessage`; renderers tolerate payload drift; a `quit` command's renderer is `None`.
- `endpoints.py` — `EndpointConfig`/`EndpointStore` (0600 JSON at `~/.config/mira-tui/config.json`), `HISTORY_FETCH_MODES`. Gotcha: the constructor does not read — callers must `store.load()`.
- `login.py` — `--login` token bootstrap: `mint_api_token()` chains `GET /v1/auth/local/session` (404 → email magic-link flow) → `POST /v1/auth/csrf` → `POST /v1/auth/api-tokens`, mirroring `auth/api.py` (same-commit on route drift); the token never prints except the can't-write-store last resort.
- `update.py` — `mira update`'s decision half: resolve the newest release via `utils/release_identity.py`, download the release asset (`RELEASE_ASSET_URL`; a 404 names the missing asset — never the auto-archive), and hand the machine work to the release's own `deploy/update.sh` with `--adopt-drifted` passed through; `--rebuild-venvs` takes the dedicated rebuild-only fast path (`_rebuild_venvs_only` → `update.sh --rebuild-venvs-only`: no release fetch, no code swap, no database steps, no consent gate); `--nightly` fetches the tarball pinned to the resolved head SHA so the payload and the recorded identity are one commit; nothing on the install is touched before the handoff, and its exit code (0/1/3) is returned unchanged.
- `migrate.py` — `mira status`, `mira migrate`, `mira restore`, `mira backup`: `migrate`/`restore`/`backup` forward their arguments verbatim to `scripts/migrate.py` on the install's SERVER venv (`runner_command`: `PYTHONPATH`, the AppRole loaded from `/opt/vault/*.txt` into the child env only, `pg_bindir` on PATH, `--backups-dir`/`--env-file` defaulted beside `MIRA_APP_DIR` — `backup` takes the `--env-file` default and never `--backups-dir`; its own `--output` defaults to `~/mira-backups` in the runner) and return its exit code unchanged (0 ok, 1 step or restore failed, 2 refused, 3 blocked); `status` is a stdlib-only report of the install repo against its newest official install/update commit (`official_baseline`; `OFFICIAL_SUBJECT_RE` twins `deploy/lib/custom_export.sh:MIRA_OFFICIAL_SUBJECT_ERE` — change both together): changes, untracked files, the operator's commits, stashes, then the database half from the runner's `status --json`. Imports nothing from the server tree. `MIRA_APP_DIR`/`MIRA_TUI_VENV` overrides scope files, never the database (the connection target is the host's Vault AppRole): under a root other than the install root `migrate`/`restore`/`backup` refuse (exit 3, nothing changed) before any child starts and `status` keeps its git half but skips its database half — the runner's Vault-free commands (`lint`/`reconcile`/`generate`) are not refused; twin of `deploy/update.sh`'s non-canonical guard; the service stop/start around `restore`/`migrate` is the service-management Rule.
- `requirements.txt` — the client's own pin set (websockets, httpx, pydantic, rich, prompt_toolkit); the server's requirements gains nothing from it.
- `BUILD_PLAN.md` — historical design record; where it differs from the code, the code is truth.
- `FRONTEND_PLAN.md` — historical design record; same rule.

## Wiring

- Startup order: `store.load()` → `app.run()` → `connect()` before any UI → `ChatSession.run()` → banner → history replay *before* the pump starts (wire frames arriving meanwhile wait in the socket) → `Screen.run` + `MiraClient.run` tasks → release-check poll (`_update_loop`, once at startup then every 24h) → inbox loop.
- Send path: `Submit` → `commands.parse` first (a command hit runs one REST action or quits; unknown word/bad args keep the text in the box) → `consume_input` → outbox → `_send_next` (text shown as `sending` in the live region) → `turn_started` moves it to its box → deltas through `ReplyStream.feed` → committed lines as `mira_rows`, tail in the live region → exactly one terminal (`turn_complete`/`turn_stopped`/`turn_error`) closes via `_end_reply`. An unrequested `turn_stopped` renders `stall` as a server-stall alert.
- Reconnect: `_reconnect` closes the client and joins the pump before the new `connect()` installs its socket (the old pump's `finally` clears the connection); `AutoReconnectDue` timers are dropped by run identity; `AUTH_FAILED` or a Ctrl+C connect cancel ends the run. Goal: session restored before any post-restart proactive push — the user never nudges.
- Counterparts: frame union + lock release ordering ↔ `cns/api/AGENTS.md` · the three twin pairings + the both-clients rule ↔ `ui/AGENTS.md` · endpoint store format ↔ `mcp/AGENTS.md` · version identity ↔ `utils/AGENTS.md` (`release_identity.py`) · the scripted auth chain mirrored by `deploy/vm/talktomira.sh` ↔ `deploy/vm/AGENTS.md` · the browser JS twin of the protocol ↔ `ui/browser/assets/javascript/AGENTS.md`.
