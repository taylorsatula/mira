## Rules

- Prohibited on sight: test files, pytest fixtures, mock objects, stubs, fakes, offline test databases, any check running against simulated infrastructure — a passing mock-based check provides no information about this system. The regime exists because every line in the repository is agent-written and type-clean never-executed code is this workflow's standard failure product; verification is mechanical and live, never assumed. A test is what a probe becomes when its answer must never change again — never a starting artifact.
- Required verification is live, in the power-on self-test tradition: the boot gate probes Vault, Postgres, Valkey, embeddings, the injection screen, and LLM reachability before the server binds (registered in `run_pre_server_post()`; full roster by `rg 'CheckSpec\(' utils/power_on_self_test.py`; mechanics owned by `utils/AGENTS.md`), and path-probes invoke critical runtime paths against the live system exactly as production would. A path-probe is production code — normal review discipline, the same credentials plumbing, production-identical failure behavior; anything less ships the probe's own bugs as checks.
- Probe-surface membership, standing: any path whose failure would report incorrect data, lose data, or degrade silently requires a path-probe — reads, writes, searches, auth flows, failure paths. A required probe that cannot run against live infrastructure is a code defect, not a probe problem: fix the code until it can; never simulate.
- The quality guarantee is boot-survival plus path-probe coverage. Code covered by neither is unverified — flag it in review. A bug found in unprobed code is fixed together with the probe that covers it, or the fix ships unverified and the next defect pays for it.
- The realtime verification loop keys tier to behavioral surface touched, never to change size — mis-tiering by bulk is how unverified work ships. Tier 0 — no behavioral surface (comments, docstrings, formatting, import regrouping, verified-mechanical renames, documentation): `py_compile` + pyflakes on the touched files; nothing further.
- Tier 1 — behavioral edits within surface already covered by boot or probes: execute the changed path once against live infrastructure; re-read the diff against the invariants (every failure path reports the failure truthfully, nothing silently degraded, no behavior asserted that never executed); end the change report **EXECUTED** (what ran) or **UNVERIFIED** (why not, and which probe would cover it).
- Tier 2 — new behavioral surface or elevated stakes (new feature, endpoint, or path; schema or data-migration change; failure-behavior, security, or auth change; new dependency): Tier 1 plus a persistence round-trip against dev infrastructure (write, read back, verify, clean up — RLS and constraints included), the path-probe registered where membership hits, and a second agent re-deriving the diff — skip that only when one-shot execution covers the change, and say so.
- Load the `writing-probes` skill before every verification decision: writing, running, or reviewing a probe; reproducing a defect live; deciding whether a check earns permanence; diagnosing a failed probe (code bug or probe bug). The skill owns the craft this map does not carry; without it the pretrained write-a-test reflex fires unopposed and the next check is a mock or a suite.
- No suite forms under `tests/`: nothing in the shipped tree runs it — no runner, no conftest, no pytest import repo-wide (reach grep in Wiring); the `pytest`/`pytest-asyncio` pins in `requirements.txt`'s testing block are dead weight — installed by every standard install, imported by nothing; remove them with the next requirements change. Every file here is admitted by a child's policy, never discovered by a collector. Read the child map before adding, editing, or deleting anything in a home; policies never cross — `tests/protected/`'s never-autodelete and exact-phrase admission apply only there, and a throwaway teardown or autodelete sweep reaching inside it deletes a permanent battery.
- A new directory under `tests/` must state which of the two homes it is and own its admission/cleanup/realism policy in its own map. An unowned third lifetime presents never-run files as checks — dead weight the no-suite rule exists to keep out.

## Wiring

- Doctrine outflow: root `AGENTS.md` routes every verification decision here (its NO MOCKS section and registry row) and attributes the "fix the code until it can" rule to this map; the two child maps cite the doctrine one-line each. Inbound citation set: `rg 'tests/AGENTS\.md'` → root and the two children (session documents under `plans/`, `notes/`, `docs/` excluded).
- Nothing in the shipped tree consumes or executes `tests/`: reach grep `rg 'tests/protected|tests/fixtures' --type py -g '!tests/**'` → two calibration-coupling comments only (`tools/implementations/bash_tool.py` naming its guardrail battery, `utils/untrusted_content.py` naming the injection battery). Batteries run by hand from the repo root; the run obligation rides the contract-change commits, owned by `tests/protected/AGENTS.md`.
- Child-owned edges, cited not restated: battery-witness couplings ↔ `tests/protected/AGENTS.md` (counterparts `tools/implementations/AGENTS.md`, `utils/AGENTS.md`, `config/prompts/AGENTS.md`, `clients/AGENTS.md`) · fixture seams — shipped-schema apply, embedding values, role provisioning — ↔ `tests/fixtures/AGENTS.md` (counterparts `deploy/AGENTS.md`, `deploy/lib/AGENTS.md`, `clients/AGENTS.md`).
- Promotion routing — which home a kept probe enters: live-infrastructure guard → `CheckSpec` under `utils/power_on_self_test.py`; offline regression battery → `tests/protected/` behind its exact-phrase admission; otherwise discard. Stated by the `writing-probes` skill's promote-or-discard moment (Moment six).
