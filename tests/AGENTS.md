# tests/ — the repository's binding verification doctrine

## Files

- `fixtures/` — throwaway real-infrastructure scaffolding a probe imports; its own map owns the roster. Open it before the first line of a probe that needs Postgres, Valkey, Vault, or a user identity.
- `protected/` — the permanent, admitted-by-phrase batteries; its own map owns what they witness and when to open them.

## Wiring

- Doctrine inflow: the repository root's `AGENTS.md` names this map the authority for the prohibition, probe-surface membership, the tiers, and the skill-load duty, and `tests/protected/AGENTS.md` defers the no-test-files rule here in one line. `tests/fixtures/AGENTS.md` does not cite this map — it sends its readers to `tests/protected/AGENTS.md` for policy — so a doctrine change reaches a fixtures reader only if that deferral is updated in the same commit. Two further citation sites move in the same commit: `utils/AGENTS.md`'s `Elsewhere` line points here for probe doctrine, and `ui/tui/BUILD_PLAN.md` restates the no-test-files and admission-phrase rules without citing either map (it names `tests/tmp`, which does not exist), so that second copy ages unread.
- Calibration coupling: two comments in the shipped tree name a battery as the reason a value holds — `tools/implementations/bash_tool.py` at `_load_app_tree`, on keeping `_validate_command` a pure decision function over an inert tuple, and `utils/untrusted_content.py` at `PASS_CEILING`/`REJECT_FLOOR`. Constant and battery change in one commit, and each counterpart map moves with it: `tools/implementations/AGENTS.md` and `utils/AGENTS.md`, both of which name `tests/protected/AGENTS.md` as the witness's owner. Those two comments are the whole consumer set: nothing in the shipped tree imports or executes this directory, and `rg 'tests/protected|tests/fixtures' --type py -g '!tests/**'` returns exactly them.
- Child-owned edges: the battery witnesses and the fixture seams are stated in full by `tests/protected/AGENTS.md` and `tests/fixtures/AGENTS.md`, each with its counterpart maps; this map only routes to them and must not grow a second copy.
- Out-of-tree pins: the `writing-probes` skill names both batteries and `tests/fixtures/AGENTS.md` in its exemplar and homes tables, so a rename or a move here strands its citations and the skill edit lands in the same commit. The skill still names the retired `jsonb_roundtrip_probe.py`; delete that pin at its next edit.

## Rules

- Prohibited on sight: test files, pytest fixtures, mock objects, stubs, fakes, offline test databases, and any check running against simulated infrastructure. A check that passes against a simulated dependency tells you nothing about this system: type-clean-but-never-executed is the standard failure product, and verification must be mechanical and live.
- A check earns a permanent home only by preserving a probe's answer that must never change again — never as a starting artifact. A suite written first preserves no answer; it asserts the design its author imagined and passes from day one.
- Probe-surface membership: any path whose failure would report wrong data, lose data, or degrade silently requires a path-probe — reads, writes, searches, auth flows, failure paths. A path-probe is production code: same review discipline, same credential plumbing, same failure behavior, or it ships its own bugs as a check. A required probe that cannot run against live infrastructure is a code defect — reshape the code until it can, and never simulate, because a probe written against a simulation certifies the simulation.
- The quality guarantee is boot survival plus path-probe coverage. Code covered by neither is unverified — say so in review. A bug found in unprobed code is fixed together with the probe that covers it; the fix alone ships unverified and the next defect pays for it.
- The tier follows the behavioral surface touched, never the size of the diff — mis-tiering by bulk is how unverified work ships. Tier 0, no behavioral surface (comments, docstrings, formatting, import regrouping, verified-mechanical renames, documentation): `py_compile` plus pyflakes on the touched files, nothing more — pyflakes comes from the operator's own install and no repo dependency pins it, so a machine without it reports which half ran instead of pip-installing one. Tier 1, a behavioral edit inside surface that boot or a probe already covers: run the changed path once against live infrastructure, re-read the diff against the invariants (every failure path reports the failure truthfully, nothing degraded silently, no behavior asserted that never executed), then end the change report EXECUTED with what ran or UNVERIFIED with why not and which probe would cover it. Tier 2, new behavioral surface or elevated stakes (a new feature, endpoint or path; a schema or data-migration change; a failure-behavior, security or auth change; a new dependency): Tier 1 plus a persistence round-trip against dev infrastructure (write, read back, verify, clean up, RLS and constraints included), the path-probe registered as a boot-gate `CheckSpec` where membership hits (`utils/power_on_self_test.py`; roster by `rg 'CheckSpec\(' utils/power_on_self_test.py`), and a second agent re-deriving the diff — skip that last only when one-shot execution covers the change, and say so.
- Load the `writing-probes` skill before every verification decision: writing, running or reviewing a probe, reproducing a defect live, deciding whether a check earned permanence, diagnosing a failed probe as code bug or probe bug. The skill carries the craft this map does not, and without it the pretrained write-a-test reflex fires unopposed and the next artifact is a mock.
- No suite forms here: no runner, no `conftest.py`, no CI job, and no pytest or unittest import anywhere in the repo. The `pytest` and `pytest-asyncio` pins in `requirements.txt`'s testing block are dead weight, installed by every standard install and imported by nothing. Every file in a home is admitted by that home's policy, never discovered by a collector.
- Policies never cross a home boundary. `tests/protected/`'s admission phrase and never-autodelete rule apply only inside it, so a throwaway teardown or a tmp-autodelete sweep reaching in deletes a permanent battery that no run can regenerate; the throwaway lifetimes under `tests/fixtures/` do not extend outside that directory either.
- A new directory under `tests/` is three edits in one commit: its own map, saying which home it is and owning its admission, cleanup and realism policy; a routing line in this map's `## Files`; and its row in the repository root `AGENTS.md`'s map registry. A home missing either registration is invisible to every session that loads this chain — its never-run files present as checks.

Elsewhere: this map does not carry the craft of writing a probe, the boot gate's own failure mechanics, or what either home admits and cleans up. The boot gate's check specs, its roster, and its parking-on-failure semantics are `utils/power_on_self_test.py`'s docstring; how any verification decision here was learned is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.
