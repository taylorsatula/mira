# tests/protected/ — permanent batteries for the bash guardrail and the untrusted-content boundary, the sole exception to the no-test-files rule

## Files

- `bash_guardrail_probe.py` — the destructive-command guardrail's witness: the real `_validate_command` driven over the default, skip-mode, operator-blocklist, and both-modes case tables. Open it before changing a guardrail pattern, `_analyze_command`, `_compile_blocklist`, or a `_validate_command` parameter.
- `injection_defense_probe.py` — the untrusted-content boundary's witness: `_reveal_hidden`, `wrap_untrusted`, and tier-1 `InjectionScreen.assess()` over labeled attack and benign corpora. Open it before rewording a screen question, moving a band edge, or changing either wrapper function.

## Wiring

- Guardrail witness: `bash_guardrail_probe.py` → `tools/implementations/bash_tool.py:_validate_command` and `_compile_blocklist`. The battery calls the same function the handlers call over the same parameter surface, except that root and audit log are pinned to module constants and the operator blocklist is supplied only inside its own case matrix; the pinned root is a placeholder no deployment produces, which costs nothing because `_validate_command` compares paths symbolically. A pattern or blocklist-compiler change is therefore either proven here or not proven at all, and the run's exit status is that proof. Counterpart: `tools/implementations/AGENTS.md`.
- Screen witness: `injection_defense_probe.py` → `utils/untrusted_content.py` (`PASS_CEILING`, `REJECT_FLOOR`, `_reveal_hidden`, `wrap_untrusted`) and the question wording under `config/prompts/injection_screen/`. The band edges and the question text are calibrated against this battery's numbers, so moving either without a run slides the pass/reject bands with nobody noticing: benign content starts being refused, or attacks are waved through. Counterparts: `utils/AGENTS.md`, `config/prompts/AGENTS.md`.
- Import chain: both batteries import project code before doing anything else, and open no connection on the way. That holds only because every client constructs its connection lazily; the first eager import-time connection makes both batteries abort at their own audit barrier rather than run. Counterpart: `clients/AGENTS.md`.
- Screen construction: `injection_defense_probe.py` builds `SystemOneClient` keyword by keyword from `config.systemone` and hands `get_llm_provider()` to `InjectionScreen`, so a renamed settings field or constructor keyword strands the live half at construction instead of at a case. Counterpart: `clients/AGENTS.md`; the `systemone` settings schema is `config`'s to own.
- Audit-event twin: the two files agree on every non-socket `_BLOCKED_AUDIT_EVENTS` name, and only the guardrail battery's list records that each was verified genuine for this interpreter. The injection battery lists no `socket.` names at all — its `_barrier` routes that whole prefix through `_network_permitted` — so a socket change is made in the guardrail list and its prefix handler, never mirrored. Every other name is corrected in both lists in the same change; a name that is not a real audit event matches nothing, so the barrier fails open and the battery reports a clean run it never earned.

## Rules

- Admission is the user typing the exact phrase `AUTHORIZE PROTECTED TEST SAVE`, per file and per save. No other act admits a file — not an agent's judgement that a probe is too valuable to lose, not a paraphrase, not an earlier authorization for a different file. An agent that believes a probe earned permanence asks and waits; until the phrase appears the work stays in `/tmp`. A battery saved here without the phrase is an unauthorized permanent test file — the thing the no-test-files rule forbids.
- Nothing in this directory removes a battery but the user — the never-autodelete policy `tests/AGENTS.md` places inside this directory.
- A change to the guardrail runs `bash_guardrail_probe.py`; a change to the screen runs `injection_defense_probe.py`; the run lands in the same commit as the change. The battery is the only witness that the guardrail still refuses what it claims and still allows what it should — a pattern edit committed without a green run has verified nothing, and the next bypass reaches the host unrefused.
- A battery here must be structurally unable to reach what it is not testing: each installs an audit hook before its first project import, and that hook refuses the blocked event names — process spawn, a named filesystem-mutation set, and every undeclared socket event — not the categories as such. `os.chown`, `os.link`, and `os.utime` are on neither list, so the hook is a CPython-event barrier, not a sandbox. An accidental call into a real transport then aborts the interpreter at the hook instead of touching the host. One recorded user-directed exception, scoped in its own file: `injection_defense_probe.py`'s live half reaches the configured System One endpoint and nothing else.

Elsewhere: this map does not own what a probe is, how one is written, or the prohibition that makes this directory an exception — it owns only which battery witnesses which boundary, and under what admission. The `writing-probes` skill is what a probe is, how to write one, and the promote-or-discard moment that decides a battery earned permanence; `tests/AGENTS.md` is the no-test-files prohibition this directory is the exception to, and the realtime verification loop that tiers a change. Why a particular spelling is refused, and which campaign found it, is `git log` and the per-case note fields; the coverage record is the case tables themselves, in the two battery files. Every other destination this directory reaches is an edge — see `## Wiring` above.
