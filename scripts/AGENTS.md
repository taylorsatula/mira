# scripts/ — thin `python -m` command entry points over machinery that lives elsewhere

## Files

- `__init__.py` — package marker; nothing is imported from it and nothing is re-exported.
- `export_user_bundle.py` — the exporter a maintainer runs by hand on a hosted instance to build one person's migration zip. Open it before changing what a bundle carries, how a per-user value is decrypted, or the instructions shipped inside the zip.
- `import_user_bundle.py` — the receiving-install side of that migration, written as a specification rather than an implementation. Open it before performing a per-user import into a fresh install by hand.
- `migrate.py` — argument parsing and rendering for the database step runner, the surface an operator, the installer, and the updater drive as a subprocess. Open it before changing a subcommand, a flag, an exit code, or a sentence an operator reads.
- `post_server_post.py` — a shim over the post-server self-test CLI, holding no logic of its own. Open it before running the post-server checks by hand.

## Wiring

- Plan handoff: `migrate._cmd_plan` → stdout markers → the two splitters, `deploy/update.sh` and `deploy/postgresql.sh`'s `carry_existing_data_forward`. The human-readable plan prints before `PLAN_BEGIN` and the machine plan between the marker pair, and the JSON block is emitted even when the command refuses with exit 2 — suppress it and both readers take the transcript as unreadable: the updater reports that it could not read the database, and the installer stops finding an adoptable plan in that JSON and sends the database down `keep_database_aside`. Counterpart: `deploy/AGENTS.md`.
- Operator transcript: `migrate.main` sets `sys.stdout.reconfigure(line_buffering=True)` because `deploy/update.sh` runs the whole update under `exec > >(tee -a "$UPDATE_LOG") 2>&1`. Drop the reconfigure, or replace the `tee` with a plain pipe, and stdout goes block-buffered: each "Running: …" line lands in the log after the step's own output instead of before it, so the update reads as if every step ran before it was announced. Nothing errors. Counterpart: `deploy/AGENTS.md`.
- TUI runner: `ui/tui/migrate.py` builds `python3 -P -m scripts.migrate …` on the install's venv and reads `status --json` by key. A renamed subcommand, flag, or payload key leaves `mira status` raising or reporting nothing rather than reporting a runner error. Counterpart: `ui/tui/AGENTS.md`.
- Post-server checks: `scripts.post_server_post` → `utils.power_on_self_test.post_server_cli`, which owns the arguments, the checks, and the verdict. The shim exists so the command name survives a reshape of that module; fold the module away and the hand-run post-server command moves with it. Counterpart: `utils/AGENTS.md`.
- Database login: `migrate.vault_admin_conninfo` → `clients.vault_client.get_database_url(admin=True)` → `clients.postgres_client.PostgresClient._parse_database_url`. The conninfo reaches psycopg only through the app's one URL parser, so a URL shape the parser does not produce is a shape this CLI cannot accept; parsing in the CLI instead leaves two readers free to disagree about a percent-encoded password. Counterpart: `clients/AGENTS.md`.
- Bundle shape and per-user key: `export_user_bundle.py`'s `users` SELECT column list moves with the `users` table in `deploy/mira_service_schema.sql`, and its inline HMAC→Fernet derivation moves with `utils/userdata_manager.py`'s `derive_session_key` + `_create_fernet`. A column added to the table and not to the SELECT vanishes from every exported profile with nothing failing; a derivation change applied to one site only turns every exported `encrypted__` value into a null under an `UNDECRYPTABLE__` flag while the bundle still passes its own manifest, so the loss surfaces on the receiving install alone. Counterparts: `deploy/AGENTS.md`, `utils/AGENTS.md`.

## Rules

- Renaming or removing a `migrate` subcommand or flag breaks every caller at once and nothing raises: they reach this CLI as subprocesses, not imports. Take the live caller set with `rg -l 'scripts.migrate'` before the rename, never from a list written in a map. A missed caller fails at the phase it runs in — mid-update, or at container start — where the operator gets a shell error instead of a Python one.

Elsewhere: this map routes commands and names who calls them; it does not own what any of them do — no database step, no bundle layout, no self-test check is decided here. The step contract, the ledger, and backup/restore mechanics are `utils/schema_migrations.py`; the bundle's file layout and its per-file drop list are `export_user_bundle.py`'s docstring; whole-instance restore, a sarcophagus, is a different mechanism from this per-user bundle and belongs to `deploy/vm/AGENTS.md`. Every other destination this directory reaches is an edge — see `## Wiring` above.
