# docs/ — operator documentation and process authorities: the writing register, the map-law research base, and plain-language operator guides

## Files

- `REGISTER.md` — the house writing register for agent-written and operator-facing text. Open it before writing or editing prose a model or an operator must act on.
- `AGENTS_MAP_RESEARCH.md` — the pointer list grounding each rule of the map law, one source per design element that source produced. Open it before amending or culling a law rule.
- `MAINTAINER_UPGRADE_GUIDE.md` — the maintainer's plain-English account of `mira update` on a user's install, the habits a database-structure change demands, and the plain-terms restatement of `deploy/RELEASE.md`'s checklist. Open it before writing a migration step or answering a failed-update report.
- `MANUAL_INSTALL.md` — the hand-executed install for platforms the installer rejects. Open it when `deploy/deploy.sh` refuses a platform, or when a step of the automated install must be reproduced by hand.
- `OFFLINE_MODELS.md` — the local llama-server endpoints, model-name configuration, and pre-start checklist. Open it before an offline-mode install.
- `SEGMENT_SYSTEM.md` — the operator-level account of segments, sentinels, collapse, and live context compaction. Open it when explaining stored conversation history to an operator.
- `GLOSSARY.md` — one sentence per codebase-specific term, each naming the map or file that owns the detail. Open it when a term in a user message or a tool result does not decode.

## Wiring

- Install recourse: `deploy/preflight.sh`, `deploy/dependencies.sh`, and `deploy/config.sh` print `docs/MANUAL_INSTALL.md` as the route for an unsupported platform; `deploy/config.sh` and `deploy/finalize.sh` print `docs/OFFLINE_MODELS.md` for offline setup; `tests/fixtures/scratch_db.py` points at the manual install for the pgvector extension. The boot refusals carry the same recourse: `utils/power_on_self_test.py:_boot_refusal` picks the `-MANUAL` twin id for a tree with no `mira` wrapper, and `utils/schema_migrations.py:_BOOT_MANUAL_MIGRATE_REMEDY` and `_BOOT_MANUAL_RESTORE_REMEDY` restate `MANUAL_INSTALL.md`'s running command verbatim, so a change to that start procedure edits both constants in the same commit — otherwise the boot refusal tells an operator to run a command the guide no longer documents. Those printed pointers are the operator's only way off the automated path, so a commit changing a port, key name, env var, path, or error code a guide states edits the guide in the same commit — a stale guide mis-setups with no error to read. Full pointer sets: `rg 'docs/(MANUAL_INSTALL|OFFLINE_MODELS)'` for the printed paths, `rg '_BOOT_MANUAL_MIGRATE_REMEDY|scripts\.migrate migrate'` for the boot-remedy twins. Counterparts: `deploy/AGENTS.md`, `tests/fixtures/AGENTS.md`, `utils/AGENTS.md`.
- Release authoring: `docs/MAINTAINER_UPGRADE_GUIDE.md` states in plain language the step-authoring rules and the operator-recovery table that `deploy/migrations/AGENTS.md` owns, and its user-report triage table quotes operator strings from `utils/schema_migrations.py:OPERATOR_MESSAGES`, `deploy/update.sh`, `deploy/lib/custom_export.sh`, and the step files' own `RAISE EXCEPTION` text (`deploy/migrations/V0001__widen_segment_sentinel_uniqueness.sql` is the live one). The rule classes the lint rejects are enumerated only in `utils/schema_migrations.py:lint_steps`, so a lint check added there without a matching plain-terms entry leaves the guide licensing a construct the release build refuses. Change a quoted string or an authoring rule and the guide changes in the same commit, or the maintainer matches a user's report against wording the user never saw. Counterpart: `deploy/migrations/AGENTS.md`.
- Sentinel mechanics: `docs/SEGMENT_SYSTEM.md` states at operator level what `cns/infrastructure/AGENTS.md` owns as code (the one-live-sentinel unique partial index) and what `cns/services/AGENTS.md` owns (collapse, live context compaction); a change to any of them verifies the guide against source in the same commit. `cns/infrastructure/AGENTS.md` carries the reciprocal line, `cns/services/AGENTS.md` does not yet, so for collapse and compaction this map is the only place the duty is stated.

## Rules

- The register splits by reader, not by file. Operator-facing docs (`MAINTAINER_UPGRADE_GUIDE.md`, `MANUAL_INSTALL.md`, `SEGMENT_SYSTEM.md`, `OFFLINE_MODELS.md`) are written loose — full clauses, no coined term left undecoded — because their reader holds one page and cannot load a sibling document for the key, so a guide rewritten in cablese stops being usable by its operator. The model-read authorities (`REGISTER.md`, `AGENTS_MAP_RESEARCH.md`, `GLOSSARY.md`) keep the condensed register.
- Add a `GLOSSARY.md` entry in the same commit as any new term that appears in a map or a prompt name. The root map sends every reader with an unrecognized term to this file, so an absent entry is where the trail ends.
- `MANUAL_INSTALL.md` trust debt: the Injection Screen section's Docker claim — "ships with the screen off because the container cannot provision the Vault key — pass the env vars and seed Vault manually to opt in" — is stale, because `deploy/docker/scripts/init-mira.sh` writes `systemone_key` into `secret/mira/api_keys` and writes `/opt/mira/systemone.env` with `MIRA_INJECTION_SCREEN_ENABLED=1` whenever a token was collected. Default-off is no-token, not cannot-provision, so an operator following the doc hand-seeds what first boot provisions. Repay by editing the doc against `init-mira.sh`, then delete this bullet.
- `OFFLINE_MODELS.md` trust debt: the block titled "Default llama-server logs" names `/opt/mira/logs/llama-main.log` and `/opt/mira/logs/llama-small.log`, and no deploy script writes or reads either — `rg 'llama-main' deploy/` hits only `deploy/finalize.sh`'s informational `llama-{main,small}.log` line, and the operator starts llama-server by hand per the doc's own checklist. An operator tailing those paths waits on logs nothing writes. Repay by editing the doc, then delete this bullet.

Elsewhere: this directory states nothing at runtime, and the mechanisms its guides describe belong to the directories implementing them. The authoritative release checklist is `deploy/RELEASE.md`; the map law itself, outside this tree, is the `maintaining-agentsmd-maps` skill; how a document came to read as it does is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.
