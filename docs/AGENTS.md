## Rules

- `MANUAL_INSTALL.md` trust debt — repay by editing the doc against the named source, then delete this rule; staleness rules are not furniture. The container claim "ships with the screen off because the container cannot provision the Vault key — pass the env vars and seed Vault manually" is stale: `deploy/docker/scripts/init-mira.sh` writes `systemone_key` into `secret/mira/api_keys` and `/opt/mira/systemone.env` with `MIRA_INJECTION_SCREEN_ENABLED=1` whenever a System One token was collected (wizard step or `MIRA_SYSTEMONE_API_KEY`) — default-off is no-token, not cannot-provision; an operator following the doc hand-seeds what first boot provisions.
- `OFFLINE_MODELS.md` trust debt — same repayment. The "Default llama-server logs" block names `/opt/mira/logs/llama-main.log` and `/opt/mira/logs/llama-small.log`, but no deploy script writes or reads them (`rg 'llama-main' deploy/` → no hits; `deploy/finalize.sh`'s offline-mode summary prints the same paths brace-expanded — `llama-{main,small}.log` — an informational pointer, not a writer); the operator starts llama-server by hand per the doc's own checklist — an operator tailing those paths waits on logs nothing writes.

## Files

- `REGISTER.md` — the house writing register for any text a model reads: skills, agent definitions, `AGENTS.md` maps, docs, commit messages, prompts. Carries the cablese directive (delete only what the reader can reconstruct; rules keep their reason, measured quantities, irreducible literals, contrastive pairs), the item-count test, the three layers (maxim ~13-word floor; template notation verbatim, never prose-ified), the condensed/loose settings, failure modes, the before-saving checklist. Self-hosting: written in the register it describes — edit it in register, never paraphrase its rules elsewhere.
- `AGENTS_MAP_RESEARCH.md` — research pointers grounding each map-law rule (culling/slot discipline, demand model, wiring/reciprocity, ancestry), one `→` note per source naming the design element it produced. ## Wiring

- Inbound pointers make the operator guides load-bearing: `deploy/preflight.sh`, `deploy/dependencies.sh`, and `deploy/config.sh` print `docs/MANUAL_INSTALL.md` as the unsupported-platform recourse; `deploy/config.sh` and `deploy/finalize.sh` print `docs/OFFLINE_MODELS.md` for offline setup; `deploy/deploy-config.example.yml` cites it inline; `tests/fixtures/scratch_db.py` cites `docs/MANUAL_INSTALL.md` for the pgvector extension. Full set by grep: `rg 'docs/(MANUAL_INSTALL|OFFLINE_MODELS)'`. A commit changing a fact a guide states (port, key name, env var, error code, path) edits the guide in the same commit — the pointers are the operator's route off the automated path, and a stale guide mis-setups silently.
- `SEGMENT_SYSTEM.md` states, at operator level, mechanics owned by `cns/infrastructure/AGENTS.md` (sentinel lifecycle, the one-live-sentinel unique partial index) and `cns/services/AGENTS.md` (collapse, live compaction). Reciprocity debt: neither counterpart map cites this guide — the same-commit duty is visible only here, so a sentinel-behavior change verifies the guide against source through this line until the cns maps carry the reciprocal.
- No runtime consumer: no code opens or parses these files — every in-tree reference is a printed pointer (deploy scripts, `tests/fixtures/scratch_db.py`), a map citation, or a historical session document (`plans/`, `notes/`). The register's other consumer is the out-of-tree `maintaining-agentsmd-maps` skill, which routes every map edit through `docs/REGISTER.md` first.
