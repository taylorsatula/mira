# utils/ — cross-cutting infrastructure primitives: user identity, scheduling, storage, security, observability

Elsewhere: infra client contracts (Postgres/Valkey/Vault/embeddings/LLM) — `clients/AGENTS.md`, `clients/llm/AGENTS.md` · tool-config access/merge semantics — `config/AGENTS.md` (storage: `tool_config_store.py`) · probe-writing craft — the `writing-probes` skill · the POST check list — `utils/power_on_self_test.py`.

## Rules

- `user_context.py` is the single accessor set for identity (`set_current_user_id`/`get_current_user_id`), segment id (`set_current_segment_id`), cancellation (`set_cancel_event`/`check_cancelled`/`set_cancel_reason`), user preferences, and the five route configs. Root `AGENTS.md` owns the contextvar doctrine; enforced here: no second source of any of these — a parallel copy breaks RLS or cancellation silently at the bypassing seam.
- `get_model_config(name)` requires `load_model_configs()` at startup (RuntimeError before); exactly five route names exist and there is no fallback route; `other` colliding with `primary` only warns — an operator with one provider must still boot.
- A new `UserPreferences` field must land in BOTH `get_user_preferences()`'s hardcoded SELECT and its constructor call, or the field silently serves its default on every cache miss; and any writer of a preference must call `invalidate_user_preferences_cache(user_id)` or every other context serves the stale Valkey entry for up to 5 minutes.
- The use-day gate is one stateless function: `scheduled_tasks.get_users_due_for_job(interval)` (`MOD(cumulative_activity_days, interval) = 0` + 2-day recency on `last_activity_date`, over `memory_manipulation_enabled AND is_active` users). A custom tracking table or last-ran column is a defect. Job bodies wrap per-user work in `set_current_user_id()`/`clear_user_context()` (`lt_memory_jobs.py` is the pattern).
- Scheduler job IDs referenced by the power-on self-test are contract names — renaming one fails the boot gate. Registration order is fixed: `initialize_all_scheduled_tasks()` before `register_segment_timeout_job()`/`register_sidebar_dispatcher_job()`, all before the POST scheduler check.
- `perf.py:install_db_instrumentation()` monkey-patches every `execute_*` method of `PostgresClient`, `LTMemorySession`, and `AdminSession` by name — never add timing inside those methods (double-counting), and a new `execute_*` method must be registered there or it runs un-instrumented.
- Outbound requests to agent-controlled URLs must validate through `url_safety.validate_public_http_url()` and connect to the returned `ValidatedURL.resolved_ip` via `http_client.pinned_request()` — re-resolving DNS after validation reopens the rebinding TOCTOU (transition ranges like `64:ff9b::/96` included). `playwright_service.py` is the sanctioned exception: Chromium re-resolves itself, so the browser tier is not rebinding-proof — use the HTTP tier whenever content survives without JS.
- Tool-config secrets ride one sentinel state machine across `tool_config_store.py` and `tools/registry.py`: `load_user_tool_config` hydrates; `redact_tool_config` returns only sentinels to clients (`__MIRA_SECRET_CONFIGURED__`, or `""` when unset); `prepare_tool_for_validation` swaps an echoed sentinel back for the stored value so validation sees real secrets while storing nothing; persisting — a sentinel writes nothing, `""` deletes the stored secret, any other value stores it, and an omitted field preserves (so `{"enabled": true}` toggles without re-sending credentials) — and `save_tool_config_update` applies public config and secret writes in one SQLite transaction, a config-write failure rolling the secret writes back. Secret discovery is registry-driven (`json_schema_extra={"secret": True}` on the registered class): an unregistered config class silently loses redaction — `redact_tool_config` returns its input untouched.
- The injection screen's band edges (`PASS_CEILING`/`REJECT_FLOOR`) and question wording are calibrated against `tests/protected/injection_defense_probe.py` (counterpart: `tests/protected/AGENTS.md`) — change them only with that battery's numbers. Screen enabled: every non-rejection failure raises `InjectionScreenUnavailable` (fail closed; its `str()` is the `web_tool` fetch-failure envelope naming both remedies). Screen disabled: `screen_untrusted` is structural wrap only — never raw.
- The TOAST log level (60) is normally registered before app code by the deploy-installed `.pth` (`deploy/_mira_log_levels.py`); `logging_config.py` re-registers it idempotently at import so bare-process runs still get `logger.toast`.

## Files

- `__init__.py` — empty, no re-exports; import submodules directly.
- `user_context.py` — identity contextvar, segment id, cancel event+reason, `UserPreferences` + cache invalidation, `ModelConfig`/`load_model_configs`/`get_model_config`, `get_user_cumulative_activity_days`. Gotcha: the preferences SELECT+construction rule above.
- `database_session_manager.py` — the singleton pool manager: `get_shared_session_manager()` only; `LTMemorySession` sets `app.current_user_id` for RLS, `AdminSession` runs BYPASSRLS with no user context. Gotcha: a clean-exit commit failure re-raises (type preserved); a failure while an exception already propagates stays log-only so the original is never masked.
- `scheduled_tasks.py` — the use-day gate + startup registration orchestration. Entry: `get_users_due_for_job`, `initialize_all_scheduled_tasks`.
- `lt_memory_jobs.py` — the four LT_Memory jobs: extraction sweep (calendar), temporal/bulk score recalc and entity merge (use-day-gated, each looping due users with explicit context set/clear).
- `sidebar_jobs.py` — dispatcher poll registration; no-op unless `config.sidebar_dispatcher.enabled`.
- `scheduler_service.py` — the APScheduler wrapper (`register_job`/`start`/`stop`); jobs added before `start()` are batched.
- `scheduled_task_monitor.py` — `wrap_scheduled_job`: logs start/finish, single-worker executor, thread dumps past 5 minutes, shutdown without waiting (a stuck thread cannot be force-killed). Counterpart: `cns/services/AGENTS.md` (segment timeout), `cns/api/AGENTS.md` (health).
- `thread_monitor.py` — operation tracking, `@monitored_operation`, `MonitoredThreadPoolExecutor`, stuck-operation dumps. Consumed by the health diagnostics.
- `failover_jobs.py` — the recovery probe job, registered only when `config.api.failover_enabled`; counts pass/fail through `clients/llm/diverter.py` (mechanics owned by `clients/llm/AGENTS.md`).
- `self_restart.py` — the in-process restart mechanism behind `bash_tool`'s `restart_mira`: `request_restart` latch, the in-flight-turn gauge (`enter_turn`/`exit_turn` at the two turn boundaries), `trigger_restart_if_pending` firing SIGTERM only at gauge zero, `main.py` exiting `RESTART_EXIT_CODE` (75) so the supervisor respawns. Counterpart: `tools/implementations/AGENTS.md` (the request path); doctrine owned by root.
- `power_on_self_test.py` — the boot gate: `run_pre_server_post_gate()` runs bounded rounds in a subprocess and parks on failure (never exits — a restart supervisor must not loop billed probes; `MIRA_POST_GATE_FAILURE_ACTION=exit` opts out), verdict at TOAST; `run_post_server_post()` HTTP checks and the required job-ID set.
- `release_identity.py` — version identity, stdlib-only so the server and the TUI's minimal venv share one implementation; the TUI consumer (`update.py`) is owned by `ui/tui/AGENTS.md`. Entry: `get_current_version`, `version_sort_key` (`YYYY.MM.DD[-N.N]`; `None` for non-release strings — callers decline to compare), `fetch_latest_release_tag`, `TAG_TARBALL_URL`.
- `update_check.py` — the cached release verdict (`check_for_update` never raises — the notice is advisory; a failed check keeps the last verdict); the TUI polls `cns/api/AGENTS.md`'s `GET /update_status`.
- `cost_accumulator.py` — per-request LLM cost accounting over a contextvar: `start()` at request entry, `record()` per completed call, `drain()` at end; pricing route → `__default__` → `FALLBACK_PRICES`; no-op unless started.
- `perf.py` — all DB/request instrumentation: `PerfMiddleware` (N+1 at DEBUG), the `execute_*` patches, `@perf_profile`, `register_perf_routes()` (authenticated session; the logger-level gate is not access control).
- `logging_config.py` — TOAST, `UserContextFilter` (injects user_id), `CredentialRedactionFilter` (scrubs pool conninfo), colored setup, and the Anthropic SDK instrumentation (`instrument_anthropic_client`) gated behind `config.system.anthropic_sdk_content_logging`, default OFF — nothing is set up or persisted unless enabled.
- `llm_tap.py` — the USR1-toggleable LLM traffic firehose (`llm_requests.jsonl`/`llm_responses.jsonl`); write failures swallowed at debug — the tap must never take a request down.
- `distributed_lock.py` — Valkey locks with a token contract: `acquire` mints a UUID (None = not acquired), `release` is a Lua compare-and-delete (mismatch = expired and re-acquired → False + warning, a logged no-op, never an error), `renew` a compare-and-EXPIRE, `start_renewal` at TTL/3. `UserRequestLock` (`user_lock:{user_id}`) is the per-turn guard. Gotcha: the Valkey client resolves lazily on first use — locks are built at module import and import must succeed without Valkey/Vault credentials.
- `timezone_utils.py` — the timezone family root doctrine names. Entry: `utc_now`, `format_utc_iso`, `ensure_utc`, `parse_time_string`, `validate_timezone` (memoized), `get_default_timezone`, `normalize_exact_local_wall_time` + `local_datetime_to_utc_iso` (DST-strict: ambiguous/nonexistent raise), `strftime_no_pad` (the portable `%-I`/`%-d` spelling).
- `device_binding.py` — the heartbeat low-power shim publisher: `notify_heartbeat_sleep` routes the earliest wake to `config.heartbeat.device_power_binding.module_path` (`arm_low_power`); log-and-continue by design — the log line states the consequence (device stays at full power). Sole publisher: `agents/triggers/AGENTS.md` (`heartbeat_trigger.py`).
- `profile_validation.py` — `validate_profile_name` (whitespace collapse, 100-char cap, no control chars or angle brackets). Consumers: signup, profile update handlers.
- `url_safety.py` — `validate_public_http_url()` → `ValidatedURL(url, hostname, resolved_ip)`; domain filters/bindings for credentials. Blocks userinfo, private/metadata hosts, non-global IPs, and IPv6 transition ranges; validates every DNS answer.
- `http_client.py` — retrying httpx drop-ins. Gotcha: status retries (429/502/503/504/529) apply to idempotent verbs only; `retry_non_idempotent=True` opts a client's POST/PATCH in — pure-inference clients only, `clients/systemone_client.py` is the sole user; connect errors retry for every verb; connection retry for a stream exists only in the module-level `stream()` (a `Client.stream` CM cannot see the connect error).
- `nominatim_client.py` — OSM + Overpass client: process-wide 1 req/s throttle, identifying `USER_AGENT`; Overpass rotates `OVERPASS_URLS` and retries read timeouts and HTTP-200 `remark` errors. Its only consumers (`maps_tool`, `weather_tool`) were retired; it is now unwired — do not build on it without a new consumer.
- `mcp_client.py` — MCP client surface (`create_session`, `call_tool`, `list_tools`, `get_resource`; OAuth from `UserCredentialService`); reserved integration surface — no in-tree consumer today; live, unreached from the request path. Do not build on it as exercised.
- `playwright_service.py` — singleton headless Chromium; every call dispatched to one thread (sync-API thread affinity); per-request route interception via `validate_browser_request_url` (defined here, not `url_safety`); idle auto-shutdown; PID capture + force-kill.
- `untrusted_content.py` — the external-content boundary. Entry: `wrap_untrusted` (structural: tag-char strip, escape `&` first, wrap with the treat-as-data sentence from `config/prompts/untrusted_content_directive.txt`; pure, never raises) and `screen_untrusted` (reveal + chunk + judge through `clients/systemone_client.py`, then wrap). Consumer of the screen: `agents/base.py:_sanitize_work_item`. Root `AGENTS.md` owns the boundary doctrine.
- `text_sanitizer.py` — `sanitize_message_content`: null bytes, invalid UTF-8, text parts of multimodal arrays; length enforcement stays at the API layer by design.
- `document_processing.py` — doc→text extraction (PDF/DOCX/XLSX/CSV/TXT/JSON) with zip-bomb guards (`validate_office_zip`) and a 1M-char cap; image-only PDFs raise. Gotcha: the stdlib extractors (`_extract_docx_stdlib`/`_extract_xlsx_stdlib`) are the normal path, not a fallback — the optional deps are commented out of `requirements.txt`, so treat edits there as hot-path.
- `image_compression.py` — `compress_image()` two tiers (1568px inference, original format; 512px storage, WebP q75, alpha flattened); animated GIFs reduce to the first frame. Counterpart: `cns/api/AGENTS.md` (chat attachment path), `tools/implementations/AGENTS.md` (imagegen storage copies).
- `artifact_store.py` — `save_file_artifact`: `{uuid}.bin` + `.meta` (sanitized filename, MIME) under `data/users/{user_id}/artifacts/{file_id}/`; ids match `^[a-zA-Z0-9_-]+$`; 32MB cap. Served by `cns/api/AGENTS.md` (files/images routes).
- `userdata_manager.py` — per-user encrypted SQLite (`data/users/{user_id}/userdata.db`; Fernet keyed by HMAC over the Vault `userdata_encryption_key`); `encrypted__` prefix drives transparent field encryption in insert/select/update. Owns the DDL and migrations for `pager_*`, `domaindocs`/`domaindoc_sections`/`domaindoc_versions`, `contacts`, `trigger_rules`, `credentials`, `sidebar_activity`, and the `ACTIVITY_*`/`SCRATCHPAD_*` constants `agents/base.py:ensure_activity_schema` runs. Gotcha: `PRAGMA foreign_keys=ON` on every connection and `INTEGER PRIMARY KEY AUTOINCREMENT` ids (a deleted row's id is never reused) — a new table must declare both to behave like the rest.
- `user_credentials.py` — `UserCredentialService` over the `credentials` table (encrypted__ value, metadata JSON): `store/get/delete/list` + `get_credential_metadata`; contextvar user by default, explicit `user_id` for admin use; `RuntimeError` outside a request.
- `tool_config_store.py` — per-user tool-config persistence: public config plus separate secret cells, redaction, validation prep, and `save_tool_config_update` (public config + secret writes in one SQLite transaction). Sentinel state machine: Rules above.
- `user_activity.py` — the first-message-of-day hook: `increment_user_activity_day` runs one atomic date-predicate UPDATE incrementing `cumulative_activity_days` and advancing `last_login_at` (a second connection would self-deadlock on the row lock); the context guard `_activity_day_incremented_today` prevents double-claims across local-date rollover.
- `skill_files.py` — the skills store with two freshness doctrines: global (`working_memory/skills/`) boot-snapshotted by `load_global_catalog` — edits serve stale until restart; per-user (`data/users/{id}/skills/`) rescanned live with an empty-dir negative cache (an accepted trade: a first skill added after an empty first check waits for restart; the writer discards the cache entry only after a successful write). Entry: `load_global_catalog`, `catalog_for`, `load_skill` (resolves through scans, never caller-built paths), `write_user_skill`/`delete_user_skill`.
- `domaindoc_shares.py` — cross-user domaindoc resolution: `resolve_domaindoc` (`_shared` suffix → Postgres share lookup → owner's `UserDataManager`), `get_accepted_shares` (joins `LATERAL active_user_identity(...)` — a plain `JOIN users` drops rows under RLS), `invalidate_domaindoc_cache`.
- `tag_parser.py` — `TagParser.parse_response()` (mira: namespaced tags → `ParsedResponse`; `referenced_memories` is always `[]` — mention handling is `memory_tool`'s touch op) and the memory short-ID family: `format_memory_id`/`parse_memory_id`/`match_memory_id` (`mem_XXXXXXXX`, 8-char prefix of the dash-stripped UUID).

## Wiring

- Activity chain: `user_activity.increment_user_activity_day` (called from the message-ingestion path — call site owned by `cns/infrastructure/AGENTS.md`) maintains the counters `scheduled_tasks.get_users_due_for_job` reads; skipping the increment makes every use-day job skip the user. The use-day gates in `cns/infrastructure/feedback_tracker.py`, `cns/services/persona_service.py`, and `cns/services/portrait_service.py` read `get_user_cumulative_activity_days` directly.
- RLS plumbing chain: `user_context.py` (contextvar) → `database_session_manager.py` (`LTMemorySession._setup_connection` sets `app.current_user_id`) → Postgres policies; `perf.install_db_instrumentation()` runs after the singleton resolves, from `main.py` (root-owned order: middleware/routes first, then instrumentation).
- Credential chain: `clients/vault_client.get_service_config` → `userdata_manager.derive_session_key` (HMAC-SHA256 over the user id) → `UserCredentialService`/`tool_config_store` — both layers resolve the user from the contextvar and raise without one.
- External edges, owned elsewhere: `clients/llm/lifecycle.py` calls `cost_accumulator.record()`; `cns/api/chat.py` calls `start()`/`drain()`; provider probes run through `clients/llm/probe.py:probe_first_token` (`clients/llm/AGENTS.md`); Postgres pool semantics (`_rls_canary`, `PostgresPoolError`) and Valkey key conventions are `clients/AGENTS.md`.
- Consumers by area (structural; grep the symbol for the full set): screen → `agents/base.py`; boundary call sites → `tools/implementations/AGENTS.md`; `skill_files` warmed by `cns/integration/factory.py`, served via the skills trinkets (`working_memory/trinkets/AGENTS.md`).
- Counterpart edges: `llm_tap`/`artifact_store`/probe consumers ↔ `clients/llm/dialects/AGENTS.md`; `tool_config_store` read by the inbox poller ↔ `cns/services/pollers/AGENTS.md`; the post-server POST CLI imports the self-test ↔ `scripts/AGENTS.md`; `UserRequestLock` gated by the VM `turn_lock_gate` ↔ `deploy/vm/AGENTS.md`; the identity contextvar contract used by probe scaffolding ↔ `tests/fixtures/AGENTS.md`.
