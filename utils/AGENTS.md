# utils/ — Cross-cutting infrastructure: identity, scheduling, storage, security, and observability primitives

## Rules

- `user_context.py` is the single source of truth for user identity (`set_current_user_id` / `get_current_user_id`), model route config, user preferences, and request cancellation. Do not duplicate any of these elsewhere; `database_session_manager.py` and every RLS-scoped `PostgresClient` read identity from it.
- `get_model_config(name)` requires `load_model_configs()` called at startup; calling it before raises `RuntimeError`. Only the five fixed route names (`primary`, `fast`, `batch`, `assessment`, `other`) exist; any other name raises `KeyError` and there is no fallback route. `load_model_configs()` validates dialect/effort coercion and the compaction budget, and only *warns* when `other` resolves to the same model as `primary` (D14/O-3: an operator with one provider must still boot) — it does not enforce distinctness.
- `get_user_preferences()` in `user_context.py` carries a hardcoded SELECT and explicit field mapping. Adding a field to `UserPreferences` requires updating both the SELECT and the `UserPreferences(...)` construction, or the new field silently returns its default on cache miss. Callers that write preferences must call `invalidate_user_preferences_cache(user_id)` or all other contexts keep serving the stale Valkey entry for up to 5 minutes.
- `database_session_manager.py` is a module-level singleton (`get_shared_session_manager()`); never instantiate `LTMemorySessionManager` directly. Its `LTMemorySession`/`AdminSession` `execute_*` methods are monkey-patched by `perf.py` at startup — do not add timing or logging inside those methods; new `execute_*` methods must be registered in `perf.install_db_instrumentation()` to be counted.
- All use-day-gated jobs call `get_users_due_for_job(interval)` from `scheduled_tasks.py` — never a custom tracking table or last-ran state. The function is stateless: `MOD(cumulative_activity_days, interval) = 0` plus a 2-day recency window on `last_activity_date`, and it only returns users with `memory_manipulation_enabled = TRUE AND is_active = TRUE`. Calendar jobs use `IntervalTrigger` directly without this filter. Job bodies must wrap per-user work in `set_current_user_id()` / `clear_user_context()` (see `lt_memory_jobs.py` for the pattern). Interval values live in `config/config.py:ScheduledJobsConfig` `*_use_days` fields.
- All scheduled job registration goes through `scheduler_service.register_job()`; jobs registered before `start()` are buffered and added in one batch when the scheduler starts. Job IDs referenced by `power_on_self_test.py` (`lt_memory_*`, `segment_timeout_detection`, `auth_cleanup`, `account_garbage_collection`) are contract names — a POST check fails the boot gate if a rename drops one.
- `tool_config_store.py` and `user_credentials.py` resolve the current user through the contextvar, so they fail with `RuntimeError` outside an authenticated request. Tool config secret fields are declared with `json_schema_extra={"secret": True}` on the tool's config model; anything returned to a client must pass through `redact_tool_config()` (`SECRET_REDACTION_SENTINEL`), never raw hydrated values.
- Outbound requests to agent-controlled URLs use `url_safety.validate_public_http_url()` and must connect to the returned `ValidatedURL.resolved_ip` — via `http_client.pinned_request()` or (for browsers) a transport that honors it. Re-resolving DNS after validation reopens the rebinding TOCTOU. `url_safety` additionally rejects IPv6 transition ranges embedding IPv4 (`64:ff9b::/96`, `::/96`) that pass CPython's `is_global` check.
- `playwright_service.py` is the known exception to the pinning rule: Chromium re-resolves DNS itself, so the browser tier is not rebinding-proof; subrequest URLs are still validated through `utils.url_safety.validate_browser_request_url()` and non-HTTP schemes are blocked. Use the HTTP tier (`http_client.pinned_request`) whenever the content is available without JS rendering.

## Files

- `__init__.py` — Empty; no re-exports. Import submodules directly (`from utils.user_context import ...`).
- `user_context.py` — User identity contextvar (`set_current_user_id` / `get_current_user_id` / `has_user_context` / `clear_user_context`), segment context (`set_current_segment_id`), cancellation signal (`set_cancel_event` / `check_cancelled` / `set_cancel_reason` with `halt`/`disconnect` persistence), `UserPreferences` + `get_user_preferences()` + `invalidate_user_preferences_cache()`, and `ModelConfig` / `load_model_configs()` / `get_model_config()` for the five fixed `model_configs` routes. `get_user_cumulative_activity_days()` caches the count in the user context dict.
- `database_session_manager.py` — Singleton PostgreSQL pool manager (`get_shared_session_manager()`); `LTMemorySession` sets `app.current_user_id` via `set_config(..., false)` for RLS, `AdminSession` uses the `mira_service_admin` BYPASSRLS role and sets no user context. `transaction()` supports nested savepoints; connection acquisition retries for 30s then raises `ValueError`. Both pools point at the `mira_service` database.
- `perf.py` — All performance instrumentation lives here: `PerfMiddleware` (request summary + N+1 detection at DEBUG), `install_db_instrumentation()` monkey-patching `PostgresClient`, `LTMemorySession`, and `AdminSession` `execute_*` methods, `@perf_profile`, and `register_perf_routes()` (`GET /dev/perf/summary`). Three-tier behavior gated by the `mira.perf` logger level: WARNING+ installs nothing at all.
- `logging_config.py` — TOAST custom log level (60, normally registered at interpreter start by a deploy-installed `.pth`), `UserContextFilter` (injects `%(user_id)s` into every record; empty outside user context), `CredentialRedactionFilter` (scrubs psycopg pool conninfo passwords), `ColoredFormatter`, `setup_colored_root_logging()`, and `setup_anthropic_sdk_logging()` / `instrument_anthropic_client()` (httpx hooks for req_id → content correlation and the traffic tap). Consumers: `main.py` startup, every logging consumer via root config.
- `llm_tap.py` — Runtime-toggleable LLM traffic firehose: `kill -USR1 <pid>` flips `_active`; output appends to `llm_requests.jsonl` / `llm_responses.jsonl` in the project root. `httpx_request_hook` captures Anthropic request bodies (attached by `logging_config.instrument_anthropic_client()`); dialects call `log_response` / `log_stream_chunk` (`kind="stream_chunk"` is pre-normalization raw SSE). Write failures are swallowed at debug — the tap must never take the request down.
- `cost_accumulator.py` — Per-request LLM cost accounting via contextvar: `start()` at request entry (`cns/api/chat.py`), `record(result)` per completed provider call (`clients/llm/lifecycle.py`), `drain()` at request end returning `CostSummary`. Pricing resolves per field: route's `usage_pricing` row → reserved `__default__` row → `FALLBACK_PRICES` hardcoded table. No-op when not started or outside user context. Consumers: `clients/llm/lifecycle.py`, `cns/api/chat.py`.
- `power_on_self_test.py` — Power-on self-test: `run_pre_server_post_gate()` (bounded gate: `PRE_SERVER_GATE_ATTEMPTS` = 3 rounds with `PRE_SERVER_GATE_RETRY_SECONDS` = 10 between failures, then parks (sleeps forever, server never binds) or exits (`SystemExit` 1) per `MIRA_POST_GATE_FAILURE_ACTION` (only `park`/`exit`; anything else raises `ValueError`); runs each round in a subprocess via `python -m utils.power_on_self_test pre-server --json --report-marker --fast-exit`), `run_pre_server_post()` with required checks for configuration, Vault, Postgres RLS (a live canary pair asserting cross-user invisibility, self-healing sweep of `post-owner-%`/`post-other-%` canary users, and relrowsecurity + ≥1-policy metadata on the 16 RLS-covered tables), Valkey, embeddings, model route config, live provider reachability (billed probes over `LLMLifecycle`), tools, dependency init, and scheduler registration (required job-ID set: `lt_memory_extract_unprocessed_segments`, `lt_memory_temporal_score_recalculation`, `lt_memory_bulk_score_recalculation`, `lt_memory_entity_merge`, `segment_timeout_detection`, `auth_cleanup`, `account_garbage_collection`), plus `run_post_server_post()` HTTP checks against the bound server. Check specs are `CheckSpec(component, required, probe)`; reports are `PostReport`/`PostCheckResult` Pydantic models delimited by `MIRA_POST_REPORT_BEGIN/END` markers. Consumers: `main.py` (gate), `scripts/post_server_post.py`.
- `scheduled_tasks.py` — `get_users_due_for_job(interval)` (the only use-day gate; see Rules) plus startup registration orchestration: `initialize_all_scheduled_tasks(scheduler_service)` walks `SCHEDULED_TASK_MODULES` (currently `auth.service` cleanup jobs) then registers LT_Memory jobs; `register_segment_timeout_job()` and `register_sidebar_dispatcher_job()` are called separately after `event_bus` / `tool_repo` initialization. Any registration failure raises `RuntimeError`.
- `lt_memory_jobs.py` — `register_lt_memory_jobs(scheduler_service, lt_memory_factory)`: extraction retry sweep (calendar, `extraction_retry_hours`), and use-day-gated temporal score recalc, bulk score recalc, and entity merge (each an `IntervalTrigger(days=1)` job whose body loops `get_users_due_for_job` with explicit context set/clear).
- `sidebar_jobs.py` — `register_sidebar_jobs(scheduler_service, tool_repo, event_bus)`: no-ops when `config.sidebar_dispatcher.enabled` is false; otherwise builds `SidebarDispatcher` with `MemoryFloorTrigger` and registers the poll job on `poll_interval_minutes`.
- `scheduler_service.py` — `SchedulerService` wrapping `AsyncIOScheduler(timezone='UTC')`; `register_job()` / `start()` / `stop()`. Module-level instance `scheduler_service` is the shared one. Jobs added before `start()` are batched to avoid per-add schedule recalculation.
- `scheduled_task_monitor.py` — `ScheduledTaskMonitor.wrap_scheduled_job(job_id, func, timeout_seconds, kill_on_timeout)`: logs start/finish, tracks `JobStats` history, runs timed jobs in a single-worker `ThreadPoolExecutor` (shutdown without waiting — a stuck thread cannot be force-killed in Python), writes thread dumps for >5-minute jobs. Consumers: `cns/services/segment_timeout_service.py`, `cns/api/health.py`.
- `thread_monitor.py` — `ThreadMonitor.start_operation`/`end_operation`/`get_stuck_operations`/`dump_thread_states`, `@monitored_operation` decorator (sync+async), `MonitoredThreadPoolExecutor` (self-monitoring submit wrapper), and `start_periodic_monitoring()`. Thresholds: 30s slow, 300s stuck. External consumer: `cns/api/health.py` (thread-state diagnostics); otherwise available diagnostics, not load-bearing wiring.
- `distributed_lock.py` — Valkey-backed cross-process locks via atomic SET NX + TTL with a token contract: `acquire()` mints and returns a UUID token (`str | None`; None = not acquired), `release(resource_id, token)` is an atomic Lua compare-and-delete (mismatch = expired and re-acquired by another owner → False + warning, a logged no-op, never an error), `renew(resource_id, token)` is an atomic compare-and-EXPIRE (False = ownership lost). `DistributedLock` also exposes `is_locked`/`get_ttl`/`lock()` context manager (`LockAcquisitionError` on contention); `UserRequestLock` passes tokens through (`acquire`/`release`/`renew`/`lock_user`), the per-user single-active-turn guard keyed `user_lock:{user_id}`. The Valkey client is resolved lazily on first lock operation, never at construction — locks are built at module import, and import must succeed without Valkey/Vault credentials. Valkey unavailability propagates at use time — locking is required infrastructure, never a silent no-lock. Consumers: `cns/api/chat.py`, `cns/api/websocket_chat.py`, `cns/services/heartbeat_service.py`.
- `timezone_utils.py` — UTC-first datetime utilities: `utc_now()`, `format_utc_iso()`, `ensure_utc()`, `validate_timezone()` (IANA + US abbreviations; per-name memoized — `available_timezones()` walks the whole TZ database directory, and this runs per message during prompt composition), `get_default_timezone()` (host system IANA detection: `/etc/timezone`, then the `/etc/localtime` symlink's `zoneinfo/` path, else `UTC` — result memoized for process life; mirrored by `deploy/config.sh:detect_system_timezone` so the install default and the app fallback agree), `convert_to_timezone()`, `parse_time_string()` / `parse_utc_time_string()`, `format_relative_time()`, `format_relationship_duration()`, and the DST-strict `normalize_exact_local_wall_time()` + `local_datetime_to_utc_iso()` pair (ambiguous/nonexistent wall times raise instead of guessing). Consumers: entire codebase per root doctrine.
- `device_binding.py` — Low-power binding site for the heartbeat wake cycle: `notify_heartbeat_sleep(wake_at_utc, metadata)` is the sole entry point, publishing the earliest next heartbeat wake obligation to a deployer-supplied shim module (`config.heartbeat.device_power_binding.module_path`) that must expose `arm_low_power(wake_at_utc, wake_lead_seconds, metadata)` and bridges to the device's C++ power management. `metadata` is the single routing field (`HeartbeatSleepMetadata` TypedDict: `kind` tag — "heartbeat_sleep" today — plus `user_wake_times`, the per-user wake schedule composing the aggregate) so the far side can route the ping to whatever it wired up; structured facts only, freeform content never crosses the link. Log-and-continue by design: shim load/call failures warn (stating the consequence — device stays at full power, the unbound behavior) and never raise; load failures cache per module path so a broken shim logs once. MIRA never suspends anything itself — the shim owns the RTC alarm. Module docstring carries the future-agent touchpoint map for making the binding configurable. Sole consumer: `cns/services/heartbeat_service.py` (end of `heartbeat_tick`).
- `profile_validation.py` — `validate_profile_name(value, field_name)`: whitespace collapse, 100-char cap, rejects control characters and angle brackets. Consumers: signup, demo conversion, profile update handlers.
- `url_safety.py` — `validate_public_http_url()` returning `ValidatedURL` (url, hostname, validated `resolved_ip`), `validate_domain_filters()` / `domain_matches()` / `normalize_domain_pattern()`, `validate_allowed_domains()` for credential binding. Blocks userinfo, private/metadata hosts, non-global IPs, and IPv6 transition ranges; resolves and validates every DNS answer. Consumers: `http_client.py`, `playwright_service.py`, web tools.
- `http_client.py` — Drop-in httpx replacements with retry (`Client`, `get`/`post`/`put`/`patch`/`delete`/`stream`); retries 429/502/503/504/529 and connect errors with exponential backoff and jitter (longer for 429/529), 3 retries default. Connection retry for streaming lives ONLY in the module-level `stream()` — `Client.stream` returns httpx's context manager, and the connection is established at the caller's `with` entry, so no retry there can see a `ConnectError`; the module-level wrapper enters the CM inside its own frame and retries `ConnectError`/`ConnectTimeout` at entry, never mid-stream. `pinned_request(method, url, hostname=, ip=)` + `PinnedHTTPTransport`/`_IPPinNetworkBackend` connect TCP to a pre-validated IP (TLS SNI/cert still use the hostname) and fail loudly on any other hostname. Consumers: `clients/llm/dialects/openai_chat_base.py`, `nominatim_client.py`, tools (`weather_tool.py`, `web_tool.py`, `homeassistant_tool.py`), `cns/api/location.py`. Note: `pinned_request` itself has exactly one consumer (`tools/implementations/web_tool.py`); the other consumers use the plain retrying client.
- `nominatim_client.py` — OpenStreetMap client shared by maps_tool and weather_tool: `search` / `reverse` / `lookup` (Nominatim) and `nearby` (Overpass). Process-wide 1 req/s throttle (`_throttle`) and identifying `USER_AGENT` per public-instance policy; Overpass rotates `OVERPASS_URLS` and retries both read timeouts and HTTP-200 `remark` runtime errors (4 attempts, exponential backoff) — neither is covered by `http_client`'s status retries. Place IDs are `<N|W|R><osm_id>`.
- `mcp_client.py` — MCP (Model Context Protocol) client: `create_session(server_name, ...)` async context manager (user-scoped connection pool keyed by user_id + server name), `call_tool` / `list_tools` / `get_resource` conveniences. `RetryableMCPConnection` retries connection/timeout errors with backoff and disconnects before retrying; `ClientSession` must be entered as an async context manager (starts the receive loop). OAuth tokens come from `UserCredentialService` (`oauth_token` / server name). Auth vs connection failures are classified into distinct `MCP*Error` types via exception unwrapping.
- `playwright_service.py` — Singleton headless Chromium (`PlaywrightService.get_instance()`): lazy launch on first `fetch_rendered_html()`, auto-shutdown after 600s idle (10 min), all Playwright calls dispatched to one persistent thread (sync API thread affinity), PID capture + force-kill on shutdown, per-request route interception calling `validate_browser_request_url()`, networkidle→domcontentloaded fallback, 10MB HTML cap. Consumers: web tool escalation path, `power_on_self_test.py` (advisory check), lifespan shutdown.
- `prompt_injection_defense.py` — `PromptInjectionDefense.sanitize_untrusted_content(content, source, trust_level, require_llm_detection=False)`: regex pattern layer over an evasion-resistant copy (NFKC-folded, zero-width/bidi stripped, whitespace-collapsed, plus a despaced second pass — homoglyph/fullwidth, zero-width, and `i g n o r e`-style splits do not evade; ≥3 hits or strong single patterns reject), LLM layer via `get_llm_provider()` route `fast` that runs on **every** `TrustLevel.UNTRUSTED` payload regardless of length or pattern results — long content analyzed in 4000-char overlapping chunks with early exit on a >0.85-score chunk (≤2 calls for an 8000-char agent work item; `DefenseMetadata.llm_chunks_analyzed` records coverage), score > 0.85 rejects — then structural defense: `&`/`<`/`>`/`"` escaped (ampersand first, so pre-encoded `&lt;` tricks stay literal) and content wrapped in `<untrusted_content source="...">` with an explicit treat-as-data directive; the wrapper label is escaped so content or a caller-supplied source cannot forge provenance. Fail-closed semantics: `require_llm_detection=True` (autonomous-agent gate) rejects when the LLM is unavailable and propagates any analysis error; `False` analyzes identically when the LLM is available but degrades to pattern-only with a loud warning otherwise. Rejection → `ValueError`; returns `(sanitized, DefenseMetadata)`. Trust levels: `TRUSTED` / `USER_INPUT` / `UNTRUSTED` / `SUSPICIOUS`. Consumers: `agents/base.py`. Module-level `wrap_untrusted(content, source, trust_level=UNTRUSTED)` is the structural-only boundary (escape + `<untrusted_content source="<origin> (<trust>)">` wrap, no LLM call, never raises) — the mandatory wrapper for external text entering model context; tool-boundary consumers: `web_tool.py`, `email_tool.py`.
- `text_sanitizer.py` — `sanitize_message_content()`: removes null bytes, fixes invalid UTF-8, sanitizes text parts of multimodal arrays. Minimal by design — length enforcement lives at the API layer. Consumers: `cns/api/chat.py`, `cns/api/websocket_chat.py`.
- `document_processing.py` — `process_document(doc_bytes, media_type, filename)` → `ProcessedDocument` (always `content_type="text"`): PDF (pypdf), DOCX (python-docx or stdlib XML fallback), XLSX (openpyxl or stdlib fallback), CSV/TXT, JSON. ZIP-bomb guards via `validate_office_zip()` (entry count, per-entry and total uncompressed size, compression ratio) and a 1M-char extracted-text cap; image-only PDFs raise. `python-docx` and `openpyxl` are commented out of the root `requirements.txt` optional block, so on a default install `HAS_DOCX`/`HAS_OPENPYXL` are False and the stdlib extractors are the normal path, not a degraded one — treat a change to `_extract_docx_stdlib`/`_extract_xlsx_stdlib` as a hot-path change. `_extract_xlsx_stdlib` handles both OOXML cell encodings (`t="inlineStr"` with `<is><t>`, which is what openpyxl itself writes, and `t="s"` shared-string indices collected per `<si>` so rich-text runs concatenate instead of shifting later indices), and `_xlsx_sheets_in_order()` resolves sheet display names and true workbook order from `xl/workbook.xml` + its rels, falling back to a natural sort of part names when the manifest is absent.
- `image_compression.py` — `compress_image()` → `CompressedImage` with two tiers: inference (1568px max, original format) and storage (512px max, WebP q75, alpha flattened to white). Animated GIFs reduce to the first frame. Consumers: message image attachment path.
- `artifact_store.py` — `UserArtifactStore.save_file_artifact()`: writes `{uuid}.bin` + `.meta` (sanitized filename, MIME) under `data/users/{user_id}/artifacts/{file_id}/`; validates artifact IDs (`^[a-zA-Z0-9_-]+$`) and caps 32MB. `sanitize_filename()` is the shared filename sanitizer.
- `userdata_manager.py` — `UserDataManager`: per-user encrypted SQLite at `data/users/{user_id}/userdata.db` (Fernet from `derive_session_key()`, HMAC over the Vault `userdata_encryption_key`); `encrypted__` column prefix drives transparent per-field encryption in `insert`/`select`/`update`. One persistent WAL connection per instance, instances cached in `_manager_cache` via `get_user_data_manager()`; `clear_manager_cache()` closes them. Owns inline schema init/migration for `pager_*`, `domaindocs`/`domaindoc_sections`/`domaindoc_versions`, `contacts`, `trigger_rules`, and `credentials` tables. `UserDataManagerCleanupHandler` closes a user's manager on `SegmentCollapsedEvent`. Consumers: `user_credentials.py`, tools (`self.db`), `domaindoc_shares.py`.
- `user_credentials.py` — `UserCredentialService(user_id=None)` CRUD bridge over `UserDataManager`'s `credentials` table (`encrypted__credential_value`, metadata JSON): `store_credential` / `get_credential` / `get_credential_metadata` / `delete_credential` / `list_user_credentials`. Uses the contextvar user by default and raises `RuntimeError` without one; an explicit `user_id` constructor argument is accepted for administrative use. Consumers: `tool_config_store.py`, `mcp_client.py`, tools (`imagegen_tool.py`, `web_tool.py`, `homeassistant_tool.py`), `cns/api/tool_config.py`.
- `tool_config_store.py` — Per-user tool config persistence: `load_user_tool_config()` / `save_user_tool_config()` / `delete_user_tool_config()` (config JSON stored as credential type `tool_config`; secret fields stored separately as `tool_config_secret` under `{tool}:{field}`), `get_secret_field_names()` (driven by `json_schema_extra={"secret": True}`), `redact_tool_config()`, `prepare_tool_config_for_validation()` + `persist_secret_updates()` (sentinel round-trip keeps stored secrets when the client echoes `__MIRA_SECRET_CONFIGURED__`), `strip_secret_fields()`. The sentinel round-trip: `redact_tool_config()` replaces hydrated secrets with `__MIRA_SECRET_CONFIGURED__` (or `""` when unset); `prepare_tool_config_for_validation()` swaps an echoed sentinel back for the stored value (so `persist_secret_updates()` writes nothing), `""` deletes the stored secret, any other value stores it — and a secret field entirely omitted from a partial PUT gets sentinel semantics too (preserve existing, write nothing), so `{"enabled": true}` toggles work without re-sending credentials. Every function resolves the tool's config class through `tools.registry.registry.get(tool_name)`; secret fields are discovered from `json_schema_extra={"secret": True}` on that class, so a tool whose config class is not registered silently loses secret redaction (`redact_tool_config` returns the config untouched). Consumers: `tools/` config actions (see `tools/implementations/AGENTS.md`), `cns/api/tool_config.py`, `config/config_manager.py`.
- `user_activity.py` — `increment_user_activity_day(user_id)`: the first-message-of-day hook point — computes the user's local date from their preferences timezone, increments `users.cumulative_activity_days` once per local day via one atomic date-predicate UPDATE (no pre-read SELECT), so concurrent first-of-day callers increment exactly once; the same statement also advances `last_login_at` (a second connection here would self-deadlock on this transaction's row lock); upserts `user_activity_days`, and marks context `_activity_day_incremented_today` for the rapidpath. The caller-side gate lives in `cns/infrastructure/continuum_repository.py` and excludes heartbeat stimuli (see that map). `get_user_cumulative_activity_days(user_id)` rounds out the module. Consumers: message ingestion path, `scheduled_tasks.get_users_due_for_job` (reads the counters it maintains).
- `domaindoc_shares.py` — Cross-user domaindoc resolution: `resolve_domaindoc(user_id, label)` (suffix `_shared` → PostgreSQL `domaindoc_shares` lookup into the owner's `UserDataManager`; plain label → own SQLite), `get_accepted_shares()` (joins `LATERAL active_user_identity(...)` — a plain `JOIN users` would drop rows under RLS), `invalidate_domaindoc_cache()` (Valkey trinket cache, key format owned by `working_memory/trinkets/base.py`). All `PostgresClient` usage passes `user_id` for RLS. Consumers: domaindoc tool.
- `tag_parser.py` — `TagParser.parse_response()` extracts `mira:` namespaced tags (my_emotion, display_title, complexity, precis, internal_monologue, checkin_response, error_analysis) and returns `ParsedResponse` with `clean_text` from `remove_all_tags()` (preserves caller-listed tags, strips errant leading timestamps). `ParsedResponse['referenced_memories']` is always `[]` — memory references are handled by the memory tool's touch operation, not here. Also owns the memory short-ID format: `format_memory_id()` / `parse_memory_id()` / `match_memory_id()` (`mem_XXXXXXXX`, 8-char case-insensitive prefix of the dash-stripped UUID). Consumers: CNS response pipeline, memory tooling (`tools/implementations/memory_tool.py`, `working_memory/trinkets/proactive_memory_trinket.py`, `lt_memory/`).

## Wiring

`user_context.py` → `database_session_manager.py`: `LTMemorySession._setup_connection()` sets `app.current_user_id` from the session's `user_id`; `perf.py` monkey-patches both sessions' `execute_*` at startup — `install_db_instrumentation()` must run after the singleton can resolve (it imports lazily, so call order is: middleware/routes first, then instrumentation, all from `main.py`).

`user_activity.py` → `scheduled_tasks.py`: `increment_user_activity_day()` advances `cumulative_activity_days` and `last_activity_date`; `get_users_due_for_job(interval)` reads them with `MOD(cumulative_activity_days, interval) = 0` and a 2-day recency window, over an `AdminSession` (the gate is intentionally cross-user). Skipping the increment makes every use-day job skip the user. Job-ID registration order: `initialize_all_scheduled_tasks()` (auth cleanup jobs, then `register_lt_memory_jobs()`) must run before `register_segment_timeout_job()` / `register_sidebar_dispatcher_job()`, and all before the POST `scheduler_registration` check asserts the required job-ID set; a rename or dropped registration fails the boot gate.

`user_credentials.py` → `userdata_manager.py` → `user_context.py` / `clients/vault_client.py`: credentials live in the per-user encrypted SQLite; both layers resolve the user from the contextvar and raise `RuntimeError` without it. The Fernet key chain is `vault_client.get_service_config("userdata_encryption_key")` → HMAC-SHA256 over the user id (`derive_session_key()`) → first 32 bytes base64 → `UserDataManager.fernet`; the `encrypted__` column prefix is the sole trigger for transparent encrypt/decrypt in `insert`/`select`/`update` and stays in the column name after encryption.

`url_safety.py` → `http_client.py` / `playwright_service.py`: validation produces `ValidatedURL.resolved_ip`; `pinned_request()` consumes it for the HTTP tier. The browser tier validates but cannot pin (Chromium resolves DNS itself).

`power_on_self_test.py` → everything: the pre-server gate exercises Vault, Postgres RLS (live canary), Valkey, embeddings, `load_model_configs()` equivalent validation, provider reachability via `clients/llm/lifecycle.LLMLifecycle`, tool discovery, and scheduler registration through `initialize_all_scheduled_tasks()`; its required job-ID set is a contract on `lt_memory_jobs.py` / `scheduled_tasks.py` registration names.

External edges (owned elsewhere, cited not restated): `clients/llm/lifecycle.py` calls `cost_accumulator.record()`; `cns/api/chat.py` calls `start()`/`drain()`; `agents/base.py` consumes `PromptInjectionDefense`.

`main.py` edges (one-sided, owned by the root map): `main.py` calls `setup_colored_root_logging()` / `setup_anthropic_sdk_logging()` at import, `perf.install_db_instrumentation()` + `register_perf_routes()` after routes are wired, and `run_pre_server_post_gate()` before Hypercorn binds. The TOAST level (60) itself is normally registered before any app code by the deploy-installed site-packages `.pth` (`deploy/_mira_log_levels.py`, installed by `deploy/python.sh` and `deploy/docker/Dockerfile.base`); `logging_config.py` re-registers it idempotently at import as the fallback so bare-process invocations (POST CLI, probes) still get `logger.toast`.

`distributed_lock.py` ← `cns/api/chat.py` / `cns/api/websocket_chat.py` / `cns/services/heartbeat_service.py`: chat turns and heartbeat ticks acquire a `UserRequestLock` token for the user before processing, enforce one active turn per user across worker processes, renew the token while the turn streams, and release by compare-and-delete. Lock contention fails the request loudly; Valkey being down also fails loudly (no silent no-lock fallback).

Infra dependencies owned by `clients/` (non-owning citations; the owning statements live in `clients/AGENTS.md`): `database_session_manager.py` / `scheduled_tasks.get_users_due_for_job()` / `cost_accumulator._fetch_prices()` / `domaindoc_shares.py` all obtain PostgreSQL access through `clients/postgres_client.py` pools or shared admin sessions — RLS fail-closed semantics, the `_rls_canary()` omission warning, and `PostgresPoolError` are owned there; `userdata_manager.derive_session_key()` and `user_credentials.py` depend on `clients/vault_client.get_service_config()` for the Vault-held master key and per-user secrets; `user_context.get_user_preferences()` reads/writes its Valkey cache through `clients/valkey_client`. Provider reachability probes run through `clients/llm/lifecycle.LLMLifecycle` (owner: `clients/llm/AGENTS.md`).

`mcp_client.py` has no external consumers today (`grep` for imports outside `utils/` returns nothing) — it is the reserved MCP integration surface; the `UserCredentialService` OAuth-token wiring inside it is live code but currently unreached from the request path.
