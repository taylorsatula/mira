# clients/ — the infrastructure clients this server owns (Vault, Postgres, Valkey, embeddings, System One, Lattice) plus the LLM caller surface

## Files

- `__init__.py` — the package's eager import chain and its `__all__`. Open it before adding a client module or a re-export.
- `embeddings_provider.py` — text to vectors at the dimensionality the install's `embedding_config` row fixes, local or remote. Open it before changing how text is encoded or which model an install embeds with.
- `lattice_client.py` — the HTTP calls to the Lattice federation service. Open it before changing how a federated message is sent or this server's federation identity is read.
- `llm_provider.py` — the LLM call application code makes. Open it before changing a request's shape or how a caller's thinking intent is read; route resolution and the stall lifecycle belong to `clients/llm/AGENTS.md`.
- `postgres_client.py` — raw SQL over per-database pools with the RLS user context applied on every checkout. Open it before changing how a user's scope reaches a query or how a pool is sized.
- `sqlite_client.py` — dead unencrypted SQLite with no user scoping. Do not open it as a model for new storage.
- `systemone_client.py` — typed `POST /v1/systemone` decision-model calls, one question per request. Open it before changing how a statement is asked for a probability.
- `valkey_client.py` — the process Valkey surface and the atomic EVAL primitives every guarded cache write goes through. Open it before writing any read-then-write against Valkey.
- `vault_client.py` — Vault secret reads, the process-lifetime secret cache, and the required-secret manifest. Open it before adding a credential, a service-config field, or a boot-gate requirement.
- `llm/` — the provider-neutral LLM boundary: neutral types, route resolution, lifecycle, diverter; its own map.
- `llm/dialects/` — per-provider wire formats and the provider error taxonomy; its own map.

## Wiring

- Boot: `preload_secrets` → `get_embeddings_provider` → `get_llm_provider` → the dialect registry's `discover` → `get_valkey_client` + `flush_except_whitelist`; shutdown runs `ValkeyClient.shutdown` before `PostgresClient.close_all_pools`. Every boot step raises rather than deferring, so a dead dependency stops the process before it binds a socket; a client constructed lazily anywhere else moves that failure to the first request that needs it. Counterpart: root `AGENTS.md` (`main.py` lifespan).
- Import chain: `clients/__init__.py` eagerly imports the embeddings, Postgres, SQLite, Valkey, and Vault modules and opens nothing; `LLMProvider` is deferred through `__getattr__`, for the reason in the signal-handler edge below. Nothing here is a single list of connection openers: getters connect at first call, and `PostgresClient(...)` builds its pool inside `__init__`, so a client constructed lazily anywhere else moves a dead-dependency failure to the first request that needs it. A new module that connects at import aborts both offline batteries at their own barrier. Counterpart: `tests/protected/AGENTS.md`.
- Import-time signal handler: `llm_provider` binds `signal.SIGUSR1` to `utils.llm_tap.toggle` as it imports, so importing the module off the main thread raises. That is why `clients/__init__.py` defers `LLMProvider` through `__getattr__`. A change to `toggle`'s signature breaks `import clients.llm_provider` outright. Counterpart: `utils/AGENTS.md`.
- LLM request: `LLMProvider.generate_response`/`stream_events` → `ModelResolver.resolve` → `get_registry().get` → `Dialect.from_selection` → `Capabilities.validate` → `LLMLifecycle.complete`/`stream`, with the capability check before the lifecycle starts so an unsupported requirement fails as a named error instead of a provider-side 400. This module owns the trip accounting around that path; which errors may be recorded is stated by `clients/llm/AGENTS.md`. Counterparts: `clients/llm/AGENTS.md`, `clients/llm/dialects/AGENTS.md`.
- Postgres consumers: `rg 'PostgresClient'`. Two are structural. `utils/perf.py:install_db_instrumentation` patches the `execute_*` methods by name — renaming one silently drops DB timing for every caller. `PostgresClient._parse_database_url` is called cross-module from `utils/database_session_manager.py`, `utils/power_on_self_test.py`, and `scripts/migrate.py` so all three share one credential-encoding rule and one hostless-URL rule; changing that private method breaks three pool families and the boot gate at once. Counterpart: `utils/AGENTS.md`, `scripts/AGENTS.md`.
- RLS canary: `_RLS_COVERED_TABLES` and the `ENABLE ROW LEVEL SECURITY` statements in `deploy/mira_service_schema.sql` are one table list held in two files and move in the same commit. A table missing from the tuple is queryable without user scope and nothing remarks on it. Counterpart: `cns/infrastructure/AGENTS.md`.
- Valkey locks: `compare_and_delete`/`compare_and_expire` carry the release-and-renew guard for `utils/distributed_lock.py`; a release that is not compare-and-delete deletes a lock another holder has since taken. Counterpart: `utils/AGENTS.md`.
- Valkey epochs: `set_if_counter_matches` and `delete_and_increment` carry the epoch guard for the message cache; a cache write outside the epoch check lands stale content after an invalidation. Counterpart: `cns/infrastructure/AGENTS.md`.
- Flush keyspace: `BOOT_FLUSH_PRESERVE_PREFIXES` is the whole of what survives a boot flush, and three of its entries are another directory's state — `session:` and `csrf:` from `auth/session.py`, `rate_limit:` from `auth/rate_limiter.py` — while `webauthn_challenge:` from `auth/webauthn_service.py` is absent from it, so an in-flight passkey ceremony dies on restart and a login does not. The flush runs in `main.py`'s lifespan before the server binds, so a prefix missing from the tuple at import has already flushed that keyspace before the first request arrives and nothing writes it back; the writer's key naming moves under this tuple in the same commit. Counterpart: `auth/AGENTS.md`.
- Vault seam: `deploy/lib/vault.sh` writes the role-id and secret-id files that `deploy/finalize.sh` bakes into the service environment, and `VaultClient` reads them back from the process environment. Counterpart: `deploy/lib/AGENTS.md`.
- Service-field reads: `get_service_config` raises `KeyError` naming the missing field and the fields the secret does carry, and the token gates that call it — `cns/api/health.py:_require_diagnostics_token` and `cns/api/federation.py:_require_lattice_delivery_token` — turn that raise into a 503 refusal rather than treating an unconfigured token as no gate. The field is seeded in `mira/services` ahead of the route's first request, because the read happens per request: a field no deploy writer seeds keeps that route answering 503 for the life of the install. Counterpart: `cns/api/AGENTS.md`.
- Installer probes: `describe_for_installer` here and in `systemone_client.py` are called by `deploy/lib/embedding_config.sh` and `deploy/lib/systemone_config.sh`; the embeddings one also has in-tree callers in `scripts/migrate.py` and `tests/fixtures/scratch_db.py`, which read the same `model dimensions` output. Both sides of each contract move in one commit — a changed output shape strands installs at the probe and those two callers at their first call. Counterpart: `deploy/lib/AGENTS.md`, `scripts/AGENTS.md`, `tests/fixtures/AGENTS.md`.
- Injection screen: `ask_nouls` ← `utils/untrusted_content.py:InjectionScreen.assess`, the screen that judges external text before it enters a model context; the screen's tiers and fail-closed contract are `utils/AGENTS.md`.
- Encoder pairing: `encode_realtime` (query) and `encode_deep` (document) are two encoders of one asymmetric model, and `lt_memory/vector_ops.py` pairs them by side. Stored text encoded on the query side writes into the wrong vector space with no error — every similarity score is quietly wrong. Counterpart: `lt_memory/AGENTS.md`.
- Lattice: `get_lattice_client` ← `tools/implementations/pager_tool.py`, which sends the federated message and reads the server identity. Counterpart: `tools/implementations/AGENTS.md`.

## Rules

- `BOOT_FLUSH_PRESERVE_PREFIXES` reaches both full-flush paths by being handed over whole: `main.py`'s lifespan and `utils/schema_migrations.py:StepContext.invalidate_valkey` each pass `list(BOOT_FLUSH_PRESERVE_PREFIXES)` to `flush_except_whitelist`. A whitelist assembled by hand at either call site is the defect, because the two boot paths then preserve different key sets across the same restart.
- Every field in `REQUIRED_SECRET_MANIFEST` must be one that every install writer fills. A field one writer omits parks that whole install class at the boot gate, because `check_required_secrets` reports the gap and the gate does not serve past it.
- Two Postgres pool families share one database: `PostgresClient._connection_pools` here, and the LTMemorySession/AdminSession pools in `utils/database_session_manager.py`, both built from `get_database_url`. `statement_timeout` is applied by the session manager only, so a wedged statement on a `PostgresClient` connection has no server-side bound; pool exhaustion can come from either family, and counting one misreads the other.

Elsewhere: this map owns what these clients offer and the constraints that span them, not the systems on the other side of their connections or the config that tells them where those systems are — and it is not the home of every client in the tree: the outbound HTTP, geocoding, headless-browser, and MCP clients live in `utils/` (`http_client.py`, `nominatim_client.py`, `playwright_service.py`, `mcp_client.py`), each with its own line there. The config field schema — `config.database`, `config.cache`, `config.systemone`, `config.lattice` — is `config/AGENTS.md`; the encrypted per-user SQLite store that `sqlite_client.py` is not is `utils/userdata_manager.py`; a bound's tuning history is `git log`; the description of any one file is that file's docstring. Every other destination this directory reaches is an edge — see `## Wiring` above.
