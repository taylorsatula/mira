# clients/ — external infrastructure clients: Vault, Postgres, Valkey, SQLite, embeddings, Lattice, and the LLM entry point

## Rules

- Vault is the sole credential source for every client in this directory. `vault_client.py:get_database_url()`, `get_api_key()`, `get_auth_secret()`, and `get_service_config()` are the only permitted access points; environment variables (`VAULT_ADDR`, `VAULT_ROLE_ID`, `VAULT_SECRET_ID`) are the primary config source only inside `VaultClient` — all other clients delegate to it and never read provider credentials from the environment. `preload_secrets()` bulk-loads the three secret groups at startup and raises `RuntimeError` on any group failure.
- Required-infrastructure clients are module-level singletons accessed only through factory functions: `get_valkey()`, `get_hybrid_embeddings_provider()`, `get_lattice_client()`, `get_sqlite_client()`. Construction failures propagate — no fallbacks.
- `get_llm_provider()` (`llm_provider.py`) is the single construction point for `LLMProvider`; direct `LLMProvider()` instantiation in application code is prohibited. All LLM calls go through `LLMProvider.generate_response()` or `LLMProvider.stream_events()`; provider-specific code belongs in `llm/dialects/` (see `clients/llm/dialects/AGENTS.md`).
- `PostgresClient` pools are class-level, keyed by database name; `admin=True` uses a separate `{name}_admin` pool with a BYPASSRLS role and never sets user context. On every non-admin checkout `get_connection()` either sets or explicitly clears `app.current_user_id` — never rely on pooled-connection state carrying context. When the context is cleared, the RLS canary (`_rls_canary`) logs the first per-(pool, table) omission, because RLS fails closed (zero rows, no error) and a forgotten user context would otherwise masquerade as empty data. Keep `_RLS_COVERED_TABLES` in sync with the `ENABLE ROW LEVEL SECURITY` statements in `deploy/mira_service_schema.sql`.
- `SQLiteClient` has no RLS. Manual `user_id` filtering in queries is the only isolation mechanism — it is not redundant with anything.
- `PostgresClient` `execute_*` methods must stay externally patchable: `utils/perf.py:install_db_instrumentation()` (owner; see `utils/AGENTS.md`) monkey-patches them by name at startup, so a new `execute_*` method is silently un-instrumented until registered there, and adding timing/logging inside the methods double-counts.
- The embeddings model is pinned by a schema invariant: `mdbr-leaf-ir-asym` produces 768-dim vectors and `deploy/mira_service_schema.sql` (`memories.embedding`, `global_memories.embedding`) plus every similarity computation depend on that dimensionality. Changing the model requires regenerating ALL stored embeddings — vectors from different models are not comparable — and a replacement must preserve the asymmetric two-mode contract (`encode_query`/`encode_document`).

## Files

- `vault_client.py` — AppRole auth, KV v2 secret retrieval, and the process secret cache. `get_secret(path, field)` re-authenticates once on token expiry (`_read_secret_version`); module functions cache per key after first fetch. `test_vault_connection()` is the health probe.
- `postgres_client.py` — Pooled raw-SQL client with RLS context injection. `execute_query`/`execute_returning`/`execute_single`/`execute_scalar`/`execute_insert`/`execute_update`/`execute_transaction` return dict rows; `get_connection(query=...)` is the checkout point described in the canary Rule. `reset_all_pools()`/`close_all_pools()`/`get_pool_stats()` for lifecycle and diagnostics. pgvector is registered only for `mira_service`.
- `valkey_client.py` — Cache, session, and rate-limit store. One module-level pool backing three surfaces: sync client, `valkey_binary` (raw bytes, e.g. embeddings), and async `.valkey`. `__init__` pings Valkey — construction fails fast if unreachable. `json_set(key, "$"|"$."field, value, ex)` is a read-modify-write for field updates; `increment_with_expiry()` only sets TTL on first increment (rate-limit window); `flush_except_whitelist()` rejects empty prefixes.
- `sqlite_client.py` — Per-user tool data storage. No pooling; fresh connection per request via `get_connection()`. `get_sqlite_client(db_path, user_id)` caches one client per `user_id:path`. `Consumers: tools/implementations/` (per-user tool stores, via `self.user_data_path`/`self.db`).
- `hybrid_embeddings_provider.py` — Asymmetric 768-dim embeddings with Valkey-backed caches (15-min TTL, float16 bytes, separate query/doc prefixes). `encode_realtime()` for queries, `encode_deep()` for documents — the pairing is contract, not preference (see the model Rule).
- `lattice_client.py` — Thin HTTP client for the Lattice federation service: `send_message()` and `get_identity()`. Only consumed by the pager tool; not exported from `__init__.py`.
- `llm_provider.py` — The public LLM API. Validates and normalizes messages (`_validate_messages`, content-block taxonomy incl. `text`/`reasoning`/`tool_call`/`file_ref`/`image`/`document`), extracts the single system message (`_prepare_messages`), coalesces `thinking=` vs `effort=`/`thinking_tokens=` (mixing raises `ValueError`), merges the resolver's per-route effort default only when the caller did not specify effort, resolves via `ModelResolver`, builds the dialect, and delegates the live call to `LLMLifecycle`. Translates `ProviderContextOverflowError` to `ContextOverflowError` at this boundary. Registers the SIGUSR1 LLM-tap toggle at import.
- `__init__.py` — Re-exports `HybridEmbeddingsProvider`, `get_hybrid_embeddings_provider`, `PostgresClient`, `SQLiteClient`, `ValkeyClient`, `get_valkey`, `get_valkey_client`, and the three vault getters; `LLMProvider` resolves lazily through `__getattr__`. `LatticeClient` is excluded — import it directly from `lattice_client.py`.
- `llm/` — Provider-neutral LLM layer (types, events, lifecycle, resolver, registry). See `clients/llm/AGENTS.md`.
- `llm/dialects/` — Per-provider wire-format dialects and the error hierarchy. See `clients/llm/dialects/AGENTS.md`.

## Wiring

- Request flow into the LLM layer starts at `llm_provider.py:generate_response()`/`stream_events()`; the full resolution → dialect → lifecycle flow is owned by `clients/llm/AGENTS.md` (Wiring). Application code must not construct dialects, the registry, or the lifecycle directly.
- `hybrid_embeddings_provider.py` depends on `valkey_client.py` (`get_valkey_client()` + `valkey_binary`); the embedding cache requires Valkey and raises on construction failure rather than degrading to uncached.
- Cost recording from completed provider results flows through `utils/cost_accumulator.py` — the hook and its inert-unless-`start()` semantics are owned by `clients/llm/AGENTS.md` (lifecycle Rule).
