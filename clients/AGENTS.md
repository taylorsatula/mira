## Rules

- Import stays connection-free; construction connects. `clients/__init__.py` eagerly imports the five infra modules — the only import-time construction anywhere here is the config singleton; every real connection happens in a getter or constructor: `_ensure_vault_client`, `get_valkey_client` (pings), `PostgresClient(...)`, `get_embeddings_provider`, `get_systemone_client`. An import-time connection breaks every offline battery — that laziness is what `tests/protected/AGENTS.md`'s import-chain doctrine stands on.
- `vault_client` caches every read for the process lifetime: `_secret_cache` has no invalidation, and `preload_secrets()` (main.py startup, fail-fast) fills the three groups (`mira/api_keys`, `mira/database`, `mira/services`) while the AppRole token is fresh. Rotating a secret in Vault never reaches a running process — code that "re-reads to refresh" serves the old value until restart. Live exceptions: `get_api_key("google_vertex")` (`_mint_vertex_token` refreshes the OAuth token when invalid) and `_read_secret_version`'s re-auth on Unauthorized/Forbidden — that serves token expiry, not rotation.
- A new RLS-covered table joins two files in one commit: the `ENABLE ROW LEVEL SECURITY` statement in `deploy/mira_service_schema.sql` (17 statements) and `_RLS_COVERED_TABLES` in `postgres_client.py` (17 entries). Skip the tuple and `_rls_canary` never fires for that table — the fail-closed zero-row result masquerades as empty data, the regression class the canary exists to surface. The canary warns once per `(pool, table)` (`_rls_canary_warned`, cleared by `reset_all_pools`).
- Two Postgres pool families, one database: `PostgresClient._connection_pools` (keyed `mira_service`/`mira_service_admin`, sized `config.database.pool_min`/`pool_max`) and the `utils/database_session_manager.py` pools (LTMemorySession/AdminSession, sized `session_pool_min`/`session_pool_max`) share only `get_database_url` and `PostgresClient._parse_database_url`. `statement_timeout` (`config.database.statement_timeout_ms`) is applied by the session manager only — a wedged query on a `PostgresClient` connection has no bound; pool-exhaustion debugging must count both families.
- `_parse_database_url` hands the URL to libpq verbatim — libpq is the single percent-decoder; decomposing with `urlparse` would send the literal `%XX` sequence as the password. Query parameters raise `ValueError` by design: they are the flag for the TLS (`sslmode`) need. Writers percent-encode (twin: `deploy/postgresql.sh`, `deploy/docker/scripts/init-mira.sh`); a stored URL carrying `?sslmode=…` bricks boot — TLS means extending this parser plus a certificate-verification Vault surface, never relaxing the rejection.
- Guarded Valkey writes use `valkey_client`'s atomic Lua primitives — `compare_and_set`/`compare_and_delete`/`compare_and_expire`, `set_if_counter_matches` (missing counter reads 0, so epoch guards compare from the first invalidation), `getdel`/`getdel_json` (single-consume), `increment_with_expiry` (EXPIRE NX — a counter can never exist without its TTL), `delete_and_increment`. Root owns the guard-in-the-mutation doctrine; these are its sanctioned forms here, and a new guard lands as one EVAL in this module — never as a call-site read-then-write pair, which races: a second writer lands between the read and the write. `json_set` at a `$.field` path is a read-modify-write, not atomic — a guarded partial update through it loses a concurrent writer.
- `encode_realtime` is the query encoder, `encode_deep` the document encoder — on the local provider they are different encoders of one asymmetric model, and retrieval only works when queries embed on the query side and stored text on the document side (consumer pairing: `lt_memory/vector_ops.py`). A storage path that encodes stored text with `encode_realtime` writes into the wrong space: no error, every similarity score quietly wrong.
- The `embedding_config` row freezes the install's vectors: the schema trigger `embedding_config_locked_once_vectors_exist` refuses UPDATE/DELETE once any vector exists, `build_embeddings_provider` refuses a local row not matching `LOCAL_EMBEDDING_MODEL`/`LOCAL_EMBEDDING_DIMENSIONS`, and `MAX_EMBEDDING_DIMENSIONS` (2000) is the pgvector index ceiling `describe_for_installer` enforces at install time. Changing the embedding model is reinstall-or-regenerate, never an UPDATE; changing the local constant strands every local install at boot until its vectors are regenerated.

## Files

- `__init__.py` — eagerly imports the five infra modules; `__getattr__` defers `LLMProvider`. Gotcha: the `__all__` re-export surface has no in-repo importer (callers import submodules directly) — the eager import chain is the load-bearing part.
- `embeddings_provider.py` — the one path from text to vectors: `EmbeddingsProvider` over local sentence-transformers (asymmetric, 768 d) or any OpenAI-compatible `/v1/embeddings`, install-picked by the one-row `embedding_config` table; single-text encodes cached per role in Valkey. Entry: `get_embeddings_provider`, `load_embedding_config`, `build_embeddings_provider`, `encode_realtime`/`encode_deep`, `request_embeddings`, `describe_for_installer`, `EmbeddingOutputError`. Gotcha: `_LOCAL_INFERENCE_LOCK` serializes every local encode process-wide — PyTorch's MPS backend is not thread-safe and sentence-transformers auto-selects it on Apple Silicon (the two-thread path is `cns/services/orchestrator.py:_compute_embeddings_parallel`); code bypassing the provider to drive the model directly reintroduces the Metal race.
- `lattice_client.py` — thin HTTP client for the Lattice discovery service: federated message send, server-identity fetch; distinct from the external `lattice` pip package `main.py` wires for username resolution. Entry: `get_lattice_client`, `send_message`, `get_identity` (404 → `ValueError`: federation not configured). Gotcha: plain per-call `httpx.Client`, not `utils/http_client` — no retries. Sole in-repo consumer: `rg 'get_lattice_client'` → `tools/implementations/pager_tool.py`.
- `llm_provider.py` — the public LLM API for application code: message validation, thinking-kwarg coalescing, request build, dialect dispatch, `ContextOverflowError`. Entry: `get_llm_provider` (single construction point, warmed fail-fast by `main.py`), `LLMProvider.generate_response`/`stream_events`, `_coalesce_thinking` (`thinking=` XOR `effort`/`thinking_tokens`), `_validate_messages`, `ContextOverflowError`. Gotcha: module import installs the SIGUSR1 traffic-tap toggle (`signal.signal` → `utils/llm_tap.py`) — import from a non-main thread raises `ValueError`. Resolver/lifecycle/diverter/capabilities mechanics owned by `clients/llm/AGENTS.md`.
- `postgres_client.py` — raw-SQL Postgres over per-database pools; RLS context from the constructor's `user_id` (`set_config('app.current_user_id', …)` on every checkout, cleared when absent), admin via the BYPASSRLS `mira_admin` role (`get_database_url(admin=True)`, pool key `{db}_admin`). Entry: `execute_query`/`execute_single`/`execute_scalar`/`execute_returning`/`execute_insert`/`execute_update`/`execute_transaction`, `get_connection`, `_rls_canary`, `reset_all_pools`/`close_all_pools`, `get_pool_stats`, `PostgresPoolError`. Gotcha: no `statement_timeout` on these connections (Rule above) — a wedged raw-SQL query hangs unbounded.
- `sqlite_client.py` — dead: raw unencrypted SQLite over a caller-supplied path, no RLS, per-path singleton (`get_sqlite_client`); nothing in-tree keeps it, and removal is a source-commit decision. Do not build on it — per-user tool SQLite is `utils/userdata_manager.py` (Fernet, `encrypted__` prefix); a new SQLite need extends that, never this module. Lives on only through `__init__.py`'s eager import.
- `systemone_client.py` — typed decision-model client: Noul statements judged P(true) ∈ [0, 1] over the `/v1/systemone` wire format; endpoint/model/credential from `config.systemone`; requests run on the construction-sized `ThreadPoolExecutor` under copied context, each answer bounded by `_answer_wait_seconds`. Entry: `get_systemone_client`, `ask_nouls`, `NoulQuestion`, `_parse_noul_answer`, `SystemOneResponseError`, `describe_for_installer`. Gotcha: one question per request (`ask_nouls` fans one `_ask_one` per name) — the wire allows several, but djev conditions each answer on the whole request (sibling questions moved one probability by up to 0.84, witnessed 2026-09-26); batching to "save calls" silently shifts judgments.
- `valkey_client.py` — the process Valkey surface: sync `_client`, binary `valkey_binary` (raw bytes — embeddings), async `valkey`; plus the atomic Lua primitive set and `flush_except_whitelist`. Entry: `get_valkey_client`/`get_valkey` (alias), `compare_and_*`, `set_if_counter_matches`, `getdel`/`getdel_json`, `increment_with_expiry`, `delete_and_increment`, `json_set`/`json_get`, `scan_iter`, `flush_except_whitelist`, `shutdown`. Gotcha: TLS URL schemes (`rediss://`, `valkeys://`) raise at construction by design — this client has no TLS, and accepting the scheme would connect in plaintext.
- `vault_client.py` — Vault KV-v2 reads over AppRole auth with the process-lifetime `_secret_cache`. Entry: `get_api_key`, `get_database_url` (`mira_service` only; `admin_url` vs `service_url`), `get_service_config`, `preload_secrets`, `test_vault_connection` (main.py startup check, warn-only), `_read_secret_version` (re-auth on Unauthorized/Forbidden), `_mint_vertex_token`. Gotcha: `get_auth_secret` (the `mira/auth` family) has no in-repo consumer — dead; do not build on it.
- `llm/` — provider-neutral LLM boundary: types, resolver, lifecycle, diverter, probe, registry, tool-message assembly — `clients/llm/AGENTS.md`.
- `llm/dialects/` — per-provider wire formats, the `ProviderError` taxonomy, thinking translation — `clients/llm/dialects/AGENTS.md`.

## Wiring

- Boot and shutdown (order owned by root `AGENTS.md`, `main.py`): `preload_secrets()` → `get_embeddings_provider()` → `get_llm_provider()` → registry `discover()` → `get_valkey_client()` + `flush_except_whitelist(...)` (prefix list root-owned) — each fail-fast; `test_vault_connection()` mid-lifespan is warn-only. Shutdown: `await valkey.shutdown()` then `PostgresClient.close_all_pools()` (close timeout 0 — pool workers are daemon threads).
- Postgres consumers: `rg 'PostgresClient'` (raw-SQL set — cns infrastructure/api/services, tools `pager_tool`, utils `user_context`/`domaindoc_shares`/`power_on_self_test`, `main.py`'s federation username resolver, `tests/fixtures/scratch_db.py`). `utils/perf.py:install_db_instrumentation` patches the `execute_*` family by name — `utils/AGENTS.md` owns the rule; the method names are the contract.
- Valkey consumers: `rg 'get_valkey_client|get_valkey\b'` (auth session/rate-limit/webauthn, cns api + services + `cns/infrastructure/valkey_message_cache.py`, working_memory, tools `memory_tool`/`subagent_tool`, the segment-scoped consult thread (`agents/implementations/phoneafriend_agent.py`, key `phoneafriend:{user_id}:{segment_id}:{thread_id}`), utils `distributed_lock`/`user_context`/`domaindoc_shares`/`power_on_self_test`, `main.py` boot flush/shutdown). Primitive edges: epoch-guarded message cache (`set_if_counter_matches`/`compare_and_set`/`delete_and_increment`) ↔ `cns/infrastructure/AGENTS.md` · lock release/renew (`compare_and_delete`/`compare_and_expire`) — contract `utils/AGENTS.md` (`distributed_lock.py`) · rate limits and extraction attempt counters (`increment_with_expiry`) → `auth/rate_limiter.py`, `cns/services/segment_collapse_handler.py` · single-consume (`getdel_json`) → `auth/webauthn_service.py`. The embedding caches ride `valkey_binary`.
- Vault consumers: `rg 'get_api_key'` → dialect `from_selection` (lazy import — `clients/llm/dialects/AGENTS.md`), `build_embeddings_provider` (remote), `get_systemone_client` (provider=remote), `tools/implementations/web_tool.py` (`kagi_api_key`) · `rg 'get_service_config'` → `valkey_client` (`valkey_url`/`valkey_password`), `auth/config.py` + `auth/email_service.py`, `cns/api/health.py` (`diagnostics_token`), `cns/api/federation.py` (`lattice_delivery_token`), `utils/userdata_manager.py` (`userdata_encryption_key`; derivation chain `utils/AGENTS.md`) · `rg 'get_database_url'` → `PostgresClient`, `utils/database_session_manager.py`, `utils/power_on_self_test.py`, `scripts/export_user_bundle.py`.
- Embeddings consumers: `rg 'get_embeddings_provider'` → `main.py` (boot), POST gate (`utils/AGENTS.md`), `cns/integration/factory.py`, `cns/api/actions.py` (memory-create `encode_deep`), `cns/services/orchestrator.py` (the two-thread encode), `cns/services/segment_collapse_handler.py`, `tools/implementations/memory_tool.py`/`continuum_tool.py`, `utils/failover_jobs.py` (advisory probe, `cache_enabled=False` — embeddings never divert); `lt_memory/vector_ops.py` is constructor-fed by the lt_memory factory — role-paired, not itself a grep hit. `describe_for_installer` ↔ `deploy/lib/embedding_config.sh` and `tests/fixtures/scratch_db.py` (probe contract `deploy/lib/AGENTS.md`; the schema's `RAISE EXCEPTION` names the lib as its variable-builder).
- System One: `get_systemone_client` ← `utils/untrusted_content.py:InjectionScreen` (screen owned by `utils/AGENTS.md`) and `tests/protected/injection_defense_probe.py` (calibration battery — `tests/protected/AGENTS.md`); `describe_for_installer` ↔ `deploy/lib/systemone_config.sh` (`deploy/lib/AGENTS.md`).
- LLM caller surface: `rg 'get_llm_provider\('` (cns services, agents, tools, lt_memory, utils — never transcribed). `ContextOverflowError` ← `cns/services/orchestrator.py`, `cns/services/summary_generator.py` (remediation `cns/services/AGENTS.md`), `lt_memory/processing/orchestrator.py` (excluded from extraction's content-failure budget), `tools/implementations/web_tool.py` (synthesis degrade set). The request flow resolver → registry → lifecycle → dialect is owned by `clients/llm/AGENTS.md`.
- Lattice: `get_lattice_client` ← `tools/implementations/pager_tool.py` (send + identity; the federation twins live there and in `cns/api/AGENTS.md`).
