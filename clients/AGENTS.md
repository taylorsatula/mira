# clients/ — external infrastructure clients: Vault, Postgres, Valkey, SQLite, embeddings, Lattice, and the LLM entry point

## Rules

- Vault is the sole credential source for every client in this directory. `vault_client.py:get_database_url()`, `get_api_key()`, `get_auth_secret()`, and `get_service_config()` are the only permitted access points; environment variables (`VAULT_ADDR`, `VAULT_ROLE_ID`, `VAULT_SECRET_ID`) are the primary config source only inside `VaultClient` — all other clients delegate to it and never read provider credentials from the environment. `preload_secrets()` bulk-loads the three secret groups at startup and raises `RuntimeError` on any group failure.
- Required-infrastructure clients are module-level singletons accessed only through factory functions: `get_valkey()`, `get_hybrid_embeddings_provider()`, `get_lattice_client()`, `get_sqlite_client()`, `get_systemone_client()`. Construction failures propagate — no fallbacks.
- `get_llm_provider()` (`llm_provider.py`) is the single construction point for `LLMProvider`; direct `LLMProvider()` instantiation in application code is prohibited. All LLM calls go through `LLMProvider.generate_response()` or `LLMProvider.stream_events()`; provider-specific code belongs in `llm/dialects/` (see `clients/llm/dialects/AGENTS.md`).
- `PostgresClient` pools are class-level, keyed by database name; `admin=True` uses a separate `{name}_admin` pool with a BYPASSRLS role and never sets user context. On every non-admin checkout `get_connection()` either sets or explicitly clears `app.current_user_id` — never rely on pooled-connection state carrying context. When the context is cleared, the RLS canary (`_rls_canary`) logs the first per-(pool, table) omission, because RLS fails closed (zero rows, no error) and a forgotten user context would otherwise masquerade as empty data. Keep `_RLS_COVERED_TABLES` in sync with the `ENABLE ROW LEVEL SECURITY` statements in `deploy/mira_service_schema.sql`.
- `SQLiteClient` has no RLS. Manual `user_id` filtering in queries is the only isolation mechanism — it is not redundant with anything.
- `PostgresClient` `execute_*` methods must stay externally patchable: `utils/perf.py:install_db_instrumentation()` (owner; see `utils/AGENTS.md`) monkey-patches them by name at startup, so a new `execute_*` method is silently un-instrumented until registered there, and adding timing/logging inside the methods double-counts.
- The embedding space is fixed per install by the one-row `embedding_config` table (`deploy/mira_service_schema.sql`): `provider` (`local` = `mdbr-leaf-ir-asym`, 768-dim, asymmetric; `remote` = any OpenAI-compatible `POST /v1/embeddings`, one model for both roles), `model`, `endpoint_url`, `api_key_name` (under Vault `secret/mira/api_keys`), and `dimensions`, which also sizes every `vector(...)` column. The installer takes model and dimensions from `hybrid_embeddings_provider.describe_for_installer` (a live probe for remote), never from literals. Vectors from different models are not comparable: the schema trigger `embedding_config_locked_once_vectors_exist` refuses UPDATE/DELETE of the row once any vector is stored, so changing providers means regenerating every stored vector or reinstalling. Locally, `encode_realtime()` → `encode_query` and `encode_deep()` → `encode_document` is contract, not preference.

## Files

- `vault_client.py` — AppRole auth, KV v2 secret retrieval, and the process secret cache. `get_secret(path, field)` re-authenticates once on token expiry (`_read_secret_version` catches `Unauthorized`/`Forbidden`); module functions cache per key after first fetch. `get_api_key('google_vertex')` special-case: mints/refreshes a short-lived Vertex access token from the `google_vertex_sa` service-account JSON instead of returning a static secret. `preload_secrets()` bulk-loads the three secret groups at startup and raises `RuntimeError` on any group failure. `test_vault_connection()` is the health probe.
- `postgres_client.py` — Pooled raw-SQL client with RLS context injection. `execute_query`/`execute_returning`/`execute_single`/`execute_scalar`/`execute_insert`/`execute_update`/`execute_transaction` return dict rows; `get_connection(query=...)` is the checkout point described in the canary Rule. Raises `PostgresPoolError` when the pool hands back no connection (distinct from `PoolTimeout` exhaustion). `_parse_database_url` hands the URL verbatim to `make_conninfo` (libpq decodes percent-encoded userinfo — the sole decoder) and rejects URLs carrying query parameters; writers (`deploy/postgresql.sh`, `deploy/docker/scripts/init-mira.sh`) percent-encode passwords when embedding them. `reset_all_pools()`/`close_all_pools()`/`get_pool_stats()` for lifecycle and diagnostics. pgvector is registered only for `mira_service`, at pool creation and again per checkout.
- `valkey_client.py` — Cache, session, and rate-limit store. Three surfaces off one module-level pool: the sync client, `valkey_binary` (raw bytes, e.g. embeddings), and async `.valkey` — the async client is built from an auth-embedded URL, so a password with reserved characters is percent-encoded. `__init__` rejects `rediss`/`valkeys` (TLS) and any non-`redis`/`valkey` scheme loudly — the client is plaintext-only, so an honored TLS URL would connect unencrypted. `__init__` pings Valkey — construction fails fast if unreachable. `json_set(key, "$"|"$."field, value, ex)` is a read-modify-write for field updates that preserves the existing TTL when `ex` is None; `increment_with_expiry()` is atomic (incr and TTL inseparable — a crash between them can never leave an immortal rate-limit counter); `getdel_json()` is an atomic GETDEL for single-use values (e.g. WebAuthn challenges); `compare_and_set(key, expected, new)` is a Lua-script atomic swap for optimistic concurrency; `delete_and_increment(del_key, incr_key)` is a Lua EVAL doing DEL and INCR in one atomic operation (the continuum cache invalidation primitive); `flush_except_whitelist()` rejects empty prefixes.
- `sqlite_client.py` — Per-user tool data storage. No pooling; fresh connection per request via `get_connection()`. `get_sqlite_client(db_path)` caches one client per path; the client does no scoping. No in-tree consumer — re-exported from `__init__.py` only; per-user tool stores go through `utils/userdata_manager.py` (`self.db`).
- `hybrid_embeddings_provider.py` — The only text→vector path. `EmbeddingsProvider` base: per-role Valkey caches for single texts (15-min TTL, float16, `embedding_{dimensions}_{query|doc}` prefixes), shape checked against `dimensions` on every encode (`EmbeddingOutputError`), unit-length float16 out (`(d,)` for a str, `(n, d)` for a list), `max_encode_seconds` bounds one batch. `LocalEmbeddingsProvider` loads offline-first (`local_files_only=True`, online fallback). `RemoteEmbeddingsProvider` posts `embeddings_batch_size` batches through `utils/http_client` (30 s timeout, 2 retries); `request_embeddings()` places results by `index` and rejects malformed bodies; zero vectors are rejected. `get_hybrid_embeddings_provider()` builds the singleton from `load_embedding_config()`; `build_embeddings_provider()` refuses a `local` row naming another model or size. `describe_for_installer()` is the installer entry (`deploy/lib/embedding_config.sh`), capped at `MAX_EMBEDDING_DIMENSIONS` (pgvector's 2,000-dimension index ceiling).
- `lattice_client.py` — Thin HTTP client for the Lattice federation service: `send_message()` and `get_identity()`. Only consumed by the pager tool; not exported from `__init__.py`.
- `systemone_client.py` — Typed client for a System One decision-model endpoint (TypeSafe `/v1/systemone` wire format; settings in `config.systemone`). `ask_nouls(state, {name: NoulQuestion})` sends one question per request, because djev conditions each answer on sibling questions, their order, and key names (witnessed shifts up to 0.84) — isolation is enforced client-side. Requests run on a worker pool sized to `max_concurrent_requests`, which makes the pool the per-process in-flight cap (the lunaroute key answers HTTP 429 above 11); each answer waits under `future.result(timeout=…)` derived from the retry policy (`max_retries=2`, 30 s sleep cap). Non-2xx -> `httpx.HTTPStatusError`; a body not holding the asked Noul probability in [0, 1] -> `SystemOneResponseError`. Noul only; Choice and Score land with their first consumer. Consumer: `utils/untrusted_content.py`.
- `llm_provider.py` — The public LLM API. Validates and normalizes messages (`_validate_messages`, content-block taxonomy incl. `text`/`reasoning`/`tool_call`/`file_ref`/`image`/`document`), extracts the single system message (`_prepare_messages`), and coalesces `thinking=` vs `effort=`/`thinking_tokens=` (mixing raises `ValueError`). Resolution, dialect construction, and lifecycle wrapping are owned by `clients/llm/AGENTS.md`. Translates `ProviderContextOverflowError` to `ContextOverflowError` at this boundary (both `generate_response` and `stream_events`); `stream_events()` yields `events.py` types, re-raises `GenerationCancelled`, and on any other failure logs, yields `ErrorEvent`, then re-raises. Registers the SIGUSR1 LLM-tap toggle at import.
- `__init__.py` — Re-exports `EmbeddingsProvider`, `get_hybrid_embeddings_provider`, `PostgresClient`, `SQLiteClient`, `ValkeyClient`, `get_valkey`, `get_valkey_client`, and the three vault getters; `LLMProvider` resolves lazily through `__getattr__`. `LatticeClient` is excluded — import it directly from `lattice_client.py`.
- `llm/` — Provider-neutral LLM layer (types, events, lifecycle, resolver, registry). See `clients/llm/AGENTS.md`.
- `llm/dialects/` — Per-provider wire-format dialects and the error hierarchy. See `clients/llm/dialects/AGENTS.md`.

## Wiring

- Request flow into the LLM layer starts at `llm_provider.py:generate_response()`/`stream_events()`; the full resolution → dialect → lifecycle flow is owned by `clients/llm/AGENTS.md` (Wiring). Application code must not construct dialects, the registry, or the lifecycle directly.
- Stream consumers of `LLMProvider.stream_events()` receive `clients/llm/events.py` dataclasses; the terminal event is `CompleteEvent` (carries the final `Result`), and `ModelStepCompletedEvent` is a non-terminal per-step boundary. `GenerationCancelled` propagates unwrapped; provider failures yield `ErrorEvent` then re-raise — a consumer must handle both.
- The embedding-space contract is owned here (Rule above): `hybrid_embeddings_provider.py` reads the `embedding_config` row, and `deploy/mira_service_schema.sql` sizes `messages.segment_embedding`, `memories.embedding`, and `global_memories.embedding` from the same `embedding_dimensions` psql variable that seeds it (`deploy/lib/embedding_config.sh` builds the variables; `deploy/AGENTS.md` carries the non-owning citation). `utils/power_on_self_test.py:_check_embeddings` witnesses the agreement at boot: column types equal `vector(<dimensions>)`, the lock trigger exists and is enabled, and a live encode returns the configured shape.
- The BYPASSRLS admin path in this directory has two halves in two files: `postgres_client.py` builds the `{name}_admin` pool from `vault_client.get_database_url(name, admin=True)`, which returns the `admin_url` secret (the `mira_admin` role). Admin connections never set `app.current_user_id`, so an admin checkout can read across users by design — code that wants user-scoped rows must use a non-admin client, not an admin one with a WHERE clause.
- All clients load runtime parameters from `config.config_manager` (pool sizes, `cache.max_connections`, `lt_memory.embeddings_batch_size`, `lattice.service_url`, `api.temperature`/`api.timeout`); secrets come only from `vault_client.py` per the Rules. The config schema is owned by `config/AGENTS.md`.
- Valkey keys are colon-namespaced `prefix:scope` strings, with scope typically the user id (`trinkets:{user_id}`, `lora_preview:{user_id}:{preview_id}`) or a content hash (`embedding_768_query:<sha256>`). Consumers construct their own keys; this directory owns only the `embedding_768_*` prefixes. `flush_except_whitelist()` at startup preserves whitelisted prefixes — a new persistent key family must be added to that whitelist or it is wiped on boot.
- `hybrid_embeddings_provider.py` depends on `valkey_client.py` (`get_valkey_client()` + `valkey_binary`); the embedding cache requires Valkey and raises on construction failure rather than degrading to uncached.
- Cost recording from completed provider results flows through `utils/cost_accumulator.py` — the hook and its inert-unless-`start()` semantics are owned by `clients/llm/AGENTS.md` (lifecycle Rule).
