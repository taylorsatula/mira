# clients/llm/ — the provider-neutral LLM boundary: the neutral contract, route resolution, the stall-and-cancel lifecycle, and the failover divert

## Files

- `__init__.py` — package marker plus a convenience re-export of `types.py` that no caller in MIRA imports through. Open it only to add a name to that convenience surface.
- `types.py` — the neutral request, result, tool, usage and reasoning dataclasses every dialect translates to and from. Open it before changing a field meaning that a dialect writes or a consumer reads.
- `artifacts.py` — the one-method Protocol a dialect satisfies to land provider-produced files. Open it before wiring an artifact sink, or when a provider-produced file has nowhere to go.
- `resolver.py` — route name to `ModelSelection`, including the selection used while the diverter is tripped. Open it before changing how a route, its credential name, or its token ceiling resolves.
- `dialect_registry.py` — `dialect_name` to `Dialect` class, discovered by walking the dialects package at boot. Open it before adding a provider, or when a configured dialect is not found.
- `capabilities.py` — a dialect's capability declaration and the gate that `clients/llm_provider.py` runs against a translated request before the lifecycle starts. Open it before requiring a new provider behavior of a request.
- `lifecycle.py` — the stall bound, the cancellation notice and the billing stamp wrapped around every live provider call. Open it before changing how long a call may take, how a halt is noticed, or how a response is recorded.
- `diverter.py` — process-global trip state for the single backup provider. Open it before changing when traffic leaves the primary or when it comes back.
- `probe.py` — the first-token reachability probe shared by the boot gate and the failover recovery job. Open it before changing what counts as a reachable provider.
- `events.py` — the stream-event union a live call yields, and `GenerationCancelled`. Open it before adding an event or changing what a streaming consumer can receive.
- `tool_messages.py` — the messages one local tool round appends to history. Open it before changing what a tool round replays to the provider.
- `thinking.py` — the adaptive-thinking model test and the note a dialect emits when a caller's thinking request is not honored verbatim. Open it before touching how a dialect maps effort or budget.
- `dialects/` — per-provider wire formats, the `ProviderError` taxonomy, thinking translation and reasoning round-trip pairing; its own map.

## Wiring

- Request path: `clients/llm_provider.py` → `ModelResolver.resolve` → `get_registry().get` → `Dialect.from_selection` → `Capabilities.validate` → `LLMLifecycle.complete`/`stream` → the dialect's own `complete`/`stream`. `validate` runs before the lifecycle starts, so an unsupported requirement fails as a named `CapabilityError` instead of a provider-side 400 the caller has to decode. `ModelResolver.resolve` reads the route row from `utils/user_context.get_model_config`, the in-memory cache `load_model_configs` fills, so route resolution and cache invalidation are one contract; a route present in Postgres but absent from that cache fails as an unknown route. Counterpart: `clients/AGENTS.md`, `utils/AGENTS.md`.
- Dialect contract: `clients/llm/dialects/base.py` supplies `Dialect` and the `ProviderError` subclasses (`ProviderRetryableError`, `ProviderStallError`, `ProviderProtocolError`, `ProviderContextOverflowError`). The class-scope declaration recipe is owned there; the walk that consumes it and the validation that refuses a malformed class are owned here. The `abort_active_stream` unblock the lifecycle calls to free a stalled or cancelled worker is not a `Dialect` member: the transports implement it and `LLMLifecycle` resolves it duck-typed with `getattr(dialect, "abort_active_stream", None)`, so a dialect that omits it registers cleanly and leaks the abandoned worker's connection with nothing raised. Counterpart: `clients/llm/dialects/AGENTS.md`.
- Stream events: the union `events.py` declares is translated into the turn's client frames by `cns/services/orchestrator.py` (`tool_stream_frame` plus the `TextEvent`/`ThinkingEvent`/`CompleteEvent` branches), and `cns/services/tool_loop.py` switches on the same union. An added or renamed member moves with that translation and with both clients' frame tables, or it is emitted and never forwarded. `GenerationCancelled` is raised from `utils/user_context.check_cancelled`, so its class identity is a contract with that module. Counterpart: `cns/services/AGENTS.md`.
- Artifact sink: `FileArtifactSink` is satisfied structurally and imported nowhere — the single implementation is `utils/artifact_store.py:UserArtifactStore.save_file_artifact`, wired at `clients/llm_provider.py:_create_file_artifact_sink`. A signature change on either side type-checks nothing and surfaces as a `TypeError` inside a dialect's file-artifact path mid-stream, so the Protocol and that implementation move in one commit. Counterpart: `utils/AGENTS.md`.
- Boot validation: dialect modules import once per process, and each process imports them from its own first `get_registry().discover()`. The pre-server POST gate runs its checks in a child process before the bind, so that child's discovery is the first one there and a dialect module that fails to import fails the gate rather than the bind; the serving process's lifespan `discover()` is likewise its own first discovery. The gate then re-reads `model_configs` from Postgres to build a `ModelSelection` per route and resolve each route's dialect, and that row-and-dialect re-read is the live part; a `model_configs` row that drifts after the gate is caught by nothing here. Counterpart: `utils/AGENTS.md`.
- Reachability probes: `probe_first_token` is called by the power-on self-test boot gate and by the failover recovery job while tripped. Both pass `FIRST_TOKEN_PROBE_SECONDS` and build their selection through `optional_api_key_name`, the boot gate from raw `model_configs` rows and the recovery job from the in-memory config cache, so one normalisation change has to reach both or the two disagree about a route with no credential. Counterpart: `utils/AGENTS.md`.
- Trip accounting: `clients/llm_provider.py` calls `diverter.record_failure`/`record_success` around every call, `ModelResolver.resolve` reads `diverter.tripped()`, and the recovery job calls `record_probe_pass`/`record_probe_fail`. The state is written here and driven entirely from outside this directory. Counterpart: `utils/AGENTS.md`.
- Cancellation and billing: `LLMLifecycle` reads the cancel event from `utils/user_context.py` and feeds every stamped `Result` to `utils/cost_accumulator.py:record`. Counterpart: `utils/AGENTS.md`.
- Tool continuation: `append_tool_result_messages` and `assistant_message_from_result` are consumed by the turn orchestrator when it persists a tool round and by the sidebar-agent base when it assembles conversation history. Neither consumer's map states the obligation, so grep the consumer set (`rg 'append_tool_result_messages'`) before changing what a tool round appends. The reasoning round-trip the assistant message carries is traced in `clients/llm/dialects/AGENTS.md`, not here.
- Types surface: `clients/llm/types.py` symbols are imported across `tools/`, `cns/`, `agents/` and `utils/`. Before changing a symbol's meaning, grep the symbol itself (`rg 'ToolDefinition'`, `rg 'EFFORT_LEVELS'`); the consumer set is a projection of the code and a list here would be stale. Counterpart: `tools/AGENTS.md`.

## Rules

- Every live provider call runs inside `LLMLifecycle`. It is the only place a stall gets a bound, a cancel gets noticed while the worker is blocked, and a `Result` gets its `ProviderMetadata` stamp and its cost record. A caller that drives a dialect directly gets none of the three: the socket read runs to the provider's own timeout, a user halt goes unseen until it returns, and the response bills nobody.
- `ToolNotLoadedError` must reach the lifecycle un-normalized. `LLMLifecycle._run` answers it with a synthetic `invokeother_tool` call whose input is `{"load": [tool_name]}`, the exact shape that tool's own schema admits, additional properties forbidden. A dialect that swallows the error into a normal `Result` or an error string removes the recovery; a change to the `load` parameter's schema breaks recovery at the next provider round-trip with a 400. Consumption needs no awareness of it: the synthetic call runs like any other tool call and its `stop_reason="tool_use"` triggers the re-invoke.
- Record a provider failure for retryable errors only. `diverter.record_failure` is called from the catch sites in `clients/llm_provider.py` for `ProviderRetryableError` and for nothing else; `record_success` follows a clean call. While tripped every record is a no-op, which is what holds the design at one diversion level — the backup's own health is structurally uncountable, so there is no failover-of-failover. A catch site that also records `ProviderAuthError` or `ProviderContextOverflowError` flips all five routes onto a backup that cannot fix a bad credential or an oversized request.
- Read `model_configs.api_key_name` only through `resolver.optional_api_key_name`. The column is `text NOT NULL`, `''` is the on-disk no-credential sentinel of an offline install, and `ModelSelection.__post_init__` rejects `''`. Four readers apply that normalisation — `utils/user_context.py:load_model_configs`, `utils/power_on_self_test.py:_load_llm_config_rows`, `utils/failover_jobs.py:_primary_probe_selections`, and `resolver._failover_selection` here — and they move in one commit when the sentinel handling changes. A direct read at any of them turns every offline boot into a Vault miss or an Anthropic `PermissionError`.
- A diverted call keeps the primary's route name. `_failover_selection` takes the backup's transport coordinates but carries `primary.model_config_name` through, so `utils/cost_accumulator.py` prices and attributes the call as the route the caller asked for. Returning the backup's own route name breaks billing and route attribution exactly when an operator is reading the logs to find out what broke.
- `Usage.input_tokens` means uncached prompt tokens in every dialect. Cache writes and reads ride `cache_creation_input_tokens` and `cache_read_input_tokens`, `total_input_tokens` is their sum, and the compaction baseline reads that sum. A dialect that copies the provider's total prompt count into `input_tokens` double-bills every cached token and inflates the baseline that triggers compaction.

Elsewhere: this map does not own how any one provider's wire format is spoken, and it does not own what a caller does with the events and results it receives. The `config.api` fields read here — the `failover_*` block and `provider_response_timeout` — are declared and validated in `config/AGENTS.md`; why a rule on this page reads as it does is in `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## One turn while the primary is down

The case that decides most of the Rules above: a turn arrives while the primary provider is unreachable.

1. The turn enters `clients/llm_provider.py`, which resolves the primary selection and drives the call inside `LLMLifecycle`. The provider stalls, so the lifecycle raises `ProviderStallError` at `config.api.provider_response_timeout`; a stall is a `ProviderRetryableError`, so the catch site records it against `selection.endpoint_url` and re-raises. That turn fails. Nothing in the process retries it, deliberately: an in-process retry loop would spend the caller's retry budget where nobody can see it being spent.
2. The counter is per endpoint, and one clean call through that endpoint on any of the five routes clears it. Only consecutive failures accumulate, so a provider that fails every other request never trips.
3. At `config.api.failover_trip_consecutive_failures`, the recording call trips the process-global state instead of counting: it journals a TOAST line naming the backup target and the cause, and zeroes the recovery pass count. The turn that tripped it still fails. Tripping is a state change for the next turn, never a retry of the current one.
4. The next turn's `ModelResolver.resolve` resolves the requested route exactly as before — an unknown route name fails identically tripped or not — and then sees `tripped()` and returns `_failover_selection`: the backup's dialect, model, endpoint and credential, `max_tokens` clamped by `config.api.failover_max_tokens_cap` when that is set, `effort=None` so the backup uses its own thinking defaults, and the primary's `model_config_name` kept. The turn now runs on the backup and bills as the route the caller asked for. Recording is a no-op from here on, so backup failures accumulate nowhere and cannot divert a second time.
5. Return is probe-driven, never traffic-driven. The recovery job — registered only when failover is enabled — builds one selection per deduped primary target and calls `probe_first_token`, which succeeds on the first well-formed streamed token and then aborts the generation rather than paying for a whole reply. One full passing pass counts once; at `config.api.failover_flipback_consecutive_passes` consecutive passes the trip clears and every counter resets. A single failed probe zeroes the pass count, so a primary that answers one probe and stalls the next never wins traffic back.
