# clients/llm/ — the provider-neutral LLM boundary: typed contracts, route resolution, the stall-and-cancel lifecycle, provider failover

Elsewhere: per-provider wire shapes, thinking translation, `ProviderError` raise sites, reasoning round-trip pairing — `clients/llm/dialects/AGENTS.md` · the public caller surface (`generate_response`/`stream_events`, message validation, thinking-kwarg coalescing, `ContextOverflowError`) — `clients/llm_provider.py`, owned by `clients/AGENTS.md` · the five route rows and `load_model_configs`/`get_model_config` — `utils/AGENTS.md` (`utils/user_context.py`) · Vault key lookup (`get_api_key`) — `clients/AGENTS.md` (`clients/vault_client.py`) · cost accounting internals — `utils/AGENTS.md` (`utils/cost_accumulator.py`) · boot/lifespan ordering — the root map (`main.py`) · how a feature was built — `git log` · full signatures — the files.

## Rules

- Every live provider call runs inside `LLMLifecycle` (`lifecycle.py:complete`/`stream`): `_run_with_response_timeout` bounds each `next()` on the dialect iterator by `config.api.provider_response_timeout`, polls the cancel contextvar between short `join` slices (a bare join hides a user halt for the whole stall window), and unblocks the stalled worker only through `dialect.abort_active_stream()` before raising `ProviderStallError` (taxonomy owned by `clients/llm/dialects/AGENTS.md`). A caller going direct to a dialect gets no stall bound and no cancellation — the socket read runs to the provider's own timeout.
- `ToolNotLoadedError` must reach the lifecycle un-normalized: the catch in `lifecycle.py:_run` answers it with a synthetic `Result` carrying one `invokeother_tool` call (`input={"load": [tool_name]}`, `stop_reason="tool_use"`, partial usage, cost recorded) so the tool loop loads the tool and re-invokes the provider. The input shape is fixed by `invokeother_tool`'s own schema (additional properties forbidden) — a schema change to `load` breaks recovery at the next provider 400. Raise sites re-raise it past the schema-repair catch (`openai_chat_base.py`); consumption is generic tool-loop machinery, not `ToolNotLoadedError`-aware — the `load` call executes like any tool call and `stop_reason="tool_use"` triggers the re-invoke (`cns/services/tool_loop.py`, `cns/services/orchestrator.py`).
- Diverter recording is retryable-only: `clients/llm_provider.py` calls `diverter.record_failure(selection.endpoint_url, error)` on `ProviderRetryableError` (stalls included) before re-raising, `record_success` after a clean call; `ProviderAuthError` and `ProviderContextOverflowError` never record, and while tripped all recording is a no-op — one diversion level, backup health structurally uncountable, no failover-of-failover. A catch site that records auth or overflow flips every route onto the backup for a misconfiguration the backup cannot fix.
- Every reader of `model_configs.api_key_name` or `failover_api_key_name` routes through `resolver.optional_api_key_name`: the column is `text NOT NULL`, `''` is the on-disk "no credential" sentinel of offline installs, and `ModelSelection.__post_init__` rejects `''`. Readers today: `utils/user_context.py:load_model_configs`, `utils/power_on_self_test.py`, `_failover_selection`. A direct read turns every offline boot into a Vault miss (or Anthropic `PermissionError`).
- The divert is transparent to accounting: while tripped, `ModelResolver.resolve` still resolves the requested route first — unknown route names fail identically tripped or not, and `utils/user_context.py`'s `_model_config_cache` is never mutated — and `_failover_selection` keeps the primary's `model_config_name`, so `utils/cost_accumulator.py` pricing and every route-keyed consumer continue unchanged. Returning the backup's own route name breaks billing and route attribution mid-outage.
- Only lifecycle-stamped `Result`s reach cost accounting: `_with_transport_metadata` stamps `ProviderMetadata` (dialect, model, endpoint, route name) and `_record_cost` feeds `utils/cost_accumulator.py:record` (no-op unless a request handler started an accumulator). A `Result` returned outside the lifecycle escapes billing silently.
- `Usage.input_tokens` is uncached prompt tokens in every dialect — cache writes and reads ride their own fields, never inside it (`types.py:Usage`). `utils/cost_accumulator.py` prices the three fields independently and the orchestrator's compaction baseline reads `Usage.total_input_tokens` (their sum); a dialect that copies a provider's total prompt count into `input_tokens` double-bills every cached token and inflates the baseline. Wire-side subtraction: `clients/llm/dialects/AGENTS.md`.
- The registry is boot-loud: `get_registry().discover()` (warmed at boot from `main.py`, re-run by the power-on self-test) walks `clients.llm.dialects` and raises at discovery for an empty/reserved/unlisted `dialect_name`, a `native_thinking_fields` that is not a tuple over `NativeField`, a non-classmethod `from_selection`, or a duplicate `dialect_name` — a malformed dialect parks the boot gate, never the first request. The class-scope declaration recipe is owned by `clients/llm/dialects/AGENTS.md`.

## Files

- `__init__.py` — docstring plus the 16-name `__all__` re-export of `types.py`; no in-repo consumer imports through it — callers use `clients.llm.types` or submodules (`from clients.llm import diverter` resolves the submodule, not this list).
- `types.py` — the neutral contract every dialect translates: `Request`/`Result`/`ThinkingConfig`/`ToolDefinition`/`ToolCall`/`ToolResult`/`ReasoningArtifact`/`Usage`/`ProviderMetadata`, the `coerce_*` gates, the `DialectName`/`EffortLevel`/`DeliberationLevel` literals. Entry: `ThinkingConfig.deliberating` (active and effort ≠ "none"), `ToolDefinition.from_mapping` (unknown keys raise, with the `descripton` typo hint), `ReasoningArtifact.to_content_blocks`/`to_signatures`. Gotcha: `EffortLevel` and `DeliberationLevel` move together — the import-time `_UNRANKED_EFFORT_LEVELS` check is the gate, and `EFFORT_LEVEL_ORDER` excludes `"none"` by design (a per-model ceiling must never turn none into a deliberating level).
- `resolver.py` — `ModelSelection` (frozen, self-validating) and the five-route resolver. Entry: `resolve`, `_failover_selection`, `optional_api_key_name`. Gotcha: the divert keeps the primary's route name and drops route-configured effort, while a caller's explicit effort survives — it travels in the `Request`'s `ThinkingConfig`, merged in `clients/llm_provider.py:_build_request` downstream of the selection.
- `lifecycle.py` — `LLMLifecycle`, the one fail-loud wrapper for live calls: stall watchdog, cancel polling, `CompleteEvent` restamping, the `ToolNotLoadedError` recovery. Entry: `complete`/`stream`, `_run_with_response_timeout`, the `ToolNotLoadedError` catch in `_run`. Gotcha: the watcher thread runs the pull under `contextvars.copy_context()` — `UserArtifactStore.save_file_artifact` resolves the user from context, and a stalled-path pull without the copy silently drops artifacts the response summary advertises.
- `diverter.py` — process-global trip state for the single backup target. Entry: `record_failure`/`record_success`/`record_probe_pass`/`record_probe_fail`/`tripped`/`trip_reason`/`reset`. Gotcha: state is process-local by design — a restart starts clean, the boot gate re-parks on the primary until it answers, and the counter re-trips within seconds; `reset()` is probe isolation, never a runtime path.
- `events.py` — the stream-event union plus `GenerationCancelled` (an `Exception`, not a `StreamEvent`). Entry: `TextEvent`/`ThinkingEvent`/`ToolDetectedEvent`/`CompleteEvent`. Gotcha: `ToolErrorEvent`/`CircuitBreakerEvent`/`ModelStepCompletedEvent`/`ErrorEvent` are produced upstream (tool loop, orchestrator, `clients/llm_provider.py`); `ToolExecutingEvent`/`ToolCompletedEvent` come from both sides — local tool execution in `cns/services`, server-side runs in `anthropic.py`. This module defines the union, not the producers.
- `probe.py` — first-token reachability probe. Entry: `probe_first_token(selection, timeout_seconds)`, `FIRST_TOKEN_PROBE_SECONDS`, `FirstTokenProbeResult`. Gotcha: success is the first well-formed token event — text, thinking, and tool detection all count, and a `CompleteEvent` with no text/reasoning/tool calls raises; a completion-shaped bound fails healthy thinking providers under load (calibration witness comments in-module).
- `capabilities.py` — `Capabilities`/`Requirements` and the pre-transport gate. Entry: `Capabilities.validate` (raises `CapabilityError` naming the unsupported set). Gotcha: `Requirements` is constructed only by `clients/llm_provider.py:_requirements_for_request` — `container_reuse` only; `batch`/`files`/`server_code_execution` are declared but required by no request path yet, so the gate is the enforcement point when one gains a caller (`rg 'Requirements\('`).
- `artifacts.py` — the `FileArtifactSink` Protocol (one method, `save_file_artifact`). Gotcha: structural typing — `UserArtifactStore` (`utils/artifact_store.py`) implements it without importing it; a sink-less dialect that still produces files fails at download time, never silently.
- `thinking.py` — `uses_adaptive_thinking` (the Claude 4.6+ regex) and `TranslationNote`. Entry: `uses_adaptive_thinking`, `TranslationNote(field, requested, applied, reason)`. Consumed only inside the boundary (dialect translation, `base.py:_log_translation`); no gotcha beyond the Rules.
- `dialect_registry.py` — filesystem-as-contract registry mapping `dialect_name` → `Dialect` subclass. Entry: `get_registry`, `discover`, `_validate_dialect_class`, `get` (raises `ValueError` listing registered names). Gotcha: discovery is idempotent and once-per-process — a dialect module dropped in after boot stays invisible until restart (isolation in tests is done by monkeypatching `_classes`, never by re-running `discover`); walk skips `is_abstract` classes, the reserved `"base"` name, and re-exported classes.
- `tool_messages.py` — neutral tool-continuation message assembly. Entry: `assistant_message_from_result`, `append_tool_result_messages`, `tool_result_messages`, `invalid_tool_call_feedback_messages`. Gotcha: invalid tool calls never replay as assistant `tool_calls` — they become user-role feedback (replaying would reintroduce schema-invalid arguments) — and tool calls without results (server-side execution) are stripped to prevent orphaned tool_call/tool pairs.
- `dialects/` — per-provider wire formats, the `ProviderError` taxonomy, thinking translation, round-trip pairing — `clients/llm/dialects/AGENTS.md`.

## Wiring

- Request flow: callers → `clients/llm_provider.py` (`generate_response`/`stream_events`; the caller set is `rg 'get_llm_provider\('`, never transcribed) → `ModelResolver.resolve` → `ModelSelection` → `get_registry().get` → `Dialect.from_selection` → `Capabilities.validate` → `LLMLifecycle` → dialect `complete`/`stream`. `clients/llm_provider.py` owned by `clients/AGENTS.md`.
- Boot: `main.py` (root-owned order) `load_model_configs()` → `get_llm_provider()` → `get_registry().discover()`; `utils/power_on_self_test.py:_check_llm_configuration` re-discovers and validates all five rows, constructing a `ModelSelection` per row and `registry.get` per dialect — an invalid row or unregistered dialect parks the boot gate. Counterpart: `utils/AGENTS.md`.
- Probes: `probe_first_token` consumed by `utils/power_on_self_test.py` (boot gate, every deduped target) and `utils/failover_jobs.py` (recovery probe while tripped); both normalize through `optional_api_key_name` + `coerce_dialect_name` — the boot gate from raw `model_configs` rows, the recovery probe from the in-memory `get_model_configs()` cache (a DB-side normalisation change reaches the gate immediately, the probe only after a cache reload). Counterpart: `utils/AGENTS.md`.
- Cancel and cost: the lifecycle reads the cancel contextvar (`utils/user_context.py:check_cancelled`/`get_cancel_event` — mechanism owned by `utils/AGENTS.md`) and feeds `utils/cost_accumulator.py:record` per completed result. Counterpart: `utils/AGENTS.md`.
- Tool continuation: `assistant_message_from_result`/`append_tool_result_messages` consumed by `cns/services/orchestrator.py` (turn persistence) and `agents/base.py` (agent conversation-history assembly); the stored reasoning round-trip (thinking_signatures/reasoning_details through message metadata to replay) is traced in `clients/llm/dialects/AGENTS.md` — cited, not restated. Counterpart: `agents/AGENTS.md`.
- Types surface (structural consumers; grep the symbol for the full set): `ToolDefinition` ← `tools/repo.py:get_tool_definition` (stored tool schemas convert through `from_mapping` — unknown keys raise there) and `utils/power_on_self_test.py`; `CacheTTL` ← `cns/core/message.py` typed cache fields (`cns/core/AGENTS.md`); `EFFORT_LEVELS` ← `cns/api/actions.py:set_effort_override` validation (`cns/services/AGENTS.md`); `Result` ← `utils/cost_accumulator.py`; `GenerationCancelled` raised by `utils/user_context.py:check_cancelled`, consumed by `cns/services` (`cns/services/AGENTS.md`).
- Diverter state: `record_failure`/`record_success` ← `clients/llm_provider.py` catch sites; `tripped()` ← `resolver.resolve` and `utils/failover_jobs.py`; `record_probe_pass`/`record_probe_fail` ← `utils/failover_jobs.py`. Flow traced below.
- Route-scoped prompt templates live in `config/prompts/` ↔ `config/prompts/AGENTS.md`.

## Failover divert: trip to flip-back

1. A live call fails retryably. `clients/llm_provider.py` catches `ProviderRetryableError` (stalls included), calls `diverter.record_failure(selection.endpoint_url, error)`, then re-raises — the turn fails; nothing retries in process. The counter is per-endpoint, and one clean call on any route through that endpoint resets it (`record_success`). At `config.api.failover_trip_consecutive_failures` (default 3) consecutive failures, `_trip_locked` flips the process-global `_tripped`, journals a TOAST line naming the backup target and the cause, and zeroes the recovery passes.
2. The next `ModelResolver.resolve` resolves the requested route first, then consults `diverter.tripped()` and swaps in `_failover_selection`: the backup's dialect/model/endpoint/key from `config.api.failover_*`, `max_tokens = min(route ceiling, config.api.failover_max_tokens_cap)` when a cap is set, `effort=None`, and the primary's `model_config_name` kept so pricing and route attribution continue unchanged. The `config.api.failover_*` block is required-when-enabled (`validate_failover_block` raises at config load for missing transport coordinates).
3. Recovery is probe-driven, never traffic-driven. `utils/failover_jobs.py` runs while tripped, building one `ModelSelection` per deduped primary target from the in-memory `get_model_configs()` cache (not the raw rows the boot gate reads) and calling `probe_first_token(selection, FIRST_TOKEN_PROBE_SECONDS)` — first-token reachability, so a slow-but-alive primary passes. A full passing pass calls `diverter.record_probe_pass()`; at `config.api.failover_flipback_consecutive_passes` (default 2) consecutive passes, `_flip_locked` clears the trip and the counters. One failed probe resets the pass count (`record_probe_fail`) — a partially recovered primary never regains traffic.
4. State is process-local by design: a restart starts clean, the boot gate re-parks on the primary until it answers, and the counter re-trips within seconds of the first retryable failure. The trade buys zero new infrastructure; the TOAST journal lines are the operator surface.

Ordering invariants: record-before-raise — the failure counts even though the call fails; primary-resolve-before-divert — route-name errors stay deterministic tripped or not; probe passes count only on full passes — flip-back needs consecutive confirmation, so one lucky probe cannot flap traffic back.
