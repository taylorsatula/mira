# clients/llm/dialects/ — one Dialect class per provider wire format, translating the neutral Request/Result contracts

## Rules

- Adding a provider is NOT drop-a-file, despite the docstrings in `__init__.py` and `clients/llm/dialect_registry.py`. Blast radius, in order: (1) dialect file in this directory — set `dialect_name`, `is_abstract = False`, `native_thinking_fields`, implement `from_selection`; (2) add the value to the `DialectName` literal and extend `coerce_dialect_name`'s `DIALECT_NAMES` (both `clients/llm/types.py`); (3) extend the `dialect_name` CHECK constraint in `deploy/mira_service_schema.sql`. Skipping (2) fails registry validation at boot — `_validate_dialect_class` in `clients/llm/dialect_registry.py` raises during `discover()`; skipping (3) fails at `model_configs` seed/insert — `clients/llm/resolver.py` resolves `dialect_name` from DB rows via `coerce_dialect_name` (`clients/llm/types.py`), not from code, so a route bound to the new dialect cannot resolve until both exist.
- A concrete dialect that forgets `is_abstract = False` silently never registers: the discovery walk in `clients/llm/dialect_registry.py` skips any subclass with the truthy inherited default (`base.py` sets `is_abstract: bool = True`). Failure is a boot-time "Unknown dialect" only when a route first selects it — there is no registry warning for the skipped class. Note `openai_chat_base.OpenAIChatBase` is skipped because it does not override `dialect_name` ("base" is reserved) — being a subclass of `OpenAIChatBase` does NOT exempt a concrete dialect from the `is_abstract` override.
- `sanitize_outbound_message()` (`base.py`) is an allowlist, not a denylist: only `_STANDARD_MESSAGE_FIELDS | _accepted_round_trip_fields` survive. Provider-specific metadata a dialect does not declare in `_accepted_round_trip_fields` is silently stripped before `_convert_messages`/`_serialize_messages` ever sees it. Anthropic whitelists `thinking_signatures`; OpenRouter whitelists `reasoning_details`; the OpenAI-family base whitelists nothing.
- `"none"` is deliberately absent from `EFFORT_LEVEL_ORDER` (`clients/llm/types.py`) — every effort clamp/ranking uses `.index()` and would raise on it. `effort="none"` semantics are per-dialect (see the thinking-translation matrix below); no dialect resolves "none" by omitting the thinking parameter, because omission means "model default" and model defaults enable deliberation.
- `current_partial_usage()` returning `None` means "usage unavailable — skip billing"; callers must never substitute fabricated numbers (`base.py` default returns `None`; `anthropic.py` overrides via `current_message_snapshot`). The OpenAI-family base never overrides it.
- `capabilities` (`base.py`, typed `clients/llm.capabilities.Capabilities`) is declared per dialect, not inferred. Only `AnthropicDialect` currently sets non-default capabilities (batch, files, container reuse, server code execution).
- `openai_chat_base.py` is a mixin transport, not a dialect: it has no `dialect_name` override, its `from_selection` raises `NotImplementedError` on the `Dialect` ABC, and the registry skips its class (its `dialect_name` remains the reserved "base"). Do not add it to a route.

## Files

- `base.py` — The `Dialect` ABC contract: `dialect_name`, `is_abstract`, `native_thinking_fields`, `capabilities`, `_accepted_round_trip_fields`, `from_selection`/`complete`/`stream` abstracts, `sanitize_outbound_message()`, `current_partial_usage()`, `_log_translation()`. Also owns the normalized error hierarchy (`ProviderError` → `ProviderAuthError`/`ProviderProtocolError`/`ProviderRetryableError`/`ProviderContextOverflowError`/`ProviderStallError`) that every dialect raises instead of raw SDK exceptions. `Consumers: clients/llm/dialect_registry.py (discovery), clients/llm/lifecycle.py (error policy)`.
- `openai_chat_base.py` — Shared OpenAI Chat Completions transport for three dialects: SSE streaming framework, non-streaming `complete()`, message/tool/usage conversion, full JSON-Schema validation of provider tool arguments (`Draft202012Validator` in `_coerce_tool_input`), HTTP error normalization. Subclasses override `_serialize_thinking`, `_extract_reasoning_message`/`_extract_reasoning_delta`, `_extract_cache_usage`. Writes raw streaming JSON chunks to the opt-in LLM tap (`utils/llm_tap`) before normalization; coalesces consecutive OpenRouter `reasoning.text` deltas via `_accumulate_reasoning_details`. `_budget_to_effort_heuristic` is the lossy budget→effort mapping (≤0→none, ≤2048→low, ≤8192→medium, ≤16000→high, ≤32000→xhigh, else max). An all-blocks-stripped user message raises `ProviderProtocolError` rather than sending an empty turn. `Consumers: groq.py, openai.py, openrouter.py` (all in this directory).
- `anthropic.py` — Anthropic Messages API dialect, the only one not built on `openai_chat_base.py`. Owns adaptive-vs-legacy thinking translation (`_translate_thinking`, canonical effort↔budget maps `_LEGACY_BUDGET_PER_EFFORT`/`_budget_to_effort_canonical`), thinking-signature and redacted-thinking round-trip, tool-result→user-message packing, overload retry (`OVERLOAD_MAX_RETRIES`), server tool use / code execution / file artifact events, Haiku 8192 max-token cap, module-level `anthropic_thinking_params()` and `normalize_anthropic_message()` entry points for dialect-free callers. `Consumers: clients/llm/dialect_registry.py, selected via clients/llm/resolver.py routes`.
- `openai.py` — Canonical OpenAI Chat Completions dialect (`reasoning_effort` top-level, `native_thinking_fields=("effort",)`). Adds per-model effort ceilings (`_MAX_EFFORT_PER_MODEL`, currently empty) via `_clamp_effort_for_model`, loopback/private-endpoint detection (`_is_local_endpoint`) that converts cache checkpoints, and `reasoning_content` extraction for OpenAI-compatible local servers. `Consumers: clients/llm/dialect_registry.py`.
- `openrouter.py` — OpenRouter dialect: nested `reasoning: {effort, max_tokens}` block, both fields native (no translation notes in the forward path; a budget accompanying `effort="none"` is discarded with a note). Whitelists `reasoning_details` for round-trip and reads cache writes from `cache_write_tokens`. `Consumers: clients/llm/dialect_registry.py`.
- `groq.py` — Groq dialect: `reasoning_effort` plus `reasoning_format: "parsed"` whenever reasoning is active (reasoning surfaces in `message.reasoning`/`delta.reasoning` instead of inline `think` tags). Inherits the lossy budget→effort heuristic from `openai_chat_base.py`. `Consumers: clients/llm/dialect_registry.py`.
- `__init__.py` — Docstring only, no re-exports; registration happens in `clients/llm/dialect_registry.py`. Its "drop-a-file operation" claim is stale — see the blast-radius Rule above.
## Wiring

- Construction flows `clients/llm/resolver.py` (`ModelSelection` carries `dialect_name`) → `clients/llm/dialect_registry.py` (`DialectRegistry.get`) → `Dialect.from_selection` in this directory. `from_selection` sources the API key from its argument or Vault via `selection.api_key_name`; a `None` `api_key_name` builds the client unauthenticated (the local llama-server route). Failure here raises — the orchestrator never sees a half-constructed dialect.
- `clients/llm/lifecycle.py` wraps every `complete()`/`stream()` call with `config.api.provider_response_timeout` stall detection; dialects raise `ProviderStallError`/`ProviderRetryableError` from this directory and the lifecycle owns no-fallback policy.
- Registry discovery edges: `clients/llm/dialect_registry.py` imports every module in this package, validating each candidate against `DialectName`/`NativeField` (`clients/llm/types.py`) and registering only classes whose home module is the dialect file (re-exports skipped). Two concrete dialects claiming one `dialect_name` raises `ValueError` at boot. The registry docstring's "single-file operation" claim is stale — see the blast-radius Rule above.
- `clients/vault_client.get_api_key` is imported lazily inside `from_selection` (this directory) when `api_key` is `None` and `selection.api_key_name` is set — the Vault dependency is deferred to dialect construction, not module import.
- Transport edges out of this directory: `openai_chat_base.py` streams via `utils/http_client` and logs raw chunks / request-response pairs via `utils/llm_tap` (opt-in); `anthropic.py` instruments its SDK client with `utils/logging_config.instrument_anthropic_client` and writes code-execution artifacts through the injected `clients/llm/artifacts.py` `FileArtifactSink`.
- Streaming dialects emit `clients/llm/events.py` event types (`TextEvent`, `ThinkingEvent`, `ToolDetectedEvent`, `CompleteEvent`, and in Anthropic's case `ToolExecutingEvent`/`ToolCompletedEvent`/`FileArtifactEvent`) — the consumer contract is `LLMProvider.stream_events()`.

## Thinking-translation matrix

The four dialects resolve the same `ThinkingConfig` differently; cross-knob translation is canonical only for Anthropic, heuristic everywhere else.

| Dialect | Native fields | effort-only | budget-only | both set | `effort="none"` wire form |
|---|---|---|---|---|---|
| `anthropic` | effort + budget | adaptive: `output_config.effort` (clamped); legacy: canonical `_LEGACY_BUDGET_PER_EFFORT` → `thinking: {type: enabled, budget_tokens}` | adaptive: canonical `_budget_to_effort_canonical`; legacy: used natively | adaptive: effort wins (note); legacy: budget wins (note) | `thinking: {type: "disabled"}` — never a budget (`_legacy_budget_for_effort` raises); on legacy models `none`+budget raises `ValueError` |
| `openai` | effort | `reasoning_effort` (clamped via `_MAX_EFFORT_PER_MODEL`) | lossy `_budget_to_effort_heuristic` + WARNING note | effort wins, budget discarded (note) | `reasoning_effort: "none"` — explicitly sent, never omitted (llama.cpp default would deliberate) |
| `openrouter` | effort + budget | `reasoning.effort` | `reasoning.max_tokens` verbatim | both sent (`max_tokens` kept unless effort is none) | `reasoning: {effort: "none"}`; a concurrent budget is discarded with a note |
| `groq` | effort | `reasoning_effort` + `reasoning_format: "parsed"` | lossy heuristic + WARNING note | effort wins, budget discarded (note) | `reasoning_effort: "none"` with no `reasoning_format` (nothing to parse) |

Temperature: `anthropic.py` `_build_params` never sends `temperature` — per the in-code comment, the API has deprecated the parameter and SDK 1.x removed it from `Messages.create` (passing it raises `TypeError`); the OpenAI family forwards `request.temperature` when set (`openai_chat_base.py` `_build_payload`).
