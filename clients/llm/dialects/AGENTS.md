# clients/llm/dialects/ — per-provider wire formats for the neutral LLM boundary: one `Dialect` transport per provider, the `ProviderError` taxonomy, thinking translation

Elsewhere: typed neutral contracts (`Request`/`Result`/`ThinkingConfig`, `EFFORT_LEVEL_ORDER` and its import-time ranking invariant, `coerce_*`, the `DialectName` literal) — `clients/llm/AGENTS.md`, storage `clients/llm/types.py` · registry walk and class validation, lifecycle stall/cancel/cost policy, route resolution, failover divert — `clients/llm/AGENTS.md` (`clients/llm/dialect_registry.py`, `clients/llm/lifecycle.py`, `clients/llm/resolver.py`, `clients/llm/diverter.py`) · request assembly, capability requirements, per-request construction — `clients/llm/AGENTS.md` (`clients/llm_provider.py`) · stall-propagation doctrine, no fallback route — root `AGENTS.md` · the `FileArtifactSink` implementation and probe consumers — `utils/AGENTS.md` (`utils/artifact_store.py`, `utils/power_on_self_test.py`, `utils/failover_jobs.py`) · full signatures and each provider's wire table — the module docstrings.

## Rules

- A concrete dialect declares, at class scope: `dialect_name` — a member of the `DialectName` literal in `clients/llm/types.py`, extended there before the registry can accept the name; `is_abstract = False`; `from_selection` as a `@classmethod`; `native_thinking_fields` a tuple over `("effort", "budget")`; `_accepted_round_trip_fields` for the provider metadata it round-trips. `_validate_dialect_class` raises at discovery for three of the five — a `dialect_name` empty/reserved/unlisted, a `native_thinking_fields` not a tuple over the literal, a non-classmethod `from_selection` (raise list owned by `clients/llm/AGENTS.md`) — and discovery runs at boot (`main.py`), so those park the boot gate. The other two fail silently: a class missing `is_abstract = False` is skipped by the discovery walk (never registers — a route naming it parks the boot gate at `registry.get`; an unnamed one simply does not exist), and a class missing `_accepted_round_trip_fields` registers on the base default `frozenset()` — its provider metadata silently vanishes at the next outbound conversion (Rule below). Mixins stay skippable via `is_abstract = True` or the reserved `dialect_name = "base"` (walk owned by `clients/llm/AGENTS.md`).
- Provider failures leave a dialect only as `base.py` taxonomy members — SDK and httpx exceptions normalize inside the boundary (`_raise_anthropic_error`, `_handle_http_error`/`_raise_provider_http_error` in `openai_chat_base.py`), with `ToolNotLoadedError` in the set. Consumers position by type, so a new member means a consumer decision at each site: retryable → diverter trip counting, overflow → `ContextOverflowError` remediation (`clients/llm_provider.py`); auth and overflow never recorded (`clients/llm/diverter.py`); `ToolNotLoadedError` → synthetic `invokeother_tool` recovery (`clients/llm/lifecycle.py`); `ProviderError` in `tools/implementations/web_tool.py`'s synthesis degrade set and excluded from extraction's content-failure budget (`lt_memory/processing/orchestrator.py:_is_content_caused_extraction_failure`, counterpart `lt_memory/processing/AGENTS.md`; `tools/implementations/web_tool.py`'s synthesis degrade set, counterpart `tools/implementations/AGENTS.md`). Provider-issued tool calls validate against `request.tools` (`ToolNotLoadedError` re-raised past the schema-repair catch — the lifecycle recovery depends on seeing it); replayed history tool_calls are exempt, or a prior turn's ephemeral tool would raise every turn. Never let a bare `ValueError` out of a normalization path: the WS turn handler classifies ValueError as `TURN_VALIDATION_FAILED` (`cns/api/websocket_chat.py`, counterpart `cns/api/AGENTS.md`) and skips overflow remediation — why unknown stop_reasons wrap as `ProviderProtocolError` (RuntimeError family → `TURN_PROCESSING_FAILED`).
- `sanitize_outbound_message` (`base.py`) strips every message key outside `_STANDARD_MESSAGE_FIELDS ∪ _accepted_round_trip_fields` before any wire conversion runs — a new provider-metadata field must be declared in the consuming dialect's `_accepted_round_trip_fields` and produced by the storage side (`clients/llm/tool_messages.py:assistant_message_from_result`, persisted through `cns/services/orchestrator.py` step metadata), or it silently vanishes on the next outbound conversion and the round-trip contract breaks at replay.
- `effort="none"` always goes on the wire as an explicit disable — `reasoning_effort: "none"` (`openai.py`, `groq.py`), `reasoning: {"effort": "none"}` (`openrouter.py`), thinking `{"type": "disabled"}` (`anthropic.py`) — omission means the model's default, and on this boundary the defaults deliberate (medium on gpt-5.5; Groq's Qwen3 documents reasoning on by default; Claude models past 4.8 think by default — 4.6 through 4.8 default off). A dropped literal makes a route seeded never-to-deliberate silently deliberate; a model that rejects the literal fails 400, which is loud.
- Dialect instances are per-request — `clients/llm_provider.py:_dialect_for_selection` constructs one per call — so `_active_stream`/`_active_response`/`_partial_usage` instance state and the abort-close are safe; a shared dialect aborts another request's connection. Every transport registers its abort handle before the blocking call (the non-streaming path holds the client, not the response — a response object exists only after the blocked read returns) and implements `abort_active_stream` closing it: `clients/llm/lifecycle.py:_run_with_response_timeout` unblocks a stalled worker only through it (`generator.close()` raises mid-frame). No handle: the watchdog abandons a daemon thread pinned to a leaked connection.
- A thinking translation that drops or reinterprets caller intent — budget→effort heuristic, per-model clamp, a discard, budget reconciled under max_tokens — emits a `TranslationNote` through `base.py:_log_translation` at WARNING; documented canonical mappings (Anthropic effort↔budget) stay silent. The note is the only observable seam between caller intent and provider behavior; a silent loss is undiagnosable from either side.
- A dialect yields only validated events — malformed wire shapes raise `ProviderProtocolError` rather than yield, and `clients/llm/probe.py:probe_first_token` treats any yielded event as well-formed by construction, resting its reachability verdict on that — and `CompleteEvent` exactly once, last, carrying the final `Result` (`clients/llm/lifecycle.py` raises without one). `ErrorEvent` is produced by `clients/llm_provider.py`'s stream catch, `ToolErrorEvent`/`CircuitBreakerEvent`/`ModelStepCompletedEvent` by `cns/services`, `GenerationCancelled` by `clients/llm/lifecycle.py` and `utils/user_context.py` — never here.
- Stored history replays through whichever dialect serves the next turn: conversion normalizes foreign storage shapes, never drops them silently. `anthropic.py:_serialize_assistant_content` accepts key-form `tool_calls` (the OpenAI family's storage) and pairs reasoning blocks with `thinking_signatures` positionally — an unpaired block raises by design (OpenAI-family reasoning carries no signatures and must not replay on a deliberating Anthropic route; recovery is a stored-history rewind or a segment collapse). `openai_chat_base.py:_convert_user_message` drops foreign reasoning blocks with a warning and raises when a user message would empty.

## Files

- `__init__.py` — docstring only, no re-exports; the registry walks this package (mechanics in `clients/llm/dialect_registry.py`, owned by `clients/llm/AGENTS.md`).
- `base.py` — the `Dialect` ABC and the normalized provider-error taxonomy. Entry: `Dialect.from_selection`/`complete`/`stream`, `sanitize_outbound_message`, `current_partial_usage` (None = usage unavailable, skip billing — never fabricate), `_log_translation`; `ProviderError` → `ProviderAuthError`/`ProviderProtocolError`/`ProviderRetryableError`/`ProviderContextOverflowError`, with `ProviderStallError` subclassing `ProviderRetryableError` — a stall reaches every `except ProviderRetryableError` catch site (diverter trip counting, `clients/llm/AGENTS.md`). Gotcha: `ProviderStallError` is defined here but raised only by the lifecycle watchdog — a dialect detecting its own stall bypasses the watchdog's cancel-first ordering.
- `openai_chat_base.py` — the shared Chat Completions transport: SSE framework, message/tool conversion, usage parsing, error normalization. Entry: `complete`/`stream`, `_convert_messages`/`_convert_assistant_message` (round-trip fields copied per `_accepted_round_trip_fields`), `_parse_tool_call`/`_coerce_tool_input` (jsonschema-validated; failures → `invalid_reason`), `_normalize_finish_reason`, `parse_error_body`/`ProviderErrorEnvelope`, `ToolNotLoadedError`, `_budget_to_effort_heuristic` (≤ 8192 → "low", else "high" — override with documented thresholds when a provider publishes them), `_new_reasoning_text` (transport-level duplicate-delta dedup). Gotcha: `_parse_usage` subtracts `_extract_cache_usage`'s write + read counts from `prompt_tokens` (the `Usage` meaning is owned by `clients/llm/AGENTS.md`) and raises `ProviderProtocolError` when the cached counts exceed it; a stream ending without `[DONE]` and without `finish_reason` raises — partial accumulations never parse into a `Result` (truncated tool arguments would read as schema violations, truncated text as complete).
- `openai.py` — canonical OpenAI dialect. Entry: `_serialize_thinking` (top-level `reasoning_effort`), `_clamp_effort_for_model` + `_MAX_EFFORT_PER_MODEL` (empty — add entries when a model ships a documented cap), `_extract_reasoning_message`/`_extract_reasoning_delta` (read `reasoning_content`, the llama.cpp/local spelling; canonical OpenAI surfaces no reasoning text). Gotcha: on local (loopback/private) endpoints, assistant content blocks carrying `cache` become `cache_checkpoint: True` (`_is_local_endpoint`) — the llama.cpp prompt-cache path; the neutral `cache` hint silently changes the wire shape there and nowhere else.
- `openrouter.py` — gateway dialect: nested `reasoning: {effort, max_tokens}`, both native. Entry: `_serialize_thinking`, `_extract_cache_usage` (cache write + read counts), `_accepted_round_trip_fields = {"reasoning_details"}`. Gotcha: `reasoning.effort` and `reasoning.max_tokens` are documented "one of the following (not both)" — effort="none" discards budget_tokens with a note, and "none" is the gateway's own disable value (a target that cannot disable, Claude via OpenRouter, fails 400 rather than deliberating).
- `groq.py` — top-level `reasoning_effort` plus `reasoning_format: "parsed"`, so reasoning returns in `delta.reasoning`/`message.reasoning` instead of inline `<think>` tags. Entry: `_serialize_thinking`, `_extract_reasoning_message`/`_extract_reasoning_delta`. No gotcha beyond the Rules.
- `anthropic.py` — the Messages API dialect over the SDK beta surface (`betas=ANTHROPIC_BETA_FLAGS`): overload retry, thinking translation (adaptive 4.6+ effort vs legacy budget map), tool-result user-message packing, native-tool-call jsonschema validation → `invalid_reason`, server code execution (`CODE_EXECUTION` tool block inserted first whenever tools are sent) with files-API artifact downloads. Entry: `complete`/`stream`, `_build_params`, `_translate_thinking`, `_serialize_messages`, `_normalize_message`, `_raise_anthropic_error`, `_file_artifact_events`/`_server_tool_completed_events`. Temperature never sent (SDK 1.x rejects it); the SDK read window pins 900s to `api.provider_response_timeout` — `config.api.timeout` reaches `from_selection` unapplied (declined). Artifact path UNTESTED against live infrastructure (provider support known buggy). Gotcha: `anthropic_thinking_params`/`normalize_anthropic_message` — module-level entry points with no repo importer (`rg 'anthropic_thinking_params|normalize_anthropic_message'` hits only the definitions): dead, do not build on them.

## Wiring

- Request flow: `clients/llm/resolver.py:ModelResolver.resolve` → `ModelSelection` → `clients/llm_provider.py:_dialect_for_selection` → `from_selection(selection, api_key, timeout, artifact_sink)` → `capabilities.validate` → `clients/llm/lifecycle.py:LLMLifecycle` → `complete`/`stream` here. `Requirements(` is constructed only by `llm_provider._requirements_for_request` (container_reuse only; `rg 'Requirements\('`) — batch/files/server_code_execution are declared, required by no request path yet; the gate is the enforcement point when one gains a caller.
- Credentials: with `api_key=None`, `from_selection` resolves `selection.api_key_name` through `clients/vault_client.py:get_api_key` (lazy import — module import stays Vault-free); `api_key_name=None` means unauthenticated, the offline llama-server route (the `""` on-disk sentinel normalizes in `clients/llm/resolver.py:optional_api_key_name`). Anthropic rejects a missing key (cannot run unauthenticated); the OpenAI family sends no Authorization header.
- Taxonomy consumers, by grep and never transcribed: `rg 'from clients\.llm\.dialects\.base import'` → `clients/llm_provider.py`, `clients/llm/lifecycle.py` (plus `ToolNotLoadedError` from `openai_chat_base`), `lt_memory/processing/orchestrator.py`, `tools/implementations/web_tool.py`; terminal classification in `cns/api/websocket_chat.py` turn-error frames (counterpart `cns/api/AGENTS.md`).
- Round-trip storage chain: `ReasoningArtifact.to_signatures`/`to_content_blocks` (`clients/llm/types.py`) → `clients/llm/tool_messages.py:assistant_message_from_result` → `cns/services/orchestrator.py` step metadata (owner `cns/services/AGENTS.md`) → `cns/core/message_formatter.py` replay injection (owner `cns/core/AGENTS.md`) → `_accepted_round_trip_fields` here. Traced below.
- Discovery: `main.py` warms `get_registry().discover()` at boot (imports every dialect module, anthropic SDK included — lazy discovery would land on the first request of every fresh process); `utils/power_on_self_test.py:_check_llm_configuration` re-discovers against the five route rows (counterpart `utils/AGENTS.md`).
- Probes: `clients/llm/probe.py:probe_first_token` builds one dialect per selection through the registry, streams to the first well-formed token, then aborts via `abort_active_stream` — consumed by the POST boot gate and `utils/failover_jobs.py` (counterpart `utils/AGENTS.md`).
- Observability and transport: every request and response taps through `utils/llm_tap.py` (USR1-gated; owner `utils/AGENTS.md`); stream chunks tap only on the OpenAI family (`openai_chat_base.py`'s stream loop) — anthropic taps its requests and responses, never chunks, so an Anthropic stream debugged through the tap shows no per-chunk records. The OpenAI family streams via `utils/http_client.py:stream` — the only in-repo stream-path connect retry; the Anthropic SDK client carries its own built-in connect retries (unoverridden in `__init__`) — and completes on a per-call `httpx.Client`; anthropic instruments its SDK client at construction via `utils/logging_config.py:instrument_anthropic_client` (gated `config.system.anthropic_sdk_content_logging`, default off).

## Reasoning round-trip: extraction to replay pairing

1. Extraction: `anthropic.py:_normalize_message` turns `thinking` blocks into `ReasoningEntry(text, signature)` and `redacted_thinking` into `redacted_data` — the only source of signatures on the boundary. The OpenAI family extracts free text through `_extract_reasoning_message`/`_extract_reasoning_delta` (groq `reasoning`, openai `reasoning_content`, openrouter `reasoning_details` blocks coalesced by `_accumulate_reasoning_details`), producing entries without signatures plus `provider_details`. Both land on `Result.reasoning` as one `ReasoningArtifact`.
2. Storage: at turn end, `clients/llm/tool_messages.py:assistant_message_from_result` builds the stored assistant message — `to_content_blocks()` writes plain `{"type": "reasoning", "text"}` blocks (unsigned), `to_signatures()` writes the ordered signature list (`{"type": "thinking", "signature"}` per signed entry, trailing `{"type": "redacted_thinking", "data"}`) onto `thinking_signatures`; OpenRouter's `provider_details` ride `reasoning_details`. `cns/services/orchestrator.py` persists both into message metadata (`cns/core/message.py`'s typed fields), and `cns/core/message_formatter.py` injects them back onto the neutral message dict at replay.
3. Replay filtering: `sanitize_outbound_message` keeps only `_STANDARD_MESSAGE_FIELDS ∪ _accepted_round_trip_fields` — anthropic accepts `thinking_signatures`, openrouter accepts `reasoning_details`, every other dialect strips both.
4. Pairing: on a deliberating request (`thinking.deliberating`), `anthropic.py:_serialize_assistant_content` walks reasoning blocks and signatures together positionally — each reasoning block takes the next `thinking` signature, `redacted_thinking` signatures pass through as their own blocks, and an exhausted signature list or a leftover `thinking` signature raises `ProviderProtocolError`. Thinking blocks serialize ahead of the rest (`thinking_blocks + result`) and drop entirely on non-deliberating requests.
5. Dialect switch: history recorded by an OpenAI-family route carries no signatures, so replaying it on a deliberating Anthropic route raises at the first reasoning block — intended, because unsigned reasoning must not replay as signed; recovery is a stored-history rewind or a segment collapse. The reverse direction drops reasoning blocks from user content with a warning and raises when a user message would empty; tool calls normalize across families — content-block form and key-form both accepted on both sides, but duplicate-id suppression exists only in `anthropic.py:_serialize_assistant_content` (`emitted_tool_use_ids`): `_convert_assistant_message` double-sends a message carrying both forms.

Ordering invariants: `to_content_blocks` and `to_signatures` both derive from the same `entries` tuple in order — a reorder between storage and replay breaks the positional pairing; signatures pair only on deliberating requests, so a request-shape change that flips `thinking_active` changes which stored blocks serialize at all.
