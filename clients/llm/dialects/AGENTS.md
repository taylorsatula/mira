# clients/llm/dialects/ — per-provider wire formats the neutral LLM boundary encodes requests into, and the error taxonomy provider failures come back as

## Files

- `__init__.py` — package docstring and nothing else; no re-exports, no code. Open it only when adding a module to the package.
- `base.py` — the `Dialect` ABC with its class-scope contract, and the normalized `ProviderError` taxonomy every transport raises. Open it before adding a dialect, a thinking knob, or an error type.
- `openai_chat_base.py` — the shared transport behind the three OpenAI-family dialects. Open it before changing anything they do in common.
- `openai.py` — the canonical OpenAI dialect. Open it when a canonical-OpenAI-shaped or air-gapped route misbehaves.
- `groq.py` — the Groq dialect. Open it when a Groq-backed route's reasoning text or effort handling looks wrong.
- `openrouter.py` — the OpenRouter gateway dialect. Open it when gateway reasoning blocks or the `reasoning_details` round-trip are in question.
- `anthropic.py` — the Anthropic Messages API dialect. Open it before touching Anthropic thinking translation, tool-result packing, or code-execution artifacts.

## Wiring

- Family inheritance: `openai.py`, `groq.py` and `openrouter.py` → `openai_chat_base.py:OpenAIChatBase` → `base.py:Dialect`; `anthropic.py` → `base.py:Dialect` directly. A family dialect overrides only the hooks the base leaves empty, and an unoverridden hook returns the base's silent default — no thinking knob on the wire, empty reasoning text, cache writes counted as zero — with no error anywhere.
- Sanitize before convert: `base.py:Dialect.sanitize_outbound_message` runs at `openai_chat_base.py:_build_payload` and `anthropic.py:_build_params`, ahead of any message conversion. Conversion code therefore sees only `_STANDARD_MESSAGE_FIELDS ∪ _accepted_round_trip_fields`, so a dialect's round-trip loop can never observe a field the dialect did not declare.
- Request construction: `clients/llm/resolver.py:ModelResolver.resolve` → `clients/llm_provider.py:_dialect_for_selection` → `from_selection(selection, api_key, timeout, artifact_sink)`, one instance per request. Counterpart: `clients/llm/AGENTS.md`. Two requests sharing an instance share `_active_response` (family) or `_active_stream` (Anthropic), and an abort then closes a connection another request is reading.
- Boot discovery: `clients/llm/dialect_registry.py:discover` imports every module in this package, so module-scope work here — the `anthropic` SDK import included — is on the boot path, not the first request's. Counterpart: `clients/llm/AGENTS.md`.
- Error taxonomy out: transport failures leave this directory normalized to `base.py:ProviderError` subclasses, and consumers position by type rather than by status — `rg 'from clients\.llm\.dialects\.base import'`. Failures raised before any transport runs are not in the taxonomy: `from_selection` and `__init__` raise `ValueError`/`PermissionError` for a missing endpoint, key or invalid timeout, and tool-schema validation raises `RuntimeError` from `openai_chat_base.py:_coerce_tool_input` and `anthropic.py:_normalize_message`. `ProviderStallError` subclasses `ProviderRetryableError`, so a stall reaches every retryable catch site. Counterpart: `clients/llm/AGENTS.md`.
- Error taxonomy consumed by type: `base.py:ProviderError` is a catch key, not only a base class — `tools/implementations/web_tool.py:_synthesize_content` degrades a failed page condensation on `except (ProviderError, ContextOverflowError, httpx.TransportError)`, so a failure normalized into any subclass declared here reaches that handler, while a new error class that stops deriving from `ProviderError`, or a raw provider exception a transport lets escape un-normalized, propagates out of a `fetch` that had already succeeded instead of falling back to the truncated page dump. Any error that must degrade there derives from `ProviderError` before it crosses the boundary; the `clients.llm_provider.ContextOverflowError` the tuple also names is a sibling outside this hierarchy. Counterpart: `tools/implementations/AGENTS.md`.
- Tool-not-loaded recovery: `openai_chat_base.py:ToolNotLoadedError` must escape `_parse_tool_call` and `_parse_stream_tool_calls` un-normalized, because `clients/llm/lifecycle.py:_run` catches it by type and replaces the result with a synthetic `invokeother_tool` call whose input is `{"load": [tool_name]}`. Folding it into a sibling `ProviderProtocolError` or a normal `Result` forfeits that recovery and the turn ends where it should have reloaded the tool. Counterpart: `clients/llm/AGENTS.md`.

## Rules

- Adding a dialect is one new transport file plus a declaration in the database's dialect vocabulary. In the file, at class scope: `dialect_name` a member of the `DialectName` literal in `clients/llm/types.py` (extend the literal first — an unlisted name is refused at discovery), `is_abstract = False`, a `@classmethod` `from_selection`, `complete` and `stream`, `capabilities` for the features the provider actually supports, `native_thinking_fields` as a tuple over `("effort", "budget")`, and `_accepted_round_trip_fields` for the provider metadata it round-trips. Outside the file: a `deploy/migrations/` step widening the `model_configs.dialect_name` CHECK, carrying the `-- dialect-twins: DialectName, DIALECT_NAMES` header, in the same commit as the literal — skip it and discovery accepts the class while the `model_configs` row that names it is rejected by the CHECK, so no route can ever select it; the step contract lives in that directory's map. Three of those omissions surface nowhere at registration: without `is_abstract = False` the class never registers, and a route naming it parks the boot gate; without `_accepted_round_trip_fields` it registers on the empty default and its provider metadata vanishes at the next outbound conversion; on the inherited all-False `capabilities` a request requiring `batch` or `files` fails the pre-transport gate naming the flag the new dialect never claimed. The raise list and the registry walk are `clients/llm/AGENTS.md`'s.
- `effort="none"` always goes on the wire as an explicit disable, never as an omitted knob — `reasoning_effort: "none"` in `openai.py` and `groq.py`, `reasoning: {"effort": "none"}` in `openrouter.py`, thinking `{"type": "disabled"}` in `anthropic.py`. Omitting means "model default", and these defaults deliberate. A dropped literal turns a route seeded never-to-deliberate into a silently deliberating one; a model that rejects the literal answers 400, which is loud.
- Every thinking translation that drops or reinterprets caller intent emits a `TranslationNote` through `base.py:_log_translation` at WARNING — the budget-to-effort heuristic, a per-model clamp, a discarded knob, a budget reduced to fit under `max_tokens`. Documented canonical mappings between the two knobs stay silent, and a clamp has one silent direction: `anthropic.py:_clamp_effort` emits the note only when the caller requested the level it clamps, so an effort derived from a `budget_tokens` hint and then capped by a model ceiling is dropped without a note. The note is the only observable seam between caller intent and provider behavior, so a silent loss cannot be diagnosed from either side.
- Each transport registers its abort handle before the blocking call and implements `abort_active_stream`. On the streaming paths the handle is the response; on the non-streaming paths it is the client, because no response object exists until the blocked read returns. `clients/llm/lifecycle.py:_run_with_response_timeout` unblocks a stalled worker only through that call, so a transport without a handle leaves the watchdog abandoning a thread pinned to a leaked connection. Nothing enforces the obligation: `abort_active_stream` is not declared on `base.py:Dialect` and is never validated at construction — `clients/llm/lifecycle.py` and `clients/llm/probe.py` reach it through `getattr` — so a dialect that omits it looks healthy until the first stall.
- A dialect yields only validated events, and exactly one `CompleteEvent`, last. A malformed SSE frame raises `ProviderProtocolError` instead of being skipped, which is what lets `clients/llm/probe.py:probe_first_token` treat any yielded event as well-formed by construction — a dialect that yields a half-parsed frame makes that reachability verdict false. The guarantee covers the event path only: per-field extraction on the response side still drops a fragment and logs it (`openai.py:_extract_reasoning_message`, `anthropic.py:_normalize_message`), so a well-formed event does not imply a complete reasoning payload. `ErrorEvent`, `ToolErrorEvent`, `CircuitBreakerEvent` and `ModelStepCompletedEvent` are yielded, and `GenerationCancelled` raised, outside this directory.

Elsewhere: this directory owns how a provider's wire format is spoken, not which provider a call goes to, what the neutral contracts mean, or how a call is bounded. The `Request`/`Result`/`ThinkingConfig` definitions, the `DialectName` literal and the `Usage` field declarations are docstrings in `clients/llm/types.py`, and what `input_tokens` counts plus how the cache fields are priced is the parent LLM boundary map's; why a rule here reads as it does is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## The signed-reasoning round-trip

The one path here that no single file shows: reasoning text leaves a provider, is stored, and has to come back in a shape the next provider accepts. Signatures only exist on one side of that trip.

1. Extraction. `anthropic.py:_normalize_message` turns each `thinking` block into a `ReasoningEntry(text, signature)` and each `redacted_thinking` into redacted data — the only source of signatures on this boundary. The OpenAI family extracts free text instead (`_extract_reasoning_message`/`_extract_reasoning_delta`, with OpenRouter's `reasoning_details` coalesced by `_accumulate_reasoning_details`), producing entries with no signature plus provider details. Both land on `Result.reasoning` as one `ReasoningArtifact`.
2. Storage. `clients/llm/tool_messages.py:assistant_message_from_result` writes `to_content_blocks()` — plain `{"type": "reasoning", "text"}` blocks, unsigned — and `to_signatures()`, the ordered signature list with redacted entries appended last. Both index the same `entries` tuple in order but drop different entries — `to_content_blocks` skips a blank `text`, `to_signatures` skips an absent `signature` — so an entry carrying a signature and no text unbalances the pairing and step 4 raises `ProviderProtocolError`, with no reordering involved. `cns/services/orchestrator.py` persists both into message metadata, and `cns/core/message_formatter.py` puts them back onto the neutral message dict at replay.
3. Filtering. `sanitize_outbound_message` keeps only the standard fields plus the dialect's declared ones: Anthropic accepts `thinking_signatures`, OpenRouter accepts `reasoning_details`, every other dialect strips both. A new round-trip field is therefore two edits, not one — declaring it here does nothing until the storage side produces it.
4. Pairing. On a deliberating request, `anthropic.py:_serialize_assistant_content` walks reasoning blocks and signatures together positionally, emits the resulting thinking blocks ahead of the rest, and raises when either list runs out first. On a non-deliberating request the thinking blocks are dropped entirely.
5. Dialect switch. History recorded on an OpenAI-family route carries no signatures, so replaying it on a deliberating Anthropic route raises at the first reasoning block. That is intended: unsigned reasoning must not replay as signed, and recovery is a stored-history rewind or a segment collapse. The reverse direction drops reasoning blocks from user content with a warning and raises when a user message would empty. Tool calls normalize in both directions, but only `_serialize_assistant_content` suppresses a duplicate id, so a stored message carrying both the content-block and key forms double-sends through the OpenAI family.
