# config/ — the Pydantic config schema, the process-global config singleton, and the system prompt

Elsewhere: prompt templates and the loader contract — `config/prompts/AGENTS.md` · section-vocabulary parsing and anchor validation — `cns/services/AGENTS.md` (`system_prompt_parser.py`) · tool-config storage and the secret sentinel machine — `utils/AGENTS.md` (`tool_config_store.py`) · the tool registry and config-class registration — `tools/AGENTS.md` · model routes and the resolver — `clients/llm/AGENTS.md` · the deploy side that writes the env file and the installer flow — `deploy/AGENTS.md` · per-user preferences (timezone, first name) — `utils/AGENTS.md` (`user_context.py`) · `main.py` mount and startup ordering — root `AGENTS.md` · a knob's tuning history — `git log` · defaults, bounds, per-field descriptions — the files.

## Rules

- The schema loads from no file — every knob is a `Field` default in `config/config.py`; an operator changes one by env var (deploy-written) or a code edit plus process restart. The singleton `config = initialize_config()` runs at import of `config/config_manager.py` and has no reload path. Runtime mutation of any `config.*` field is visible to every user and thread in the process — a probe that flips `config.system.injection_screen_enabled` mid-run changes screening for all in-flight turns; restore the value or restart, never leave it mutated.
- Adding a deploy-settable knob is a recipe; each skipped step fails silently. (1) The `Field` in the section class owning the domain, description carrying the operator contract. (2) The entry in the matching override dict in `config/config_manager.py` — `SYSTEM_FEATURE_FLAG_ENVIRONMENT_FIELDS` (flags), `SYSTEM_STRING_ENVIRONMENT_FIELDS`, `API_INT_ENVIRONMENT_FIELDS`, `SYSTEMONE_STRING_ENVIRONMENT_FIELDS` + `SYSTEMONE_PROVIDER_ENVIRONMENT_FIELD` — because `AppConfig.load()` passes overrides for exactly three sections: `api`, `system`, `systemone`. Skip (1) and the override dies as a pydantic `extra='ignore'` no-op; skip (2) and the env var deploy writes is silently ignored (unset vars are omitted, defaults apply). Parsing is strict by design — flags exactly `0`/`1`, token counts positive integers, systemone provider exactly `local`/`remote`; anything else raises at `import config`, killing boot before the POST gate. Never relax the strictness to accept "true".
- `ApiConfig.validate_compaction_budget(primary_max_tokens)` has no in-directory caller: `utils/user_context.py:load_model_configs` invokes it at startup and the POST gate re-checks — it couples `compaction_trigger_tokens` to the DB-configured primary route's `max_tokens` (`context_window_tokens - max_tokens` must leave room). Raise `MIRA_CONTEXT_WINDOW_TOKENS` or `MIRA_COMPACTION_TRIGGER_TOKENS` without the DB route and boot fails at model-config load with the budget error. The construction-time validators fire earlier still, at `import config`: `validate_failover_block` (`failover_enabled` requires `failover_endpoint_url`+`failover_model`+`failover_dialect_name`, positive cap), `validate_compaction_trigger_tokens` (trigger < window), `SystemConfig.validate_timezone_name` (IANA names only).
- `system_prompt.txt` is loaded by `config_manager.py:_load_system_prompt` directly by `Path` — never through `load_prompt()`, which resolves only inside `config/prompts/`. Missing or empty-after-strip raises `FileNotFoundError` at import and fails boot: prompts are system configuration, not optional features. Its five placeholders — `{first_name}`, `{user_context}`, `{relative time since account creation}`, `{model_id}`, `{model_name}` — are filled by `.replace()` in `working_memory/core.py:_handle_compose_prompt` (`{model_id}` = the primary route's model string, `{model_name}` = its route label). Rename a placeholder on either side alone and the literal `{placeholder}` reaches the model every turn, no error anywhere.
- Every top-level `<tag>` in `system_prompt.txt` is a section identifier, not just markup: `get_assessable_section_ids(config.system_prompt)` (parser owned by `cns/services/AGENTS.md`; `user`/`environment` blocklisted as runtime data) is the anchor vocabulary for stored user-model observations, pre-fills the examples in two `config/prompts/` templates, and `validate_section_anchors` enforces it at the save paths (corpus side owned by `config/prompts/AGENTS.md`). Rename or remove a section tag and the model imitates dead anchors — save-time validation rejects them with the valid-set error — while stored observations anchored to the old name strand, because validation compares against the live prompt. The system prompt, the template corpus, and the save-path validators move in one commit.
- Tool config access: `AppConfig.__getattr__` routes only `*_tool`-suffixed names to `get_tool_config` — any other spelling raises `AttributeError` and silently loses the per-user merge and the `enabled` gate; consumers across `tools/implementations/AGENTS.md` depend on the suffix. `get_tool_config` resolves the class through `registry.get_or_create` (registration owned by `tools/AGENTS.md`): unregistered → `create_default`, a bare class with `enabled=True` — a typo'd tool name yields all-defaults, never an error. Outside a request (no user context) it returns the global default; inside one it merges the user's stored row (`load_user_tool_config(..., hydrate_secrets=True)`) over the default fresh on every access.
- `*_use_days` fields are modular activity-day gates (mechanics owned by `utils/AGENTS.md`); `1` means every activity day. Three spell as interval arguments to `scheduled_tasks.get_users_due_for_job(interval)` — a new scheduled cadence is a new field here plus its job reading it; a per-user last-ran column is the drift defect `utils/AGENTS.md` names. Two compute inline per user as `get_user_cumulative_activity_days() % field`: the memory-curator floor gate (`agents/triggers/AGENTS.md` documents why it must not converge to the all-users function) and portrait synthesis — `scheduled_jobs.portrait_synthesis_use_days` rides the segment-collapse chain (`cns/services/segment_collapse_handler.py` → `portrait_service.py:should_synthesize_portrait`), never `get_users_due_for_job`; tracing that knob through the job file dead-ends.

## Files

- `__init__.py` — package facade: imports `tools.registry`, re-exports `config`, `AppConfig`, `registry`. Gotcha: only `config` has consumers (`rg 'from config import'`, `rg 'from config\.config_manager import'` — both spellings, one object); the docstring's `config.get()`/`config.require()` dot-notation and the `registry` re-export have no callers — attribute access is the interface.
- `config.py` — all section schemas: the 14 `AppConfig` section classes plus `DevicePowerBindingConfig` (module-level, before `HeartbeatConfig`, typed onto `heartbeat.device_power_binding`); a knob lives in the class matching its domain; `Field` descriptions are the operator-facing documentation. Gotcha: model validators fire at import — a bad value bricks boot, not first use.
- `config_manager.py` — the singleton and access layer: `AppConfig.load()` (env overrides → `_load_system_prompt`), `initialize_config` (`logging.basicConfig` from `system.log_level`, constructs at import), `__getattr__`/`get_tool_config` (Rules), `_load_system_prompt` (fail-fast; its traversal/suffix checks guard a hardcoded path — vestigial). Gotcha: a bare `AppConfig()` never runs `_load_system_prompt`, so `.system_prompt` raises `AttributeError`; only `load()` builds a usable instance. Dead, do not build on: the `system_prompt_text` field (always `""`, excluded, unread — the live store is the private `_system_prompt`), `as_dict` (excludes a `prompt_cache` field that does not exist), `get`, `require`, `list_available_tool_configs` — zero callers each.
- `announcement.py` — startup announcement cache: `load_announcement()` (once, from the `main.py` lifespan), `get_cached_announcement()` (lazy first call). Gotcha: a JSON edit does nothing until restart; malformed JSON or null fields degrade to no-announcement with a warning — sanctioned optional degrade, never a boot failure.
- `announcement.sample.json` — filled-shape example for operators; nothing reads it. Do not build on it.
- `system_prompt.txt` — Mira's behavioral contract, `<mira:system_prompt>`-wrapped sections; the only prompt file loading here; placeholder and section-tag blast radii in Rules.
- `vault.hcl` — dev Vault server config (file storage under `./vault_data`, loopback listener, `ui = true`); nothing in the repo invokes it — deploy generates its own at `deploy/vault.sh`. Run by hand for a local dev Vault: `vault server -config=config/vault.hcl`.
- `prompts/` — the template corpus and the single loader: `config/prompts/AGENTS.md`.

## Wiring

- Singleton: any import under `config/` — including `config.prompts.loader`, whose own imports are stdlib-only — runs `config/__init__.py` first and constructs the singleton; consumer sets are the named greps in the `__init__.py` card.
- Env writer ↔ `deploy/AGENTS.md`: deploy resolves operator choices at install time and writes `/opt/mira/systemone.env` (unit EnvironmentFile, no-systemd launcher, container) with the `MIRA_*` names the override dicts and `SYSTEMONE_PROVIDER_ENVIRONMENT_FIELD` read; a var named outside them is dead on arrival.
- System prompt chain: `config.system_prompt` (raw template) → chat turn handlers pass it as the base prompt (`cns/api/AGENTS.md`) → `working_memory/AGENTS.md` (`core.py:_handle_compose_prompt`, the placeholder fill) → composed per-turn prompt; vocabulary and contract consumers `cns/services/AGENTS.md` (`system_prompt_parser.py`, `persona_service.py` behavioral contract); boot witness `utils/AGENTS.md` (`power_on_self_test.py` re-checks non-empty).
- Tool-config chain: `config.<tool>_tool` → `get_tool_config` → `tools/AGENTS.md` (`registry.py:get_or_create`) for the class, `utils/AGENTS.md` (`tool_config_store.py`) for storage and the secret sentinels; write-side validation also runs through the registry (`cns/api/AGENTS.md`, `tool_config.py`).
- LLM bounds and failover ↔ `clients/llm/AGENTS.md`: `api.timeout` is the HTTP bound (`clients/llm_provider.py`), `api.provider_response_timeout` the no-progress stall bound (`clients/llm/lifecycle.py`) — the max of the two bounds a single provider call, never a turn (up to `MAX_LOCAL_TOOL_CALLS_PER_TURN` loop steps); the per-user turn-lock TTL derives from `(MAX_LOCAL_TOOL_CALLS_PER_TURN + 1) × max(the two) × 2` — a crash backstop, not a turn deadline (`cns/api/AGENTS.md`). `failover_*` feed `clients/llm/diverter.py` and `resolver.py`; the recovery probe job registers only when enabled (`utils/AGENTS.md`, `failover_jobs.py`).
- Boot validation ladder (ordering): import-time (strict env parse, section validators, prompt fail-fast) → `load_model_configs` compaction-budget check (`utils/AGENTS.md`, `user_context.py`) → POST `_check_configuration`/`_check_llm_configuration` re-checks (`utils/AGENTS.md`, `power_on_self_test.py`). A config defect surfaces at the earliest moment it is checkable — reproduce it at that moment, not just at the later gate.
- Use-day jobs: `temporal_score_recalc_use_days`/`bulk_score_recalc_use_days`/`entity_merge_use_days` → `utils/AGENTS.md` (`lt_memory_jobs.py` passes each interval to `get_users_due_for_job`); inline floor gate (`memory_curator.floor_use_days`) → `agents/triggers/AGENTS.md`; floor query parameters → `lt_memory/db_access.py`; `portrait_synthesis_use_days` → inline in the collapse chain (`cns/services/segment_collapse_handler.py`, `cns/services/AGENTS.md`).
- Gated construction: `system.subcortical_enabled`/`persona_enabled`/`peanutgallery_enabled` gate CNS graph construction (`cns/integration/AGENTS.md`, `factory.py` — consumers tolerate absence); `system.mcp_enabled` and `lattice.enabled` gate mounts in `main.py` (root-owned wiring); `system.injection_screen_enabled` gates the screen, disable and fail-closed contract owned by `utils/AGENTS.md`.
- Heartbeat and dispatcher: `heartbeat.*` + `sidebar_dispatcher.*` → `agents/AGENTS.md` (`base.py` timeout wiring, dispatcher caps), `agents/triggers/AGENTS.md` (heartbeat cadence rides `poll_interval_minutes`), `tools/implementations/AGENTS.md` (`heartbeat_tool` clamps against `max_interval_seconds`, honors `max_failures`), `utils/AGENTS.md` (`device_binding.py` reads `heartbeat.device_power_binding`; `sidebar_jobs.py` re-checks `enabled` at poll time).
- Local account: `system.timezone` (the install-level default — per-user timezone lives in the users table) and `system.local_session_first_name` → `auth/service.py:create_local_session` (`auth/AGENTS.md`); `auth.max_api_tokens_per_user` caps token minting there.
- Announcement: `main.py` lifespan calls `load_announcement()`; `cns/api/AGENTS.md` (`data.py:_get_user`) serves the cached copy inside the profile payload.
- Counterparts: use-day interval semantics consumed by activity-day queries ↔ `cns/infrastructure/AGENTS.md`; the container bootstrap reads the injection-screen keys here ↔ `deploy/docker/scripts/AGENTS.md`.
