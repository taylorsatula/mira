# config/ — the settings schema, the singleton that holds it, and the system prompt it carries

## Files

- `__init__.py` — the package facade whose package-level import of `config.config_manager` triggers construction of the singleton at first `import config`. Open it when an `import config` cycle is suspected, or before adding a config import anywhere else.
- `config.py` — the section schemas: every operator-settable setting plus the validators that reject a bad one at import, except `validate_compaction_budget`, which runs against the database-owned route. Open it before adding or changing a setting.
- `config_manager.py` — the singleton, the environment-override loaders, and dynamic tool-config access. Open it before making a setting deploy-settable.
- `announcement.py` — the cached startup announcement. Open it before changing how an operator posts or removes one.
- `announcement.sample.json` — the filled shape an operator copies to `announcement.json`; nothing reads it.
- `system_prompt.txt` — Mira's behavioral contract. Open it before editing anything the model is told about itself.
- `vault.hcl` — a dev Vault server config run by hand. No repo path invokes it, because deploy generates its own.
- `prompts/` — the template corpus and the single loader; its own map.

## Wiring

- Env override: deploy writes the env file → `config_manager._load_api_int_overrides` / `_load_system_feature_flag_overrides` / `_load_system_string_overrides` / `_load_systemone_overrides` → `AppConfig.load()` → the section classes in `config.py`. Only the `api`, `system`, and `systemone` sections take overrides. Four dicts carry them, plus the one scalar `SYSTEMONE_PROVIDER_ENVIRONMENT_FIELD` (`MIRA_SYSTEMONE_PROVIDER`, exactly `local` or `remote`); a variable outside that set is never read, so deploy can write it forever with no effect. Counterpart: `deploy/AGENTS.md`.
- Import cycle: `config/__init__.py` imports `tools.registry` at package level and `config_manager` constructs the singleton at module scope, so any import under `config/` also constructs it — `import config.prompts.loader` included. `tools/registry.py` must keep importing nothing from `config` at top level, or the cycle closes and `import config` fails at boot. Counterpart: `tools/AGENTS.md`.
- System prompt chain: `config.system_prompt` → turn entry in `cns/api/chat.py` and `cns/api/websocket_chat.py` → `orchestrator._compose_llm_messages` publishes `ComposeSystemPromptEvent` carrying it as `base_prompt` → `working_memory/core.py:_handle_compose_prompt` fills the placeholders → composed prompt. The prompt is loaded once at import and personalized per turn; see the deep-dive below for what a step reordering or a renamed placeholder does. Counterpart: `working_memory/AGENTS.md`.
- Section vocabulary: `system_prompt.txt`'s top-level tags minus the `_BLOCKLISTED_SECTIONS` set in `cns/services/system_prompt_parser.py` → `get_assessable_section_ids(config.system_prompt)` → the generated `{example_section_a}`/`{example_section_b}` anchors in `lora_refinement_system.txt` and `user_model_synthesis_system.txt` → `validate_section_anchors` at the save paths. The prompt, the templates generated from that vocabulary, and the validators move in one commit. Counterparts: `cns/services/AGENTS.md` (the parser and the save-path validators), `config/prompts/AGENTS.md` (the generated template examples).
- Boot validation ladder: import time (strict env parse, the section validators, the prompt fail-fast) → `utils/user_context.load_model_configs` checks `ApiConfig.validate_compaction_budget` against the DB-configured primary route's output reserve → the POST gate re-checks configuration. A config defect surfaces at the earliest moment it is checkable; the later gate only re-tests what survived the earlier one, so reproduce a suspected defect at its earliest gate. Counterpart: `utils/AGENTS.md`.
- Tool config: `config.<tool>_tool` → `AppConfig.__getattr__` → `get_tool_config` → `tools.registry.get_or_create` for the class and `utils.tool_config_store.load_user_tool_config` for the current user's row. Counterparts: `tools/AGENTS.md`, `utils/AGENTS.md`.
- Gated construction: `system.subcortical_enabled`, `persona_enabled`, and `peanutgallery_enabled` are read where the CNS graph and services are built, so a runtime flip leaves what already exists in place. Counterpart: `cns/integration/AGENTS.md`.
- Gated mount: `system.mcp_enabled` and `lattice.enabled` are read once inside `create_app`, so a runtime flip cannot mount or unmount a route. `system.injection_screen_enabled` is the opposite case — `utils/untrusted_content.py` reads it per screened call, so a change takes effect on the next external item. Counterpart: `utils/AGENTS.md`.
- LLM bounds, retry and failover: `api.timeout` and `api.provider_response_timeout` each bound one provider call, never a turn, and the failover `*` fields feed the diverter and its recovery probe job, which registers only while the diverter is enabled. The `api.provider_retry_*` fields feed the per-call retry loop in `clients/llm_provider.py`; retries run with or without a configured backup. Counterpart: `clients/llm/AGENTS.md`.
- Scheduled cadences: the `*_use_days` fields feed `utils/scheduled_tasks.get_users_due_for_job`, or a modulo the consumer evaluates inline. Counterpart: `utils/AGENTS.md`.
- Sidebar, heartbeat and curator: `heartbeat.*` and `sidebar_dispatcher.*` configure the brief system and the agent dispatcher; `heartbeat.device_power_binding` is what `utils/device_binding.py` imports to resolve the operator's power-binding module; `memory_curator.*` gates the curator's integration spawn and its floor trigger, whose `floor_*` sample and use-day cadence the trigger reads inline. Counterparts: `agents/AGENTS.md`, `agents/triggers/AGENTS.md`, `utils/AGENTS.md`.
- Announcement: the `main.py` lifespan calls `load_announcement()`, and `cns/api/data.py` serves the cached copy inside the `preferences` block of the `?type=user` payload. Counterpart: `cns/api/AGENTS.md`.

## Rules

- Adding a deploy-settable knob takes four code edits plus the deploy writer: a `Field` in the section class that owns its domain (skip it and the override dies silently against the model's `extra='ignore'`), an entry in the matching override dict in `config_manager.py` (skip it and the env var deploy writes is never read), the read site that acts on the value — the construction or omission point where a closed flag actually leaves its subsystem out (skip it and the flag is set, deployable and inert) — and the deploy writer, the `MIRA_*` line in `deploy/finalize.sh` plus the container default in `deploy/docker/scripts/init-mira.sh`, both emitting into `/opt/mira/systemone.env` (skip those and no install ever sets it). Parsing stays strict — flags exactly `0` or `1`, counts positive integers, the systemone provider exactly `local` or `remote` — because anything else raises at import and kills boot before the POST gate, which is the point: never widen the parser to accept `true`.
- A runtime assignment to a `config.*` field is visible process-wide until restart: a probe that flips a flag to exercise a branch must restore it, and a consumer that assigns to a config field changes behavior for every concurrent user rather than only for its own call.
- Every top-level `<tag>` in `system_prompt.txt` except the blocklisted `user` and `environment` is an assessable section identifier, not markup; those two hold runtime data, so `validate_section_anchors` never accepts an anchor naming them. Renaming or removing one of the assessable tags strands stored user-model observations anchored to the old name, because `validate_section_anchors` compares candidates against the live prompt and rejects the now-invalid set at the next save. The prompt edit, the generated template examples, and the validators ship together.
- Tool config reaches the merge and the `enabled` gate only through a `*_tool`-suffixed attribute name: `AppConfig.__getattr__` routes that suffix, and any other spelling hits the `AttributeError` branch. An unregistered tool name is not an error either — `get_tool_config` fabricates a class carrying only `enabled=True`, so a typo reads as an all-defaults config that is switched on. Verify a tool's registration rather than trusting the attribute to fail.
- `*_use_days` fields are modular activity-day gates, not calendar cadences: a job fires on a user's activity days, so `1` means every active day. A new scheduled cadence is a field here plus the job that reads it — a per-user last-ran column is the drift defect `utils/AGENTS.md` rejects.
- `ApiConfig.validate_compaction_budget` takes the primary route's `max_tokens` as an argument precisely because that number lives in the database, not here: raising `MIRA_CONTEXT_WINDOW_TOKENS` or `MIRA_COMPACTION_TRIGGER_TOKENS` without checking the configured route's output reserve moves the failure from import time to model-config load, where it reads as a broken install rather than a bad setting.

Elsewhere: this map owns the setting schema, the singleton and the prompt it loads, not where the prompt templates live or where a tool's per-user config is stored. A setting's tuning history is `git log`; the field defaults, bounds, and operator-facing descriptions are the `Field` declarations in `config/config.py`; the activity-day gate a cadence feeds is `utils/scheduled_tasks.py`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## One turn's system prompt, from the file on disk

The path that makes the prompt rules above binding, traced across four directories.

1. Import time: `AppConfig.load()` calls `_load_system_prompt`, which reads `config/system_prompt.txt` by path and raises on a missing or empty-after-strip file. The text becomes the private `_system_prompt`, served as `config.system_prompt`. The process refuses to bind without it.
2. Turn entry: both `cns/api/chat.py` and `cns/api/websocket_chat.py` pass `app_config.system_prompt` down, and only `websocket_chat.py` re-checks it — it raises `RuntimeError` on an empty string, while `chat.py` has no turn-time check and leans entirely on step 1's import-time fail-fast. A prompt that a future loader makes loadable-but-empty is a turn error on the WebSocket path only, and a model call with no instructions on the HTTP path.
3. Compose request: `orchestrator._compose_llm_messages` publishes `ComposeSystemPromptEvent` carrying the string as `base_prompt` under `_compose_lock`, then reads the composed text back from the orchestrator's own instance attributes. The handler runs inline on that publish call, and a handler that fails leaves `_cached_content` as None, which makes composition raise instead of sending an empty prompt.
4. Fill: `working_memory/core.py:_handle_compose_prompt` replaces the five placeholders literally — `{first_name}` from the user's preference, falling back to `friend`; `{user_context}` from the user's portrait, not from a general context blob; `{relative time since account creation}` from the account's `created_at`; `{model_id}` and `{model_name}` from the primary route's model string and route label. Each is a `.replace()` against text loaded once, so a template placeholder and its `.replace()` call that disagree leave the literal `{placeholder}` in the prompt the model reads, every turn, with no error anywhere.
5. Compose: the personalized base goes into the composer, every registered trinket is asked for its section, and the assembled prompt returns through `SystemPromptComposedEvent`.
6. Later and independently, the same file acts as the anchor authority: `get_assessable_section_ids(config.system_prompt)` derives the top-level tags that user-model observations and Persona edits may use, which is why step 1's tag names outlive the turn and must match what the validators accept.
