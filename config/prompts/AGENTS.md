# config/prompts/ — LLM prompt templates for every model call MIRA makes

## Rules

- All prompt loading goes through `load_prompt(filename, required=True)` in `loader.py`, re-exported as `from config.prompts import load_prompt`. It enforces `.txt`-only filenames, rejects path traversal, reads UTF-8, strips whitespace, and raises `FileNotFoundError` on missing or empty files when `required=True`; `required=False` returns `""` instead (used for optional addenda: `thinking_block_instructions.txt`, `synthesis_summary_system.txt`/`_user.txt`). Never `open()` a prompt file directly.
- Naming: `{feature}_system.txt` is the system message (instructions + output contract); `{feature}_user.txt` is the user message with `{variable}` placeholders. Some prompts are a single system file with the user message built inline by the consumer (`portrait_refinement_system.txt`, `lora_refinement_system.txt`, `persona_manual_refinement_user.txt`).
- Standard templates are filled with Python `.format()`, so literal braces (JSON examples) must be doubled: `{{` / `}}`. Two consumers bypass `.format()` with plain `str.replace()` because their output contracts contain literal JSON braces: `live_context_compaction_*` (`cns/services/live_context_compaction_service.py:_build_compactor_messages` replaces `{covered_end}` and `{new_history}`) and `subcortical_user.txt` (`cns/services/subcortical.py` chains `.replace()` for `{conversation_turns}`, `{previous_memories}`, `{user_message}`). A third variant: `assessment_extraction_system.txt` carries the literal token `{{THINKING_BLOCK_INSTRUCTIONS}}` and the consumer splices it via `.replace()` only when thinking content exceeds the inclusion threshold (constant `THINKING_INCLUSION_THRESHOLD` in `cns/services/assessment_extractor.py`).
- Wrap runtime data in descriptive XML tags inside user templates (`<conversation>`, `<entity_groups>`, `<tool_output_untrusted>`, ...), never bare text. Untrusted payloads (`<tool_output_untrusted>` in `tool_result_summarization_user.txt`) carry explicit do-not-obey instructions in both system and user templates.
- `agents/` holds prompts for autonomous sidebar agents. `base_system.txt` is the shared loop-mechanics preamble (`agents/base.py:load_agent_prompt`, prepended when the agent class sets `inherit_base_prompt=True`); agent rubrics are `{agent_id}_system.txt`. The two `memory_curator_*.txt` rubrics are self-contained and run with `inherit_base_prompt = False` (`agents/implementations/memory_curator_agent.py`).
- `memory_extraction_system_qwen_experimental.txt` and `memory_extraction_system_qwen_v2.txt` are unreferenced by any loader call — dead experiments kept on disk. Do not build on them or treat their content as the live extraction contract.

## Files

- `loader.py` — single prompt-loading entry point. `load_prompt(filename, required=True) -> str`. Consumers: everywhere below; all calls are `load_prompt(...)` from `config.prompts`.
- `__init__.py` — re-exports `load_prompt` only; no other content.
- `memory_extraction_system.txt` / `memory_extraction_user.txt` — LT_Memory extraction: distills durable memories from collapsed conversation segments (shapes, entity tagging, durability filter, JSON array output). Variable: `{formatted_messages}`. Consumers: `lt_memory/processing/extraction_engine.py`.
- `segment_summary_system.txt` / `segment_summary_user.txt` — Segment collapse diarist: first-person memory trace with temporal anchoring, keyword anchors, complexity score. Variables: `{current_time}`, `{previous_summaries}`, `{conversation_text}`, `{tools_used}`. Output tags: `<mira:precis>`, `<mira:display_title>`, `<mira:complexity>`. Consumer: `cns/services/summary_generator.py`.
- `synthesis_summary_system.txt` / `synthesis_summary_user.txt` — Merges multi-chunk partial summaries into one unified memory trace; same output tags as segment summaries. Variables: `{chunk_summaries}`, `{tools_used}`. Loaded with `required=False` — absent templates disable synthesis. Consumer: `cns/services/summary_generator.py`.
- `live_context_compaction_system.txt` / `live_context_compaction_user.txt` — Active-chat continuation brief for live request shaping (see Rules for the `.replace()` contract). Variables: `{covered_end}`, `{new_history}`. The `<mira:compacted_active_context>` wrapper and the search-based recovery note are appended programmatically by `_wrap_brief()` in the consumer, not emitted by the LLM. Consumer: `cns/services/live_context_compaction_service.py`.
- `assessment_extraction_system.txt` / `assessment_extraction_user.txt` — Evaluates conversation against system-prompt sections; per-section alignment/misalignment/contextual_pass signals with evidence. Variables: `{{THINKING_BLOCK_INSTRUCTIONS}}` (system, conditional splice), `{anonymized_system_prompt}`, `{user_model_observations}`, `{section_id_list}`, `{conversation_text}`. Output tags: `<mira:assessment>`, `<mira:section>`, `<mira:signal>`; `<mira:assessment/>` when no signals. Consumer: `cns/services/assessment_extractor.py`.
- `thinking_block_instructions.txt` — Addendum spliced into the assessment system prompt when thinking traces exceed the threshold. Not a standalone prompt. Consumer: `cns/services/assessment_extractor.py` (`required=False`).
- `user_model_synthesis_system.txt` / `user_model_synthesis_user.txt` — Evolves user-model observations from assessment signals; calibration-not-restatement discipline, signal lifecycle, changelog per observation. Variables: `{current_user_model}`, `{assessment_signals}`. Output tags: `<mira:user_model>`, `<mira:observation>`, `<mira:checkin>`, `<mira:topic>`. Consumer: `cns/services/user_model_synthesizer.py`.
- `user_model_critic_system.txt` / `user_model_critic_user.txt` — Quality critic for candidate user models: observation laundering, personality labels, internal contradictions; binary PASS/FAIL. Variables: `{section_id_list}`, `{candidate_user_model}`. Output tags: `<mira:critic_review>`, `<mira:issue>`. Consumers: `cns/services/user_model_synthesizer.py` and `cns/services/lora_service.py` (shared gate for synthesized and user-instructed revisions).
- `portrait_synthesis_system.txt` / `portrait_synthesis_user.txt` — Produces the 4-5 sentence factual user portrait injected into the system prompt's user context. Variable: `{segment_summaries}`. Consumer: `cns/services/portrait_service.py`.
- `portrait_refinement_system.txt` — Minimal-change portrait revision from user instructions; user message built inline from existing portrait + instructions. No template variables. Consumer: `cns/services/portrait_service.py:refine_portrait()`.
- `subcortical_system.txt` / `subcortical_user.txt` — Pre-LLM IR stage: entity extraction, stored-passage filtering, query expansion, complexity classification. Variables: `{conversation_turns}`, `{previous_memories}`, `{user_message}` (spliced via `.replace()` — see Rules). Output tags: `<analysis>`, `<entities>`, `<relevant_passages>`, `<query_expansion>`, `<complexity>`. Consumer: `cns/services/subcortical.py`.
- `domaindoc_summary_system.txt` / `domaindoc_summary_user.txt` — One-sentence (max 100 chars) section summaries for domaindoc tables of contents; plain text. Variables: `{section_header}`, `{content}`. Consumer: `cns/services/domaindoc_summary_service.py`.
- `peanutgallery_system.txt` / `peanutgallery_user.txt` — Metacognitive observer ("Tuning Fork"): receives conversation + execution trace, emits at most one out-of-band corrective signal. Variables: `{formatted_messages}`, `{execution_trace}`. Output tags: `<mira:noop/>`, `<mira:peanutgallery type="concern|coaching|initiative">` with `<guidance>`; `severity="critical"` only for user-visible failures. Consumer: `cns/services/peanutgallery_model.py`.
- `repulsion_rewriter_system.txt` / `repulsion_rewriter_user.txt` — Register-aware rewrite removing assistant-shaped contamination from Repulsed feedback captures; preserves claims exactly, adjusts expression by register. Variables: `{user_message}`, `{ai_response}`, `{matched_tells}`. Consumer: `cns/api/actions.py` (constants `_REWRITER_SYSTEM_PROMPT_FILE`/`_REWRITER_USER_PROMPT_FILE`, runs on `model_config="primary"`).
- `persona_evaluation_system.txt` / `persona_evaluation_user.txt` — Persona pipeline: scores a collapsed segment against the behavioral contract + current Persona. Variables: `{behavioral_contract}`, `{current_persona}`, `{conversation}`. Output tags: `<mira:persona_evaluation>`, `<mira:signal>`. Consumer: `cns/services/persona_service.py:evaluate_segment()`.
- `persona_refinement_system.txt` / `persona_refinement_user.txt` — Persona pipeline: proposes a revised directive set from accumulated evaluation signals. Variables: `{current_persona}`, `{evidence}`, `{critic_feedback}`. Output tag: `<mira:persona>`. Consumer: `cns/services/persona_service.py` (automatic cadence refinement).
- `persona_manual_refinement_user.txt` — Persona pipeline: user-instruction-driven revision (`propose` action); reuses `persona_refinement_system.txt` as its system message. Variables: `{current_persona}`, `{user_instructions}`, `{critic_feedback}`. Consumer: `cns/services/persona_service.py:create_preview()`.
- `persona_critic_system.txt` / `persona_critic_user.txt` — Pass/fail gate for candidate Persona revisions before a preview or automatic revision is published. Variable: `{candidate_persona}`. Output tags: `<mira:persona_review>`, `<mira:issue>`. Consumer: `cns/services/persona_service.py:_validate_candidate()`.
- `lora_refinement_system.txt` — User-instructed revision of the user model (LoRA), mirroring the synthesis prompt's observation constraints. User message built inline; no template variables. Consumer: `cns/services/lora_service.py`.
- `tool_result_summarization_system.txt` / `tool_result_summarization_user.txt` — Hot-cache compaction of oversized tool results; JSON mode (`{"keep_indices": ..., "summary": ...}`) or text mode depending on `input_format`. Variables: `{tool_name}`, `{input_format}`, `{target_mode}`, `{target_field}`, `{tool_output}`. Consumer: `cns/services/tool_result_summarizer.py`.
- `behavioral_primer.txt` — Static synthetic dialogue (4 turns, `[role]` headers, `---` separators) injected between collapsed segment summaries and continuity messages as ambient behavioral priming. No template variables; parsed into Message objects once at init by the consumer. Consumer: `cns/core/segment_cache_loader.py`.
- `entity_merge_system.txt` / `entity_merge_user.txt` — Entity dedup judge: decides which trigram-matched entity groups are the same real-world thing and picks a canonical 8-char ID. Variable: `{groups}`. Output: JSON `{"merges": [{"canonical": ..., "merge": [...]}]}`. Consumer: `lt_memory/entity_merge.py`.
- `agents/` — five sidebar-agent prompts, no map of their own:
  - `agents/base_system.txt` — shared agent loop preamble (identity, loop mechanics, mandatory `complete_task`); prepended when `inherit_base_prompt=True`. Consumer: `agents/base.py:load_agent_prompt("base_system.txt")`.
  - `agents/forage_system.txt` — background research rubric: three-phase search protocol, exit condition requiring a Phase-2 drill, anti-hallucination discipline. Consumer: `agents/implementations/forage_agent.py`.
  - `agents/whilethecatsaway_system.txt` — curiosity-driven idle-time research: explore, store memories with `pending_id` tracking, structured completion summary. Consumer: `agents/implementations/whilethecatsaway_agent.py`.
  - `agents/memory_curator_integration.txt` — integration-mode rubric: merge / link (exact link-type vocabulary) / stand-alone decisions for newly extracted memories. Self-contained (runs with `inherit_base_prompt=False`). Consumer: `agents/implementations/memory_curator_agent.py`.
  - `agents/memory_curator_floor.txt` — floor-mode rubric: archive / salvage / leave triage for sampled low-value memories. Self-contained. Consumer: `agents/implementations/memory_curator_agent.py`.

## Wiring

- One shared contract, one documented deviation: every consumer calls `load_prompt()`; the only variable-substitution deviations are the `.replace()` consumers listed in Rules. Adding a new prompt means: create the `.txt` here, load it via `load_prompt` in the consumer, and (if the output contract contains literal JSON braces) either double the braces and use `.format()` or switch that consumer to `.replace()` — the `live_context_compaction` and `subcortical` pairs are the precedent for `.replace()`.
- `user_model_critic_*` is the only prompt pair shared across two services (`cns/services/user_model_synthesizer.py`, `cns/services/lora_service.py`); changing its variables or output tags affects both call sites.
