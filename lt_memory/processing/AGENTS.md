# lt_memory/processing/ — memory extraction pipeline: collapse-time extraction, response parsing, storage, and consolidation

Elsewhere: factory construction and the `on_memories_stored` seam — `lt_memory/AGENTS.md` · the collapse-handler side (submit path, pending-manual drain, `segment_id` from queue keys) — `cns/services/AGENTS.md` · curator context shapes — `agents/implementations/memory_curator_agent.py` · short-ID format — `utils/tag_parser.py` (root doctrine "Memory short IDs") · prompt variables and examples — `config/prompts/AGENTS.md` · full signatures — the files.

## Rules

- One execution path: `DirectExecutionStrategy.execute_extraction()` calls `generate_response(model_config="batch")` synchronously per chunk and stores through `store_and_tend_extraction()`; `create_execution_strategy()` builds only `DirectExecutionStrategy`. A deferred or remote submission layer reintroduces the divergence this shape removed.
- `store_and_tend_extraction()` is the single storage path for extraction output: embeddings + INSERT → `persist_llm_entities()` → candidate hints → the `on_memories_stored` callback. Every post-store step is tolerate-and-log — the boundary is marked extracted only after the whole call returns, and `store_memories` is a plain non-idempotent INSERT, so a post-store raise leaves the segment unmarked and the sweep's re-entry duplicates the rows.
- Every producer storing memories outside consolidation routes entity links through `persist_llm_entities()` — extraction storage and the pending-manual drain share one linking treatment (drain side owned by `cns/services/AGENTS.md`); two entity-linking paths drift.
- No typed links from extraction or storage code: the model's `related_memory_ids` + bonds reach the curator as `CandidateRef` hints (`discovery_signal: "extraction"`, merged with `LinkingService.find_candidate_hints`), never as edges; `db.create_links` has exactly two callers, both outside this flow (owned by `lt_memory/AGENTS.md`).
- Model-supplied `happens_at`/`expires_at` are the user's local wall time, parsed here — never by Pydantic. `_parse_model_temporal_field()` returns None with a diagnosable warning instead of raising (a raise aborts every memory built so far in the response — no per-memory catch exists upstream — and the model is off the call stack by then); the timezone resolves once per response, broad-except → UTC; a naive string reaching `ExtractedMemory` binds under whatever Postgres `TimeZone` is set, and the stored instant drifts by the offset difference. DST-strictness belongs to model-facing scheduling tools; extraction is lenient by design.
- `referenced_memories` in message metadata must hold full UUIDs: `_build_memory_context()` calls `UUID(ref_id)` unguarded — a short id raises; on the collapse path it fails the collapse, in the sweep it is caught per-segment and that segment never extracts. The guarantee holds by construction (`memory_tool._touch()` resolves short ids server-side); any new writer resolves through `utils/tag_parser.py`.
- A degenerate LLM response is a failure, not a zero: empty, whitespace-only, unrepairable JSON, or a non-list `memories` value raises `LLMResponseFormatError` and leaves the segment unextracted for retry — returning `[]` for garbage would mark the segment extracted and end its extraction forever. A well-formed `[]` / `{"memories": []}` is a genuine zero and marks extracted.
- Budget classification is order-fragile: `_is_content_caused_extraction_failure()` excludes `LLMResponseFormatError` before `ValueError` and `ProviderError` before `RuntimeError` (each subclasses the type it must not match) — only a missing boundary row (RuntimeError) or a no-payload chunk (ValueError) is content-caused. `extraction_attempts` is observability only; `extraction_content_failures` gates, and its exhaustion writes the operator-visible `extraction_abandoned` marker (`EXTRACTION_MAX_CONTENT_FAILURES` owned by `cns/infrastructure/continuum_repository.py`). Infra/LLM failures must never consume the budget (root doctrine "Retry Counters Never Gate Data on Infrastructure Failure").
- Everything interpolated into extraction XML is html-escaped at the interpolation point — message content into `<user>`/`<assistant>` turns, memory text into `<references_memory>` — so conversation text cannot forge turn boundaries (root doctrine "External Content Crosses One Boundary", pinned at its load-bearing site here).

## Files

- `__init__.py` — re-exports the seven `__all__` names; in-repo callers import the submodules directly, not this root.
- `orchestrator.py` — the extraction lifecycle: boundary lookup, message walk to the next boundary, single `ProcessingChunk`, context snapshot, execute, mark. Entry: `submit_segment_extraction`, `extract_unprocessed_segments`, `_build_memory_context`, `_is_content_caused_extraction_failure`. Gotcha: `segment_id` defaults to the boundary message id when the boundary metadata lacks one.
- `execution_strategy.py` — synchronous batch execution plus the storage trio. Entry: `execute_extraction`, `store_and_tend_extraction`, `persist_llm_entities`, `_build_candidate_hints`, `create_execution_strategy`. Gotcha: a chunk with an empty `user_prompt` is skipped silently; `execute_extraction` raises (content-caused) only when no chunk built a payload.
- `extraction_engine.py` — payload construction: fail-fast prompt loading, bidirectional ID maps, memory-context retrieval (snapshot first; DB fallback raises ValueError naming missing ids), XML turn formatting with `<meta>` attribution on memory-informed assistant turns. Entry: `build_extraction_payload`, `ExtractionPayload`, `_build_identifier_maps`, `_get_memory_context_for_chunk`. Gotcha: `_build_identifier_maps` raises RuntimeError on short-ID collision — impossible for real UUID v4, so a hit names a broken generator.
- `memory_processor.py` — response parsing → remap → validation → dedup → `ExtractedMemory`. Entry: `process_extraction_response`, `_parse_extraction_response`, `_remap_short_ids_to_full`, `_validate_extracted_memory`, `_is_duplicate_memory`, `sanitize_entity_list`, `_parse_model_temporal_field`, `LLMResponseFormatError`, `DEDUP_SIMILARITY_THRESHOLD`. Gotcha: write-free but not I/O-free — dedup runs a live vector search (`find_similar_for_dedup`, ≥ 0.92) after a fuzzy pass (≥ 0.95 against context texts), and timezone resolution reads preferences.
- `consolidation_handler.py` — merge execution: link-bundle transfer, affected-side rewriting, access/mention sums, provenance annotation, archive of sources. Entry: `execute_consolidation`. Gotcha: when links collapse onto one target, the most-recent `created_at` entry wins — transferred bundles and rewritten sides dedupe identically; a missing source memory raises, so no partial merge ever persists.

## Wiring

- Callers: `rg 'lt_memory\.processing'` → `lt_memory/factory.py` (construction) and `cns/services/segment_collapse_handler.py` (submit path; the pending drain's use of `persist_llm_entities`/`sanitize_entity_list`); the sweep is registered through the factory (scheduled jobs owned by `lt_memory/AGENTS.md`).
- `extract_unprocessed_segments()` iterates users with explicit contextvar set/clear per user; `submit_segment_extraction()` itself sets no context — callers must have it (the collapse path inherits HTTP context).
- Exception policy is positional: the sweep isolates per segment and per user (log-and-continue); the collapse-handler submit path propagates — a RuntimeError from a missing boundary, or the False return, fails the collapse.
- The `on_memories_stored` callback is registered by the collapse handler on the factory (seam owned by `lt_memory/AGENTS.md`), invoked None-safe after storage, and spawns `MemoryCuratorAgent` in integration mode — context shapes owned by `agents/implementations/memory_curator_agent.py`.
- Prompts: the `memory_extraction_*` pair (variables and examples — `config/prompts/AGENTS.md`); `pending_memory_entities_*` consumed by the drain-side pass (`cns/services/AGENTS.md`).
- Consolidation is reached only through `memory_tool` `merge_memories` (short ids resolved first; link rules owned by `lt_memory/AGENTS.md`).
- Inbound counterparts: the extraction content-failure budget is set by the dialect error taxonomy ↔ `clients/llm/dialects/AGENTS.md`; `Message`/`ProcessingChunk` shapes arrive from the domain model ↔ `cns/core/AGENTS.md`; the pi check-in's extraction promise lands here at collapse-time ↔ `mcp/AGENTS.md`.

## Extraction, collapse to curator

1. Collapse completes; the handler calls `submit_segment_extraction(user_id, boundary_id)` — or the sweep finds the segment via `find_failed_extraction_segments()` and bumps `extraction_attempts`.
2. Boundary row → `segment_id` (metadata or boundary id); messages walk from the boundary to the next boundary, system notifications filtered in SQL. Zero rows → warn + return False (sweep retries); rows but nothing extractable → mark extracted + return True (never retried).
3. `_build_memory_context()` collects `referenced_memories` full UUIDs (unguarded `UUID()`) and pinned short ids from message metadata; texts load now, reflecting memory state at chunk-creation time.
4. The engine builds the payload: prompts loaded fail-fast, ID maps built, messages html-escaped into `<user>`/`<assistant>` turns, `<meta>` attribution added on assistant turns that cited memories.
5. One batch call per chunk; `extract_text_content` yields the response text.
6. The processor parses (list / `{"memories": []}` / json_repair fallback; degenerate → `LLMResponseFormatError`), remaps short ids through the normalized vocabulary (case-folded, `mem_`-stripped — case-drifted echoes resolve; unresolved drop with warning), validates in-place (text ≥ 10 chars; malformed refs and entities degrade, never reject the memory), dedups (fuzzy then vector), parses temporal fields in the user's timezone, stamps `source_segment_id`.
7. `store_and_tend_extraction()`: embeddings + INSERT, then tolerate-and-log tending — entities, candidate hints, the callback.
8. Only now is the boundary marked `memories_extracted=true`. Any earlier raise leaves the segment unmarked; the sweep retries — infra/LLM failures forever, content failures until `extraction_abandoned`.
9. The callback spawns the integration-mode curator with `new_memories` and `candidate_hints`.

Ordering invariants: the mark follows the whole store call — a raise before it, and the sweep's re-entry duplicates rows; the engine's `short_to_uuid` map is the processor's remap input — reorder the payload-build → parse → store chain and the remap contract breaks.
