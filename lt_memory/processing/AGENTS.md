# lt_memory/processing/ — Memory extraction pipeline and consolidation

## Rules

- Memory extraction has exactly one execution path: `DirectExecutionStrategy.execute_extraction()` calls `LLMProvider.generate_response(model_config="batch")` synchronously per chunk and stores through `store_and_tend_extraction()`. Do not reintroduce a deferred/remote batch submission layer — `create_execution_strategy()` builds only `DirectExecutionStrategy` (`lt_memory/factory.py` wires it once at startup as `ExtractionOrchestrator.execution_strategy`).
- All LLM routing comes from `model_config='<route>'` on `generate_response()`. Extraction uses the `"batch"` route. Never pass model, endpoint, or API key explicitly.
- `store_and_tend_extraction()` (`execution_strategy.py`) is the single storage path for extraction output: stores memories with embeddings via `VectorOps.store_memories_with_embeddings`, persists LLM-extracted entities via `_persist_llm_entities()`, builds candidate hints via `_build_candidate_hints()`, then invokes the `on_memories_stored` callback (seam contract owned by `lt_memory/AGENTS.md`, Rules). Do not duplicate any of this elsewhere.
- No typed links are written by extraction/storage code. The model's `related_memory_ids` + bonds flow to the `MemoryCuratorAgent` as `CandidateRef` hints (`discovery_signal: "extraction"`, merged with deterministic hints from `LinkingService.find_candidate_hints`) — not as edges. Typed `CandidateRef`/`NewMemory` shapes are owned by `agents/implementations/AGENTS.md` (`agents/implementations/memory_curator_agent.py`); `lt_memory` never imports from `agents/`.
- `MemoryProcessor` and `ExtractionEngine` are side-effect-free: pure data transformation and payload construction. All DB writes happen in `execution_strategy.py` and `consolidation_handler.py`.
- Model-supplied temporal fields (`happens_at`/`expires_at`) are the **user's local wall time**, never UTC instants. `MemoryProcessor.process_extraction_response()` resolves the timezone once per response via `_resolve_extraction_timezone()` (broad-except → `"UTC"`: extraction is a background durability path, not fail-loud) and parses each field through `_parse_model_temporal_field()` → `ensure_utc(parse_time_string(value, tz_name=...))`. Never let a raw naive string reach `ExtractedMemory`: a naive datetime binds to `timestamptz` under whatever Postgres `TimeZone` is configured (observed four-hour drift), and a `ValidationError` at construction aborts every memory in the segment batch — no per-memory catch exists upstream. An unparseable value logs the raw value, timezone, and parser reason, and the memory is stored without that field; text is never lost. Daylight-saving strictness belongs to model-facing scheduling tools, not here.
- `extract_unprocessed_segments()` (`orchestrator.py`) sets the user contextvar per user (`set_current_user_id` / `clear_user_context`) because it runs outside HTTP context on a scheduled sweep. `submit_segment_extraction()` itself does not set context — its callers must have it set (`cns/services/segment_collapse_handler.py` does; see `utils/user_context` doctrine in root AGENTS.md).

## Files

- `orchestrator.py` — Owns the segment extraction lifecycle: query the boundary message, load messages up to the next boundary, build a single `ProcessingChunk` (segments are natural units — no chunking), attach `memory_context_snapshot` via `_build_memory_context()`, execute through the strategy, and mark `memories_extracted=true` on the boundary row. Entry points: `submit_segment_extraction()` (per-segment; raises `RuntimeError` if the boundary message is missing or yields no messages) and `extract_unprocessed_segments()` (6-hour safety-net sweep; per-segment error isolation, increments `extraction_attempts` before each attempt). `Consumers:` `cns/services/segment_collapse_handler.py` (submit path), `utils/lt_memory_jobs.py` (sweep), `utils/power_on_self_test.py`.
- `execution_strategy.py` — Owns `DirectExecutionStrategy` and the `create_execution_strategy()` factory, plus module-level `store_and_tend_extraction()` / `_persist_llm_entities()` / `_build_candidate_hints()`. `execute_extraction()` processes every chunk synchronously and returns `str` (`direct_<uuid>`), or raises `ValueError` when no chunk yielded a valid payload. `Consumers:` `lt_memory/factory.py`.
- `extraction_engine.py` — Owns `ExtractionPayload` construction: prompt loading (`config/prompts/loader.py:load_prompt` — fail-fast on missing files), bidirectional UUID shortening via `_build_identifier_maps()` (raises `RuntimeError` on short-ID collision), memory context retrieval from `ProcessingChunk.memory_context_snapshot` (DB fallback raises `ValueError` if any referenced memory is missing), and XML message formatting via `_format_chunk_for_extraction()` with `<meta>` memory attribution on assistant turns. File-local types: `ExtractionMessage`-style dicts, `ExtractionPayload`. `Consumers:` only within this directory (`execution_strategy.py`, `orchestrator.py`).
- `memory_processor.py` — Owns LLM response parsing: `json.loads` with `json_repair` fallback (`_parse_extraction_response`, raises `ValueError` if unparseable after repair), short→full UUID remapping with unresolved-ref dropping (`_remap_short_ids_to_full`), field validation/sanitization with in-place fixes (`_validate_extracted_memory`), model-supplied temporal-field parsing in the user's timezone (see Rules), and two-stage duplicate detection (`_is_duplicate_memory`: rapidfuzz ≥ 0.95 against context texts, then vector search at `DEDUP_SIMILARITY_THRESHOLD = 0.92` excluding cold-storage memories). File-local types: `DuplicateCheckResult`, `RawMemoryDict`. `Consumers:` only within this directory (`execution_strategy.py`).
- `consolidation_handler.py` — Owns memory merge execution: `execute_consolidation()` loads the full old-memory set (raises `ValueError` if any is missing), creates the consolidated memory with median importance and earliest source `source_segment_id`, transfers deduplicated inbound/outbound/entity link bundles, records the merge note as a `consolidation` annotation with `archived_source_ids`, rewrites `outbound_links` on memories that pointed at the old set, and archives the old memories. Pure business logic — no routing decisions, no LLM calls. `Consumers:` `tools/implementations/memory_tool.py` (agent-invoked `merge_memories`).
- `__init__.py` — Re-exports the five public classes (`MemoryProcessor`, `ExtractionEngine`, `ExtractionPayload`, `DirectExecutionStrategy`, `create_execution_strategy`, `ConsolidationHandler`, `ExtractionOrchestrator`) for `lt_memory/factory.py`.

## Wiring

**Extraction flow (strict order):**
`cns/services/segment_collapse_handler.py` (or the sweep) → `ExtractionOrchestrator.submit_segment_extraction()` → `DirectExecutionStrategy.execute_extraction()` → per chunk: `ExtractionEngine.build_extraction_payload()` → `generate_response(model_config="batch")` → `MemoryProcessor.process_extraction_response()` → `store_and_tend_extraction()` → `on_memories_stored` callback spawns `MemoryCuratorAgent` in integration mode. Extraction completes inline, so memories are durable before the user's next conversation. Reordering payload-build → parse → store breaks the `short_to_uuid` mapping contract between engine and processor.

**`segment_id` provenance:** `DirectExecutionStrategy` carries `str(chunk.segment_id)` from `ProcessingChunk` through `store_and_tend_extraction(segment_id=...)` so each memory gets `source_segment_id` — required for segment-scoped memory cleanup on session resume and for the curator work-item's source-segment record. The orchestrator defaults `segment_id` to `boundary_message_id` when boundary metadata lacks one.

**Contextvar boundary:** the sweep sets user context per user; the collapse-handler path inherits HTTP context. `lt_memory/factory.py` owns all component construction for this directory (`create_execution_strategy`, `ConsolidationHandler`, `ExtractionOrchestrator`).
