# lt_memory/ — storage, scoring, linking and surfacing of long-term memories

## Files

- `__init__.py` — a re-export surface no in-repo caller uses; every consumer imports `lt_memory.<submodule>`. Open it only when adding a name, and add the import with the `__all__` entry — a name in `__all__` without one fails only at the single import that asks for it.
- `db_access.py` — the storage gateway: the application's one write path for `memories` and `entities`, plus their shared read queries. Open it before changing what is written, how a score is recalculated, or which rows a caller can see.
- `models.py` — the shared row and payload shapes, including the TypedDicts that mirror the JSONB columns. Open it before adding a column, a link kind, or a payload field.
- `factory.py` — construction and lifecycle of the service graph. Open it before adding a service or reaching something off the factory.
- `vector_ops.py` — embeddings and similarity, over the install's embeddings provider and the gateway. Open it before changing which encoder a path uses or what dimensionality it assumes.
- `hybrid_search.py` — a BM25 arm and a vector arm fused by rank. Open it before tuning retrieval weights or adding an arm.
- `hub_discovery.py` — entity-anchored retrieval: the names a turn extracted, to the memories behind them. Open it before changing how a mention reaches memories.
- `linking.py` — candidate discovery for the memory curator, and link traversal for surfacing. Open it before changing what the curator is offered or how a link is followed.
- `proactive.py` — per-turn surfacing: pool fetch, merge, rerank, and the generation caps that other directories import. Open it before changing what a turn surfaces or how many memories reach the model.
- `entity_merge.py` — the background sweep that merges duplicate entities under an LLM's judgment. Open it before changing when two entities are judged duplicates or what a merge does.
- `scoring_formula.sql` — the importance formula as a SQL expression fragment. Open it before changing how importance decays or what a signal is worth.
- `processing/` — the extraction pipeline and consolidation; its own map.

## Wiring

- Surfacing: `cns/services/orchestrator.py` → `memory_relevance_service` → `proactive.search_with_embedding` → `hybrid_search.hybrid_search` and `hub_discovery.discover_hub_memories`. Every cap and threshold on that chain is imported from `proactive.py`. Two exceptions restate them as literals — `memory_relevance_service.get_relevant_memories`'s own `limit: int = 10` default, and the tool arm below — so moving a cap there changes nothing. Counterpart: `cns/services/AGENTS.md`.
- Second surfacing arm: `tools/implementations/memory_tool.py`'s search runs its own two-worker pool straight into `HybridSearcher.hybrid_search` and `HubDiscoveryService.discover_hub_memories`, bypassing `ProactiveService` with its own similarity threshold, `min_importance`, and `top_n=limit * 2`. A signature, threshold, or RRF change in either arm must reach that file, and no grep of `proactive.py` finds it. Counterpart: `tools/implementations/AGENTS.md`.
- Store: `lt_memory/processing/execution_strategy.py` → `vector_ops.store_memories_with_embeddings` → `db_access.store_memories`. This directory performs the insert; what must happen between the insert and the segment's extracted mark is the pipeline's contract, owned elsewhere. Counterpart: `lt_memory/processing/AGENTS.md`.
- Construction: the `main.py` lifespan calls `factory.get_lt_memory_factory` with all four infrastructure dependencies and later calls `factory.cleanup` at shutdown. The pre-bind self-test is a second lifecycle path: it may be the first construction call in a fresh process, passing all four dependencies too, and its teardown reaches the singleton through the module-private `_lt_memory_factory_instance` and nulls it after `cleanup()` — rename that global or change `cleanup`'s contract and the self-test teardown breaks silently. Counterpart: `utils/AGENTS.md`. A construction path bypasses the singleton altogether: `rg 'LTMemoryDB\('` finds six production sites outside the factory, each building the gateway over the shared session manager, so a gateway constructor or `_resolve_user_id` change reaches all of them. The same sites construct the other services directly — `tools/implementations/memory_tool.py` builds `HybridSearcher`, `HubDiscoveryService`, `VectorOps` and `LinkingService` — so a change to those constructors is invisible to a grep run for the gateway alone.
- Curator: `linking.find_candidate_hints` produces the candidate hints; `db_access.get_floor_candidates` is sampled by the floor trigger; the agent stamps `db_access.update_last_tended` after a run. Counterparts: `agents/implementations/AGENTS.md`, `agents/triggers/AGENTS.md`.
- Curator seam: `factory.on_memories_stored` is registered by the segment-collapse handler after construction and read None-safe once memories are stored; `lt_memory` never imports `agents/`, so this attribute is the boundary. Counterpart: `cns/services/AGENTS.md`.
- Scheduled jobs: `utils/lt_memory_jobs.py:register_lt_memory_jobs` registers the extraction sweep, the two score-recalculation sweeps, and the entity merge against `config.scheduled_jobs`. The one knob in that job set from `config.lt_memory` is the entity-merge candidate cap, read by `db_access.find_similar_entity_pairs`, not by the registration. Their job IDs are the POST contract. Counterpart: `utils/AGENTS.md`.
- Infrastructure: the encoder pairing and dimensionality contract belong to the embeddings provider — counterpart: `clients/AGENTS.md`. The tables, RLS policies, and the `global_memories_runtime` view are DDL — counterpart: `deploy/AGENTS.md`.

## Rules

- `_resolve_user_id()` is the only way a `db_access` method learns whose rows it may touch: an explicit argument, else the ambient contextvar, else `ValueError`. The exception is the two session sites in `hub_discovery`, which take no explicit `user_id` and call `get_current_user_id()` themselves. A new `db_access` method that opens its session under some other id reads zero rows under RLS, and an empty result reads to the caller as "nothing stored", not as a failure; the resolver's `ValueError` is what distinguishes a missing context from an empty result. `get_users_with_memory_enabled()` is the only method on an admin session.
- Every parameter inside `jsonb_build_object` or `jsonb_build_array` carries an explicit cast. Postgres cannot infer a type from a variadic argument, so an untyped one fails the whole statement at parse time with `IndeterminateDatatype`, before any row is touched — production entity merges no-opped exactly this way. The rule binds every new JSONB query in this directory, not only the ones in `db_access.py`.
- Activity-day snapshots are what the formula decays over, never wall time: `store_memories()` stamps both at insert and `update_access_stats()` re-stamps the last-access one. A store or access path that skips the stamp writes NULL, the formula falls back to zero, and the memory scores as old as the account — newness, recency, and access momentum collapsing at once. Two writers outside this package skip it: the four bootstrap memories `auth/database.py` inserts per new account and the same four in `deploy/prepopulate_new_user.sql` both INSERT into `memories` without either snapshot.
- One formula, five entry points: `update_access_stats`, `apply_mention_boost`, `apply_pin_boost`, `bulk_recalculate_scores`, and `recalculate_temporal_scores` all recalculate through `_recalculate_importance_scores()`, which interpolates `_SCORING_FORMULA_SQL` expecting the `m`/`u` aliases and their join. A second spelling of the formula drifts path by path. The auto-archive floor the two sweeps apply lives in `db_access.py`, not in the formula file — retune one, check the other.
- Archive is a sequence, and the hygiene rides it: `archive_memory` runs `_recount_entity_link_counts` inside the transaction, then `remove_dead_links` outside it, because that call opens its own session; both sweeps mirror the shape. `link_count` counts non-archived linked memories only, so a deletion path that skips the recount inflates every entity hub score and the link counts the merge prompt shows the model.
- SQL in this package is not confined to `db_access.py`: `hybrid_search._bm25_search` and three statements in `hub_discovery` query the same tables through `db.session_manager` directly — the exact-name and trigram `entities` matches, plus the entity-anchored `memories` read in `_get_entity_linked_memories`. A table rename, a new column, or an RLS audit that stops at the gateway leaves those four reads broken or unscoped.
- Links are written only through `create_links()`: bidirectional add-or-replace, one entry per counterparty, each row guarded against archived targets. `rg 'create_links'` names the callers. A direct UPDATE on the link arrays writes one side, and the two memories then disagree about whether the relationship exists.
- The `memories`/`global_memories_runtime` UNION in `search_similar` and `hybrid_search._bm25_search` lists its columns explicitly. A new `memories` column must land in both branches, with a typed default in the global one, or every similarity and BM25 query fails at prepare time. Global rows are operator-curated and read-only to the application: access tracking and the debut boost skip them.
- Fused results carry no embedding from the BM25 arm, and `Memory.similarity_score` means a raw cosine on the vector path but a normalized fusion score on the hybrid one. A consumer that reads `embedding` off a fused result, or applies a threshold tuned on the other path, is comparing quantities that are not the same thing.
- The generation caps — `MAX_SURFACED_MEMORIES`, `MAX_PINNED_MEMORIES`, `MIN_FRESH_MEMORIES` — are imported by `cns/services/`; `MAX_PINNED_MEMORIES` sits deliberately below `MAX_SURFACED_MEMORIES` so the pinned budget can bind while fresh slots stay open. Raising pinned past surfaced starves fresh discovery silently. `rg 'MAX_SURFACED_MEMORIES'` names the consumers.
- Every retrieval fan-out in this directory copies user context into its workers: `hybrid_search` and `proactive.search_with_embedding`. An arm that spawns a worker without the copy fails closed under RLS to zero rows, which is indistinguishable from a corpus with no matches.
- Dead, callerless repo-wide — do not build on them: `db_access.apply_pin_boost`, `db_access.get_memories_by_segment_id`, `vector_ops.update_memory_embedding`, and `LTMemoryDB.transaction()`. The pinned-boost pipeline is unwired end to end: `pinned_short_ids` is collected into `MemoryContextSnapshot` and consumed by nothing, so extraction's advertised pin boost does not happen.

Elsewhere: this map owns a memory's storage, scoring, linking and surfacing, not how a memory comes to exist and not where the tables come from — extraction is a separate concern with its own map and its own failure modes, and the tables are DDL that the deployment owns. What each scoring constant is called, and what it means, is stated in `scoring_formula.sql`; why it has the value it has is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## Importance, from store to the floor

One memory's score across its whole life — the chain no single file shows.

1. Birth. Extraction stores the extractor's default importance regardless of what the model emitted: a new memory earns its standing from behavior, not from the extractor's opinion. Browser create keeps the operator's value; consolidation takes the median of its sources. `store_memories()` stamps both activity-day snapshots here.
2. Touch. A surfaced memory bumps its access count and re-stamps its last-access activity day inside one transaction, and the same transaction recalculates it through the formula. A curator touch adds a mention. Otherwise the stored score moves only when something explicitly updates the row: a link, an annotation, a consolidation merge.
3. The formula sums five signals — access rate against a baseline with momentum decay, inbound links, weighted entity links, explicit mentions, and a newness grace — scales the sum by recency and by the nearness of `happens_at` or `expires_at`, and squashes the result through a sigmoid centered so an average memory lands mid-range. Decay runs on activity days; the temporal fields run on calendar days, because a real deadline does not pause when the user stops logging in.
4. Cold. Surfacing filters below a minimum importance, so a memory whose score has fallen into the low band stays stored and stays dedup-visible while no turn will surface it. Nothing archives it at read time.
5. Read-time adjustments. Debut boost, the supersedes penalty, and the link-type rerank reorder the pools and persist nothing; the only write a surfacing turn makes is the access tracking in step 2, so these adjustments leave no trace in the row.
6. Floor. `get_floor_candidates()` samples low-scoring memories the curator has not tended recently — or never tended, and old enough that integration never reached them — and `update_last_tended()` keeps them out of the next sample. The curator decides, not the score. A memory that arrives already below the archive floor, from a browser create or the queued drain, is invisible to both sweeps: the bulk sweep selects above that floor and the temporal sweep sees only temporal rows in its window. It never recalculates, never archives, and stays floor-eligible from birth.

Ordering invariants: the snapshots are written before anything recalculates; an access recalculates inside its own transaction, because a second connection cannot see the uncommitted update; and a sweep archives only after the recalc it scored by.
