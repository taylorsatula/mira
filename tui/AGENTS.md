# tui/ — Streaming WebSocket terminal chat client for a deployed MIRA instance

Standalone client (`python -m tui`) with a bottom-pinned input bar over native terminal scrollback. A pure client: imports nothing from the server tree except `update.py`'s stdlib-only `utils.release_identity` (shared with the server's daily release check).

## Rules

- Twin contract: `protocol.py` mirrors the frames of `cns/api/websocket_chat.py` and the history envelope of `cns/api/data.py`; `client.py:_frame_to_event` maps them to events. A server frame change lands here in the same commit; drift shows as `ProtocolError`/`UNPARSEABLE_FRAME` (strict `extra="forbid"`). Two-endpoint protocol: this map owns the client side, `cns/api/AGENTS.md` (`## WebSocket turn protocol (server side)`) owns the server side. The release-update notice is NOT a frame: it rides REST (`client.py:fetch_available_update` → `GET /v0/api/update_status`), so adding it required no change to the frame union.
- One terminal writer: while the app runs, only `screen.py:Screen.emit` writes to the terminal, in a print step that never leaves raw mode. `run_in_terminal`/`print` for chat output switches the tty to cooked mode, re-enables ECHO, and keys typed during the emit print twice. No hand-counted cursor movement — the renderer measures and erases the bar.
- One consumer: `chat.py:ChatSession.run` is the only reader of the inbox. `MiraClient` and `Screen` only post (`put`/`put_nowait`); a second reader steals items. `ChatSession._update_loop` is a third producer (it posts `UpdateChecked`), still writing only through the inbox. Handlers run strictly in order; `ChatSession` derives `Live` on read (`_live`), never keeps it in step by hand.
- A message lives in exactly one place (input box, live region, or scrollback). It reaches scrollback only in `ChatSession._on_turn_started` (the server accepted it). Every undeliverable path (`_restore_unsent`: send failure, attributed `protocol_error`, connect failure or cancel, lost connection, user halt with queued follow-ups) returns it, with queued siblings, to the box via `Screen.restore_input`. `Screen.consume_input` is the compare-and-clear that ignores a duplicate Enter.
- Display safety: every model or user string passes `text.py:sanitize` (Rich passes ESC through to the terminal), and `transcript.py` builds `Text` from plain strings, never markup. A new scrollback element goes in `transcript.py` and sanitizes there.
- MIRA's box stays open for the whole turn: everything emitted while a turn runs goes through `ChatSession._in_box` (MIRA's content; its first row carries the `:MIRA` label and sets `_Turn.opened`) or `_meta` (notices and alerts, inside the box once it is open). A plain emit mid-turn breaks the `╵` gutter. Every turn end closes the box with `transcript.mira_close()`: `_end_reply`, `_lost_connection`, `_print_remaining`. A user halt adds a `stopped` row, so a halted turn with no text still has a labelled row.
- `turn_complete.response` is displayed only when `ReplyStream.has_text` is false (`ChatSession._on_turn_complete`); otherwise the streamed lines already showed it and it prints twice. `ReplyStream.flush`/`finish` never reveal held-back text (an unclosed tag is metadata — every reply ends inside `<mira:my_emotion>` tokens, so a cut-off reply would otherwise print tag text); a reply held back entirely falls through to `response`.
- Tag-literal hazard: literal think/mira tag strings written through agent tool payloads get HTML-entity-mangled on disk. `text.py` builds them by concatenation; any new code needing them does the same and verifies on-disk bytes by execution.
- Bounded waits: constants live at the top of `client.py` (`WS_OPEN_TIMEOUT`, `SEND_TIMEOUT`, `CLOSE_TIMEOUT`, `HTTP_PAGE_TIMEOUT`, `UPDATE_STATUS_TIMEOUT`) and `chat.py` (`EMIT_TIMEOUT`, `PUMP_JOIN_TIMEOUT`, ...). The idle `await self._inbox.get()` in `ChatSession.run` is the one sanctioned unbounded await; every other await carries a bound.
- Settings have NO UI: the 0600 JSON store (`endpoints.py`) plus `--config-debug` is the interface, and `/exit` is the only command (any other `/text` is a message). Do not add interactive configuration or commands.
- Deployed instances register `/usr/local/bin/mira` — a wrapper over `python3 -m tui` on the TUI venv, cwd-independent via `PYTHONPATH=/opt/mira/app` (mechanism owned by `deploy/AGENTS.md`).

## Files

- `__init__.py` — docstring only, no re-exports.
- `__main__.py` — CLI `main()`: the `update` subcommand (dispatched BEFORE argparse — no endpoint store is loaded and no chat client starts; `tui/update.py:run_update` runs standalone), then `--config PATH`, `--config-debug` (store layout, never the api_key), `--login [--endpoint NAME | --base-url URL [--save-as NAME]] [--chat]` (exits before the chat app unless `--chat` continues into it after a successful mint); otherwise `app.run(store)`. Exit 1 on store-load failure.
- `app.py` — `run(store)`: resolves the active endpoint, checks both stdin and stdout are TTYs, connects BEFORE any UI exists (failures print `_connect_guidance` keyed on `ClientError.code`, exit 1; Ctrl+C while connecting exits 130), then hands the live client to `ChatSession`. Owns `INBOX_MAX` and `setup_guidance` (first-run text).
- `chat.py` — `ChatSession`: the turn/queue/reconnect state machine (`_handle` dispatch, `_send_next`, `_end_reply`, `_lost_connection`, `_teardown`, `_print_remaining`). Private inbox items `ConnectFailed`, `RetrySend`, `AutoReconnectDue`, `UpdateChecked` and `ScreenExited` let background tasks report to the single consumer. An attributed `TURN_BUSY` keeps the message in flight and retries (`TURN_BUSY_RETRY_DELAYS`, then every `TURN_BUSY_POLL_SECONDS`, up to `TURN_BUSY_MAX_WAIT_SECONDS`; Ctrl+C cancels) before the text returns to the box: the server sends the terminal frame before releasing its per-user lock (`cns/api/websocket_chat.py:process_turn` `finally`), and heartbeat turns hold the same lock for minutes; `AuthFailed` is ignored because every connect failure also raises out of `connect()`. Ctrl+C: halt a turn, halt-on-start for an in-flight send, cancel a connect, clear the box, else quit; a second Ctrl+C while stopping quits. Ctrl+T flips `_show_thinking`: `thinking` frames feed a second per-turn `ReplyStream` (`_Turn.thinking`) shown as `transcript.thinking_lines` and flushed/discarded at every reply-stream boundary site, tail-followed by the live region while reasoning; forward-looking only. `_load_history` replays the current segment before the bar exists (`fetch_history("session_only")` → `history.replay_blocks`); a fetch failure degrades to an alert. `_update_loop` polls `fetch_available_update` once at startup then every `UPDATE_CHECK_INTERVAL_SECONDS` (24 h), posting `UpdateChecked`; `_available_update` is rendered by `_status()` as an `alert`-tone row — deliberately last in that precedence chain, so an active turn or a lost connection keeps the row and the notice returns when it frees.
- `screen.py` — `Screen`: owns prompt_toolkit. Pinned bar (live region, rule, input box, rule), `emit`/`set_live`/`consume_input`/`restore_input`/`clear_input`/`close`, and the intents `Submit`/`Interrupt`/`Quit`/`ToggleThinking`. Enter submits; Alt+Enter or Ctrl+J inserts a newline; Ctrl+D quits on an empty box; Ctrl+T posts `ToggleThinking`; Up/Down jump the cursor to the start/end of the box text (overriding the built-in per-line movement). Scrollback blocks and `Live.pending` are Rich renderables rendered at the live terminal width (`_render` sets `console.width` each print; no `soft_wrap`); the live region renders through a second console (`_live_console`) at the same width, so a line keeps its wrap when it commits. Wrapped lines do not reflow on a later resize. Before `run()` starts or after it ends, `emit` writes direct to stdout.
- `text.py` — pure, stdlib-only: `sanitize`, `ReplyStream` (streaming think/mira-tag filter that holds back possible tag fragments, blank lines, and a leading `[5:47pm]` stamp; `breaks_before_pending` lets the live view show a held-back paragraph break ahead of the tail), `display_lines` (one-shot path through the same machinery). Gotcha: `feed` sanitizes per delta, so an escape split across deltas can leak its printable tail, never ESC.
- `transcript.py` — pure: the look of each scrollback element. Turns are open boxes in a band of five sixths of the terminal width (`_band`), word-wrapped at render time (`_wrap`: wrapped rows drop the break's leading spaces and hang under a line's indentation or list marker) so the gutter repeats on every wrapped row. `you` is the user's box (`╴╴╴╮` top-right border, `ME:` / `╵` on the right, bright magenta). `mira_rows(body, opens=)` is rows of MIRA's box (`:MIRA` label on the opening row, `╵` gutter after, bright green), `mira_close` its `╰╴╴╴` bottom border, `mira_box`/`mira_reply` a whole box (proactives, history). Body `Text`: `mira_lines` and `thinking_lines` (inline markdown applied: headings, bold, italic, code), `tool_line`, `reply_footer`, `notice`, `alert`; `banner`. A body outside a box goes through `Flow.place` (one per session, applied in `ChatSession._emit`): wrapped to the band, a blank line above when a box precedes it. Widths are terminal cells (Rich `cell_len`), never `len`. Spacing lives here only.
- `history.py` — pure: REST history rows → scrollback blocks (`replay_blocks`), reusing `transcript` elements and `text.display_lines` so replayed conversation looks like live. Assistant and tool rows sharing `metadata.turn_id` form one MIRA box (JSON content-block rows yield their `text` blocks; a tool row is a `tool_line` from `metadata.tool_name` and `is_error`; tool-count footer); sentinels and empty text skipped. History cannot recover the reasoning view or a halted turn's `stopped` row.
- `client.py` — `MiraClient`: WS auth and frame pump (`connect`, `run`, `send_message`, `send_halt`, `close`), the `ClientEvent` dataclass union, `ClientError` (sole exception). `run()` posts `Disconnected` on any unannounced close, clean or not; `connect()` resets `_closing` and `_server_shutdown_seen` so a reconnect is a fresh lifecycle, and raises the frame limit to `MAX_FRAME_BYTES` (server `tool` frames carry untruncated results; the websockets 1 MiB default closes the socket with 1009 mid-turn). `fetch_history` (REST keyset pager) is called by `ChatSession._load_history` at startup with `"session_only"`; `_fetch_history_page` is its internal, and `_is_sentinel` is also imported by `tui/history.py` for the defensive sentinel skip. `EndpointConfig.history_fetch` remains stored but unused — the startup replay is hardcoded to the current segment; summaries skipped. `fetch_available_update` is the one other REST call: it reads `GET /v0/api/update_status` and returns the newest release name only on an explicit `update_available` with a version string — every other outcome (no verdict, 404 from a server older than the route, transport failure, malformed body) returns `None`, because the notice is advisory and must never surface as a chat error.
- `protocol.py` — strict pydantic v2 mirror of all WS frames plus `parse_inbound_frame`/`dump_outbound_frame` and the REST history models. The twin of the server frames (see Rules).
- `endpoints.py` — `EndpointConfig`, `EndpointStore` (0600 JSON at `~/.config/mira-tui/config.json`), `HISTORY_FETCH_MODES`. Gotcha: the constructor does not read; callers must `store.load()`. The store's format has a second consumer: `mcp/talkto_mira.ts` reads the active endpoint (twin contract owned by `mcp/AGENTS.md`) — a format change updates both in the same commit.
- `login.py` — `--login` token bootstrap: `mint_api_token()` chains `GET /v0/auth/local/session` (404 → email magic-link flow) → `POST /v0/auth/csrf` → `POST /v0/auth/api-tokens`, mirroring `auth/api.py` (same-commit change on route drift). The token goes into the 0600 store and is never printed except the can't-write-store last resort. Live multi-mode flow is code-verified only.
- `update.py` — `mira update`: the decision half of the in-place install update. Resolves the newest published release and compares via `utils/release_identity.py` (shared with the server; importable on the TUI venv because it is stdlib-only), downloads the release tarball (bounded, `tarfile` `filter="data"`), refuses a release whose tree carries `BREAKING.md` (prints it plus the manual path — reinstall + agent-run history import), and hands the machine work to the release's own `deploy/update.sh` via subprocess — the newest release's code does the work, same doctrine as `install.sh`. `MIRA_APP_DIR`/`MIRA_TUI_VENV` env overrides flow through to the shell half so probes can run the real flow against a throwaway root; nothing on the install is touched before `deploy/update.sh` starts. Breaking-release contract owner: `deploy/AGENTS.md`.
- `requirements.txt` — the client's own pin set (websockets, httpx, pydantic, rich, prompt_toolkit); the server's `requirements.txt` gains nothing from it.
- `BUILD_PLAN.md`, `FRONTEND_PLAN.md` — historical design records (the 2026-09-18 Textual build; the 2026-09-30 streaming rebuild with its pinned contracts and event table); where they differ from the code, the code is truth.

## Wiring

- Startup: `__main__.main()` → `store.load()` → `app.run()` → `MiraClient.connect()` (bounded; `AuthOk` lands on the inbox) → `ChatSession.run()` → banner emit → history replay (the current segment's earlier messages, `_load_history` → `fetch_history("session_only")` → `history.replay_blocks`; failure degrades to an alert) → `Screen.run` and `MiraClient.run` tasks → release-check poll task (`_update_loop`) → inbox loop. Connecting before the UI keeps auth failures plain printed errors — reordering them leaves a half-drawn bar; the replay runs before the pump starts, so wire frames arriving meanwhile wait in the socket.
- Send: Enter → `Submit` → `_on_submit` → `consume_input` → outbox → `_send_next` (text shown in the live region as `sending`) → `turn_started` → the user's box in one emit → `assistant_delta` → `ReplyStream.feed` → committed lines emitted as rows of MIRA's box, tail in the live region as the same rows → `turn_complete`/`turn_stopped`/`turn_error` → `_end_reply` (last rows and the bottom border, deferred proactives, then the next queued message). One active turn per user is server-enforced (`TURN_BUSY`). A `turn_stopped` the user did not request renders `reason == "stall"` as a server-stall alert, anything else as a notice.
- Reconnect: Enter on an empty box (or a send) while disconnected → `_reconnect` → `client.close()` → `_join_pump` → `connect()` task. The old pump's `finally` clears the client connection, so the join must finish before `connect()` installs the new socket. A lost connection (`ServerShutdown` or `Disconnected` → `_lost_connection`) also starts an `_AutoReconnect` run: timers post `AutoReconnectDue` (`AUTO_RECONNECT_DELAYS`, then every `AUTO_RECONNECT_POLL_SECONDS`, up to `AUTO_RECONNECT_MAX_WAIT_SECONDS`); a stale timer is dropped by run identity; `AUTH_FAILED` or a Ctrl+C connect cancel ends the run. The point is a restart that the user never has to nudge: the session is back before MIRA's post-restart heartbeat pushes its message, and a push sent while the socket is down never arrives.
- Quit: `/exit`, Ctrl+D on an empty box, Ctrl+C on an idle empty box, or a second Ctrl+C while stopping → `_teardown` (`Screen.close` erases the bar, then the client closes, tasks joined with bounds) → `_print_remaining` prints a cut-off reply, held proactives, and unsent or unconfirmed texts as notices.
