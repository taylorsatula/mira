## Rules

- No module-level import from `cns.services` in any file on the `cns/core/__init__.py` chain (`message`, `continuum`, `state`, `events`): importing any `cns.services` module runs `cns/services/__init__.py`, which eagerly imports the orchestrator, whose module-level `from cns.core.continuum import Continuum` re-enters the mid-load package and dies on the partially-initialized `.message` — ImportError at boot. `message_formatter.py` keeps its `segment_helpers` import function-local for this reason; `segment_cache_loader.py`'s module-level import boots only because nothing in that chain imports the loader back — its module-level importers are `cns/infrastructure/continuum_pool.py` and `cns/integration/factory.py`, neither reachable from `cns/services/__init__.py`.
- `Continuum`'s `add_user_message`/`add_assistant_message`/`add_tool_history` mutate the hot cache only — a message becomes durable when the same `Message` object is staged into `UnitOfWork.add_messages` (`cns/infrastructure/continuum_pool.py`) and committed. The orchestrator stages every add except `_internal_continuation` scaffolds; `cns/api/chat.py` stages its rejection row. A new append path that skips staging shows the message until the next cache invalidation, then loses it.
- Every concrete event's `create()` resolves `user_id` from the contextvar (`utils/user_context.py:get_current_user_id`) except `SegmentTimeoutEvent.create`, which takes `user_id` as a parameter: the timeout sweep thread and the queued manual-collapse thread run outside request context — `get_current_user_id()` raises RuntimeError on a bare scheduler thread — and `cns/api/actions.py`'s manual trigger passes the explicit parameter from inside request context (`ActionsEndpoint.process_request` sets the contextvar before dispatch). `SegmentCollapseHandler.collapse_segment` re-establishes context from the event payload at entry. Design a new background-published event around one of those two shapes.
- Renaming or deleting an event class is a repo-wide same-commit edit: `EventBus.subscribe` validates the event-type string against the `ContinuumEvent` subclass walk (`cns/integration/event_bus.py:_iter_event_names`) and raises ValueError at graph construction, and subscriptions reference the name as a plain string — invisible to import tooling. Update the class, every string subscription, every `create()` site in one commit; a miss fails at boot or strands the publisher with zero subscribers.
- `Message` is frozen at the attribute layer only; `metadata` is a shared mutable dict. `with_metadata(**updates)` is the copy path (the repository stamps `content_type` through it, the loader stamps `display_mode`), and in-place metadata writes are real — `cns/services/segment_collapse_handler.py` sets the `downstream_failed` flag on a live sentinel. Two holders of one `Message` see each other's metadata writes; copy with `dict(message.metadata)` where isolation matters (the cache patcher does).
- A new `Message` field lands in the dataclass AND in `to_dict`/`from_dict`: the Valkey hot cache round-trips through exactly those two (`cns/infrastructure/valkey_message_cache.py`), so a field missing from them silently vanishes from every message at the next cache read. The repository path is unaffected — it constructs `Message` directly and reconstitutes content by the persisted `content_type` tag, never `from_dict`.
- Summary display is a three-site contract: `segment_cache_loader.py:_load_segment_summaries` stamps the ephemeral `display_mode` (`extended` tier 1, `precis` tier 2 — never persisted, carried in Valkey metadata only); `format_messages_for_api` routes on it and raises ValueError on any other value at request build; `cns/services/segment_helpers.py` renders both shapes (`format_segment_for_display`/`format_precis_for_display`, KeyError when `display_title`/`segment_start_time` are missing). A new mode or a rename touches all three in the same commit, or the turn fails at request build.
- Injected non-conversation messages carry `system_notification: True` (collapse and session markers, primer turns): the flag excludes them from segment creation (`continuum_repository.py:save_message`'s `is_real_message` check), from timestamp injection, from compaction XML, and from `UnitOfWork._get_real_messages`. A synthetic message without the flag is treated as a real turn: it triggers `_ensure_active_segment` and enters compaction ranges — the signup bootstrap's intro pair (`auth/database.py:_prepopulate_welcome_content`: the "Hi, my name is…" turn and MIRA's reply, `system_generated` only) is unflagged and counts as the account's first real turns; only the welcome-marker and system-context rows there carry the flag.

## Files

- `__init__.py` — re-exports `Message`/`Continuum`/`ContinuumState`/`ContinuumEvent`; no in-repo importer uses the package root — every caller names a submodule (`rg 'from cns\.core\.'`). Gotcha: the docstring's "no external dependencies" is stale — `message.py` imports `utils` and `clients.llm`, `segment_cache_loader.py` imports `cns.infrastructure` and `cns.services`.
- `continuum.py` — the aggregate root: `ContinuumState` plus the mutable hot cache. Entry: `create_new` (signup, via `cns/infrastructure/continuum_repository.py:create_continuum`), `apply_cache` (sole caller: the pool, miss and hit paths), `add_user_message` (sole caller: `cns/services/orchestrator.py:process_message` — takes the transport's `message_id` and turn metadata so the durable row id matches the client's optimistic id and the `turn_started` frame), `add_assistant_message` (sole caller: `cns/api/chat.py` size-limit rejection), `add_tool_history` (sole caller: orchestrator turn completion). Gotcha: uncalled today — `add_tool_message`, `discard_transient_user_message`, `Continuum.to_dict`/`from_dict` (the repository constructs `ContinuumState` directly), and the event-list returns of `add_user_message`/`add_assistant_message`/`add_tool_message` are always `[]`; do not build on the dead surface.
- `events.py` — the domain event taxonomy: frozen `ContinuumEvent` base (`continuum_id`, `user_id`, `event_id`, `occurred_at`), four category bases (`MessageEvent` and `ToolEvent` carry no concrete subclasses and no subscribers — reserved categories; the module docstring is the extension law), nine concrete events with `create()` factories. Entry: the concrete `create()` methods; subscriber sets are the named greps (`rg 'TurnCompletedEvent'`, `rg 'UpdateTrinketEvent'`, `rg 'SegmentCollapsedEvent'`, `rg 'ComposeSystemPromptEvent'`). Gotcha: `SegmentCollapsedEvent`'s docstring names ForageTrinket as a subscriber — stale: the flush is centralized in `working_memory/core.py:_flush_stateful_trinkets`, and trinkets never subscribe directly (`working_memory/trinkets/base.py`).
- `message.py` — message value objects: the `ContentBlock` union (`TextBlock`/`ImageBlock`/`DocumentBlock`/`FileRefBlock` carrying `CacheTTL`, `ToolCallBlock`, `ReasoningBlock`), `MessageMetadata` (the typed inventory of known metadata keys), frozen `Message`, and `preprocess_content_blocks` (digest text + image count; `reasoning` display text enters the digest, provider `thinking`/`redacted_thinking` never do). Entry: `Message`, `with_metadata`, `to_dict`/`from_dict`/`to_db_tuple`, `preprocess_content_blocks`. Gotcha: `_MEDIA_BLOCK_TYPES` is private yet imported across the boundary (`cns/services/assessment_extractor.py`) — grep before renaming.
- `message_formatter.py` — provider-neutral serialization: `Message` list → neutral request dicts. Entry: `format_messages_for_api`; the sole runtime caller is the visibility-filtering wrapper `cns/services/live_context_compaction_service.py:format_messages_for_api` — the orchestrator calls that wrapper, not this module.
- `segment_cache_loader.py` — new-session cache assembly: what a cache-miss session loads, and in what order. Entry: `load_session_cache`, `_select_two_tier_summaries` (tier 1 extended, complexity ≤ 4.5, max 4; tier 2 precis, max 4; 14-segment query window), `_load_behavioral_primer` (`behavioral_primer.txt` parsed once at init — `[role]` header lines, `---` separators; included only when summaries exist). Gotcha: the concat `marked_tier2 + marked_tier1` keeps the list chronological so `segment_summaries[-1]` is the newest segment — `create_session_boundary_marker` reads `[-1].segment_end_time` for the gap line; reorder and the boundary states the wrong session gap.
- `state.py` — `ContinuumState` frozen dataclass (`id`, `user_id`, `metadata`) and its `ContinuumStateDict`. Gotcha: the state round-trip (`to_dict`/`from_dict`, `Continuum.to_dict`/`from_dict`) has no caller — the repository constructs `ContinuumState` directly; dead, do not build on.

## New-session load → provider request

A cache miss in `ContinuumPool.get_or_create()` (`cns/infrastructure/continuum_pool.py`) — the cache is invalidated by segment collapse (an epoch bump in Valkey), not by a TTL — routes to `SegmentCacheLoader.load_session_cache(continuum_id, user_id)`, which re-establishes user context and queries the repository four ways: `find_collapsed_segments(limit=14)`, `load_continuity_messages(turn_count=2)`, `find_active_segment()`, then `load_segment_messages()` for the active sentinel.

Two-tier selection walks the candidates newest-first: tier 1 accumulates extended summaries while total `complexity_score` stays at or under 4.5, capped at four, with the newest segment always entering even when over the limit (the `len(tier1) > 0` guard); tier 2 continues from tier 1's stopping point, taking up to four further segments that carry a non-empty `precis`. Tier 2 entries are stamped `display_mode='precis'`, tier 1 `'extended'`, and the concatenation tier2-then-tier1 is chronological end to end.

Assembly order: collapse marker, but only when older history exists (an empty history must not claim searchable past conversations); segment summaries; primer turns, but only when summaries exist; the two continuity turns; the session boundary marker, which reads `segment_summaries[-1].segment_end_time` to state the gap; then the active segment's messages. `apply_cache` installs the list, and the pool writes it to Valkey under the captured epoch.

At turn build, `format_messages_for_api` renders that list into the neutral request: each collapsed sentinel becomes a synthetic pair — an assistant `tool_call` on `continuum_tool` (input `operation: search`, `query: display_title`, call id `seg_` plus the first 22 chars of the segment id) followed by a tool result holding the rendered summary — so past segments arrive with tool-result framing, which the model weighs above plain assistant prose. Conversational user and assistant messages gain a `[h:mm]` user-local timestamp (ephemeral, first text block only), assistant prose is wrapped into a text block, and `thinking_signatures`/`reasoning_details` pass through for the dialect round-trip.

Ordering invariants: the collapse marker precedes the summaries it announces; the boundary precedes the active messages; the chronological concat feeds the boundary's gap line — reorder any of these and the boundary reads the wrong segment's end time or the model's context starts mid-history.
