# cns/core/ — Immutable CNS domain model: aggregate root, message value objects, domain events

## Rules

- No database access, no HTTP calls, no infrastructure imports in this directory. The single permitted boundary crosser is `segment_cache_loader.py`, which imports `cns.infrastructure.continuum_repository.ContinuumRepository` — always construct it with a repository injected via the constructor (done in `cns/integration/factory.py`), never with a direct infrastructure import.
- `Message` and `ContinuumState` are `frozen=True` dataclasses. Mutations produce new objects via `Message.with_metadata()` or `from_dict()`. The `Continuum` aggregate is itself mutable — its `_message_cache` list is appended to and replaced — but its embedded `_state` is frozen.
- Domain events: subclass one of the four base categories in `events.py` (`MessageEvent`, `ToolEvent`, `WorkingMemoryEvent`, `ContinuumCheckpointEvent`), use `@dataclass(frozen=True)`, and give the subclass a `.create()` classmethod that generates `event_id`/`occurred_at` and sources `user_id` from `utils.user_context.get_current_user_id()`. Exception: `SegmentTimeoutEvent.create()` takes `user_id` as an explicit parameter because it fires from background scheduling outside request context. Do not create new categories — adapt existing ones.
- `MessageMetadata` in `message.py` is the canonical, exhaustive list of known metadata keys. Any new `Message.metadata` key must be added there as a typed field; consumers (`message_formatter.py`, segment services, the Anthropic dialect) read keys by name and an unlisted key is invisible to future readers.
- `cns.services.live_context_compaction_service.TOOL_RESULT_TRUNCATION_LIMIT` (500 chars) owns tool-result truncation for live compaction. `preprocess_content_blocks()` does NOT truncate — do not reintroduce truncation there.

## Files

- `continuum.py` — `Continuum` aggregate root. Owns the mutable message cache: `apply_cache()`, `add_user_message()`, `add_assistant_message()` (rejects blank content), `add_tool_message()`, `add_tool_history()`, `discard_transient_user_message()` (refuses any message lacking `metadata['transient_system_scaffold'] is True`). All add methods append to cache only; persistence is the orchestrator's job. `get_messages_for_api()` no longer exists here — formatting lives in `cns.services.live_context_compaction_service.format_messages_for_api` (see Wiring).
- `message.py` — `Message` frozen value object with role/content validation in `__post_init__`; `MessageMetadata` TypedDict (canonical metadata key list); `ContentBlock` union (`TextBlock`, `ImageBlock`, `DocumentBlock`, `FileRefBlock`, `ToolCallBlock`, `ReasoningBlock`); `preprocess_content_blocks()` shared preprocessing returning a `PreprocessedContent` dataclass (text parts + image count); `to_db_tuple()` for Postgres insertion. Reasoning signatures round-trip via metadata `thinking_signatures`, not via content blocks. Consumers: `preprocess_content_blocks` and `_MEDIA_BLOCK_TYPES` are imported across `cns/services/` (extraction, summarization, peanut gallery, persona, live compaction — e.g. `cns/services/assessment_extractor.py` imports `_MEDIA_BLOCK_TYPES` directly) and `lt_memory/processing/extraction_engine.py`.
- `message_formatter.py` — `format_messages_for_api()`: converts `Message` sequences to the provider-neutral request shape. Owns tool-result compaction breadcrumbs (`continuum_tool get_tool_result` framing), collapsed-segment synthetic `continuum_tool` tool_call/tool pairs routed by `display_mode`, ephemeral local-time timestamp injection (skipped for tool-call assistant and system-notification messages; for list content only the FIRST text block gets the timestamp — the `break` in the injection loop), and pass-through of `has_tool_calls`/`thinking_signatures`/`reasoning_details` metadata. Consumers: called by `cns/services/live_context_compaction_service.py` (`format_messages_for_api` method), which `cns/services/orchestrator.py` invokes.
- `state.py` — `ContinuumState` frozen dataclass + `ContinuumStateDict` TypedDict for persistence round-trips (`to_dict`/`from_dict`). Intentionally minimal — real conversation state lives in the message cache.
- `events.py` — Domain event hierarchy: `ContinuumEvent` base (`frozen=True, kw_only=True`) plus the four concrete base categories and their event subclasses, each with a `.create()` classmethod. `TurnCompletedEvent` carries the live `Continuum` object (documented race-condition rationale in its docstring) and types it under a `TYPE_CHECKING` guard to break the circular import with `continuum.py`. `ToolResultHistoryCommittedEvent` is emitted only from a `UnitOfWork` post-commit callback (`cns/services/orchestrator.py`) and carries the exact tool messages made durable in that commit; `cns/services/tool_result_summarizer.py` subscribes to it. Consumers: subscribed via `cns/integration/factory.py` event-bus registration.
- `segment_cache_loader.py` — `SegmentCacheLoader`: reconstructs message history on Valkey cache miss via `load_session_cache()`. Two-tier segment selection: Tier 1 extended summaries bounded by accumulated `complexity_score` (`SESSION_SUMMARY_COMPLEXITY_LIMIT` 4.5, max 4) from a 14-segment query window; Tier 2 up to 4 precis-only segments for broader lookback. Marks segments with ephemeral `display_mode` (`extended`/`precis`) metadata for display routing. Behavioral primer parsed once at init from `config/prompts/behavioral_primer.txt` via `config.prompts.loader.load_prompt`. Consumers: constructed in `cns/integration/factory.py`, handed to `cns/infrastructure/continuum_pool.py`.
- `__init__.py` — Re-exports `Message`, `Continuum`, `ContinuumState`, `ContinuumEvent` only.

## Wiring

- `format_messages_for_api()` reads the user's timezone via `utils.user_context.get_user_preferences()` at call time, so user context must be set before it runs; it is invoked from `cns/services/live_context_compaction_service.py`'s `format_messages_for_api` method, which `cns/services/orchestrator.py` calls.
- `message_formatter.format_messages_for_api()` imports `format_segment_for_display` and `format_precis_for_display` from `cns.services.segment_helpers` at call time (deferred import to avoid circular dependency). Changes to collapsed-segment display format must be coordinated between the two files.
- `SegmentCacheLoader` is the only file here importing from `cns.infrastructure`; it receives `ContinuumRepository` by constructor injection. It also imports segment-marker constructors from `cns.services.segment_helpers` (`create_collapse_marker`, `create_session_boundary_marker`).
- Session-cache assembly order in `load_session_cache()` is fixed: collapse marker (emitted only when older content actually exists — `segment_summaries` or continuity turns non-empty; an empty history gets no marker and must not claim a searchable past) → segment summaries (oldest-first, Tier 2 then Tier 1) → behavioral primer (only when summaries exist) → continuity turns → session boundary → active segment messages. Downstream consumers rely on `segment_summaries[-1]` being the most recent segment; reordering breaks both the boundary marker and narrative reading order.
- Event flow out of this directory: `TurnCompletedEvent` and `ToolResultHistoryCommittedEvent` are created in `cns/services/orchestrator.py` and subscribed in `cns/integration/factory.py`; the four-category taxonomy in `events.py` is the contract those registrations hang off.
