# cns/api/ — FastAPI routing layer: auth gate, input validation, delegate to services

## Rules

- Every protected route uses `Depends(get_current_user)` from `auth/api.py`. That dependency already calls `set_current_user_id()` + `set_current_user_data()` (`auth/api.py:get_current_user`), but handlers running through `BaseHandler.handle_request` still call `set_current_user_id()` inside `process_request` — keep both; the handler-side call re-establishes context in the worker-thread execution path.
- No business logic here. Handlers validate input, acquire the user request lock, call `orchestrator.process_message()` or a tool/repository, then return. Logic belongs in `cns/services/` or `tools/implementations/`.
- HTTP status mapping is owned by `main.py`, not by this directory: the global `APIError` exception handler in `main.py` maps the error *code string* to status (`NOT_FOUND`→404, `UNAUTHORIZED`→401, `FORBIDDEN`→403, `SERVICE_UNAVAILABLE`→503, `INTERNAL_ERROR`→500, `RATE_LIMIT_EXCEEDED`→429, anything else→400); `RequestValidationError`→422. Individual routers in this directory also catch `ValidationError`/`NotFoundError`/`NotImplementedError` explicitly and build `JSONResponse` bodies themselves (`actions.py`, `data.py`, `chat.py`) — when raising, rely on the global handler; only catch to build a custom envelope.
- `UserRequestLock(ttl=60)` appears twice with different scopes: module-level in `chat.py` (`_user_request_lock`, one instance shared across all HTTP requests) and per-connection in `websocket_chat.py:WebSocketChatHandler` (one per socket). Never instantiate it per-request.
- There is no billing gate in this layer. Handlers do not import `billing`, do not map HTTP 402, and do not guard optional-payment imports — access control is authentication only (`get_current_user`).
- Per-user request serialization applies to both chat transports: an HTTP chat while a WS turn is active (or vice versa) fails with `USER_CONNECTION_BUSY` / a `ValidationError` until the 60s TTL clears. This is the same `UserRequestLock` keying on `user_id`.

## Files

- `__init__.py` — Docstring only, no re-exports; router registration happens in `main.py`.
- `base.py` — Owns the response contract everything here shares: `SuccessResponse`/`ErrorResponse` dataclasses (`.to_dict()` → `{"success": ..., "data"|"error", "meta"}`), the `APIError` hierarchy (`ValidationError`, `NotFoundError`, `ServiceUnavailableError`), `create_success_response()` / `create_error_response()` / `generate_request_id()`, and `BaseHandler.handle_request()` (validate → process → success envelope; APIError → error envelope). `BaseHandler` never sets HTTP status — routers do. Consumers: every file in this directory, plus `main.py` (imports `APIError`, `create_error_response`, `generate_request_id` for global handlers).
- `chat.py` — `POST /chat`. Non-streaming HTTP chat. Owns two-tier image compression (1200px inference / 512px WebP storage via `utils/image_compression.py`), document-to-`ContentBlock` assembly, `MAX_TEXT_MESSAGE_LENGTH = 20000` rejection (persisted as an assistant message, not an error), and the module-level `_user_request_lock`. Deliberately sync (`def`, not `async def`) so Starlette runs it in a threadpool. Calls `continuum_pool.repository.increment_segment_turn()` at the boundary, then `orchestrator.process_message()` and `uow.commit()`. Opt-in `show_cost` wraps the turn in `utils.cost_accumulator` start/drain.
- `websocket_chat.py` — `WS /ws/chat`. Streaming chat; owns the full server side of the turn protocol (see Deep-dive) and `_active_connections` / `close_all_connections()` for shutdown fan-out. Consumers: `main.py` (shutdown calls `close_all_connections`); client side documented in `web/assets/javascript/AGENTS.md`.
- `actions.py` — `POST /actions` (domain-routed mutations) and `GET /tools/{tool_name}/query` (read-only tool queries, whitelisted to `QUERYABLE_TOOLS` = reminder_tool, contacts_tool). Owns all ten `BaseDomainHandler` subclasses: reminder, memory, user, contacts, domain_knowledge, continuum, lora, persona, feedback, portrait. Adding a domain = new `DomainType` member + handler class with `ACTIONS` schema + entry in `ActionsEndpoint.domain_handlers` — skip any step and the domain is rejected as unknown. `PersonaDomainHandler` is registered only when `config.system.persona_enabled`. Shared domaindocs: share actions use PostgreSQL `domaindoc_shares` + `resolve_active_user_identity()` (RLS blocks direct `users` reads); section edits on shared docs route through the owner's `UserDataManager` via `utils.domaindoc_shares.resolve_domaindoc()`. `FeedbackDomainHandler.capture_repulsion` appends to `data/users/{user_id}/repulsion_feedback/{date}.jsonl` then submits a non-critical background rewrite (`_REWRITER_MODEL_CONFIG = "primary"`, prompts `config/prompts/repulsion_rewriter_{system,user}.txt`) on `_REPULSION_REWRITER_EXECUTOR` with `contextvars.copy_context()`. `BaseDomainHandler.__init__` reads `get_current_user_id()` at construction — handlers are constructed per-request inside `ActionsEndpoint.process_request`, never at import. Consumers: UI (client side in `web/assets/javascript/AGENTS.md`).
- `data.py` — `GET /data?type=...`. Read-only access routed by `DataType` enum: HISTORY, MEMORIES, DASHBOARD, USER, DOMAINDOCS, WORKING_MEMORY, LORA, PERSONA. Owns the opaque keyset cursor (`_encode_history_cursor` / `_decode_history_cursor`): base64url JSON `{created_at, id}`; passing `offset` or `search` for history raises `ValidationError`. MEMORIES keeps offset/limit paging. DOMAINDOCS merges shared docs from other users (accepted shares, owner's SQLite read via `get_user_data_manager(share.owner_user_id)`).
- `files.py` — `GET /files/{file_id}` (attachment) and `GET /images/{file_id}` (inline). Serves `data/users/{user_id}/artifacts/{file_id}/` as `.bin` content + `.meta` sidecar (filename, media type). Security: `FILE_ID_PATTERN` regex (`^[a-zA-Z0-9_-]+$`) plus resolved-path-must-stay-within-`base_dir` check.
- `health.py` — `GET /health` is public (DB `SELECT 1` + uptime + version). `/health/threads` and `/health/thread-dump` require the Vault-backed `X-MIRA-Diagnostics-Token` header via `_require_diagnostics_token` (503 when unconfigured, 401 missing, 403 mismatch). `/health/threads` returns 503 itself when thread status is critical.
- `tool_config.py` — CRUD under `/actions/tools` for per-user tool configuration. Discovers configurable tools via `registry._registry`, delegates storage/secret redaction to `utils/tool_config_store.py`, and calls each tool's optional `validate_config()` classmethod (module import guarded — a bad tool name returns `{}` with a warning). Entry points: `list_configurable_tools`, `get_tool_config`, `get_tool_schema`, `update_tool_config`, `validate_tool_config`, `reset_tool_config`.
- `trigger_rules.py` — CRUD for per-user sidebar trigger filter rules (`GET/POST /triggers/rules`, `PUT/DELETE /triggers/rules/{rule_id}`, `GET /triggers/conflicts`). Rules live in user SQLite `trigger_rules` with optional per-rule `prompt`; validated against `_TRIGGER_FIELDS` (currently only `imap_email`: from/subject/body) and regex-compilable patterns. Conflicts read `sidebar_activity` rows with status `'conflict'`.
- `location.py` — `POST /location`. Reverse geocodes via Nominatim, fetches forecast from Open-Meteo (3h hourly + today's sun/UV; adds past-day dailies for gap days computed from `users.last_activity_date`), caches under `location:{user_id}` in Valkey (24h TTL). External-fetch failures degrade to `{"cached": False}` for the fetches themselves; the Valkey write failure propagates. WMO code map is `WMO_DESCRIPTIONS`.
- `update.py` — `GET /check_update` (local version compare via `packaging.version`) and `GET /check_remote_update` (proxies to miraos.org, browser-CORS workaround; swallows all proxy errors → `update_available: False`). No auth. Reads repo-root `VERSION` via `get_latest_version()`; logs checks to `data/update_checks.log` through a dedicated RotatingFileHandler. Consumers: `health.py` imports `get_latest_version`.
- `federation.py` — `POST /federation/deliver`. Lattice server-to-server webhook: Vault-backed `X-Lattice-Delivery-Token` header (`_require_lattice_delivery_token`: 503 unconfigured / 401 missing / 403 mismatch) plus `sender_verified=true`. Sets user context from `payload.to_user_id` and delivers via `PagerTool.deliver_federated_message` (idempotent by `external_message_id`). 400 = permanent failure, 500 = Lattice retries. Module import is `ImportError`-guarded in `main.py` — MIRA runs with federation disabled when the `lattice` package is absent.

## Wiring

- All routers are registered in `main.py` under `/v0/api` (`health`, `update`, `chat`, `data`, `actions`, `tool_config`, `trigger_rules`, `files`, `location`, `federation`), except `websocket_chat.router` at `/v0` (so the endpoint is `/v0/ws/chat`). A new router file is inert until added to `main.py:include_router` block.
- Chat flow (both transports): validate attachments → `UserRequestLock.acquire(user_id)` → `get_async_work_barrier().wait_for_user(...)` → `continuum_pool.get_or_create()` → `increment_segment_turn()` → `orchestrator.process_message(...)` → `unit_of_work.commit()`. Dropping the commit loses the turn; dropping the barrier lets background tool-result compaction race the hot continuum load.
- Shutdown ordering: `main.py` awaits `websocket_chat.close_all_connections()` during app shutdown; it sends `server_shutdown` through each connection's writer queue, then closes. Only works because each connection has exactly one writer task.
- `auth/api.py:get_current_user` is the single auth dependency; its credential ladder (Authorization header → session cookie; session → API token fallback) is documented in `auth/AGENTS.md` (### Credential ladder). `websocket_chat.py` implements its own WS ladder (`authenticate()`) because WebSockets cannot use FastAPI dependencies with HTTP semantics.
- Cross-user domaindoc reads span this directory and `utils/domaindoc_shares.py`: `actions.py` owns share *mutations*, `data.py` owns the shared-doc *read* merge; the resolver and cache invalidation live in `utils/domaindoc_shares.py`.

## WebSocket turn protocol (server side)

The client side (frame table, `Calls:`) is documented in `web/assets/javascript/AGENTS.md`; this section covers the server contract in `websocket_chat.py`.

- Frame validation: every frame is a `ProtocolModel` subclass with `ConfigDict(extra="forbid")`; inbound union is `CLIENT_FRAME_ADAPTER` (`AuthFrame | MessageFrame | HaltFrame | PingFrame`, discriminated on `type`), outbound is `SERVER_FRAME_ADAPTER` (12 frame types). A malformed inbound frame gets `protocol_error`/`MALFORMED_FRAME`, not a silent pass-through. `MessageFrame.validate_attachment_pairs` enforces image/document bodies and MIME types travel together, and never both.
- Connection ownership: `ChatConnection` spawns exactly one reader task (`_read_frames`, pushes validated frames or `ClientDisconnected` into a maxsize-32 queue) and one writer task (`_write_frames`, drains a maxsize-128 queue). Never call `websocket.receive_json()` anywhere else — a second reader silently steals frames. All sends go through `connection.send()`, which validates via `SERVER_FRAME_ADAPTER` before queuing.
- Auth: first inbound frame must be `AuthFrame` within 10s or `AUTH_TIMEOUT`. `authenticate()` ladder: frame `token` if present (session, then API token), else the `session` cookie. Success installs `set_current_user_id()` + `set_current_user_data()`, then acquires the per-connection `UserRequestLock` (`USER_CONNECTION_BUSY` on collision).
- Turn lifecycle: `message` frame → `turn_started` → stream of `assistant_delta`/`thinking`/`tool`/`model_error` → exactly one terminal frame. `_dispatch` refuses concurrent turns (`TURN_BUSY`); a `halt` frame with matching `turn_id` sets the cancel event (`set_cancel_event`/`set_cancel_reason`), and `process_turn` maps `metadata.stopped` to `turn_stopped(reason=halt|disconnect)`. Disconnect sets the same event with reason `disconnect` and, in `handle_connection`'s finally, gathers the active turn task before releasing the lock and calling `clear_user_context()`.
- Stream translation: `_server_frame_for_event` maps orchestrator events (`text`, `thinking`, `tool_event`, `model_error`) to frames; `thinking` frames are suppressed unless the client's `include_thinking` was set. `ToolFrame` payload rules are model-validated (`tool_executing` requires `arguments`, `tool_completed` requires `result`, `is_error` must match the event).
- Failure semantics: `orchestrator.process_message()` stages the user message before model work; `_process_with_orchestrator` commits pending messages even when the turn fails, so the client's message is durable, then the exception surfaces as `turn_error`. Validation failures before `turn_started` become `protocol_error`/`INVALID_MESSAGE`; after, `turn_error`/`TURN_VALIDATION_FAILED`. Provider errors are humanized by `get_friendly_error_message`.
- Thread discipline: the orchestrator runs via `run_in_threadpool(context.run, ...)` with `contextvars.copy_context()` — the user context must ride the copied context, not a closure variable.
