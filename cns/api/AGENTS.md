# cns/api/ — FastAPI routing layer and the server side of the WebSocket turn protocol

Elsewhere: mount sites, middleware, lifespan, APIError→HTTP-status mapping — root `AGENTS.md` (main.py) · orchestrator, tool loop, segment collapse — `cns/services/AGENTS.md` · Continuum model, UnitOfWork, repositories — `cns/core/AGENTS.md`, `cns/infrastructure/AGENTS.md` · signup/login/session/token endpoints — `auth/AGENTS.md` · the client side of every frame and the history envelope — `ui/tui/AGENTS.md`, `ui/browser/AGENTS.md` (frame-handling table in `ui/browser/assets/javascript/AGENTS.md`); the both-clients same-commit rule — `ui/AGENTS.md` · tool implementations and schemas — `tools/implementations/AGENTS.md` · the tool-config sentinel state machine — `utils/AGENTS.md` (`tool_config_store.py`) · the check-in design contract and its pi client — `mcp/AGENTS.md` · signatures and per-route operation tables — the files.

## Rules

- A handler that can touch blocking infrastructure (DB, Valkey, LLM, filesystem, geocode HTTP) is deliberately sync `def` so Starlette threadpools it; the WS dispatcher offloads each blocking step through `run_in_threadpool` over `contextvars.copy_context()` so RLS rides along (`chat_endpoint`, `data_endpoint`, `actions_endpoint`, `location_endpoint` docstrings). The two async routes are async by design: `websocket_chat_endpoint` (its own reader/writer tasks) and `thread_health_endpoint` (in-memory monitor reads only). An async route doing blocking work wedges the one loop pumping every socket: each concurrently-streaming turn then trips `STREAM_SEND_TIMEOUT_SECONDS` and ends `turn_stopped` reason `stall`.
- Two error channels, chosen knowingly: `BaseHandler.handle_request` folds every error into an `ErrorResponse` serialized HTTP 200 — right where a client branches on `success`; wrong where a client checks status. Real-status routes subclass `PropagatingHandler` (`base.py`) so `APIError` re-raises to `main.py:api_error_handler` (code→400/401/403/404/429/500/503; main.py owned by root `AGENTS.md`), or carry the status on the response: `response.status_code` per catch (tool_config.py, trigger_rules.py), `JSONResponse(status_code=…)` returns (health.py, actions.py `query_tool`), `HTTPException` where FastAPI's own handler assigns the status (files.py, federation.py). Mismatch the channel and a failure reads as a success, or a status lies about one.
- The per-user turn lock is one Valkey key with one TTL derivation: `user_lock:{user_id}` (prefix hardcoded in `UserRequestLock`, `utils/distributed_lock.py` — a stateless wrapper, so chat.py's module-level `_user_request_lock`, websocket_chat.py's per-connection instance, and `cns/services/segment_timeout_service.py`'s probe-only instance all address the same key), TTL `_HTTP_TURN_LOCK_TTL_SECONDS` derived once in chat.py from `(MAX_LOCAL_TOOL_CALLS_PER_TURN + 1) × max(api.timeout, provider_response_timeout) × 2`, imported by websocket_chat.py as `_TURN_LOCK_TTL_SECONDS` and probed by actions.py `is_locked`. A second TTL derivation drifts the lock window — collapse/pause under a live turn, or a turn outliving its lock and admitting a concurrent second turn on one segment.
- Turn boundaries carry the restart duty: `enter_turn()` after lock acquire, `exit_turn()` + `trigger_restart_if_pending()` after release — HTTP after the response dict is built (`chat_endpoint`), WS in `process_turn`'s finally before the terminal frame queues. Skip one and a pending `restart_mira` never fires (gauge never zero) or fires under a live turn. Mechanism owned by `utils/AGENTS.md` (`self_restart.py`).
- A failure after acceptance still commits: both transports stage the accepted user message into the UnitOfWork before model work and, when `orchestrator.process_message` raises, commit `uow.pending_messages` then re-raise (chat.py, websocket_chat.py `_process_with_orchestrator`). Drop the commit and a provider failure loses a message the client watched `turn_started` accept.
- Transport twins, same-commit: image-or-document exclusion wording identical in `ChatRequest.validate_attachment_exclusion` and `MessageFrame.validate_attachment_pairs` (pre-validator HTTP silently dropped the document); text gates deliberately divergent — WS `MAX_CONTENT_LENGTH` 100_000 vs HTTP `MAX_TEXT_MESSAGE_LENGTH` 20_000, the HTTP bound protecting synchronous-request duration, not model input. Aligning either "fixes" a deliberate difference and breaks the HTTP bound's purpose.
- `encrypted__` storage keys never cross this boundary: API payloads pass explicit per-field allowlist projections — `_project_reminder`/`_project_contact` (actions.py; also applied to `query_tool` results) — or `redact_tool_config` (tool_config.py). Tool results keep the storage keys LLM-facing (owned by `tools/implementations/AGENTS.md`); the projection is owned here. A new storage column joins a projection, or it leaks ciphertext into responses.
- An actions.py mutation that changes composed content drops the stale trinket hash field in Valkey (`{TRINKET_KEY_PREFIX}:{user_id}`): domaindoc mutations `hdel` "domaindoc" (plus the owner's `invalidate_domaindoc_cache` on shared docs), lora update/reset "behavioral_directives" (accept/decline invalidate from `cns/services/lora_service.py`), persona accept/rollback "persona_directives" (from `cns/services/persona_service.py`), skills create/delete "skills_catalog". Reminder mutations are the exception — no path drops "active_reminders", so the reminder section serves pre-write content until the next compose. Skip the drop and `data.py` `_get_working_memory` serves pre-write content between composes. Field names owned by `working_memory/trinkets/AGENTS.md`.
- Add-one (action domain): (1) `DomainType` member, (2) `BaseDomainHandler` subclass with an `ACTIONS` schema — required/optional/types; `validate_action` rejects unknown fields, (3) `ActionsEndpoint.domain_handlers` entry, (4) config-gated domains follow the persona pattern (omitted at construction when the flag is off, so a disabled install rejects the domain as unknown). Skip (2) and every action 400s; skip (3) and the domain is unknown; skip (4) and a disabled feature gains a live endpoint.

## Files

- `__init__.py` — docstring only, no re-exports; `main.py` imports the router modules directly.
- `base.py` — the response envelope + error taxonomy every router shares (also imported by `auth/api.py` and main.py's handlers). Entry: `APIError`/`ValidationError`/`NotFoundError`/`ServiceUnavailableError`, `SuccessResponse`/`ErrorResponse`/`create_error_response`, `generate_request_id`, `BaseHandler`/`PropagatingHandler`. Gotcha: `create_error_response` never serializes raw exception text — unexpected errors get fixed INTERNAL_ERROR copy with the request_id as the log correlation.
- `chat.py` — one synchronous HTTP chat turn (`POST /chat`). Entry: `ChatEndpoint.process_request`, `_user_request_lock`, `_HTTP_TURN_LOCK_TTL_SECONDS`, `_BUSY_REJECTION_MESSAGE` (imported by mcp.py — a rename breaks the MCP busy mapping), `MAX_TEXT_MESSAGE_LENGTH`. Gotcha: the oversized-message rejection persists the assistant rejection row through UnitOfWork staging but never the rejected user message — storing it would feed the text back into the history the limit protects.
- `websocket_chat.py` — WS connection and the strict turn protocol, server side. Entry: the frame models (every frame `extra="forbid"`, validated by `CLIENT_FRAME_ADAPTER`/`SERVER_FRAME_ADAPTER`), `ChatConnection` (sole socket reader/writer tasks; bounded queues 32 in / 128 out), `WebSocketChatHandler.authenticate`/`_dispatch`/`process_turn`, `close_all_connections` (main.py shutdown), `push_proactive_message_sync`. Gotcha: the proactive push seam is unwired — `rg 'push_proactive_message'` hits this file only, while both clients render `proactive_message` (counterparts `ui/tui/AGENTS.md`, `ui/browser/AGENTS.md`); a producer calling the sync bridge from a background thread re-activates it; do not build on it as exercised.
- `actions.py` — domain-routed mutations (`POST /actions`) and the whitelisted tool read surface (`GET /tools/{tool}/query`, `QUERYABLE_TOOLS` + `TOOL_QUERY_REQUIRED_KWARGS` — per-operation required args the tools' JSON schemas do not state). Entry: `ActionsEndpoint.process_request`, `DomainType`, the domain handlers (reminder, memory, user, contacts, domain_knowledge, continuum, lora, persona, feedback, portrait, skills), `_project_reminder`/`_project_contact`, `_not_found_envelope` (service preview/revision ValueErrors → 404, never the 500 catch-all). Gotcha: reminder/contacts actions pass `**data` straight to the tool's `run()` — API field names must equal tool parameter names exactly, or the drop is silent (one-term rule owned by `tools/implementations/AGENTS.md`).
- `data.py` — read surface, type-routed (`GET /data`). Entry: `DataType`, `DataEndpoint.process_request` → `_get_history`/`_get_memories`/`_get_dashboard`/`_get_user`/`_get_domains`/`_get_working_memory`/`_get_lora`/`_get_persona`/`_get_skills`, `_encode_history_cursor`/`_decode_history_cursor`. Gotcha: history is keyset-only — `before` is an opaque exclusive cursor; `offset` and `search` are rejected (removed, not deprecated: offset over a descending insert-heavy table skips/repeats rows, and search has no stable keyset to page on) while memories remain offset-paginated.
- `federation.py` — inbound Lattice webhook (`POST /federation/deliver`; mounted only when `config.lattice.enabled`). Entry: `receive_federation_delivery`, `_require_lattice_delivery_token` (Vault `lattice_delivery_token`, `secrets.compare_digest`), `FederationDeliveryPayload`. Gotcha: status is Lattice's retry contract — 4xx permanent (no retry), 5xx retried; delivery sets the recipient's contextvar, writes through `PagerTool.deliver_federated_message` (write-only entry, counterpart `tools/implementations/AGENTS.md`), clears context in finally.
- `files.py` — artifact serving (`GET /files/{file_id}`, `GET /images/{file_id}`) over the `utils/artifact_store.py` layout (`.bin` + `.meta` sidecar). Gotcha: inline rendering only for `INLINE_IMAGE_MIME_TYPES` + `nosniff`; every other stored MIME is forced to octet-stream attachment — a stored `text/html` must not execute as stored XSS. The URL shapes `/v0/api/files/{id}` and `/v0/api/images/{id}` are built by `cns/services/orchestrator.py` and `tools/implementations/imagegen_tool.py` — a path change is a cross-directory edit.
- `health.py` — public `GET /health` (status only — detail to the log; DB down → 503) and Vault-token-gated `GET /health/threads`, `GET /health/thread-dump`. Entry: `HealthEndpoint`, `_require_diagnostics_token`. Gotcha: `_PROCESS_START` is captured at import during app assembly — `uptime_seconds` is this process's age, not the host's; unauthenticated endpoints return static error bodies, never exception text.
- `heartbeat_api.py` — briefs read/cancel over `heartbeat_tool`'s per-user store (`GET /heartbeat/briefs…`, `POST …/cancel`). Gotcha: imports the tool's private `ensure_briefs_table`/`_brief_row_public` (`tools/implementations/heartbeat_tool.py`) — rename in the same commit or this breaks at import; cancel rides `HeartbeatTool().run("cancel", …)`, the tool's real entry, never direct SQL. No in-tree consumer yet — surface for the web frontend; live and auth-gated.
- `location.py` — `POST /location`: Nominatim reverse geocode + Open-Meteo forecast cached to Valkey `location:{user_id}` (TTL 86400), read by the location trinket. Gotcha: bypasses `utils/nominatim_client.py`'s process-wide 1 req/s throttle — raw `http_client.get` with its own User-Agent; gap-day weather (`past_days`) is capped at 3 from `users.last_activity_date`.
- `mcp.py` — opt-in MCP surface (`/v0/mcp` when `config.system.mcp_enabled`; SDK imported inside `mount()` so disabled mode constructs nothing MCP at boot): one `check_in` tool self-calling `POST /v0/api/chat` on this process's listener with the client's Authorization header forwarded verbatim. Entry: `mount`, `_AuthGate`, `_check_in`, `_self_call_base_url`, `_forwarded_authorization` (contextvar — per-call context, not instance state). Gotcha: `_AuthGate` accepts the header rung only — session then API token, same order as `auth/api.py:get_current_user`, never the cookie rung: a cookie session cannot ride the forwarded header to the self-call.
- `tool_config.py` — tool-config CRUD (`/actions/tools…`: list, get, schema, PUT, POST validate, DELETE reset). Entry: the six routes, `prepare_tool_config_for_validation`, `_call_tool_validation`, `ToolValidationResult`. Gotcha: `_call_tool_validation` imports the tool module directly (avoids `ToolRepository.discover_tools()` side effects) and only a true override is a live check — `validate_config.__func__ is Tool.validate_config.__func__`; the base no-op is not, and the response's `live_validation` field must keep saying so. PUT refuses `enabled=false` for `ESSENTIAL_TOOLS` (forced at startup — the write would never take effect).
- `trigger_rules.py` — CRUD for per-user sidebar trigger filter rules (`/triggers/rules…`, `/triggers/conflicts`). Valid trigger_ids and fields derive per call from `agents/triggers/registry.py:registered_trigger_specs` — no hand-maintained table; what dispatches is what is rule-addressable (dispatch-time application owned by `agents/triggers/AGENTS.md`; `trigger_rules` DDL owned by `utils/AGENTS.md`). Gotcha: a rule shape change reaches the dispatcher in the same commit — `prompt` attaches to matching work items as `context['rule_prompt']`; consumer: the browser settings page (`ui/browser/settings/index.html`).
- `update.py` — version surface: public `GET /check_update` (compares a caller-supplied version via `version_sort_key` — unparseable input declines to compare), public `GET /check_remote_update` (server-side proxy to miraos.org so browsers dodge CORS; failure → no-update), authed `GET /update_status` (cached daily verdict from `utils/update_check.py`; TUI polls at startup + every 24 h). Gotcha: the check log `data/update_checks.log` (rotating 10MB×5) scrubs the client-supplied version one-line via `_sanitize_log_field` — forgeries stay visible, no free 4xx oracle; `X-Forwarded-For` ignored (no proxy deployed).

## Wiring

- Mount topology (main.py owned by root `AGENTS.md`): health, update, chat, data, actions, tool_config, trigger_rules, files, location, heartbeat routers mount at `/v0/api`; `websocket_chat.router` at `/v0` → `/v0/ws/chat`; federation only when `config.lattice.enabled`; `mcp.mount(app)` at `/v0` only when `config.system.mcp_enabled` (session manager parked on `app.state.mcp_session_manager`, entered by main.py's lifespan); shutdown awaits `close_all_connections()` so every open client receives `server_shutdown`.
- Frame twins: a server frame change lands same-commit in `ui/tui/protocol.py` (strict mirror) and the browser WS client (`ui/browser/assets/javascript/AGENTS.md`); the both-clients rule is owned by `ui/AGENTS.md`; the `data.py` history envelope is mirrored by `ui/tui/protocol.py` (`ui/tui/AGENTS.md`).
- Lock probes outside this directory: `cns/services/segment_timeout_service.py` skips timeout-collapse for a locked user; manual collapse under the lock defers through `SegmentCollapseHandler.queue_manual_collapse`, consumed at turn completion (`cns/services/AGENTS.md`); the manual trigger is `cns/core/events.py:SegmentTimeoutEvent.create` with `inactive_duration_minutes=0`.
- Shared Valkey keys: `effort_override:{user_id}` (setex 3600) written by `UserDomainHandler`, read by `cns/services/orchestrator.py` — rename or TTL drift silently disables the override; `location:{user_id}` (ex 86400) written by location.py, read by `working_memory/trinkets/location_trinket.py` (`working_memory/trinkets/AGENTS.md`).
- Domaindoc shares: Postgres `domaindoc_shares` rows are keyed on the mutable label with no FK across the SQLite↔Postgres boundary — `delete` revokes accepted shares first or delete/recreate silently re-grants access; user lookups cross RLS only via the SECURITY DEFINER pair `resolve_active_user_identity`/`active_user_identity` (DDL `deploy/mira_service_schema.sql`, owned by `deploy/AGENTS.md`); resolver + cache owned by `utils/AGENTS.md` (`domaindoc_shares.py`); the section depth contract is twin with `tools/implementations/AGENTS.md` (domaindoc_tool).
- Tools counterparts (`tools/implementations/AGENTS.md`): the `**data` passthrough one-term rule; heartbeat_tool's private helpers; pager's write-only delivery entry; imagegen's artifact URLs; the domaindoc depth twins.
- Auth edges: every route gates through `auth/api.py:get_current_user` except the public probes (`GET /health`, `GET /check_update`, `GET /check_remote_update`), federation's Vault-token gate (`_require_lattice_delivery_token`), and the MCP surface's header-only `_AuthGate`; WS `authenticate` runs its own ladder (AuthFrame token → `session` cookie → API-token rung) and installs `set_current_user_data` so WS-originated work can call `get_current_user()`; `auth/api.py` imports the envelope from `cns.api.base` — an envelope change reaches `auth/AGENTS.md` in the same commit.
- Vault token gates via `clients/vault_client.get_service_config`: `lattice_delivery_token` (federation), `diagnostics_token` (health detail) — a missing token 503s, never skips the check.
- Skills: `SkillsDomainHandler` mutations and `data.py:_get_skills` reads ride `utils/AGENTS.md` `skill_files` (`write_user_skill`/`delete_user_skill`/`catalog_for`/`load_skill`); global skills are read-only — deleting one is a 400 misunderstanding, never a 404.
- Cost: `chat.py` `show_cost` brackets the turn with `utils/cost_accumulator.py` `start()`/`drain()`.
- Consumers by grep (projections of code, never transcribed): browser client — `rg '/v0/api' ui/browser/assets/javascript`; artifact URL shapes — `rg '/v0/api/(files|images)'` (→ `cns/services/orchestrator.py`, `tools/implementations/imagegen_tool.py`); TUI reads — `ui/tui/client.py` (`fetch_history`, `post_action`, `fetch_available_update`).
- Counterparts: the dialect error taxonomy classifies the turn failures this handler frames ↔ `clients/llm/dialects/AGENTS.md`; `repulsion_rewriter_*` prompts drive the actions rewrite pool ↔ `config/prompts/AGENTS.md`; the container `healthcheck.sh` probes `/v0/api/health` ↔ `deploy/docker/scripts/AGENTS.md`; `deploy/vm/talktomira.sh` exercises the auth/chat/health routes ↔ `deploy/vm/AGENTS.md`.

## One turn per user: the lock

1. Entry: both transports acquire `_user_request_lock` before any continuum work — HTTP synchronously in `ChatEndpoint.process_request` (before size validation, because the oversized-rejection path persists like a turn), WS via `run_in_threadpool` in `process_turn`. Failure → HTTP 400 `_BUSY_REJECTION_MESSAGE`; WS `protocol_error TURN_BUSY` carrying `message_id` so the client attributes it to the send that caused it.
2. TTL: the structural bound `(MAX_LOCAL_TOOL_CALLS_PER_TURN + 1) × max(api.timeout, provider_response_timeout) × 2` — every legal turn plus margin. Renewal at TTL/3 (`start_renewal`) keeps a live turn inside its lock; HTTP renews again just before commit, WS renews per streamed frame. The TTL is a crash backstop, not a turn-length estimate — approximating it downward lets a legal turn outlive the lock and admit a concurrent second turn on the same segment.
3. Probes: `is_locked` (key existence, TTL-irrelevant; raises when Valkey is down — fail-fast, never a false "not locked") is the shared "a turn is live" oracle over the one key: actions collapse/pause/resume import chat.py's `_user_request_lock`; `cns/services/segment_timeout_service.py` probes its own module-level instance — same hardcoded key, no cross-import.
4. Deferral mechanism: turn messages commit only at turn end, and the collapse recheck stamps `last_turn_at` at message arrival — an interleaving turn is invisible to a collapse running beside it and ends orphaned from the digest; hence collapse-under-lock defers via `queue_manual_collapse`, pause/resume refuse.
5. Release ordering (WS): the finally stops renewal, releases the lock, runs `exit_turn()` + `trigger_restart_if_pending()` — then the terminal frame queues outside the try, so a client that watched the turn end can resend immediately (earlier frames were queued while the lock held; frame order unaffected). HTTP mirrors it: release in the finally, then `trigger_restart_if_pending()` with the response dict already built — hypercorn's graceful shutdown drains the in-flight request before exit.
6. Stall: a frame send exceeding `STREAM_SEND_TIMEOUT_SECONDS` means the loop is wedged — cancel the future, `set_cancel_reason("stall")` (the user halted nothing; a wedged loop otherwise reads in the logs as users changing their minds), end the turn `turn_stopped`. Every concurrently-streaming turn trips the same probe; hunt the blocking call.
