# cns/api/ — FastAPI routing layer: auth gate, input validation, delegate to services

## Rules

- Every protected route uses `Depends(get_current_user)` from `auth/api.py`. That dependency already calls `set_current_user_id()` + `set_current_user_data()` (`auth/api.py:get_current_user`), but handlers running through `BaseHandler.handle_request` still call `set_current_user_id()` inside `process_request` — keep both; the handler-side call re-establishes context in the worker-thread execution path.
- No business logic here. Handlers validate input, acquire the user request lock, call `orchestrator.process_message()` or a tool/repository, then return. Logic belongs in `cns/services/` or `tools/implementations/`.
- HTTP status mapping is owned by `main.py`, not by this directory: the global `APIError` exception handler in `main.py` maps the error *code string* to status (`NOT_FOUND`→404, `UNAUTHORIZED`→401, `FORBIDDEN`→403, `SERVICE_UNAVAILABLE`→503, `INTERNAL_ERROR`→500, `RATE_LIMIT_EXCEEDED`→429, anything else→400); `RequestValidationError`→422. Handlers built on `PropagatingHandler` (actions, chat, data, heartbeat_api, location) let every error propagate to the `main.py` global handlers, and their routes do not catch. Two exceptions build `JSONResponse` bodies themselves: `GET /tools/{name}/query`, and the `health.py` routes (`HealthEndpoint` keeps `BaseHandler`'s envelope and the route maps an `ErrorResponse` to 503).
- `UserRequestLock(ttl=_HTTP_TURN_LOCK_TTL_SECONDS)` appears twice: module-level in `chat.py` (`_user_request_lock`, one instance shared across all HTTP requests) and as a `WebSocketChatHandler` instance attribute importing the same constant. The TTL is derived from the structural max turn length (steps × max provider timeout × margin — see `chat.py`), not a short fixed value: after acquire, every transport starts background renewal (`start_renewal`, cadence TTL/3, stopped before release) so a legal turn can never outlive its lock; the TTL is a crash backstop. Never instantiate it per-request.
- There is no billing gate in this layer. Handlers do not import `billing`, do not map HTTP 402, and do not guard optional-payment imports — access control is authentication only (`get_current_user`).
- Per-user request serialization is per-turn on every chat transport: `acquire()` returns a lock token (None = contention), `release(token)` is an atomic compare-and-delete (a mismatched token — expired and re-acquired by another owner — is a logged no-op), and turns keep the token alive both by background renewal (`start_renewal` at acquire, cadence TTL/3) and spot `renew()` calls (WS: on streaming events; HTTP: before commit), so the TTL is only a crash backstop. Contention fails the request: HTTP `ValidationError` (400), WS `protocol_error`/`TURN_BUSY` with the frame's `message_id`. A second browser authenticates normally; heartbeat can fire while a browser sits idle-open.

## Files

- `__init__.py` — Docstring only, no re-exports; router registration happens in `main.py`.
- `base.py` — Owns the response contract everything here shares: `SuccessResponse`/`ErrorResponse` dataclasses (`.to_dict()` → `{"success": ..., "data"|"error", "meta"}`), the `APIError` hierarchy (`ValidationError`, `NotFoundError`, `ServiceUnavailableError`), `create_success_response()` / `create_error_response()` / `generate_request_id()`, `BaseHandler.handle_request()` (validate → process, errors converted to an `ErrorResponse` envelope — kept only by `health.py`), and `PropagatingHandler`, the variant that logs and re-raises so `main.py`'s global exception handlers assign the real HTTP status. Every other class a route calls `handle_request` on subclasses `PropagatingHandler` — never convert an error to an `ErrorResponse` return in those. (`actions.py`'s `BaseDomainHandler` family extends `BaseHandler` but is dispatched through `execute_action` inside `ActionsEndpoint`, never through `handle_request`.) Consumers: every file in this directory, plus `main.py` (imports `APIError`, `create_error_response`, `generate_request_id` for global handlers).
- `chat.py` — `POST /chat`. Non-streaming HTTP chat. Owns two-tier image compression (1200px inference / 512px WebP storage via `utils/image_compression.py`), document-to-`ContentBlock` assembly, `MAX_TEXT_MESSAGE_LENGTH = 20000` rejection (persisted as an assistant message, not an error, inside the user request lock so it is ordered with in-flight turns), and the module-level `_user_request_lock`. Deliberately sync (`def`, not `async def`) so Starlette runs it in a threadpool. Calls `continuum_pool.repository.increment_segment_turn()` at the boundary, then `orchestrator.process_message()` and `uow.commit()`. A failure after the user message is staged commits the pending rows before re-raising, so the client's message is durable (chat.py failure path; WS equivalent in the Deep-dive). Opt-in `show_cost` wraps the turn in `utils.cost_accumulator` start/drain.
- `websocket_chat.py` — `WS /ws/chat`. Streaming chat; owns the full server side of the turn protocol (see Deep-dive) and `_active_connections` / `close_all_connections()` for shutdown fan-out. Also owns `ProactiveMessageFrame` (`proactive_message`: server-initiated assistant message for heartbeat breakout turns) and `push_proactive_message(user_id, ...)`, which fans out to a user's open connections by the `user_id` stamped on `ChatConnection` after auth; consumers: `cns/services/heartbeat_service.py`. Consumers: `main.py` (shutdown calls `close_all_connections`). The client side of these frames is owned by `tui/AGENTS.md`.
- `heartbeat_api.py` — `POST /v0/api/heartbeat/{cancel|resume|status}`: external control for the heartbeat wake cycle, backed by `cns/services/heartbeat_service.py`. Cancel sets a Valkey `heartbeat:paused:{user_id}` latch (survives restarts because `heartbeat:` is in main.py's flush whitelist) and signals the in-flight turn's cancel event; resume clears the latch; status reports latch, config, in-flight state, and recent decisions.
- `actions.py` — `POST /actions` (domain-routed mutations) and `GET /tools/{tool_name}/query` (read-only tool queries, whitelisted to `QUERYABLE_TOOLS` = reminder_tool, contacts_tool). Owns all eleven `BaseDomainHandler` subclasses: reminder, memory, user, contacts, domain_knowledge, continuum, lora, persona, feedback, portrait, skills. Adding a domain = new `DomainType` member + handler class with `ACTIONS` schema + entry in `ActionsEndpoint.domain_handlers` — skip any step and the domain is rejected as unknown. `PersonaDomainHandler` is registered only when `config.system.persona_enabled`. The user domain also owns `set/get/clear_effort_override`, the writer of the Valkey `effort_override:{user_id}` key cited by `cns/services/AGENTS.md`. Shared domaindocs: share actions use PostgreSQL `domaindoc_shares` + `resolve_active_user_identity()` (RLS blocks direct `users` reads); section edits on shared docs route through the owner's `UserDataManager` via `utils.domaindoc_shares.resolve_domaindoc()`. The skills domain (create/delete of `data/users/{user_id}/skills/*/SKILL.md`) delegates all file mechanics to `utils/skill_files.py` (the sanctioned path, which also clears the empty-dir negative cache on create) and after every write hdel's the stale `skills_catalog` field from the `trinkets:{user_id}` Valkey hash; global skills are read-only — deleting one is a 400 (`GlobalSkillReadOnlyError`), never a 404. `FeedbackDomainHandler.capture_repulsion` appends to `data/users/{user_id}/repulsion_feedback/{date}.jsonl` then submits a non-critical background rewrite (`_REWRITER_MODEL_CONFIG = "batch"`, `effort="high"`, prompts `config/prompts/repulsion_rewriter_{system,user}.txt`; batch keeps rewrites off the single local llama-server slot so they cannot evict the chat KV cache) on `_REPULSION_REWRITER_EXECUTOR` with `contextvars.copy_context()`. `BaseDomainHandler.__init__` reads `get_current_user_id()` at construction — handlers are constructed per-request inside `ActionsEndpoint.process_request`, never at import. Memory domain deletes follow one convention: `delete` and `bulk_delete` validate UUIDs at entry (400 on malformed) and 404 when any id is missing — no partial deletes, no phantom success. Consumers: the browser UI that called this was removed; no in-tree client today (the skills domain exists for the future skills UI).
- `data.py` — `GET /data?type=...`. Read-only access routed by `DataType` enum: HISTORY, MEMORIES, DASHBOARD, USER, DOMAINDOCS, WORKING_MEMORY, LORA, PERSONA, SKILLS. Owns the opaque keyset cursor (`_encode_history_cursor` / `_decode_history_cursor`): base64url JSON `{created_at, id}`; passing `offset` or `search` for history raises `ValidationError`. MEMORIES keeps offset/limit paging. DOMAINDOCS merges shared docs from other users (accepted shares, owner's SQLite read via `get_user_data_manager(share.owner_user_id)`). SKILLS lists the merged catalog (user + boot-cached global, each entry `source`-tagged) or, with `name=`, returns one skill with its body (user names winning on collision; global skills surfaced read-only).
- `files.py` — `GET /files/{file_id}` (attachment) and `GET /images/{file_id}` (inline). Serves `data/users/{user_id}/artifacts/{file_id}/` as `.bin` content + `.meta` sidecar (filename, media type). Security: `FILE_ID_PATTERN` regex (`^[a-zA-Z0-9_-]+$`) plus resolved-path-must-stay-within-`base_dir` check. `/images` never trusts the stored MIME for inline rendering: only whitelisted image types (`INLINE_IMAGE_MIME_TYPES`) keep inline disposition; everything else serves as `application/octet-stream` with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff` (a provider-supplied MIME must not become stored XSS). Both routes send `Cache-Control: no-store` (authenticated per-user bytes must never be cacheable by a shared intermediary) and are plain `def` handlers (Starlette threadpools the filesystem syscalls off the event loop).
- `health.py` — `GET /health` is public (DB `SELECT 1` + uptime + version). `/health` and the two diagnostics endpoints report status only in failure bodies — never `str(e)` of an infrastructure exception (DB/Vault/DNS detail would leak to unauthenticated callers); the full exception goes to the log. Any DB-layer failure marks the component `unhealthy` → 503 `SYSTEM_UNHEALTHY`. `/health/threads` and `/health/thread-dump` require the Vault-backed `X-MIRA-Diagnostics-Token` header via `_require_diagnostics_token` (503 when unconfigured, 401 missing, 403 mismatch). `/health/threads` returns 503 itself when thread status is critical.
- `tool_config.py` — CRUD under `/actions/tools` for per-user tool configuration. Discovers configurable tools via `registry._registry`, delegates storage/secret redaction to `utils/tool_config_store.py`, and calls each tool's optional `validate_config()` classmethod (module import guarded — a bad tool name returns `{}` with a warning). `update_tool_config` REJECTS `enabled=false` for any `ESSENTIAL_TOOLS` entry with a clear error before any write — a setting that can never take effect must not save. Entry points: `list_configurable_tools`, `get_tool_config`, `get_tool_schema`, `update_tool_config`, `validate_tool_config`, `reset_tool_config`.
- `trigger_rules.py` — CRUD for per-user sidebar trigger filter rules (`GET/POST /triggers/rules`, `PUT/DELETE /triggers/rules/{rule_id}`, `GET /triggers/conflicts`). Rules live in user SQLite `trigger_rules` with optional per-rule `prompt`; validated against `_TRIGGER_FIELDS` (currently only `imap_email`: from/subject/body) and regex-compilable patterns. Conflicts read `sidebar_activity` rows with status `'conflict'`.
- `location.py` — `POST /location`. Reverse geocodes via Nominatim, fetches forecast from Open-Meteo (3h hourly + today's sun/UV; adds past-day dailies for gap days computed from `users.last_activity_date`), caches under `location:{user_id}` in Valkey (24h TTL). External-fetch failures degrade to `{"cached": False}` for the fetches themselves; the Valkey write failure propagates. WMO code map is `WMO_DESCRIPTIONS`.
- `update.py` — `GET /check_update` (local version compare via `packaging.version`) and `GET /check_remote_update` (proxies to miraos.org, browser-CORS workaround; swallows all proxy errors → `update_available: False`). No auth. `get_client_ip()` returns the socket peer address only — `X-Forwarded-For` is deliberately ignored (client-controlled header; no proxy is deployed). The client-supplied `version` param is scrubbed (`_sanitize_log_field`: control chars visibly escaped, one physical line) before it reaches `data/update_checks.log` via the dedicated RotatingFileHandler. Reads repo-root `VERSION` via `get_latest_version()`. Consumers: `health.py` imports `get_latest_version`.
- `federation.py` — `POST /federation/deliver`. Lattice server-to-server webhook: Vault-backed `X-Lattice-Delivery-Token` header (`_require_lattice_delivery_token`: 503 unconfigured / 401 missing / 403 mismatch) plus `sender_verified=true`. Sets user context from `payload.to_user_id` and delivers via `PagerTool.deliver_federated_message` (idempotent by `external_message_id`). 400 = permanent failure, 500 = Lattice retries. Module import is `ImportError`-guarded in `main.py` — MIRA runs with federation disabled when the `lattice` package is absent.

## Wiring

- All routers are registered in `main.py` under `/v0/api` (`health`, `update`, `chat`, `data`, `actions`, `tool_config`, `trigger_rules`, `files`, `location`, `federation`), except `websocket_chat.router` at `/v0` (so the endpoint is `/v0/ws/chat`). A new router file is inert until added to `main.py:include_router` block.
- Chat flow (both transports): validate attachments → `UserRequestLock.acquire(user_id)` → token (None = contention, reject) → `get_async_work_barrier().wait_for_user(...)` → `continuum_pool.get_or_create()` → `increment_segment_turn()` → `orchestrator.process_message(...)` → tokenized lock renewal (WS: per streaming event; HTTP: pre-commit) → `unit_of_work.commit()` → `UserRequestLock.release(user_id, token)` (compare-and-delete). Dropping the commit loses the turn; dropping the barrier lets background tool-result compaction race the hot continuum load.
- Shutdown ordering: during app shutdown `main.py` awaits `websocket_chat.close_all_connections()`; this directory's side of the contract is that `websocket_chat.py` exports `close_all_connections()` and that each `ChatConnection` has exactly one writer task — the fan-out sends `server_shutdown` (with machine-readable `code: "SERVER_SHUTDOWN"` — the client rejects active callbacks on `data.code`) through each connection's writer queue, drains (2s timeout per connection), then closes. A second writer per connection would race the drain and clients would never receive the shutdown frame.
- `auth/api.py:get_current_user` is the single auth dependency: the token source is the `Authorization` header, falling back to the `session` cookie; a header token is validated as a session first, then as an API token, while a cookie token is session-only. Cookie-sourced requests on unsafe methods additionally require the `X-CSRF-Token` header (`auth/api.py:_requires_cookie_csrf`). Both `set_current_user_id()` and `set_current_user_data()` are installed by the dependency. The full ladder is owned by `auth/AGENTS.md` (### Credential ladder); `websocket_chat.py:WebSocketChatHandler.authenticate()` implements its own WS ladder (auth-frame `token` wins — session then API token — else the `session` cookie) because WebSockets cannot use FastAPI dependencies with HTTP semantics.
- Cross-user domaindoc reads span this directory and `utils/domaindoc_shares.py`: `actions.py` owns share *mutations*, `data.py` owns the shared-doc *read* merge; the resolver and cache invalidation live in `utils/domaindoc_shares.py`.

## WebSocket turn protocol (server side)

The client side of the frames is owned by `tui/AGENTS.md`; this section covers the server contract in `websocket_chat.py`.

- Frame validation: every frame is a `ProtocolModel` subclass with `ConfigDict(extra="forbid")`; inbound union is `CLIENT_FRAME_ADAPTER` (`AuthFrame | MessageFrame | HaltFrame | PingFrame`, discriminated on `type`), outbound is `SERVER_FRAME_ADAPTER` (12 frame types). A malformed inbound frame gets `protocol_error`/`MALFORMED_FRAME`, not a silent pass-through. `MessageFrame.validate_attachment_pairs` enforces image/document bodies and MIME types travel together, and never both.
- Connection ownership: `ChatConnection` spawns exactly one reader task (`_read_frames`, pushes validated frames or `ClientDisconnected` into a maxsize-32 queue; a non-JSON frame gets `protocol_error`/`MALFORMED_FRAME` and the reader continues) and one writer task (`_write_frames`, drains a maxsize-128 queue, `send_json` wrapped in a 15s send timeout — a stalled socket stops the writer). Never call `websocket.receive_json()` anywhere else — a second reader silently steals frames. All sends go through `connection.send()`, which validates via `SERVER_FRAME_ADAPTER` then `put_nowait`s — send is non-blocking; a full queue means a dead client, so it drops the frame, sets `accepts_output = False`, and cancels the writer (a dropped terminal frame would leave a client promise pending forever).
- Auth: first inbound frame must be `AuthFrame` within 10s or `AUTH_TIMEOUT`. `authenticate()` ladder: frame `token` if present (session, then API token), else the `session` cookie. Success installs `set_current_user_id()` + `set_current_user_data()`; authentication holds no lock — the per-turn `UserRequestLock` is acquired at the top of `process_turn`.
- Turn lifecycle: `message` frame → `turn_started` → stream of `assistant_delta`/`thinking`/`tool`/`model_error` → exactly one terminal frame. `_dispatch` refuses concurrent turns (`TURN_BUSY`) with the inbound frame's `message_id` so the client can attribute it; `protocol_error` frames carry an optional `message_id` (present on `TURN_BUSY`/`NO_MATCHING_ACTIVE_TURN`) for attribution before `turn_started` exists. a `halt` frame with matching `turn_id` (and optional `message_id`) sets the cancel event (`set_cancel_event`/`set_cancel_reason`), and `process_turn` maps `metadata.stopped` to `turn_stopped(reason=halt|disconnect)`. Disconnect sets the same event with reason `disconnect` and, in `handle_connection`'s finally, gathers the active turn task before calling `clear_user_context()`; the per-turn lock is released in `process_turn`'s own finally, tokenized.
- Stream translation: `_server_frame_for_event` maps orchestrator events (`text`, `thinking`, `tool_event`, `model_error`, `context_reset`) to frames; `thinking` frames are suppressed unless the client's `include_thinking` was set. `context_reset` (emitted by the orchestrator's overflow retry/terminal-fallback branches before regenerating) tells the client to discard the turn's streamed-so-far text so the retried attempt renders as the single response. `ToolFrame` payload rules are model-validated (`tool_executing` requires `arguments`, `tool_completed` requires `result`, `is_error` must match the event).
- Failure semantics: `orchestrator.process_message()` stages the user message before model work; `_process_with_orchestrator` commits pending messages even when the turn fails, so the client's message is durable, then the exception surfaces as `turn_error`. Validation failures before `turn_started` become `protocol_error`/`INVALID_MESSAGE`; after, `turn_error`/`TURN_VALIDATION_FAILED`. Provider errors are humanized by `get_friendly_error_message`. A `validate_session` infrastructure failure during the WS handshake (e.g. Valkey unreachable) emits `protocol_error`/`AUTH_UNAVAILABLE` before the socket closes — never a silent drop.
- Thread discipline: the orchestrator runs via `run_in_threadpool(context.run, ...)` with `contextvars.copy_context()` — the user context must ride the copied context, not a closure variable.
