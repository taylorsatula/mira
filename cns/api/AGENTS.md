# cns/api/ — the HTTP and WebSocket request boundary

## Files

- `__init__.py` — package marker only; nothing is defined or re-exported here.
- `base.py` — the response envelope, the error taxonomy, and the two handler bases the handler-backed routers inherit. Open it before deciding how a new route reports failure.
- `chat.py` — one synchronous HTTP chat turn. Open it before changing turn-lock acquisition, the attachment gates, or where a pending restart fires on the HTTP path.
- `websocket_chat.py` — the socket, every frame model, and the server side of the turn protocol. Open it before touching a frame shape, the reader and writer tasks, or the streamed-frame timeout.
- `actions.py` — domain-routed mutations plus the whitelisted tool query surface. Open it before adding an action domain, mutating a domaindoc, or moving a value across the storage boundary.
- `data.py` — the read surface, one `_get_*` per `DataType`. Open it before adding a read or changing history pagination.
- `federation.py` — the inbound Lattice delivery webhook, mounted only when federation is enabled. Open it before changing what Lattice's retry contract sees.
- `files.py` — artifact download and inline image serving. Open it before changing a stored artifact's headers or URL shape.
- `health.py` — the public health probe and the token-gated thread diagnostics. Open it before changing what liveness requires of the database.
- `heartbeat_api.py` — brief inspection and cancellation over the heartbeat tool's store. Open it before changing a brief state name or the cancel path.
- `location.py` — coordinates in, geocode and forecast cached for the location trinket. Open it before changing the cached payload's shape or TTL.
- `mcp.py` — the single-tool MCP surface that self-calls the chat endpoint. Open it before touching MCP auth, the self-call URL, or the busy mapping.
- `tool_config.py` — tool-configuration CRUD with schema and live validation. Open it before changing how a config write or a validation result is reported.
- `trigger_rules.py` — CRUD for sidebar trigger filter rules. Open it before changing a rule's shape or the fields a rule may match.
- `update.py` — the version compared against this instance and the cached server-side verdict. Open it before changing what a client is told about updates.

## Wiring

- Mount topology: main.py mounts these routers at `/v1/api`, with `websocket_chat.router` at `/v1`, `mcp.mount` at `/v1` behind `config.system.mcp_enabled`, and federation behind `config.lattice.enabled`; shutdown awaits `close_all_connections`. A router that stops being mounted takes its routes out of service with no import error; counterpart: `AGENTS.md` at the repo root.
- MCP session manager: `mcp.mount` also parks its session manager on `app.state.mcp_session_manager`, and main.py's lifespan enters it through a `getattr` because a mounted sub-app receives no lifespan events. Renaming that attribute is a silent no-op — startup skips, the sub-app stays mounted, and `/v1/mcp` fails only when a client calls it; counterpart: `mcp/AGENTS.md`.
- Turn handoff: `chat_endpoint` and `websocket_chat_endpoint` each open a UnitOfWork, call `orchestrator.process_message`, and commit it themselves. The commit belongs to the transport, never to the orchestrator — a transport that stops committing loses the ability to persist an accepted message whose generation failed. `process_message` is `cns/services/AGENTS.md`; the UnitOfWork's open, staging and commit with its post-commit callbacks are `cns/infrastructure/AGENTS.md`.
- Live sentinel: `actions.py`'s session-status, pause, resume and collapse actions call `find_active_segment`, `load_segment_messages`, `pause_segment` and `unpause_segment`, and compare `sentinel.metadata["status"]` against the literal `"paused"`. Those status values and the repository methods are shared vocabulary, so a change to either breaks the settings page's pause and resume from this directory with no error; counterpart: `cns/infrastructure/AGENTS.md`.
- Auth gate: the routes that resolve an identity do it through `auth/api.py:get_current_user`. Four route families run their own gate instead — the socket through `websocket_chat.py:WebSocketChatHandler.authenticate` (auth-frame token, then session cookie, then issued API token), `health.py`'s `GET /health/threads` and `GET /health/thread-dump` through `_require_diagnostics_token`, federation through its Vault token, and MCP through its header-only `_AuthGate` — and three probes are public (`GET /health`, `GET /check_update`, `GET /check_remote_update`). `auth/api.py` imports the envelope from `cns.api.base`, so an envelope change reaches `auth/AGENTS.md` in the same commit.
- Frame protocol: every frame this path emits is mirrored by `ui/tui/protocol.py` and by the browser client's WebSocket layer, and the `data.py` history envelope is mirrored too. The rule that both clients change in the same commit is owned by `ui/AGENTS.md`; the frame-handling table is `ui/browser/assets/javascript/AGENTS.md`.
- MCP surface: `mcp.py`'s `check_in` tool rides `POST /v1/api/chat` rather than reimplementing a turn, and imports `_BUSY_REJECTION_MESSAGE` from `chat.py` to key its busy mapping. A rename on either side breaks the mapping with no error; counterpart: `mcp/AGENTS.md`.
- Tool boundary: `actions.py` passes action data straight into `run()` and projects tool results back onto API field names; the tool side of that contract is `tools/implementations/AGENTS.md`. `tool_config.py` reaches further into the same layer: `_get_configurable_tools` enumerates the registry's private `_registry` map and the essential-tool rule imports `tools.repo.ESSENTIAL_TOOLS`, so a rename of either returns an empty configurable-tool list rather than an error; counterpart: `tools/AGENTS.md`.
- Trigger registry: `trigger_rules.py` derives valid trigger ids and matchable fields per request from `agents/triggers/registry.py:registered_trigger_specs`, so what dispatches is exactly what a rule can address; counterpart: `agents/triggers/AGENTS.md`.
- Shared Valkey keys: `effort_override:{user_id}` written by `UserDomainHandler` and read by the orchestrator, and `location:{user_id}` written here and read by `working_memory/trinkets/location_trinket.py`. A rename or a TTL drift disables the feature on both sides with no error anywhere; counterparts: `cns/services/AGENTS.md` and `working_memory/trinkets/AGENTS.md`.
- Domaindoc shares: rows are keyed on the mutable label with no foreign key across the SQLite and Postgres boundary, so `delete` revokes accepted shares before deleting the document — otherwise deleting and recreating the same label silently re-grants prior collaborators. Cross-user email lookup crosses RLS only through the SECURITY DEFINER pair `resolve_active_user_identity`/`active_user_identity`; the resolver and its cache are `utils/AGENTS.md`.
- Vault token gates: `lattice_delivery_token` and `diagnostics_token` come from `clients/vault_client.get_service_config`, and a token that is not configured returns 503 rather than skipping the check; `clients/AGENTS.md`.

## Rules

- Every route that can touch blocking infrastructure is deliberately sync `def`, so Starlette runs it on a threadpool. The two async routes are `websocket_chat_endpoint`, which owns its reader and writer tasks, and `thread_health_endpoint`, which reads in-memory monitors only. An async route that blocks wedges the single loop pumping every socket: every concurrent streaming turn then trips `STREAM_SEND_TIMEOUT_SECONDS` and ends `turn_stopped` with reason `stall`, which reads in the logs as users changing their minds.
- Choose the failure channel per route and keep it. Three channels are in force. Handler-backed routers subclass `PropagatingHandler`, where `APIError` is re-raised to main.py's status mapping; `BaseHandler.handle_request` instead returns the failure as an `ErrorResponse` body, and `health.py`'s `HealthEndpoint` is the only `BaseHandler` here — its route turns that body into a 503. The injected-Response routes (`tool_config.py`, `trigger_rules.py`) are plain functions with no handler base: each catch builds the envelope itself and sets `response.status_code`. The direct-response routes set their own status too — `health.py`'s probes and `actions.py`'s `query_tool` return a `JSONResponse(status_code=...)`, while `files.py` and `federation.py` raise `HTTPException`. A route on the wrong channel reports a failure as a success, or a status code the server never assigned.
- Both turn boundaries carry the restart duty: `enter_turn()` after the lock is acquired, then `exit_turn()` and `trigger_restart_if_pending()` after it is released. Skip it and a pending `restart_mira` either never fires, because the in-flight gauge never reaches zero, or fires under a live turn. Mechanism owner: `utils/AGENTS.md`.
- A failure after a message is accepted still commits it. Both transports stage the accepted user message into the UnitOfWork before any model work and commit `pending_messages` when the orchestrator raises, then re-raise. Dropping that commit loses a message the client watched `turn_started` accept.
- `encrypted__` storage keys never cross this boundary. Every payload is one of three explicit paths: a per-field projection in the domaindoc handlers and `data.py:_get_domains`, whose rows arrive decrypted from `db._decrypt_dict` or `db.select` and are rebuilt field by field — `data.py`'s docstring states why reading the raw cursor with `fetchall` would bypass it; the `_project_reminder`/`_project_contact` projections, also applied to `query_tool` results; or `redact_tool_config`/`strip_secret_fields`. A new storage column joins one of them or it ships ciphertext to clients — including a new domaindoc section field, which is added where the domaindoc rows are projected.
- An `actions.py` mutation that changes composed content drops the stale trinket hash field in `{TRINKET_KEY_PREFIX}:{user_id}`: domaindoc mutations drop `domaindoc`, lora update and reset drop `behavioral_directives`, skills create and delete drop `skills_catalog`. Persona is not one of them — `accept_preview` and `rollback` clear `persona_directives` inside `persona_service._invalidate_cache`, never from this layer. Reminder mutations are the known exception — no path drops `active_reminders`, so that section serves pre-write content until the next compose. Field names are owned by `working_memory/trinkets/AGENTS.md`.
- Adding an action domain is four coordinated edits: a `DomainType` member; a `BaseDomainHandler` subclass declaring an `ACTIONS` schema of required, optional and typed fields, which `validate_action` enforces against unknown and missing fields; an entry in `ActionsEndpoint.domain_handlers`; and, for a config-gated domain, the persona pattern of omitting the entry at construction when the flag is off. Skip the schema and every action in the domain 400s; skip the registry entry and the domain is unknown; skip the gate and a disabled feature gains a live endpoint.

Elsewhere: this map owns the request boundary — which route answers, what is validated at the edge, how failure is reported, and the order a turn starts and ends — not what happens inside a turn, and not where anything is stored. The Continuum aggregate is `cns/core/AGENTS.md`. Which client code calls which path is a grep, not a list: `rg '/v1/api' ui/browser/assets/javascript`. Every other destination this directory reaches is an edge — see `## Wiring`.

## The per-user turn lock

One Valkey key governs several of the Rules above: what a turn holds while it runs, and what a collapse, a pause, or a second message has to respect.

1. `UserRequestLock` is a stateless wrapper over `user_lock:{user_id}`, so `chat.py`'s module-level `_user_request_lock`, `websocket_chat.py`'s per-connection instance and `cns/services/segment_timeout_service.py`'s probe-only instance all address the same key without sharing an object.
2. The TTL is derived once, in `chat.py`, as the structural worst-case turn rather than an estimate of one, and `websocket_chat.py` imports it as `_TURN_LOCK_TTL_SECONDS`. Renaming or re-deriving it on one transport drifts the window between them.
3. Both transports acquire before any continuum work — HTTP synchronously and before size validation, because the oversized-message rejection persists a message like a real turn; the socket through `run_in_threadpool`. Refusal is HTTP 400 with `_BUSY_REJECTION_MESSAGE`, and on the socket a `protocol_error` with code `TURN_BUSY` carrying `message_id`, so the client can attribute it to the send that caused it.
4. `start_renewal` refreshes at TTL/3 for as long as the turn lives, so the TTL is a crash backstop and never the turn's own deadline. HTTP renews once more just before its commit; the socket renews per streamed frame.
5. `is_locked` is key existence, ignoring TTL, and it raises when Valkey is down: a failed probe refuses the operation instead of answering "not locked". `actions.py`'s collapse, pause and resume import `chat.py`'s instance to ask it.
6. A collapse inside that window would orphan the turn. Turn messages commit only at turn end, and the collapse recheck stamps `last_turn_at` at message arrival, so a turn interleaving with a collapse is invisible to it and ends outside the digest. Collapse therefore queues through `SegmentCollapseHandler.queue_manual_collapse` and runs at turn completion, while pause and resume refuse outright.
7. Release order on the socket is: stop renewal, release the lock, `exit_turn()` and `trigger_restart_if_pending()`, and only then queue the terminal frame. Releasing after the frame leaves a window where the client's next message bounces `TURN_BUSY` against a turn it had already watched complete.
