# cns/api/ — FastAPI routing layer: auth gate, input validation, delegate to services

## Rules

- Every protected route uses `Depends(get_current_user)` from `auth/api.py`. That dependency already calls `set_current_user_id()` + `set_current_user_data()` (`auth/api.py:get_current_user`), but handlers running through `BaseHandler.handle_request` still call `set_current_user_id()` inside `process_request` — keep both; the handler-side call re-establishes context in the worker-thread execution path.
- No business logic here. Handlers validate input, acquire the user request lock, call `orchestrator.process_message()` or a tool/repository, then return. Logic belongs in `cns/services/` or `tools/implementations/`.
- HTTP status mapping is owned by `main.py`, not by this directory: the global `APIError` exception handler in `main.py` maps the error *code string* to status (`NOT_FOUND`→404, `UNAUTHORIZED`→401, `FORBIDDEN`→403, `SERVICE_UNAVAILABLE`→503, `INTERNAL_ERROR`→500, `RATE_LIMIT_EXCEEDED`→429, anything else→400); `RequestValidationError`→422. Handlers built on `PropagatingHandler` (actions, chat, data, heartbeat_api, location) let every error propagate to the `main.py` global handlers, and their routes do not catch. Two exceptions build `JSONResponse` bodies themselves: `GET /tools/{name}/query`, and the `health.py` routes (`HealthEndpoint` keeps `BaseHandler`'s envelope and the route maps an `ErrorResponse` to 503).
- `UserRequestLock(ttl=_HTTP_TURN_LOCK_TTL_SECONDS)` appears twice: module-level in `chat.py` (`_user_request_lock`, one instance shared across all HTTP requests) and as a `WebSocketChatHandler` instance attribute importing the same constant. The TTL is derived from the structural max turn length (steps × max provider timeout × margin — see `chat.py`), not a short fixed value: after acquire, every transport starts background renewal (`start_renewal`, cadence TTL/3, stopped before release) so a legal turn can never outlive its lock; the TTL is a crash backstop. Never instantiate it per-request.
- There is no billing gate in this layer. Handlers do not import `billing`, do not map HTTP 402, and do not guard optional-payment imports — access control is authentication only (`get_current_user`).
- Per-user request serialization is per-turn on every chat transport: `acquire()` returns a lock token (None = contention), `release(token)` is an atomic compare-and-delete (a mismatched token — expired and re-acquired by another owner — is a logged no-op), and turns keep the token alive both by background renewal (`start_renewal` at acquire, cadence TTL/3) and spot `renew()` calls (WS: on streaming events; HTTP: before commit), so the TTL is only a crash backstop. Contention fails the request: HTTP `ValidationError` (400), WS `protocol_error`/`TURN_BUSY` with the frame's `message_id`. A second browser authenticates normally; heartbeat can fire while a browser sits idle-open.

## Wiring

- All routers are registered in `main.py` under `/v0/api` (`health`, `update`, `chat`, `data`, `actions`, `tool_config`, `trigger_rules`, `files`, `location`, `federation`), except `websocket_chat.router` at `/v0` (so the endpoint is `/v0/ws/chat`). A new router file is inert until added to `main.py:include_router` block. The one non-router mount on the `/v0` surface: `mcp.py`'s sub-app is mounted at `/v0` by `main.py` inside the `config.system.mcp_enabled` flag branch (final path `/v0/mcp`, its session manager entered in lifespan); the web UI's `/assets` StaticFiles mount is the one other mount in the app.
- Chat flow (both transports): validate attachments → `UserRequestLock.acquire(user_id)` → token (None = contention, reject) → `get_async_work_barrier().wait_for_user(...)` → `continuum_pool.get_or_create()` → `increment_segment_turn()` → `orchestrator.process_message(...)` → tokenized lock renewal (WS: per streaming event; HTTP: pre-commit) → `unit_of_work.commit()` → `UserRequestLock.release(user_id, token)` (compare-and-delete). Dropping the commit loses the turn; dropping the barrier lets background tool-result compaction race the hot continuum load.
- Shutdown ordering: during app shutdown `main.py` awaits `websocket_chat.close_all_connections()`; the MCP session manager's task group (`app.state.mcp_session_manager`) closes after all other shutdown steps; this directory's side of the contract is that `websocket_chat.py` exports `close_all_connections()` and that each `ChatConnection` has exactly one writer task — the fan-out sends `server_shutdown` (with machine-readable `code: "SERVER_SHUTDOWN"` — the client rejects active callbacks on `data.code`) through each connection's writer queue, drains (2s timeout per connection), then closes. A second writer per connection would race the drain and clients would never receive the shutdown frame.
- `auth/api.py:get_current_user` is the single auth dependency: the token source is the `Authorization` header, falling back to the `session` cookie; a header token is validated as a session first, then as an API token, while a cookie token is session-only. Cookie-sourced requests on unsafe methods additionally require the `X-CSRF-Token` header (`auth/api.py:_requires_cookie_csrf`). Both `set_current_user_id()` and `set_current_user_data()` are installed by the dependency. The full ladder is owned by `auth/AGENTS.md` (### Credential ladder); `websocket_chat.py:WebSocketChatHandler.authenticate()` implements its own WS ladder (auth-frame `token` wins — session then API token — else the `session` cookie) because WebSockets cannot use FastAPI dependencies with HTTP semantics.
- Cross-user domaindoc reads span this directory and `utils/domaindoc_shares.py`: `actions.py` owns share *mutations*, `data.py` owns the shared-doc *read* merge; the resolver and cache invalidation live in `utils/domaindoc_shares.py`.

## WebSocket turn protocol (server side)

The client side of the frames is owned by `tui/AGENTS.md`; this section covers the server contract in `websocket_chat.py`.

- Frame validation: every frame is a `ProtocolModel` subclass with `ConfigDict(extra="forbid")`; inbound union is `CLIENT_FRAME_ADAPTER` (`AuthFrame | MessageFrame | HaltFrame | PingFrame`, discriminated on `type`), outbound is `SERVER_FRAME_ADAPTER` (14 frame types). A malformed inbound frame gets `protocol_error`/`MALFORMED_FRAME`, not a silent pass-through. `MessageFrame.validate_attachment_pairs` enforces image/document bodies and MIME types travel together, and never both.
- Connection ownership: `ChatConnection` spawns exactly one reader task (`_read_frames`, pushes validated frames or `ClientDisconnected` into a maxsize-32 queue; a non-JSON frame gets `protocol_error`/`MALFORMED_FRAME` and the reader continues) and one writer task (`_write_frames`, drains a maxsize-128 queue, `send_json` wrapped in a 15s send timeout — a stalled socket stops the writer). Never call `websocket.receive_json()` anywhere else — a second reader silently steals frames. All sends go through `connection.send()`, which validates via `SERVER_FRAME_ADAPTER` then `put_nowait`s — send is non-blocking; a full queue means a dead client, so it drops the frame, sets `accepts_output = False`, and cancels the writer (a dropped terminal frame would leave a client promise pending forever).
- Auth: first inbound frame must be `AuthFrame` within 10s or `AUTH_TIMEOUT`. `authenticate()` ladder: frame `token` if present (session, then API token), else the `session` cookie. Success installs `set_current_user_id()` + `set_current_user_data()`; authentication holds no lock — the per-turn `UserRequestLock` is acquired at the top of `process_turn`.
- Turn lifecycle: `message` frame → `turn_started` → stream of `assistant_delta`/`thinking`/`tool`/`model_error` → exactly one terminal frame. `_dispatch` refuses concurrent turns (`TURN_BUSY`) with the inbound frame's `message_id` so the client can attribute it; `protocol_error` frames carry an optional `message_id` (present on `TURN_BUSY`/`NO_MATCHING_ACTIVE_TURN`) for attribution before `turn_started` exists. a `halt` frame with matching `turn_id` (and optional `message_id`) sets the cancel event (`set_cancel_event`/`set_cancel_reason`), and `process_turn` maps `metadata.stopped` to `turn_stopped(reason=halt|disconnect)` — whichever phase the turn was in when the cancel landed, because the orchestrator converts every cancellation to stopped-turn semantics and journal-logs it (owner: `cns/services/AGENTS.md`). Disconnect sets the same event with reason `disconnect` and, in `handle_connection`'s finally, gathers the active turn task before calling `clear_user_context()`; the per-turn lock is released in `process_turn`'s own finally, tokenized.
- Stream translation: `_server_frame_for_event` maps orchestrator events (`text`, `thinking`, `tool_event`, `model_error`, `context_reset`) to frames; `thinking` frames are suppressed unless the client's `include_thinking` was set. `context_reset` (emitted by the orchestrator's overflow retry/terminal-fallback branches before regenerating) tells the client to discard the turn's streamed-so-far text so the retried attempt renders as the single response. `ToolFrame` payload rules are model-validated (`tool_executing` requires `arguments`, `tool_completed` requires `result`, `is_error` must match the event).
- Failure semantics: `orchestrator.process_message()` stages the user message before model work; `_process_with_orchestrator` commits pending messages even when the turn fails, so the client's message is durable, then the exception surfaces as `turn_error`. Validation failures before `turn_started` become `protocol_error`/`INVALID_MESSAGE`; after, `turn_error`/`TURN_VALIDATION_FAILED`. Provider errors are humanized by `get_friendly_error_message`. A `validate_session` infrastructure failure during the WS handshake (e.g. Valkey unreachable) emits `protocol_error`/`AUTH_UNAVAILABLE` before the socket closes — never a silent drop.
- Thread discipline: the orchestrator runs via `run_in_threadpool(context.run, ...)` with `contextvars.copy_context()` — the user context must ride the copied context, not a closure variable.
