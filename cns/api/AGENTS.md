# cns/api/ — FastAPI routing layer: auth gate, input validation, delegate to services

## Rules

- Every protected route uses `Depends(get_current_user)` from `auth.api`. Set `set_current_user_id(user_id)` immediately inside the handler — before any service call. No exceptions.
- No business logic here. Handlers validate input, acquire the distributed lock if needed, call `orchestrator.process_message()` or a repository, then return. Logic belongs in `cns/services/` or tools.
- All responses go through `create_success_response()` / `create_error_response()` from `base.py`. HTTP status codes map: 400 → `ValidationError`, 404 → `NotFoundError`, 503 → `ServiceUnavailableError`, 500 → unhandled.
- `UserRequestLock(ttl=60)` is module-level in `chat.py` — one lock instance shared across requests. Do not instantiate per-request.
- There is no billing gate in this layer. Handlers do not import from `billing`, do not map HTTP 402, and do not guard optional-payment imports — access control is authentication only (`get_current_user`).

## Files

- `base.py` — Owns `SuccessResponse`, `ErrorResponse`, `APIResponse`, `ErrorDetail`, `ResponseMeta`, the `APIError` hierarchy, `BaseHandler`, `create_success_response()`, and `create_error_response()`. All other files in this directory import from here.
- `chat.py` — `POST /chat`. Non-streaming HTTP chat. Owns two-tier image compression (1200px inference / 512px WebP storage) and document-to-`ContentBlock` assembly before handing to `orchestrator.process_message()`.
- `websocket_chat.py` — `WebSocket /ws/chat` (`/v0/ws/chat`). Streaming chat on the strict turn protocol: every frame in both directions validates against a Pydantic protocol model that forbids unknown fields; exactly one reader task and one writer task own the socket. First frame is `AuthFrame` (`{"type":"auth","token":...}`); `authenticate()` walks the credential ladder — validated session (cookie or token) → issued API token → and only under `MIRA_AUTH_MODE=single` the process-global bearer key resolving `app.state.single_user_id`. Each turn ends in exactly one of `turn_complete` / `turn_stopped` / `turn_error`; a client `halt` frame ends the active turn with `turn_stopped` and the orchestrator persists the partial turn in provider-step order.
- `actions.py` — `POST /actions`. Domain-routed mutations via `DomainType` enum and `BaseDomainHandler` subclasses (reminder, memory, user, contacts, domain_knowledge, continuum, lora, persona, feedback, portrait). Also owns `GET /tools/{tool_name}/query`. New domains require a handler class extending `BaseDomainHandler` and registration in `ActionsEndpoint`. `PersonaDomainHandler` (`persona`) evaluates MIRA against the behavioral contract: `current`/`history` read append-only revisions, `propose` stores a validated candidate in Valkey under an opaque `preview_id`, `approve`/`discard` consume it, `rollback` re-appends a historical revision. The domain is registered only when `config.system.persona_enabled` — a disabled install rejects `persona/*` as an unknown domain. `DomainKnowledgeDomainHandler` supports shared domaindocs via `domaindoc_shares` PostgreSQL table — share actions (`share`, `unshare`, `accept_share`, `reject_share`, `list_shares`, `list_pending_shares`, `list_shared_with_me`) use PostgreSQL; section edit actions on shared docs route through owner's `UserDataManager` via `utils.domaindoc_shares.resolve_domaindoc()`. `FeedbackDomainHandler` handles `feedback.capture_repulsion`: writes click records to `data/users/{user_id}/repulsion_feedback/{date}.jsonl`, then starts a non-critical background rewrite using `model_config="primary"` (`_REWRITER_MODEL_CONFIG`) and `config/prompts/repulsion_rewriter_{system,user}.txt`.
- `data.py` — `GET /data?type=...`. Read-only access routed by `DataType` enum (HISTORY, MEMORIES, DASHBOARD, USER, DOMAINDOCS, WORKING_MEMORY, LORA, PERSONA). HISTORY pages backwards with an opaque keyset cursor (`before`); passing `offset` for history raises `ValidationError`. MEMORIES keeps `offset`/`limit` paging. DOMAINDOCS type includes shared docs from other users (accepted shares via `domaindoc_shares` table) alongside personal docs.
- `files.py` — `GET /files/{file_id}` (download) and `GET /images/{file_id}` (inline). Serves `data/users/{user_id}/artifacts/{file_id}/`. Security: `FILE_ID_PATTERN` regex + resolved-path-must-stay-within-base-dir check. `.meta` sidecar provides filename and media type.
- `health.py` — `GET /health` is public. `/health/threads` and `/health/thread-dump` require the Vault-backed diagnostics token header. Owned by `ThreadMonitor` and `ScheduledTaskMonitor`.
- `tool_config.py` — CRUD for per-user tool configuration. Discovers configurable tools via `registry._registry`, stores non-secret config via `UserCredentialService`, stores schema-marked secret fields separately, and redacts secret fields in all responses.
- `trigger_rules.py` — CRUD for per-user sidebar trigger filter rules (`GET/POST /triggers/rules`, `PUT/DELETE /triggers/rules/{rule_id}`, `GET /triggers/conflicts`). Settings-tier config for what triggers sidebar agents. Rules stored in user SQLite `trigger_rules` table with optional per-rule `prompt` for agent instructions, validated against `_TRIGGER_FIELDS` (known trigger types and valid fields). Conflicts endpoint reads `sidebar_activity` records with status `'conflict'` for UI display.
- `location.py` — `POST /location`. Reverse geocodes via Nominatim, fetches 2-hour forecast from Open-Meteo, caches at `location:{user_id}` in Valkey (24h TTL). Also back-fills weather for gap days since last conversation.
- `update.py` — `GET /check_update` (direct version compare) and `GET /check_remote_update` (proxies to miraos.org for browser CORS). No auth. Reads `/VERSION` file; logs checks to `data/update_checks.log`.
- `federation.py` — `POST /federation/deliver`. Lattice server-to-server webhook requiring the Vault-backed `X-Lattice-Delivery-Token` header and `sender_verified=true`. Delivers inbound federated messages idempotently via `PagerTool.deliver_federated_message` (sets user context from `payload.to_user_id`). Optional: the `lattice` package + daemon are external; the resolver in `main.py` is `ImportError`-guarded, so MIRA runs with federation disabled when absent.
- `oss_ui.py` — `GET /oss-auth/token`, `GET /oss-assets/*`. Always-on OSS browser-auth router: exposes the single-user API key at `/oss-auth/token` (the web UI's Bearer-key login source) and serves the two vendored JS files from `deploy/oss_ui/` (marked.min.js, purify.min.js) from memory at import time. No `/` or `/chat` routes — those are owned by `main.py`'s de-auth-gated page routes over `web/*/index.html`. No auth dependency. `deploy/oss_ui/chat.html` is served by no route — it predates the `web/` pages and remains an unreferenced file in the asset directory; the live chat UI is `web/chat/index.html`.
