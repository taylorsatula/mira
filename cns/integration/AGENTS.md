# cns/integration/ — the process's one event bus, and the boot-time factory that builds the CNS dependency graph

## Files

- `__init__.py` — package marker only: a docstring, no code, no re-exports. Open it before deciding whether anything belongs at package level; nothing does.
- `event_bus.py` — the in-process bus every component publishes through, and the registry of who hears what. Open it before subscribing a handler, or when a subscription exists and its handler never runs.
- `factory.py` — the composition root: constructs the orchestrator and every service beneath it, so every in-process subscription is created as a side effect of calling it. Open it before adding a service, a trinket, a poller, or a subscriber, and before reordering a step of `create_orchestrator()`.

## Wiring

- Boot: `main.py` lifespan → `get_lt_memory_factory(...)` → `create_cns_orchestrator()` → `initialize_orchestrator(...)` → `register_segment_timeout_job` and `register_sidebar_dispatcher_job`, both handed `orchestrator.event_bus`. The lt_memory singleton must already exist: `_get_memory_relevance_service` and `_initialize_segment_collapse_handler` fetch it with no arguments, and that call raises RuntimeError against an unbuilt singleton. Lifespan order is root's; the factory contract is `lt_memory/AGENTS.md`.
- Event-name registry: `EventBus.subscribe` validates every subscription string against `_iter_event_names()`, a live walk of `cns/core/events.py`'s subclass tree — a class added there is subscribable, a class renamed there fails boot at the next `subscribe()` rather than at import. Name a subscription by the class `__name__`, never a category base: dispatch is a dict lookup on the exact name with no MRO walk, so a subscriber on `MessageEvent` hears nothing. Counterpart: `cns/core/AGENTS.md`.
- Construction order inside `create_orchestrator()`: `_get_embedding_model` → `_get_event_bus` → `_get_working_memory` → `_get_tool_repository` → `_get_llm_provider` and `_get_tag_parser` → `get_continuum_repository` → `_get_live_context_compaction_service` → `_get_memory_relevance_service` → `_get_subcortical_layer` → `_initialize_session_cache` → `_initialize_segment_collapse_handler` → `_initialize_userdata_cleanup_handler` → `_initialize_manifest_query_service` → `_initialize_peanutgallery_service` → `_initialize_inbox_poller` → `ContinuumOrchestrator(...)`. Two orderings are load-bearing: `_get_event_bus` must precede working memory, because working memory stores the bus and every constructor that wants one afterwards reads it from `working_memory.event_bus`; `_get_tool_repository` must follow working memory for the same reason, since `ToolRepository.__init__` skips its `SegmentCollapsedEvent` subscription when that attribute is None (`tools/AGENTS.md`). `_initialize_session_cache` must precede the collapse handler, because `get_continuum_pool()` raises until `initialize_continuum_pool` has run (`cns/infrastructure/AGENTS.md`).
- Subscription assembly: every subscription in the process registers during `create_orchestrator()` — this factory's own `TurnCompletedEvent` → `cleanup_ephemeral_tools` lambda, plus one made inside each constructor it calls, the orchestrator's own two included. Full set: `rg '\.subscribe\('`; publishers: `rg '\.publish\('`. A subscription added anywhere else in the process hangs off a bus this orchestrator does not own. Counterparts: `working_memory/AGENTS.md`, `working_memory/trinkets/AGENTS.md`, `cns/services/AGENTS.md`, `cns/services/pollers/AGENTS.md`, `tools/AGENTS.md`.
- Config gates, where a closed gate means the construction never happens and every consumer must tolerate the absent handle rather than a raise: `config.system.subcortical_enabled` → `_get_subcortical_layer` returns None and the orchestrator runs without the layer; `persona_enabled` → no `PersonaTrinket`; `peanutgallery_enabled` → no `PeanutGalleryService` and no `PeanutGalleryTrinket`; `api.subcortical_prefill_warmup` reaches `SubcorticalLayer`. Flag semantics: `config/AGENTS.md`.
- Skills snapshot: `load_global_catalog()` runs once here, immediately after trinket construction — the single boot read of the skills catalog every later reader is served from. Why a reader still sees a stale global skill until restart: the `utils/skill_files.py` module docstring.

## Rules

- Nothing in `factory.py` may write non-idempotently. The graph is built once per process start and once per pre-server POST round — normally twice per boot, once by the `main.py` lifespan and once by the POST child (`utils/power_on_self_test.py:_check_dependency_initialization`), and the gate repeats its round up to `PRE_SERVER_GATE_ATTEMPTS` times — against the same real Postgres and Valkey. A row inserted during construction therefore lands once per round, and the duplicates are live state the operator never asked for.

Elsewhere: this map does not own what an event means, who publishes it, or what a subscriber does with one. Event payload fields are `cns/core/events.py`; the provider construction behind the `_get_*` accessors is `clients/AGENTS.md`; why a constructor step sits where it does, where no comment says so, is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.
