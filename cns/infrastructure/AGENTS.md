## Rules

- Cache writes are guarded: full-cache writes go through `set_continuum_if_epoch` with the epoch captured in `get_or_create` before the message read and threaded via `begin_work` into `UnitOfWork.commit`. A plain SET — any unguarded write — re-caches the pre-collapse message set after `invalidate_continuum` bumped the epoch, and the stale copy serves until the next collapse. A skipped epoch write is not an error: the cache stays empty, the next `get_or_create` reloads from the database.
- One live (status `active` OR `paused`) sentinel per continuum — partial index `idx_messages_live_segment_unique` (`deploy/mira_service_schema.sql`). `_ensure_active_segment` reuses an existing live sentinel, paused included — never mints a second — and its INSERT is `ON CONFLICT DO NOTHING` so the race loser no-ops; `increment_segment_turn` pins its UPDATE to the subquery's single row. Mint a second live sentinel and the index rejects the minting write itself — `_ensure_active_segment`'s INSERT no-ops on the conflict; a rogue live-status INSERT fails at that write, not at some later turn entry. New sentinel queries match `status IN ('active', 'paused')`; the sanctioned exception is `find_all_active_segments_admin` (timeout sweep) — an active-only match treats a paused user as segment-less and re-mints.
- New-segment ids are born at turn entry, persisted at commit: `increment_segment_turn` mints a fresh id in memory and exposes it via `set_current_segment_id`; only `save_messages_batch` → `_ensure_active_segment` INSERTs the sentinel, on the autocommit connection before the message transaction opens — separate commits by design, so a failed batch leaves a residual orphan sentinel. `_ensure_active_segment` re-checks the contextvar id against existing sentinels before reuse (a stale contextvar outliving its segment collides) and re-points the contextvar to the sentinel that exists — persisting under the stale id mismatches the segment tools recorded this turn.
- `increment_user_activity_day` is called from one tree, here: `save_message` and `save_messages_batch`, only when the batch holds a `role == 'user'` message; failure is logged, never raised. Chain consequence owned by `utils/AGENTS.md` (`user_activity.py`): a missed increment makes every use-day job skip the user.
- Events that must observe durable state ride `UnitOfWork.add_post_commit_callback` — `cns/services/orchestrator.py` stages `TurnCompletedEvent` there. Callbacks run only after the database write and the cache write, the list cleared before running (a callback may commit new work); a callback exception propagates with the turn already durable. Publishing at build time instead makes subscribers observe a turn whose commit can still fail.
- Persona revisions are append-only: `append_revision` is the sole writer, serialized by `SELECT … FOR UPDATE` on `persona_state` with `revision_number` computed inside the lock; `expected_parent_revision_id` compares against the live current — a stale preview accept raises `ValueError` and the caller regenerates the preview. Signal consumption is single-shot (`consumed_by_revision_id IS NULL` guard). Direct UPDATEs in new code race two writers into duplicate revision numbers or a lost parent edge.
- `save_message`'s `ON CONFLICT (id) DO UPDATE` is the collapsed-sentinel path: collapse rewrites the same row (`cns/services/segment_helpers.py:collapse_segment_sentinel` copies the sentinel, status flipped). A sentinel is one message row for its whole life — delete-and-reinsert breaks `find_segment_by_id` history and the collapse re-read guard.

## Files

- `__init__.py` — re-exports `ContinuumRepository` only; no in-repo consumer imports through the package — import submodules directly.
- `continuum_pool.py` — `UnitOfWork` (staging plus two-store commit) and the per-user-locked pool over it. Entry: `get_or_create`, `begin_work`, `UnitOfWork.commit`/`add_messages`/`add_post_commit_callback`, `initialize_continuum_pool`/`get_continuum_pool` (module singletons; construction owned by `cns/integration/AGENTS.md`). Gotcha: `add_messages` enforces the 150_000-char persistence cap in place — string content cut to a copy, list content trimmed block-by-block by `_trim_content_blocks` mutating the message — so the in-memory continuum matches the durable row; a caller reading content after `add_messages` sees the truncated form.
- `continuum_repository.py` — all `messages`/`continuums` SQL behind the singleton `get_continuum_repository()`. Entry: save path — `save_message` (single row, autocommit), `save_messages_batch` (one transaction), `_ensure_active_segment`; turn entry — `increment_segment_turn`; segment lifecycle — `pause_segment`/`unpause_segment` (actions.py pause/resume sessions); finders — `find_active_segment`, `find_segment_by_id`, `find_collapsed_segments`, `find_all_segments`, `find_failed_extraction_segments` (content-failure budget `EXTRACTION_MAX_CONTENT_FAILURES`), `find_all_active_segments_admin` (the one BYPASSRLS query; stale-claim window `COLLAPSE_CLAIM_STALE_MINUTES`); loaders — `load_segment_messages`, `load_continuity_messages`, `load_messages_for_live_compaction_range`; `get_history` (keyset `(created_at, id)`); `get_user_db_client` (per-user `PostgresClient` lent cross-directory — `rg 'get_user_db_client'`). Gotcha: list content persists as `json.dumps` (durable form owned by `cns/core`'s `Message.to_db_tuple`) and reloads by the `content_type` tag stamped at write, never by shape — a plain-text message that is valid JSON must reload as text; pre-tag rows stay text. Dead: `load_messages_with_metadata` — no in-repo caller (`rg 'load_messages_with_metadata'`); kept as the metadata-filter loader for the next consumer — do not build on it as exercised.
- `feedback_repository.py` — assessment-signal rows in `feedback_signals` (user-model pipeline). Entry: `save_signals`, `get_unsynthesized_signals` (row shape `FeedbackSignalRow`), `mark_signals_synthesized`. Gotcha: the directory's one upward import — input type `AssessmentSignal` comes from `cns/services/assessment_extractor.py`.
- `feedback_tracker.py` — `feedback_synthesis_tracking` gating and storage, stateless by design (activity-day snapshot; no counters to reset). Entry: `should_synthesize`/`mark_synthesized` (snapshot pair with the `activity_days > last_snapshot` dedup guard), `get_last_synthesis_output` (the collapse handler's continuity read of the live model), `get_lora_content`, `get_tracking_status`, `set_synthesis_output`, `reset_synthesis` (fresh-install baseline; a pending check-in is discarded with the model it referred to), `initialize_user` (account creation via `auth/seed_lora.py`), `acknowledge_checkin`. Gotcha: check-in feedback has two read modes — `get_checkin_response` peeks, `get_and_clear_checkin_response` consumes atomically (`UPDATE … RETURNING`); a path that consumes before all fallible work is done destroys the user's feedback on its first failure.
- `persona_repository.py` — immutable Persona revisions and evidence over `persona_state`/`persona_revisions`/`persona_signals` (evidence never in `feedback_signals`). Entry: `get_current_revision` (RuntimeError on missing baseline — no Optional hedging), `get_revision`/`list_revisions`, `save_signals` (raises on a cross-user signal), `get_unconsumed_signals`, `refinement_due`, `append_revision`, `mark_refinement_attempt`, `segment_was_evaluated`/`mark_segment_evaluated`. Gotcha: rollback is an append — `source="rollback"` re-writes the target's directives; rows are never updated in place.
- `valkey_message_cache.py` — the hot message cache and collapse-epoch counter, keys `continuum:{user_id}:messages` / `continuum:{user_id}:epoch`. Entry: `get_continuum`, `get_epoch`, `set_continuum_if_epoch`, `invalidate_continuum` (atomic delete + epoch bump over `delete_and_increment`).

- Turn flow: API entry (`cns/api/chat.py`, `cns/api/websocket_chat.py`) → `get_or_create` (epoch captured) → `increment_segment_turn` (takes the continuum id, so it follows the load; sets `current_segment_id`) → `cns/services/orchestrator.py:process_message(..., unit_of_work=…)` stages → `commit()` → post-commit callbacks publish turn events. - Segment-lifecycle surface: `cns/api/actions.py` collapse/pause/resume sessions ride `find_active_segment` (plus `_latest_boundary_is_collapsing` over `get_user_db_client`), `pause_segment`/`unpause_segment`, and `load_segment_messages` for the status payload. Counterpart: `cns/api/AGENTS.md`.

## Sentinel and epoch lifecycle, turn to collapse

1. Load: `get_or_create` (per-user lock) captures the epoch before the cache read. Cache hit → continuing session. Miss → `load_session_cache` composes summaries, continuity turns, the session boundary, and the active segment's messages; the reload lands in the cache only if the epoch still matches.
2. Turn entry: `increment_segment_turn` runs one subquery-pinned UPDATE against the live (active-or-paused) sentinel — turn count +1, `paused_at` dropped, status → `active`, `last_turn_at` stamped with the arrival time. That stamp is the crash grace: a turn that dies before committing still recorded fresh activity, which the timeout sweep's lock probe reads after the request lock expires. No live sentinel → fresh `uuid4` in memory, exposed via the `current_segment_id` contextvar, nothing persisted.
3. Turn body: the orchestrator stages every durable message of the turn into the `UnitOfWork`, tool results included; `add_messages` caps content at 150_000 chars, trimming in place.
4. Commit: `_ensure_active_segment` INSERTs the sentinel on the autocommit connection (separate commit; the partial-index conflict makes the race loser a silent no-op), then all messages land in one `execute_transaction`. A user-role message increments the activity day, logged not raised. `set_continuum_if_epoch` writes the cache — skipped, not failed, on epoch mismatch. A batch failure invalidates the cache so no stale copy outlives the rollback, then re-raises.
5. Idle → event: the timeout sweep scans active segments plus stale `collapsing` claims, skips users whose request lock shows a turn in flight, and publishes a timeout event.
6. Claim: `cns/services/segment_collapse_handler.py:_claim_collapse` runs one conditional UPDATE — it lands only while the sentinel is still active/paused, or while a previous claim is older than `COLLAPSE_CLAIM_STALE_MINUTES` (the crash-recovery path: a process death between claim and save must not strand the segment). Every concurrent claimant that gets no rows — scheduled timeout vs manual collapse vs tombstone — aborts.
7. Collapse: the handler re-reads the sentinel and aborts if `last_turn_at` moved (a turn interleaved) or the status left the claimable set; otherwise rewrites the same row `collapsed` via `save_message`'s `ON CONFLICT (id)`, calls `invalidate()` — one atomic delete + epoch bump, so no writer holding the pre-collapse epoch can land stale content after it — and publishes `SegmentCollapsedEvent`. A segment that exhausted its collapse retries gets a `processing_failed` tombstone through the same row and the same event.
8. Next load: cache miss → reload from the database → collapse-correct message set; the bumped epoch counter and the empty cache agree.

Ordering invariants: the epoch is captured before the message read (a collapse between read and commit makes the commit's cache write skip); invalidation follows every sentinel write; the collapse re-read precedes the collapsed write; the sentinel INSERT precedes the message transaction — its failure window is the orphan sentinel, which the next turn's live-sentinel reuse simply adopts.
