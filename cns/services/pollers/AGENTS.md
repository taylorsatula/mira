# cns/services/pollers/ — segment-lifecycle-bound pollers: per-user threads start on a segment's first compose, stop on collapse

Elsewhere: event definitions and bus dispatch (synchronous, inline on the publishing thread, at-most-once, subscriber errors logged not raised, subscribe validated against `cns/core/events.py` class names) — `cns/integration/AGENTS.md` (`cns/integration/event_bus.py`), taxonomy `cns/core/AGENTS.md` (`cns/core/events.py`) · trinket registration keys, the StatefulTrinket flush, `<inbox_status>` rendering and its untrusted wrap — `working_memory/trinkets/AGENTS.md` (`working_memory/trinkets/email_trinket.py`) · the compose round-trip and `_compose_lock` — `working_memory/AGENTS.md` (`working_memory/core.py`) · the full `EmailToolConfig` schema and email_tool's own IMAP/SMTP use — `tools/implementations/AGENTS.md` · tool-config storage, secret hydration, redaction sentinel — `utils/AGENTS.md` (`utils/tool_config_store.py`) · copy-context/RLS doctrine and the per-user turn lock — root `AGENTS.md` · signatures — the files.

## Rules

- Add-one recipe (a new poller): subclass `SegmentPoller`; set `poll_interval_seconds`/`target_trinket`/`poller_name`; implement `_try_load_config()` (None = user unconfigured, a normal case, not an error) and `_poll_once()`; construct exactly one instance plus its target trinket in `cns/integration/factory.py`. Skip-failures: not constructed there → never runs, no error (no auto-discovery); `target_trinket` ≠ the trinket class `__name__`, or trinket never constructed → `working_memory/core.py:_handle_update_trinket` drops every update with one warning (registration keys by `__class__.__name__`); a second instance → double-polls — the bus appends subscribers without dedup, so each instance spawns its own thread per user. The trinket side must tolerate the compose-broadcast refresh (`context={}`, no `'data'` key) and wrap poller data as external content in `generate_content` — `working_memory/trinkets/email_trinket.py` is the pattern (one `wrap_untrusted` region for the whole listing).
- `_poll_once()` returns `None` for a failed cycle, `[]` for a genuinely empty source — never swap them. `None`: `_poll_loop` skips the publish and the trinket serves its last snapshot through the outage (stale by design). `[]`: publishes, renders empty, and the empty render clears the trinket's Valkey entry (`working_memory/trinkets/base.py:handle_update_request`). `[]` on failure masks an outage as an empty source; `None` on empty blanks a good listing.
- `_try_load_config()` runs on the turn path under `_compose_lock`: the bus dispatches inline on the publishing thread, and `cns/services/orchestrator.py:_compose_llm_messages` publishes `ComposeSystemPromptEvent` inside that lock on every LLM request. A slow or hung config load stalls every concurrent compose process-wide — keep it a cheap local read, never a network call. The no-config path has no negative cache: an unconfigured user re-reads the config store on every compose. Symmetric: the poll thread's `UpdateTrinketEvent` publish dispatches the trinket handler synchronously and waits on `_compose_lock` — a compose in flight delays a poll publish.
- `_on_compose`'s membership check and its insert are separate lock sections; their safety rests on the upstream one-turn-per-user Valkey lock (root spine). A second concurrent composer for one user double-starts a poller, and the later insert orphans the earlier thread's stop handle — that thread polls until process exit (daemon), duplicating external calls and trinket publishes alongside its replacement. Never publish `ComposeSystemPromptEvent` outside the per-user turn lock.

## Files

- `__init__.py` — docstring only, no re-exports; the factory imports submodules directly.
- `segment_poller.py` — the base class: subscribes at construction (`ComposeSystemPromptEvent` → start, `SegmentCollapsedEvent` → stop), the per-user thread registry `_active_pollers` under `_pollers_lock`, `copy_context()` thread spawn, the interval loop, and the two-method subclass protocol. Entry: `SegmentPoller`, `_on_compose`, `_on_segment_collapsed`, `_poll_loop`, `_PollerState`. Gotcha: the stop path is best-effort — `state.thread.join(timeout=5)`; a cycle hung inside `_poll_once` (the inbox IMAP timeout is 15s) outlives the collapse, keeps publishing, and co-exists with the replacement poller the next compose starts.
- `inbox_poller.py` — the only subclass: IMAP unread headers every 180s, newest `MAX_UNREAD_EMAILS` (20) UIDs, config from the user's `email_tool` config. Entry: `InboxPollerService`, `_try_load_config` (requires `imap_server`/`email_address`/`password`), `_poll_once`, `_extract_uid`, `_decode_header`. Gotcha: `select(readonly=True)` + `BODY.PEEK` — polling must never set `\Seen`; a plain `FETCH` marks the user's mail read as a side effect of a chat turn.

## Wiring

- Construction, ungated at boot (the per-user gate is `_try_load_config` returning None): `cns/integration/factory.py:_initialize_inbox_poller` constructs `EmailTrinket` and `InboxPollerService` together, after working memory exists (the trinket self-registers into it) and before the orchestrator. Counterpart: `cns/integration/AGENTS.md`.
- Lifecycle in: `ComposeSystemPromptEvent` ← `cns/services/orchestrator.py:_compose_llm_messages` (per LLM request, under `_compose_lock`); `SegmentCollapsedEvent` ← `cns/services/segment_collapse_handler.py` on both the normal and the tombstone path — the tombstone comment names poller threads as the reason the failure path must publish. Counterparts: `cns/services/AGENTS.md`, `cns/core/AGENTS.md`.
- Data out: `_poll_loop` → `UpdateTrinketEvent(target_trinket='EmailTrinket', context={'data': ...})` → routed by `working_memory/core.py:_handle_update_trinket` → `EmailTrinket` stores the snapshot keyed by contextvar user and renders the `inbox_status` section. Rendering and the untrusted wrap: `working_memory/trinkets/AGENTS.md`.
- Config chain: `inbox_poller._try_load_config` → `utils/tool_config_store.py:load_user_tool_config("email_tool", hydrate_secrets=True)` → `UserCredentialService` per-user SQLite; secret hydration is registry-driven off `EmailToolConfig`'s `json_schema_extra={"secret": True}` (`tools/implementations/email_tool.py`) — a schema field rename there silently disables polling (missing-fields warning → None → no start). `email_tool` additionally requires `smtp_server`; an IMAP-only config polls fine while send refuses. Counterparts: `utils/AGENTS.md`, `tools/implementations/AGENTS.md`.
- Context: the poll thread runs `ctx.run(...)` over a copied context — the user contextvar flows to `UpdateTrinketEvent.create` and the trinket's keyed writes (doctrine owned by root `AGENTS.md`).
- Importers and subclassers are greps, not lists: outside this directory `rg 'cns\.services\.pollers'` → `cns/integration/factory.py`; `rg 'SegmentPoller'` → this directory only.
