# cns/services/ — Application services: turn orchestration, segment collapse, memory surfacing, and the user model / Persona pipelines

## Rules

- Services receive dependencies via constructor injection and call repository methods; SQL lives in `cns/infrastructure/`. The acknowledged exceptions are `segment_collapse_handler._load_segment_messages()` (defensive "stop at next boundary" query, documented in its docstring as accepted debt) and `_count_user_segments()`; `segment_timeout_service` is an admin-level scheduled job and uses `get_admin_session()` directly.
- Prompts load from `config/prompts/` via `config.prompts.loader.load_prompt()` in `__init__` or `_load_prompts()`. Never inline prompt strings. The template inventory is owned by `config/prompts/AGENTS.md` — add new files there, not here.
- `preprocess_content_blocks()` and `_MEDIA_BLOCK_TYPES` (owned by `cns/core/AGENTS.md` via `cns/core/message.py`) are the canonical multimodal preprocessing boundary. Import them; do not re-implement media stripping or truncation. Every service that renders message content for an LLM uses them (`live_context_compaction_service`, `summary_generator`, `peanutgallery_model`, `persona_service._format_messages`).
- Exception policy split: critical-path services propagate (`orchestrator.process_message()`, `summary_generator.generate_summary()`, `segment_collapse_handler.collapse_segment()`, `tool_result_summarizer` user-mismatch check). Fire-and-forget consumers log and swallow: `peanutgallery_service`, poller cycles (`SegmentPoller._poll_loop`), `subcortical.warm_cache()` / `_save_output()`, live-compaction scheduling, and the post-collapse `feedback`/portrait steps. The collapse chain itself is the boundary: everything after the sentinel save is best-effort, everything before raises.
- Background collapse is **not** a fail-loud path: by collapse time the model is off the call stack, so an exception discards data instead of prompting a clarifying question. `segment_collapse_handler._resolve_pending_memory_timezone()` resolves the user's timezone once per batch (falling back to UTC inside a guard — `memory_tool` queues `happens_at`/`expires_at` as naive local wall times) and `_parse_pending_temporal_field()` returns None with a diagnosable warning (raw value, timezone, parser reason) instead of raising. Never add a raise there and never mutate the memory text to compensate.
- Per-user collapse handling is a scheduled context: `collapse_segment()` starts with `clear_user_context()` then `set_current_user_id(event.user_id)` — the timeout service iterates users sequentially on one thread, so stale contextvars would leak across users. Background threads spawned in this directory follow the `cns/AGENTS.md` copy-context rule (pollers, `PeanutGalleryService`, live compaction, subcortical warmup, curator spawn).
- Model route convention for LLM calls in this directory: `"primary"` for all user-facing synthesis and chat, `"fast"` for high-frequency auxiliary calls (`subcortical`, `peanutgallery_model`, `domaindoc_summary_service`, `tool_result_summarizer`), `"batch"` for background synthesis/durability calls (`summary_generator`, `live_context_compaction_service`, `persona_service`, `user_model_synthesizer`, `lora_service`, `portrait_service`), `"assessment"` only in `assessment_extractor`. Route ownership and stall behavior live in `clients/llm/AGENTS.md`; there is no fallback route.
- Manual-revision previews (portrait, LoRA/user model, Persona) all follow one contract: LLM output stored in Valkey under `f"{prefix}:{user_id}:{preview_id}"` with a 600s TTL and an opaque `preview_id`, consumed once by `_pop_preview()`-style delete-after-read so the client never round-trips the stored text. A preview accepted after expiry raises `ValueError`, not a silent no-op.
- The user-model cache slot in the shared trinket hash is `"behavioral_directives"` (LoraTrinket, user model); Persona owns a separate `"persona_directives"` slot. Invalidating the wrong slot leaves the other stale — see the slot comment in `persona_service._invalidate_cache()`.

## Files

- `__init__.py` — Docstring plus a single re-export of `ContinuumOrchestrator`; all other services are imported from their modules directly.
- `orchestrator.py` — Owns the message→LLM→response cycle: memory surfacing, system prompt composition via `ComposeSystemPromptEvent` round-trip, the tool loop, context-overflow remediation, halt handling, and provider-step-ordered persistence. Entry points: `process_message()`, `get_orchestrator()`, `initialize_orchestrator()`. Persistence builds one `Message` per provider step (`_build_turn_messages()`), each carrying only the text streamed under its own `entry_id`, with monotonic microsecond timestamps so repository keyset ordering stays stable. `ContextOverflowError` gets one deep request-shrink retry (`_apply_deep_context_overflow_fallback()`), then a second overflow persists the literal fallback `collapse the segment, please. incremental compaction failed` with `model_error_reason="incremental_compaction_failed"`. Tool results stored in history are truncated via `_truncate_tool_result()` (`TOOL_RESULT_MAX_CHARS = 31999`; JSON arrays sliced to N complete elements, everything else raw chars). The compaction schedule check uses the **previous turn's provider-reported input tokens** (`self._last_turn_usage`), invalidated on `SegmentCollapsedEvent` — not a fresh estimate of the composed request. An invalid tool call (`invalid_reason`) is never persisted as an assistant tool_call, so schema-invalid arguments never replay on later turns. Effort comes from subcortical complexity unless a Valkey `effort_override:{user_id}` key (1h TTL) is present, which wins and skips the assessment. Exports `TurnMetadata`, `LLMKwargs`, `TurnAccumulator`, `AssistantStep`, `ToolInteraction`, `tool_stream_frame()`. Singleton via `get_orchestrator()`. Consumers: `cns/api/chat.py` (turns), `portrait_service`/`lora_service` (working-memory cache invalidation through `get_orchestrator().working_memory`).
- `live_context_compaction_service.py` — Background compaction of the active segment into a single rolling Valkey brief. `LiveContextCompactionStore` owns the per-user artifact (`live_context_compaction:{user_id}`) and a non-blocking per-user lock; repeated compactions keep the original `covered_start` and increment `compaction_count`. `LiveContextCompactionService.select_range()` loads DB-backed ranges while preserving the last `config.api.compaction_raw_user_turns_to_preserve` user turns raw; `compact_once()` formats XML role-tag history via `format_messages_for_live_compaction()` (tool results truncated to `TOOL_RESULT_TRUNCATION_LIMIT = 500`), calls `model_config="batch"`, and wraps the brief in `<mira:compacted_active_context>` with search recovery instructions. `format_messages_for_api()` / `get_visible_messages()` read the current artifact and drop only ordinary messages in `(covered_start, covered_end]` before delegating to `cns.core.message_formatter.format_messages_for_api()`; never mutates `Continuum.messages`. Gotcha: `get_visible_messages()` catches artifact-read failures and returns the full continuum (logged at error) so a Valkey outage degrades to uncompacted context instead of failing the turn. Exports `filter_messages_for_live_context()`, `LiveContextCompactionArtifact`, `LiveContextCompactionStore`. Consumers: `orchestrator.py` (scheduling + request assembly), `working_memory` segment-collapse clears the artifact through the stateful trinket.
- `tool_result_summarizer.py` — Post-commit hot-cache compactor: subscribes to `ToolResultHistoryCommittedEvent`, LLM-compacts oversized committed tool results (>2000 chars, non-error, not a `get_tool_result` retrieval) in Valkey while PostgreSQL keeps the original. JSON results are compacted structurally (`JsonCompactionDecision` keeps array indices or replaces one prose field, validated: sorted unique indices, strictly smaller, no invented URLs — enforced in `_apply_json_decision()`). Conditional cache patches carry `expected_content` so stale patches no-op. Compacted results gain the `continuum_tool.get_tool_result` breadcrumb via `cns/core/message_formatter.py`; retrieved results carry `tool_result_retrieved=True` and are never compacted again. Uses `model_config="fast"`. Entry points: `initialize_tool_result_summarizer()`, `get_tool_result_summarizer()`.
- `async_work_barrier.py` — Per-user latch (`register_work()` returns an idempotent `done()` callback; `wait_for_user()` blocks, timeout fails open with a warning) so chat entry points can wait for bounded cross-turn background work before loading the hot continuum. Single-process design. Entry points: `initialize_async_work_barrier()`, `get_async_work_barrier()`. Consumers: `tool_result_summarizer.py`, `cns/api/chat.py` and `cns/api/websocket_chat.py` (pre-turn wait).
- `tool_loop.py` — Orchestrator-owned local tool execution. `ToolLoopExecutor.execute_tools()` runs sequential vs parallel batches (split by `is_call_parallel_safe()`), emits `clients/llm/events.py` tool events, and honors cancellation (a started tool finishes; later parallel calls never start). `CircuitBreaker` trips when the same tool with the same input hash fails twice. Gotcha: a dict result with `success=False` is converted to `ToolReportedError` (`_execute_tool()`), otherwise the breaker would see success and let the model repeat the identical failing call forever. Parameter errors get a schema hint appended (`_schema_hint()`). Consumers: `orchestrator.py` only.
- `subcortical.py` — Pre-LLM processing: query expansion (which *replaces* the raw query for retrieval), named-entity extraction, retention pin evaluation, and complexity assessment from `<query_expansion>`, `<entities>`, `<complexity>`, `<passage>` tags. `generate()` returns `SubcorticalResult` and raises on empty/unparseable responses — never returns None. Uses `model_config="fast"`. The pressure vocabulary is shared with the orchestrator via `lt_memory/proactive.py` constants: warning at `MAX_PINNED_MEMORIES=6`, critical at `MAX_SURFACED_MEMORIES=8`; under pressure the conversation window narrows to 2 pairs (`CONTEXT_PAIRS=3` normally) and passage text truncates to 15 words. Memory IDs pinned by regex from the conversation text are unioned with the LLM's picks, so conversation-mentioned memories are always retained. `warm_cache()` fires a max_tokens=1 prefill-warming call only when `prefill_warmup_enabled` (vLLM-only optimization; billed waste on cloud providers) and requires `_build_user_prompt()` to be byte-identical to the real call. Debug prompt/response pairs persist under `data/users/{user_id}/subcortical_debuglogs/`. Complexity→effort (`SubcorticalResult.get_effort_level()`) emits only `low` (straightforward) or `high` (complex): `medium` is absent from several provider ladders (DeepSeek V4.1 accepts low/high/xhigh/max only), so deriving it 400s every straightforward turn. Consumers: `orchestrator.py` (`generate`, `warm_cache`), `SurfacedMemory`/`SubcorticalResult` types.
- `summary_generator.py` — Segment summary generation (`generate_summary()` → `SummaryResult(synopsis, precis, display_title, complexity)`), thinking enabled, `model_config="batch"`. On `ContextOverflowError`, falls back to hierarchical chunking (~200k chars per chunk, `_CHUNK_TARGET_CHARS`) with synthesis prompts loaded `required=False`; if chunking also fails, raises. A missing `<mira:display_title>` tag — empty output, refusal, or reasoning tokens that consumed the budget before content — raises `ValueError` so the collapse handler's retry + `MAX_COLLAPSE_ATTEMPTS` force-tombstone owns degradation (a silent generator-level tombstone is indistinguishable from a real summary downstream). Previous collapsed sentinels (last 5) feed narrative continuity; only the first chunk receives them. Imports `preprocess_content_blocks` from `cns.core.message`.
- `segment_collapse_handler.py` — Owns the `SegmentTimeoutEvent` response. Entry points: `collapse_segment(event)` (raises on failure; also called by the actions API which needs exceptions), `handle_timeout()` (subscriber wrapper that swallows and lets failures count toward `MAX_COLLAPSE_ATTEMPTS = 3` before tombstoning), singletons `get_segment_collapse_handler()` / `initialize_segment_collapse_handler()`. Chain: sentinel lookup → attempt counter persisted via `jsonb_set` *before* the expensive LLM call → summary+embedding → Persona pass → `collapse_segment_sentinel()` → `SegmentCollapsedEvent` → downstream (extraction via `lt_memory_factory.extraction_orchestrator.submit_segment_extraction()`, pending manual memories) → user-model feedback loop → portrait gate → `ManifestUpdatedEvent`. `_load_segment_messages()` stops at the next boundary sentinel even though the repo query already fetched past it. The `on_memories_stored` callback seam (`_on_memories_stored`) lets lt_memory spawn `MemoryCuratorAgent` without importing `agents/` — the handler owns `tool_repo` + `event_bus`. The Persona pass (`_process_persona`) deliberately does not catch inside collapse and runs *before* the sentinel save, so failures propagate to the retry + `MAX_COLLAPSE_ATTEMPTS` budget instead of stranding a collapsed segment with its persona signal lost; `evaluate_segment` is idempotent per segment via the `persona_state.latest_evaluated_segment_id` pointer (`segment_was_evaluated`) — a known edge: the pointer comparison can miss if a different segment evaluates between a post-persona flip failure and the retry, so a failed flip save followed by an interleaved clean collapse can duplicate one segment's signals. Unlike `_process_feedback_loop` and `_process_portrait_synthesis`, which swallow because the segment is already saved. Consumers: `cns/integration` factory (construction), `cns/api/actions.py` (manual collapse).
- `segment_helpers.py` — Pure sentinel utilities: `create_segment_boundary_sentinel()` (sentinel `created_at` precedes the first message by 1µs so chronological queries place it correctly), `collapse_segment_sentinel()` (returns a new immutable `Message`; embedding rides in metadata for the repository to extract), `format_segment_for_display()` / `format_precis_for_display()`, `create_collapse_marker()`, `create_session_boundary_marker()`. Canonical place for sentinel operations — never construct or parse sentinel messages manually.
- `segment_timeout_service.py` — Scheduled admin job (every 5 min, `register_timeout_job()`) that queries all users' active segments and publishes `SegmentTimeoutEvent` for those past the inactivity threshold. Threshold is time-of-day aware in the segment owner's local timezone (`segment_timeout_morning` / `segment_timeout_late_night` overrides, falling back to `config.system.segment_timeout`). Last-activity time is the max of the last committed message and the sentinel's `last_turn_at` (stamped atomically at user-message arrival, before uow commit — without this a resumed segment looks timed-out). Orphaned segments with no messages use sentinel creation time so they reach the collapse tombstone naturally. Returns `TimeoutCheckResult` TypedDict; re-raises after logging (fail-loud scheduled job).
- `assessment_extractor.py` — User model pipeline step 1: `extract_signals()` evaluates a collapsed segment against the *anonymized* system prompt sections, producing `AssessmentSignal`s (`alignment`/`misalignment`/`contextual_pass` × `strong`/`moderate`/`mild` + evidence). Uses `model_config="assessment"`. Thinking traces (`reasoning` blocks) are included only when they exceed `THINKING_INCLUSION_THRESHOLD = 0.7` of assistant content. Imports `_MEDIA_BLOCK_TYPES` from `cns.core.message`.
- `user_model_synthesizer.py` — User model pipeline step 2: `synthesize()` turns unsynthesized signals into section-anchored `UserObservation`s with a critic validation loop (`CRITIC_MAX_ATTEMPTS = 3`). On critic exhaustion it keeps the *previous* model rather than injecting known-suspect content (unless no previous model exists). Also consumes atomically-cleared check-in feedback (`FeedbackTracker.get_and_clear_checkin_response()`, stored by `orchestrator._process_checkin_response()`). All calls use `model_config="batch"`. The `user_model_critic_system.txt` / `user_model_critic_user.txt` prompt pair is shared with `lora_service.py` — a change to either file must be checked against both consumers. Exports `UserObservation`, `CriticResult`, `SynthesisResult`.
- `system_prompt_parser.py` — Pure utilities shared by the user-model pipeline and `lora_service`: `get_assessable_sections()` (top-level sections only, `user`/`environment` blocklisted), `anonymize_prompt()` (strips template vars and user-identifying sections), `format_section_list()`. No LLM calls.
- `peanutgallery_model.py` — Single-stage metacognitive observer (`evaluate()` → `PeanutGalleryResult`). Actions: `noop`, `concern`, `coaching`, `initiative`; `concern`/`coaching` may carry `severity="critical"` for user-facing repair authorization (`initiative` is never critical). Parses `<mira:peanutgallery>` attributes order-independently. Builds an execution-trace ledger (latest user request, latest response, assistant commitments, tool activity) and judges only current-session evidence; messages are formatted with 8-char IDs. Uses `model_config="fast"`.
- `peanutgallery_service.py` — Fire-and-forget wrapper: subscribes to `TurnCompletedEvent`, runs every `PG_TRIGGER_INTERVAL = 5` segment turns via `ThreadPoolExecutor` + `contextvars.copy_context()` over a snapshot of `event.continuum.messages`, injects guidance into `PeanutGalleryTrinket` with `PG_GUIDANCE_TTL_TURNS = 2`. Swallows exceptions.
- `memory_relevance_service.py` — Thin CNS-side wrapper around `lt_memory.ProactiveService`: validates the 768d expansion embedding (raises `ValueError` otherwise), delegates to `search_with_embedding()`, returns `list[MemoryDict]`. Consumers: `orchestrator.py`.
- `portrait_service.py` — Module-level function service (no class). `synthesize_and_store()` builds a prose portrait from collapsed segment summaries (min `MIN_SUMMARIES = 3`, window of `ACTIVITY_DAY_WINDOW = 20` activity days) gated by `should_synthesize_portrait()` use-day modular arithmetic with an in-process dedup dict; stores on `users.portrait`. Read path: `read_portrait(user_id)` — working memory reads only; collapse is the sole automatic synthesis trigger. User refinement follows the preview contract (`refine_portrait()` → `accept_portrait()` / `decline_portrait()`), and acceptance invalidates the working-memory portrait cache. Uses `model_config="batch"`.
- `persona_service.py` — Persona pipeline (second system beside the user model; the user model describes the user, Persona prescribes to MIRA). `evaluate_segment()` scores a collapsed segment against the behavioral contract and stores `PersonaSignal`s (skips already-evaluated segments; a bare `<mira:persona_evaluation/>` means no signals). `refine_automatically_if_due()` appends a critic-validated revision on `PERSONA_REFINEMENT_USE_DAYS = 7` with optimistic parent-revision concurrency (`expected_parent_revision_id`). `create_preview()`/`accept_preview()`/`decline_preview()` implement the manual propose→preview→approve flow under the standard Valkey preview contract; `rollback()` re-appends a historical revision so `persona_revisions` stays append-only. Persists through `cns.infrastructure.persona_repository.PersonaRepository`; directives reach prompts through `PersonaTrinket` (`persona_directives` slot). Every LLM call uses `model_config="batch"`. Gated by `config.system.persona_enabled` (construction-time switch, not per-collapse). Malformed evaluator XML raises `PersonaParseError` and consumes a validation attempt.
- `manifest_query_service.py` — Segment data retrieval for manifest display (`get_segments()` → `list[ManifestSegment]`), Valkey-cached (`MANIFEST_CACHE_TTL = 3600`) with invalidation on `ManifestUpdatedEvent`. Formatting belongs to ManifestTrinket. Cache reads/writes tolerate Valkey outages with a warning and fall through to the DB query. Singleton via `initialize_manifest_query_service()` / `get_manifest_query_service()` split. Consumers: `working_memory` trinkets.
- `domaindoc_summary_service.py` — One-sentence DomainDoc section summaries via `model_config="fast"` (`update_section_summary(db, section_id, header, content)`), stored on the section record; failures log and never block the save. Lazy module-level prompt/provider singletons. Called from DomaindocTool and `cns/api/actions.py`.
- `lora_service.py` — User-model ("LoRA" is the legacy name) manual refinement service mirroring `portrait_service.py`: `read_lora()`, `refine_lora()` → `accept_lora()` / `decline_lora()` under the standard preview contract. Unlike synthesis, critic exhaustion still presents the last candidate to the user (user-initiated, user decides). Acceptance persists via `FeedbackTracker.set_synthesis_output()` and invalidates `LoraTrinket`. Reuses the `user_model_critic_*` prompts and section vocabulary from `system_prompt_parser`.
- `pollers/` — Segment-lifecycle-bound polling services; see the two files below (no separate map; the directory covers the coverage gate via its two members).
- `pollers/segment_poller.py` — `SegmentPoller` ABC: per-user daemon threads start on the first `ComposeSystemPromptEvent` (if `_try_load_config()` returns config) and stop on `SegmentCollapsedEvent` (5s join). Subclasses set `poll_interval_seconds` / `target_trinket` / `poller_name` and implement `_try_load_config()` (runs on the event-bus thread, user context available; returning None is a normal "not configured") and `_poll_once(config)` (runs on the copied-context daemon thread; None means transient failure, cycle skipped). Poll results publish `UpdateTrinketEvent` to `target_trinket`.
- `pollers/inbox_poller.py` — `InboxPollerService(SegmentPoller)`: IMAP unread-header poller every 180s → `EmailTrinket`, capped at `MAX_UNREAD_EMAILS = 20`, readonly + `BODY.PEEK` so flags are never set; headers only (From/Subject/Date/UID) for token economy. Loads `email_tool` config through `utils.tool_config_store.load_user_tool_config(..., hydrate_secrets=True)` so split secret fields exist only server-side; infrastructure failures propagate out of `_try_load_config()`, only "no config configured" returns None.

## Wiring

Memory surfacing (inside `orchestrator.process_message()`, via `_surface_memories()`): `subcortical.generate()` → LLM-guided retention applied to the previous turn's cache (`_apply_retention()`, matched by 8-char ID prefix) → pinned cap (`MAX_PINNED_MEMORIES=6`) → sliding fresh budget (`max(MIN_FRESH_MEMORIES=2, MAX_SURFACED_MEMORIES - pinned)`) → `memory_relevance_service` embedding search (query-expansion + recent-assistant-text, the latter via `_merge_assistant_memories()` gated by `ASSISTANT_SIMILARITY_THRESHOLD` and capped at `MAX_ASSISTANT_MEMORIES`, merged and deduped by ID) → hard cap to 8 (pinned-first, then fresh by score) → `UpdateTrinketEvent` → `ProactiveMemoryTrinket`, whose cached memories become next turn's retention input. The cap bounds that cache, so subcortical retention never sees more than 8 passages.

User model pipeline (triggered in the collapse chain by `_process_feedback_loop()`): `assessment_extractor.extract_signals()` → `FeedbackRepository.save_signals()` → on the 7-use-day threshold, `user_model_synthesizer.synthesize()` (critic loop) → `FeedbackTracker.mark_synthesized()` → LoRA trinket cache invalidation. `system_prompt_parser` supplies the anonymized prompt and section vocabulary to both steps. The Persona pass (`persona_service.evaluate_segment()` → cadence-gated `refine_automatically_if_due()`) runs on the same collapse chain as a parallel, independent system with its own repository and trinket — it neither feeds nor reads the user model.

Collapse ordering constraint: the sentinel collapse and `SegmentCollapsedEvent` must precede downstream processing — pollers stop and live-compaction artifacts clear on `SegmentCollapsedEvent`, and `_trigger_downstream_processing()` needs the collapsed sentinel id. `_process_persona` runs *earlier* than the tail — before the sentinel save — so its failures count toward the `MAX_COLLAPSE_ATTEMPTS` budget (see its Files bullet). `_trigger_downstream_processing` → `_process_feedback_loop` → `_process_portrait_synthesis` → `ManifestUpdatedEvent` is the tail order; `ManifestUpdatedEvent` last, so manifest cache invalidation reflects the completed collapse.

Live compaction loop: `orchestrator` checks `_last_turn_usage` against `config.api.compaction_trigger_tokens` → `LiveContextCompactionService.schedule()` (lock-guarded, single `ThreadPoolExecutor` worker) → `compact_once()` (`model_config="batch"`) replaces the Valkey artifact → next turn's `format_messages_for_api()` filters covered messages. Segment collapse invalidates the token baseline; a new segment starts compaction counting fresh.

Segment display formatting (cross-directory edge): `cns/core/message_formatter.py` calls `format_segment_for_display()` and `format_precis_for_display()` from `segment_helpers.py` at call time (deferred import breaking the circular dependency), routing on the ephemeral `display_mode` (`extended`/`precis`) metadata and wrapping the output in the synthetic `continuum_tool` tool_call/tool pair that carries collapsed-segment context into the LLM request. The display format is a two-file contract — changes to it are coordinated with `cns/core/message_formatter.py`; the owning statement lives in `cns/core/AGENTS.md` (Wiring).
