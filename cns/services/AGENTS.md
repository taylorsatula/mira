## Rules

- Process singletons here are constructed by `cns/integration/factory.py:create_cns_orchestrator` — except `SegmentTimeoutService`, built on first `register_timeout_job` from `utils/scheduled_tasks.py` — and reached through getters that raise RuntimeError before boot (`get_orchestrator`, `get_segment_collapse_handler`, `get_manifest_query_service`); the POST re-runs construction and checks `get_orchestrator() is orchestrator` (`utils/power_on_self_test.py:_check_dependency_initialization`). `PersonaService` is the exception — stateless over `cns/infrastructure/persona_repository.py`, constructed per consumer (collapse handler, `cns/api` handlers). A singleton built anywhere else never replaces the one the API layer calls — code verified against a hand-built instance silently never ships.
- Cancellation is a stop, never an error: `tool_loop.py:_execute_tool` re-raises `GenerationCancelled` ahead of its broad handler, a halt stops later parallel calls from starting but never abandons one already running, and the batch drains every started sibling's terminal event before re-raising the deferred cancel (`execute_tools`). A broad `except Exception` around tool execution converts a user halt into model-facing "the tool failed" text and the turn continues.
- Every tool stop yields text: `CircuitBreaker` trips only when the same tool fails twice on the same input hash, `ToolReportedError.from_result` makes `success: False` count as that failure, and all three finalization paths (breaker trip, `MAX_LOCAL_TOOL_CALLS_PER_TURN` exhaustion, tool request after disable) emit `CircuitBreakerEvent` plus fallback text. A breaker-stopped turn with blank output gets fixed model-error text instead of the blank-response raise — skip the finalization yields and the user receives nothing.
- Tool-result rendering (counterpart, producer side: `tools/implementations/AGENTS.md`): in `_execute_tool` a list passes verbatim as provider content blocks, a dict carrying `context_files` renders as JSON plus one `<context_file path>` text block per entry, any other dict `json.dumps`-es; `_image_artifact` is consumed only in `_consume_stream`, injected as streamed image markdown. The provider conversation keeps the full result; the durable row truncates at `TOOL_RESULT_MAX_CHARS` (31999) with JSON-list-aware slicing in `_build_turn_messages`. A new underscore-prefixed result key with no consumer here is invisible forever.
- Turn persistence order: `process_message` stages the user message in the `UnitOfWork` before any model work; each assistant step persists under its own `entry_id` (streamed text and durable text match per step; microsecond offsets keep the repository's `created_at DESC, id DESC` keyset stable); `TurnCompletedEvent` rides `add_post_commit_callback` — publish earlier and subscribers see pre-commit state. A stopped turn keeps partial text, commits the staged user message, publishes no `TurnCompletedEvent`; a completed turn with blank clean text raises rather than persisting emptiness.
- Effort is a two-value ladder: `SubcorticalResult.get_effort_level` emits only "low"/"high" — "medium" is absent from several providers' ladders and 400s every straightforward turn. The Valkey `effort_override:{user_id}` (3600s TTL; writer `cns/api/actions.py` set_effort_override, validated against `clients/llm/types.py:EFFORT_LEVELS`) wins and the `get_effort_level()` readout is skipped (the `"effort" not in llm_kwargs` guard) — the subcortical call itself still runs every enabled turn, because `_surface_memories` needs its query expansion for retrieval.
- The compose round-trip: `_compose_llm_messages` publishes `ComposeSystemPromptEvent` inside `working_memory/core.py:_compose_lock` and fails on `self._cached_content is None` — is-None, not falsy: trinket sections may legally be empty strings, and a truthiness check aborts every turn for a legitimately-empty compose. Post-history items re-compose before each local tool follow-up (tool mutations visible immediately); the notification center rides after the stable messages, immediately before the current user message, with `"cache": "1h"`.
- Collapse mutual exclusion lives in one UPDATE: `_claim_collapse` flips status to 'collapsing' only while the sentinel is active/paused or a prior claim is stale past `COLLAPSE_CLAIM_STALE_MINUTES` — the crash-recovery path, so a process death between claim and save never strands a segment. Scheduled timeout, manual collapse, and a racing tombstone all go through it; a loser gets zero rows and aborts. The pre-save re-read guard (status + `last_turn_at` unchanged) aborts on an interleaved turn instead of overwriting; an empty segment counts its attempt without claiming (a late message heals it); a tombstone also claims. Success and tombstone both publish `SegmentCollapsedEvent` and `ManifestUpdatedEvent` — poller stop and manifest-cache invalidation must fire on both.
- Collapse stage order is the exception policy: Persona evaluation runs before the sentinel save and propagates (persistent breakage counts toward `MAX_COLLAPSE_ATTEMPTS` and surfaces as the force-tombstone; `evaluate_segment`'s skip-guard makes a retry re-run nothing). Everything downstream runs after the save and never unwinds it: each stage tolerate-and-log, the sentinel flagged `downstream_failed`, the manifest publish in `finally`. The pending-memory drain runs first — the queue is the sole durable record of user-confirmed memories, so an extraction failure must not strand it. Move a stage across the save line and its failure semantics silently change.
- Pending-memory drain idempotence is the done marker, not the queue: `pending_memories_done:{user_id}:{pending_id}` is claimed by SET NX before the store because `store_memories` is not idempotent and two overlapping drains (this segment's drain + the rescue sweep over stranded `pending_memories:{user_id}:*` queues) would double-store. Only content-caused failures (`ValidationError`, `psycopg.errors.DataError`) consume the 3-attempt budget and dead-letter — the terminal marker carries a full item copy, repairable by hand; infrastructure failures release the claim uncounted (root doctrine "Retry Counters Never Gate Data on Infrastructure Failure", pinned at its load-bearing site). A queue deletes only when every item is durably consumed, else its TTL extends to `PENDING_QUEUE_RETRY_TTL_SECONDS` (7d); done markers outlive it (14d), which outlives the producer's 24h.
- One section vocabulary, three consumers: `system_prompt_parser.get_assessable_section_ids(config.system_prompt)` feeds the synthesis/refinement prompt examples (`{example_section_a}/{example_section_b}` — generated, never hand-written; a hand-written example drifts past the checker), `validate_section_anchors` (the single sanctioned check, attribute-order-independent, raising with the full valid set), and `cns/api/actions.py`'s manual user-model update before `set_synthesis_output`. The example fill requires ≥2 sections and raises at prompt load — fewer breaks loudly, not silently.
- Critic verdicts fail closed: an unparseable `<mira:critic_review`/`<mira:persona_review` status is a retryable failure, never a pass (`user_model_synthesizer._validate_with_critic`, mirrored in `lora_service`, `persona_service._validate_candidate`). Exhaustion splits by path: synthesis raises `CriticExhaustedError` so callers skip every destructive post-step (`mark_synthesized`, `mark_signals_synthesized`, the check-in consume) and inputs stay intact for retry; `refine_lora` presents the last candidate for human review — but `validate_section_anchors` still gates the exhaustion path; `create_preview` raises after `PERSONA_VALIDATION_ATTEMPTS`.
- Preview-before-save trio (`portrait_service`, `lora_service`, `persona_service`): Valkey key `{prefix}:{user_id}:{uuid4}`, 600s TTL, `GETDEL` single-consume (`_pop_preview` in each), accept persists and invalidates the trinket cache, decline no-ops on absence — the client never round-trips stored text. Persona's preview is a `PersonaPreview` JSON carrying `parent_revision_id`; accept CASes through `append_revision(expected_parent_revision_id=...)`.
- One Valkey hash, two trinket fields: `behavioral_directives` is LoraTrinket's cache field, `persona_directives` is PersonaTrinket's (`working_memory/trinkets/lora_trinket.py`, `working_memory/trinkets/persona_trinket.py`). Invalidate the field the edit changed: user-model synthesis and check-in responses hdel `behavioral_directives` (`segment_collapse_handler._invalidate_lora_trinket_cache`, `orchestrator._process_checkin_response`); Persona accept/rollback hdel `persona_directives` (`persona_service._invalidate_cache`); portrait accept goes through `working_memory.invalidate_portrait`. Swapped, the stale section stays cached and the fresh one drops.
- Timeout agreement: `segment_timeout_service._segment_activity_anchor` is the single source for both the timeout decision and the published `inactive_duration_minutes` — they agree by construction, and activity is keyed on the segment's own `segment_id` metadata, never on position. The live-turn guard is the `_user_request_lock.is_locked` probe in `check_timeouts`; its raise on Valkey failure propagates and fails the job, and `main.py`'s lifespan boot sweep re-runs `check_timeouts()` on the same singleton — a raise there refuses startup. An unverifiable "no turn in flight" must never default to collapsing. `last_turn_at` is only the crash grace for a turn that died uncommitted.
- `MAX_LOCAL_TOOL_CALLS_PER_TURN` (1000) bounds turn length alongside per-step timeouts, and its derived consumers size themselves from it (the HTTP chat lock TTL and ws/MCP timeout rationales — `cns/api/AGENTS.md`); change it without re-deriving those and their arithmetic breaks silently.
- The sentinel metadata vocabulary is a cross-directory contract: written by `segment_helpers.create_segment_boundary_sentinel`/`collapse_segment_sentinel` and the collapse claim/flags in `segment_collapse_handler`, read by `segment_timeout_service` (anchor), `manifest_query_service` (display), `cns/core/segment_cache_loader.py` (tier selection), `cns/core/message_formatter.py` (extended/precis display). A new key lands with its writer and every reader in one commit; persistence semantics owned by `cns/infrastructure/AGENTS.md` (`cns/infrastructure/continuum_repository.py`).

## Files

- `__init__.py` — docstring plus the `ContinuumOrchestrator` re-export (`__all__`); no in-repo consumer — callers import submodules (`cns/integration/factory.py` uses `from ..services.orchestrator import ContinuumOrchestrator`).
- `orchestrator.py` — the turn engine: compose round-trip, streaming tool loop, memory surfacing, per-step persistence, post-commit events. Entry: `process_message`, `_compose_llm_messages`, `_stream_model_tool_loop`, `_consume_stream`, `_surface_memories`, `_build_turn_messages`, `TurnAccumulator`. Gotcha: every step carrying a container id writes `container:{continuum_id}` to Valkey (1h) — no reader exists (`rg 'container:'` → this writer only); do not build on the key.
- `tool_loop.py` — local tool execution for the model-turn loop: sequential-then-parallel split, cancellation drain, input-hash circuit breaker, typed-parameter schema hints. Entry: `ToolLoopExecutor.execute_tools`, `CircuitBreaker.should_continue`, `ToolReportedError.from_result`. Gotcha: sequential tools run before parallel ones — a parallel+sequential pair in one response executes in reverse response order.
- `segment_collapse_handler.py` — the collapse pipeline: mutual-exclusion claim, summary + embedding, event fan-out, downstream stages (drain, extraction, feedback loop, Persona, portrait), tombstone circuit breaker, manual-collapse queue. Entry: `collapse_segment`, `handle_timeout`, `queue_manual_collapse`, `_process_pending_manual_memories`, `_process_feedback_loop`, `_process_persona`. Gotcha: `clear_user_context()` before `set_current_user_id()` at entry — set merges into the current context, and the timeout service collapses users sequentially on one thread, so a reused thread leaks the prior user's cached fields.
- `segment_timeout_service.py` — the 5-minute admin sweep: per-user timezone windows, activity anchor, lock probe, `SegmentTimeoutEvent` publish; job registration. Entry: `check_timeouts`, `_segment_activity_anchor`, `_is_timed_out`, `register_timeout_job`. Gotcha: morning (6–9 local) and late-night (23–≤6) overrides fall back to base `segment_timeout` when unset, and the timezone row read falls back to `config.system.timezone`.
- `segment_helpers.py` — sentinel constructors and display formatters; the writer of the segment metadata vocabulary. Entry: `create_segment_boundary_sentinel`, `collapse_segment_sentinel`, `format_segment_for_display`, `format_precis_for_display`, `create_collapse_marker`, `create_session_boundary_marker`. Gotcha: sentinel `created_at` = first message −1µs — chronological precedence over the messages it brackets, no insertion-order reliance; the `segment_id` param is honored only when passed (the API layer pre-allocates via contextvar so tools already saw the id).
- `summary_generator.py` — segment synopsis/precis/display_title/complexity on the batch route, with chunked hierarchical fallback on `ContextOverflowError` (~50k-token chunks; synthesis prompts optional at init, required if chunking ever runs). Entry: `generate_summary`, `_extract_summary_components`, `SummaryResult`. Gotcha: a response missing `<mira:display_title>` raises — the collapse handler's `processing_failed=True` tombstone is the designed degradation, never a silent empty summary; invalid complexity defaults to 2, missing precis only warns.
- `subcortical.py` — fast-route query expansion (replaces the raw query for retrieval), memory-retention evaluation with two-tier pressure alerts, entity extraction, effort assessment; optional vLLM prefix-cache warmup. Entry: `SubcorticalLayer.generate`, `warm_cache`, `SubcorticalResult.get_effort_level`. Gotcha: `_build_user_prompt` is the byte-exact shared source for `generate()` and `warm_cache()` — divergence silently breaks the prefix-cache hit (the optimization, not the response).
- `memory_relevance_service.py` — the CNS wrapper over `lt_memory.proactive:ProactiveService.search_with_embedding`; requires a precomputed embedding (None → ValueError), never re-embeds. No gotchas.
- `manifest_query_service.py` — manifest rows from sentinels, Valkey-cached. Entry: `get_segments`, `initialize_manifest_query_service`/`get_manifest_query_service`, `_handle_manifest_updated`. Gotcha: a Valkey outage degrades to the DB on both read and write failures (cache is optional infrastructure); `'collapsing'` surfaces as `'active'` — the mid-claim state lasts seconds and the segment is still open.

## Collapse: timeout to tombstone

1. The sweep (`segment_timeout_service.check_timeouts`, every 5 minutes, admin session across users): per active sentinel, the anchor is max of last committed message keyed on the segment's own id, sentinel `created_at` fallback, `last_turn_at` crash grace; the threshold is `segment_timeout` with local-hour overrides; a held per-user lock defers the segment (no event, no attempt). The published `inactive_duration_minutes` comes from the same anchor helper.
2. `handle_timeout` is the bus wrapper — it catches everything so a subscriber failure never unwinds dispatch; `collapse_segment` itself raises, because the actions API calls it directly and maps the errors. Two callers, one exception contract.
3. `collapse_segment` entry: clear-then-set the user contextvar, find the sentinel, check the attempt budget — `collapse_attempts ≥ MAX_COLLAPSE_ATTEMPTS` (3) routes to the tombstone path. An empty segment increments the budget without claiming (unfixable by retry: the sentinel persists atomically with its messages, so zero rows means a non-atomic save lost them) and raises; claim only after the cheap emptiness check.
4. Claim (`_claim_collapse`) flips 'collapsing'; summary + embedding run claimed (previous 5 collapsed segments feed narrative continuity; a missing `<mira:display_title>` raises — the retry budget owns it). Persona evaluation runs pre-save and propagates (persistent breakage surfaces as the force-tombstone); its skip-guard makes a post-failure retry a no-op.
5. Re-read guard: if `last_turn_at` moved (an interleaving turn) or status left active/paused/collapsing, abort before the save — the segment stays active, only this attempt's summary work is discarded. Save, invalidate the continuum pool, publish `SegmentCollapsedEvent`.
6. Downstream (post-save, per-stage tolerate-and-log, sentinel flagged `downstream_failed` on any failure): the pending-memory drain first (its rescue sweep also re-drains queues stranded by earlier downstream failures — done markers make re-drains safe), then extraction submission (False → raise → flag; extraction retries belong to the sweep owned by `lt_memory/processing/AGENTS.md`, never a second submit here), then the feedback loop (assessment → maybe synthesis; failures swallowed — the user model is a best-effort overlay), then portrait synthesis (use-day gate; failures swallowed). The manifest publish sits in `finally` — both the success and failure paths invalidate the cache.
7. Tombstone path: claim (no claim = someone else owns it), zero-vector embedding, `processing_failed=True`, publish both events, best-effort drain — a tombstoned segment's user-confirmed memories still must not strand on the queue.
8. Manual paths (entry in `cns/api/AGENTS.md`): the endpoint probes the per-user turn lock; held → `queue_manual_collapse` writes a single Valkey flag (24h TTL) consumed by `_handle_turn_completed` at the completing turn's `TurnCompletedEvent`, run on its own copied-context daemon thread; unheld → direct `collapse_segment` with exceptions mapped by the API.

Ordering invariants: contextvar clear-before-set (thread reuse); claim after the cheap check but before expensive work; drain before extraction; Persona before the save (counted in the budget), everything else after (never unwinds it); manifest always. Reorder any of these and a failure either loses user-confirmed memories or unwinds a durable collapse.
