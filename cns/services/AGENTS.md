# cns/services/ — Application services: turn orchestration, segment collapse, memory surfacing, and the user model / Persona pipelines

## Rules

- Services receive dependencies via constructor injection and call repository methods; SQL lives in `cns/infrastructure/`. The acknowledged exceptions are `segment_collapse_handler._load_segment_messages()` (defensive "stop at next boundary" query, documented in its docstring as accepted debt) and `_count_user_segments()`; `segment_timeout_service` is an admin-level scheduled job and uses `get_admin_session()` directly.
- Prompts load from `config/prompts/` via `config.prompts.loader.load_prompt()` in `__init__` or `_load_prompts()`. Never inline prompt strings. The template inventory is owned by `config/prompts/AGENTS.md` — add new files there, not here.
- `preprocess_content_blocks()` and `_MEDIA_BLOCK_TYPES` (owned by `cns/core/AGENTS.md` via `cns/core/message.py`) are the canonical multimodal preprocessing boundary. Import them; do not re-implement media stripping or truncation. Every service that renders message content for an LLM uses them (`live_context_compaction_service`, `summary_generator`, `peanutgallery_model`, `persona_service._format_messages`, `subcortical._format_recent_turns`).
- Exception policy split: critical-path services propagate (`orchestrator.process_message()`, `summary_generator.generate_summary()`, `segment_collapse_handler.collapse_segment()`). Fire-and-forget consumers log and swallow: `peanutgallery_service`, poller cycles (`SegmentPoller._poll_loop`), `subcortical.warm_cache()` / `_save_output()`, live-compaction scheduling, and the post-collapse `feedback`/portrait steps. The collapse chain itself is the boundary: everything after the sentinel save is best-effort, everything before raises. (`tool_result_summarizer`'s user-mismatch check is listed in the module's DISABLED note — the service is deadheaded pending redesign.)
- Background collapse is **not** a fail-loud path: by collapse time the model is off the call stack, so an exception discards data instead of prompting a clarifying question. `segment_collapse_handler._resolve_pending_memory_timezone()` resolves the user's timezone once per batch (falling back to UTC inside a guard — `memory_tool` queues `happens_at`/`expires_at` as naive local wall times) and `_parse_pending_temporal_field()` returns None with a diagnosable warning (raw value, timezone, parser reason) instead of raising. Never add a raise there and never mutate the memory text to compensate.
- Per-user collapse handling is a scheduled context: `collapse_segment()` starts with `clear_user_context()` then `set_current_user_id(event.user_id)` — the timeout service iterates users sequentially on one thread, so stale contextvars would leak across users. Background threads spawned in this directory follow the `cns/AGENTS.md` copy-context rule (pollers, `PeanutGalleryService`, live compaction, subcortical warmup, curator spawn).
- Model route convention for LLM calls in this directory: `"primary"` for all user-facing synthesis and chat, `"fast"` for high-frequency auxiliary calls (`subcortical`, `peanutgallery_model`, `domaindoc_summary_service`), `"batch"` for background synthesis/durability calls (`summary_generator`, `live_context_compaction_service`, `persona_service`, `user_model_synthesizer`, `lora_service`, `portrait_service`), `"assessment"` only in `assessment_extractor`. Route ownership and stall behavior live in `clients/llm/AGENTS.md`; there is no fallback route.
- Manual-revision previews (portrait, LoRA/user model, Persona) all follow one contract: LLM output stored in Valkey under `f"{prefix}:{user_id}:{preview_id}"` with a 600s TTL and an opaque `preview_id`, consumed once by `_pop_preview()`-style delete-after-read so the client never round-trips the stored text. A preview accepted after expiry raises `ValueError`, not a silent no-op.
- The user-model cache slot in the shared trinket hash is `"behavioral_directives"` (LoraTrinket, user model); Persona owns a separate `"persona_directives"` slot. Invalidating the wrong slot leaves the other stale — see the slot comment in `persona_service._invalidate_cache()`.

## Files

- `__init__.py` — Docstring plus a single re-export of `ContinuumOrchestrator`; all other services are imported from their modules directly.
- `orchestrator.py` — Owns the message→LLM→response cycle: memory surfacing, system prompt composition via `ComposeSystemPromptEvent` round-trip, the tool loop, context-overflow remediation, halt handling, and provider-step-ordered persistence. A cancelled turn never escapes `process_message`: one `except GenerationCancelled` guard spans every phase that can observe the cancel signal — memory surfacing (its subcortical LLM call) through the stream/tool loop — so a user halt or client disconnect converts to stopped-turn semantics (partial assistant response retained, staged user message committed, no `TurnCompletedEvent`) whichever phase it interrupts, instead of escaping to the transport as a `turn_error`; genuine failures still propagate. The guard logs one WARNING carrying `stop_reason` (`halt`|`disconnect` — the WS transport sets the reason; callers that set the bare event, like heartbeat's external cancel, get the default `halt`), turn/continuum/segment ids, and the consequence — the journal's only trace of a stopped turn, since `turn_stopped` frames reach only still-connected clients. Entry points: `process_message()`, `get_orchestrator()`, `initialize_orchestrator()`. Persistence builds one `Message` per provider step (`_build_turn_messages()`), each carrying only the text streamed under its own `entry_id`, with monotonic microsecond timestamps so repository keyset ordering stays stable. `ContextOverflowError` gets one deep request-shrink retry (`_apply_deep_context_overflow_fallback()`), then a second overflow persists the literal fallback `collapse the segment, please. incremental compaction failed` with `model_error_reason="incremental_compaction_failed"`. Loader-pass continuation is suppressed when the turn was halted (`auto_continuing` requires `not stopped`) — a stopped loader pass falls through to tag parsing and ends as a stopped turn, never a `turn_error` or an unintended continuation. `_compose_llm_messages` fails fast: after the `ComposeSystemPromptEvent` round-trip, `_cached_content is None` raises `RuntimeError` — the base prompt always lands, so None means the compose handler failed and a turn must never proceed with an empty system prompt. That reset → publish → field-read window runs under `working_memory.core._compose_lock` (process-wide compose serialization; `working_memory/AGENTS.md` owns the lock). Tool results stored in history are truncated via `_truncate_tool_result()` (`TOOL_RESULT_MAX_CHARS = 31999`; JSON arrays sliced to N complete elements, everything else raw chars). The compaction schedule check uses the **previous turn's provider-reported input tokens** (`self._last_turn_usage`), invalidated on `SegmentCollapsedEvent` — not a fresh estimate of the composed request. An invalid tool call (`invalid_reason`) is never persisted as an assistant tool_call, so schema-invalid arguments never replay on later turns. Effort comes from subcortical complexity unless a Valkey `effort_override:{user_id}` key (1h TTL) is present, which wins and skips the assessment. `TurnCompletedEvent.turn_number` counts user-role cache rows — tool and assistant rows and the transient scaffold (excluded by its own metadata flag) never inflate it. Exports `TurnMetadata`, `LLMKwargs`, `TurnAccumulator`, `AssistantStep`, `ToolInteraction`, `tool_stream_frame()`. Singleton via `get_orchestrator()`. Consumers: `cns/api/chat.py` (turns), `portrait_service`/`lora_service` (working-memory cache invalidation through `get_orchestrator().working_memory`).
- `live_context_compaction_service.py` — Background compaction of the active segment into a single rolling Valkey brief. `LiveContextCompactionStore` owns the per-user artifact (`live_context_compaction:{user_id}`) and a non-blocking per-user lock; repeated compactions keep the original `covered_start` and increment `compaction_count`. `LiveContextCompactionService.select_range()` loads DB-backed ranges while preserving the last `config.api.compaction_raw_user_turns_to_preserve` user turns raw; `compact_once()` formats XML role-tag history via `format_messages_for_live_compaction()` (tool results truncated to `TOOL_RESULT_TRUNCATION_LIMIT = 500`), calls `model_config="batch"`, and wraps the brief in `<mira:compacted_active_context>` with search recovery instructions. `format_messages_for_api()` / `get_visible_messages()` read the current artifact and drop only ordinary messages in `(covered_start, covered_end]` before delegating to `cns.core.message_formatter.format_messages_for_api()`; never mutates `Continuum.messages`. Gotcha: `get_visible_messages()` catches artifact-read failures and returns the full continuum (logged at error) so a Valkey outage degrades to uncompacted context instead of failing the turn. Exports `filter_messages_for_live_context()`, `LiveContextCompactionArtifact`, `LiveContextCompactionStore`. Consumers: `orchestrator.py` (scheduling + request assembly), `working_memory` segment-collapse clears the artifact through the stateful trinket.
- `tool_result_summarizer.py` — DISABLED (deadheaded 2026-09-30, human-directed): the factory no longer constructs it at startup; the module is kept for reference pending a REDESIGN of the compaction path (its two uncoordinated size-reduction layers and the wrapper-stripping text-mode branch are the recorded motivation — compaction-flow map attached to census-20260930b's sqdf ticket). Historical behavior, for the redesign's reference: post-commit hot-cache compactor subscribing to `ToolResultHistoryCommittedEvent`, LLM-compacting oversized committed tool results (>2000 chars, non-error, not a `get_tool_result` retrieval) in Valkey while PostgreSQL keeps the original. JSON results compacted structurally (`JsonCompactionDecision` keeps array indices or replaces one prose field, validated in `_apply_json_decision()`). Conditional cache patches carry `expected_content` so stale patches no-op. Compacted results gain the `continuum_tool.get_tool_result` breadcrumb via `cns/core/message_formatter.py`; retrieved results carry `tool_result_retrieved=True` and are never compacted again. Used `model_config="fast"`. Entry points: `initialize_tool_result_summarizer()` (not called), `get_tool_result_summarizer()` (raises if uninitialized). With the service off, the hot cache keeps full tool results, bounded only by the orchestrator's raw 31999-char truncation.
- `async_work_barrier.py` — Per-user latch (`register_work()` returns an idempotent `done()` callback; `wait_for_user()` blocks, timeout fails open with a warning) so chat entry points can wait for bounded cross-turn background work before loading the hot continuum. Single-process design. Entry points: `initialize_async_work_barrier()`, `get_async_work_barrier()`. Consumers: `tool_result_summarizer.py`, `cns/api/chat.py` and `cns/api/websocket_chat.py` (pre-turn wait).
- `tool_loop.py` — Orchestrator-owned local tool execution. `ToolLoopExecutor.execute_tools()` runs sequential vs parallel batches (split by `is_call_parallel_safe()`), emits `clients/llm/events.py` tool events, and honors cancellation (a started tool finishes; later parallel calls never start). `CircuitBreaker` trips when the same tool with the same input hash fails twice. Gotcha: a dict result with `success=False` is converted to `ToolReportedError` (`_execute_tool()`), otherwise the breaker would see success and let the model repeat the identical failing call forever. Parameter errors get a schema hint appended (`_schema_hint()`). Consumers: `orchestrator.py` only.
- `heartbeat_service.py` — The heartbeat wake cycle: a scheduler-initiated turn that asks MIRA to decide keepsleeping vs breakout. Entry points: `register_heartbeat_job()` (dispatcher job at `ticker_interval_seconds` cadence + one-shot 15s boot tick, registered from `main.py`; double-gated on `config.heartbeat.enabled`), `heartbeat_tick()` (re-checks config; enumerates users via `find_all_active_segments_admin()` and skips users whose sentinel metadata `heartbeat_wake_at` (a real sleep commitment) or `heartbeat_retry_at` (the failure backoff) is in the future), `cancel_heartbeat()` / `resume_heartbeat()` / `heartbeat_state()` (external control surface consumed by `cns/api/heartbeat_api.py`). Turn path: per-tick tokenized user lock (own `UserRequestLock` with `turn_lock_ttl_seconds` TTL — the TTL is a crash backstop, not a turn bound; a live tick releases by compare-and-delete token; the turn itself is wall-clock bounded by `heartbeat.turn_deadline_seconds` — a `threading.Timer` in `_run_heartbeat_turn` sets the turn's cancel event and the orchestrator stops the turn at the next stream/tool boundary under the external-cancel contract below: keepsleeping fallback, normal re-arm, no failure-streak entry — so a slow provider or tool-loop wandering cannot stretch one background turn to minutes of TURN_BUSY for chat) → `async_work_barrier.wait_for_user` → `find_active_segment()` resolves the segment id and sets the contextvar **without** `increment_segment_turn` (heartbeat turns must not bump turn counts or extraction cadence) → `orchestrator.process_message()` with a synthetic stimulus (metadata `heartbeat=true`, `tick_id`) and the heartbeat addendum appended to the system prompt → post-turn, the decision read from `heartbeat_tool`'s `heartbeat_log` is stamped onto the stimulus row as `heartbeat_decision`, and `_stamp_wake_at()` writes the next wake time onto the sentinel: keepsleeping honors the requested `wake_in_seconds` (no intervening ticks until then), every other usable outcome falls back to `interval_seconds`; a turn is FAILED in two forms with one accounting — it raised, or it completed without a valid confirm record (in-turn `heartbeat_tool` failures never raise out of the turn, so the missing `heartbeat_log` row for the tick is the signal, surfaced as `confirm_valid=False` in the turn result; an externally cancelled turn, `turn_metadata["stopped"]`, is exempt) — and a failed turn stamps `heartbeat_retry_at` and increments the `heartbeat_failures` counter instead: a backoff is not a sleep commitment, so the timeout sweep (which defers only on `heartbeat_wake_at`) cannot be starved by persistent failures, and once the counter reaches 3 the pre-turn `stamp_segment_liveness` is suspended (it would reset the sweep's inactivity clock the same way), letting the sweep collapse the segment — the terminal condition that bounds a stuck-model loop instead of re-arming one LLM turn per interval forever. Only a usable outcome (valid confirm or exempted cancel) resets the counter — the readback-fallback keepsleeping no longer does. Heartbeat stimuli never advance activity days — the repository's activity-day gates exclude `metadata.heartbeat="true"` user rows (see `cns/infrastructure/AGENTS.md`). Breakout turns push the final assistant message via `websocket_chat.push_proactive_message_sync` (the thread→loop bridge over the async `push_proactive_message`; `heartbeat_tick` is a plain sync callable that APScheduler runs off-loop in its threadpool — no asyncio in this service). Consumers keep *keepsleeping* heartbeat turns out of history/live-context/extraction/summaries by the `heartbeat`+`heartbeat_decision` metadata predicate and keep breakout turns visible — with one exemption: the **in-flight** turn (stimulus + same-`turn_id` rows) is exempted from the keepsleeping exclusion at compose time via `active_turn_id` threaded from `process_message`, because the decision stamp lands only post-commit; historical settled keepsleeping turns stay excluded.; `peanutgallery_service` skips heartbeat turns. Cancellation rides the standard `set_cancel_event` contextvar machinery; a cancelled heartbeat turn commits its stimulus row and falls back to the keepsleeping decision (the orchestrator converts cancellation to stopped-turn semantics — `cns/services/AGENTS.md` owns the mechanism — so an external cancel no longer stamps the failure backoff or increments `heartbeat_failures`, and the no-confirm failure accounting exempts it via the stopped-turn signal). Pregated mode (`wake_mode="pregated"`) wakes only when `sidebar_activity` changed since the last wake (in-memory stamp; resets on restart). Device binding: at the end of every `heartbeat_tick()` pass the dispatcher aggregates the earliest next wake obligation across all users (min `heartbeat_wake_at`, including freshly stamped ones) and publishes it to `utils.device_binding.notify_heartbeat_sleep` with the per-user wake schedule as the metadata routing field (see that map); any branch that obligates full power now — lock held (mid-turn), pregated-out, breakout, failed turn, failed wake stamp — sets the pass-level `stay_awake` flag and suppresses publishing. No active segments → nothing published.
- `subcortical.py` — Pre-LLM processing: query expansion (which *replaces* the raw query for retrieval), named-entity extraction, retention pin evaluation, and complexity assessment from `<query_expansion>`, `<entities>`, `<complexity>`, `<passage>` tags. `generate()` returns `SubcorticalResult` and raises on empty/unparseable responses — never returns None. Uses `model_config="fast"`. The pressure vocabulary is shared with the orchestrator via `lt_memory/proactive.py` constants: warning at `MAX_PINNED_MEMORIES=6`, critical at `MAX_SURFACED_MEMORIES=8`; under pressure the conversation window narrows to 2 pairs (`CONTEXT_PAIRS=3` normally) and passage text truncates to 15 words. Memory IDs pinned by regex from the conversation text are unioned with the LLM's picks, so conversation-mentioned memories are always retained. `warm_cache()` fires a max_tokens=1 prefill-warming call only when `prefill_warmup_enabled` (vLLM-only optimization; billed waste on cloud providers) and requires `_build_user_prompt()` to be byte-identical to the real call. Debug prompt/response pairs persist under `data/users/{user_id}/subcortical_debuglogs/`. Complexity→effort (`SubcorticalResult.get_effort_level()`) emits only `low` (straightforward) or `high` (complex): `medium` is absent from several provider ladders (DeepSeek V4.1 accepts low/high/xhigh/max only), so deriving it 400s every straightforward turn. Consumers: `orchestrator.py` (`generate`, `warm_cache`), `SurfacedMemory`/`SubcorticalResult` types.
- `summary_generator.py` — Segment summary generation (`generate_summary()` → `SummaryResult(synopsis, precis, display_title, complexity)`), thinking enabled, `model_config="batch"`. On `ContextOverflowError`, falls back to hierarchical chunking (~200k chars per chunk, `_CHUNK_TARGET_CHARS`) with synthesis prompts loaded `required=False`; if chunking also fails, raises. A missing `<mira:display_title>` tag — empty output, refusal, or reasoning tokens that consumed the budget before content — raises `ValueError` so the collapse handler's retry + `MAX_COLLAPSE_ATTEMPTS` force-tombstone owns degradation (a silent generator-level tombstone is indistinguishable from a real summary downstream). Previous collapsed sentinels (last 5) feed narrative continuity; only the first chunk receives them. Imports `preprocess_content_blocks` from `cns.core.message`.
- `segment_collapse_handler.py` — Owns the `SegmentTimeoutEvent` response. Entry points: `collapse_segment(event)` (raises on failure; also called by the actions API which needs exceptions), `handle_timeout()` (subscriber wrapper that swallows and lets failures count toward `MAX_COLLAPSE_ATTEMPTS = 3` before tombstoning), singletons `get_segment_collapse_handler()` / `initialize_segment_collapse_handler()`. Chain: sentinel lookup → empty-check (a still-processing turn raises before any attempt is burned) → attempt counter claimed via compare-and-set (`UPDATE ... WHERE status IN ('active','paused') RETURNING`; no row means another collapse claimed it and this one raises) *before* the expensive LLM call → summary+embedding → Persona pass → `collapse_segment_sentinel()` → pre-save recheck (re-read the sentinel; abort unless still active/paused with unchanged `last_turn_at` — an interleaved turn stays visible, only this attempt's summary work is discarded) → save → `SegmentCollapsedEvent` → downstream (extraction via `lt_memory_factory.extraction_orchestrator.submit_segment_extraction()`, pending manual memories) → user-model feedback loop → portrait gate → `ManifestUpdatedEvent`. `_load_segment_messages()` stops at the next boundary sentinel even though the repo query already fetched past it. The `on_memories_stored` callback seam (`_on_memories_stored`) lets lt_memory spawn `MemoryCuratorAgent` without importing `agents/` — the handler owns `tool_repo` + `event_bus`. The Persona pass (`_process_persona`) deliberately does not catch inside collapse and runs *before* the sentinel save, so failures propagate to the retry + `MAX_COLLAPSE_ATTEMPTS` budget instead of stranding a collapsed segment with its persona signal lost; `evaluate_segment` is idempotent per segment via the `persona_state.latest_evaluated_segment_id` pointer (`segment_was_evaluated`) — a known edge: the pointer comparison can miss if a different segment evaluates between a post-persona flip failure and the retry, so a failed flip save followed by an interleaved clean collapse can duplicate one segment's signals. Unlike `_process_feedback_loop` and `_process_portrait_synthesis`, which swallow because the segment is already saved. Consumers: `cns/integration` factory (construction), `cns/api/actions.py` (manual collapse). Its `_find_memory_by_short_id` (supersedes linking of pending manual memories) uses the LIMIT 2 ambiguity-raise contract owned by `tools/implementations/AGENTS.md`. The pending-manual drain (`_process_pending_manual_memories`) owns the drain-side store contract: every stored row carries `source_segment_id` parsed from its queue key by `_segment_provenance_from_queue_key()` (the collapsed segment's own queue AND each rescue-swept older queue keep their truthful segment; the `presegment` queue has none), and drain-stored rows get the SAME entity treatment extraction-stored memories get — one `model_config="batch"` entity pass over the batch (`_extract_pending_entities`, prompt pair `pending_memory_entities_*`, output keyed by `pending_id`, format example generated from the `PENDING_ENTITY_*` key constants) linked through the shared `persist_llm_entities()` (`lt_memory/processing/execution_strategy.py`) — so both store paths converge on one entity-linking contract instead of two. Both passes are tolerate-and-log: the memories are the deliverable; a failure stores them without tags (or with provenance None) and logs the recall consequence, never retrying or dead-lettering the item.
- `segment_helpers.py` — Pure sentinel utilities: `create_segment_boundary_sentinel()` (sentinel `created_at` precedes the first message by 1µs so chronological queries place it correctly), `collapse_segment_sentinel()` (returns a new immutable `Message`; embedding rides in metadata for the repository to extract), `format_segment_for_display()` / `format_precis_for_display()`, `create_collapse_marker()`, `create_session_boundary_marker()`. Canonical place for sentinel operations — never construct or parse sentinel messages manually.
- `segment_timeout_service.py` — Scheduled admin job (every 5 min, `register_timeout_job()`) that queries all users' active segments and publishes `SegmentTimeoutEvent` for those past the inactivity threshold. Threshold is time-of-day aware in the segment owner's local timezone (`segment_timeout_morning` / `segment_timeout_late_night` overrides, falling back to `config.system.segment_timeout`). Last-activity time is the max of the last committed message and the sentinel's `last_turn_at` (stamped atomically at user-message arrival, before uow commit — without this a resumed segment looks timed-out). `_is_timed_out` first checks the sentinel's `heartbeat_wake_at`: a pending or in-flight heartbeat wake (now < wake_at + `config.heartbeat.wake_grace_seconds`) is a liveness commitment, so the segment is not timed out — this is what keeps a long MIRA sleep from collapsing the session; a malformed stamp is warned and ignored. Orphaned segments with no messages use sentinel creation time so they reach the collapse tombstone naturally. Returns `TimeoutCheckResult` TypedDict; re-raises after logging (fail-loud scheduled job).
- `assessment_extractor.py` — User model pipeline step 1: `extract_signals()` evaluates a collapsed segment against the *anonymized* system prompt sections, producing `AssessmentSignal`s (`alignment`/`misalignment`/`contextual_pass` × `strong`/`moderate`/`mild` + evidence). Uses `model_config="assessment"`. Thinking traces (`reasoning` blocks) are included only when they exceed `THINKING_INCLUSION_THRESHOLD = 0.7` of assistant content. Imports `_MEDIA_BLOCK_TYPES` from `cns.core.message`.
- `user_model_synthesizer.py` — User model pipeline step 2: `synthesize()` turns unsynthesized signals into section-anchored `UserObservation`s with a critic validation loop (`CRITIC_MAX_ATTEMPTS = 3`). Deterministic section-anchor validation (`_validate_section_anchors` → `system_prompt_parser.validate_section_anchors`) runs before the LLM critic each attempt — an invalid anchor retries with feedback naming the valid set and exhaustion raises like any critic failure; never left for the critic to catch. On critic exhaustion it keeps the *previous* model rather than injecting known-suspect content (unless no previous model exists). Also consumes atomically-cleared check-in feedback (`FeedbackTracker.get_and_clear_checkin_response()`, stored by `orchestrator._process_checkin_response()`). All calls use `model_config="batch"`. The `user_model_critic_system.txt` / `user_model_critic_user.txt` prompt pair is shared with `lora_service.py` — a change to either file must be checked against both consumers. The synthesis system/user prompts are templates: changelog examples use `{example_section_a/b}` filled at load, and the user template injects `{section_id_list}` — both generated from the assessable taxonomy (`cns/services/AGENTS.md` `system_prompt_parser` bullet), never hand-written. Exports `UserObservation`, `CriticResult`, `SynthesisResult`.
- `system_prompt_parser.py` — Pure utilities shared by the user-model pipeline and `lora_service`: `get_assessable_sections()` (top-level sections only, `user`/`environment` blocklisted), `get_assessable_section_ids()` (the canonical section vocabulary in prompt order — single source for prompt examples and validation), `validate_section_anchors()` (deterministic check that every `<mira:observation>`/`<mira:topic>` `section` attribute names an assessable section; raises `ValueError` naming the invalid anchor and the valid set; attribute-order independent — the sanctioned path, run before any user model is stored or previewed), `anonymize_prompt()` (strips template vars and user-identifying sections), `format_section_list()`. No LLM calls.
- `peanutgallery_model.py` — Single-stage metacognitive observer (`evaluate()` → `PeanutGalleryResult`). Actions: `noop`, `concern`, `coaching`, `initiative`; `concern`/`coaching` may carry `severity="critical"` for user-facing repair authorization (`initiative` is never critical). Parses `<mira:peanutgallery>` attributes order-independently. Builds an execution-trace ledger (latest user request, latest response, assistant commitments, tool activity) and judges only current-session evidence; messages are formatted with 8-char IDs. Uses `model_config="fast"`.
- `background_digest.py` — Pluggable sources for the heartbeat wake briefing. `BackgroundDigestContributor` protocol (`name()` + `contribute(user_id) -> list[str]`, header line first, `[]` to stay silent) with a module-level registry (`register_background_digest_contributor`, order = digest order) and `build_background_digest(user_id)` as the single consumer entry point. Failure contract: required infrastructure may propagate (the wake fails and retries); an optional external source catches its own failure and renders it in band ("surface unavailable: ...") so the wake still happens. Contributors are process-global singletons — per-user state comes from the argument, never instance attributes. Built-ins self-register at import: `SidebarActivityContributor` (24h window, 15 rows, `interface_name` provenance marker) and `HeartbeatDecisionsContributor` (last 5 decisions). The module docstring carries a worked example for an optional external source. Sole consumer: `heartbeat_service.py` stimulus build.
- `peanutgallery_service.py` — Fire-and-forget wrapper: subscribes to `TurnCompletedEvent`, runs every `PG_TRIGGER_INTERVAL = 5` segment turns via `ThreadPoolExecutor` + `contextvars.copy_context()` over a snapshot of `event.continuum.messages`, injects guidance into `PeanutGalleryTrinket` with `PG_GUIDANCE_TTL_TURNS = 2`. Swallows exceptions. Heartbeat turns are skipped (`heartbeat_service.py` guard): the scheduler talking to itself must not trigger observation.
- `memory_relevance_service.py` — Thin CNS-side wrapper around `lt_memory.ProactiveService`: requires an expansion embedding (raises `ValueError` on None; vector length is enforced by the embeddings provider), delegates to `search_with_embedding()`, returns `list[MemoryDict]`. Consumers: `orchestrator.py`.
- `portrait_service.py` — Module-level function service (no class). `synthesize_and_store()` builds a prose portrait from collapsed segment summaries (min `MIN_SUMMARIES = 3`, window of `ACTIVITY_DAY_WINDOW = 20` activity days) gated by `should_synthesize_portrait()` use-day modular arithmetic with an in-process dedup dict; stores on `users.portrait`. Read path: `read_portrait(user_id)` — working memory reads only; a failed read logs and returns `""` (portrait is genuine domain optionality; the compose None-guard in `orchestrator._compose_llm_messages` is the fail-fast boundary); collapse is the sole automatic synthesis trigger. User refinement follows the preview contract (`refine_portrait()` → `accept_portrait()` / `decline_portrait()`), and acceptance invalidates the working-memory portrait cache. Uses `model_config="batch"`.
- `persona_service.py` — Persona pipeline (second system beside the user model; the user model describes the user, Persona prescribes to MIRA). `evaluate_segment()` scores a collapsed segment against the behavioral contract and stores `PersonaSignal`s (skips already-evaluated segments; a bare `<mira:persona_evaluation/>` means no signals). `refine_automatically_if_due()` appends a critic-validated revision on `PERSONA_REFINEMENT_USE_DAYS = 7` with optimistic parent-revision concurrency (`expected_parent_revision_id`). `create_preview()`/`accept_preview()`/`decline_preview()` implement the manual propose→preview→approve flow under the standard Valkey preview contract; `rollback()` re-appends a historical revision so `persona_revisions` stays append-only. Persists through `cns.infrastructure.persona_repository.PersonaRepository`; directives reach prompts through `PersonaTrinket` (`persona_directives` slot). Every LLM call uses `model_config="batch"`. Gated by `config.system.persona_enabled` (construction-time switch, not per-collapse). Malformed evaluator XML raises `PersonaParseError` and consumes a validation attempt.
- `manifest_query_service.py` — Segment data retrieval for manifest display (`get_segments()` → `list[ManifestSegment]`), Valkey-cached (`MANIFEST_CACHE_TTL = 3600`) with invalidation on `ManifestUpdatedEvent`. Formatting belongs to ManifestTrinket. Cache reads/writes tolerate Valkey outages with a warning and fall through to the DB query. Singleton via `initialize_manifest_query_service()` / `get_manifest_query_service()` split. Consumers: `working_memory` trinkets.
- `domaindoc_summary_service.py` — One-sentence DomainDoc section summaries via `model_config="fast"` (`update_section_summary(db, section_id, header, content)`), stored on the section record; failures log and never block the save. Lazy module-level prompt/provider singletons. Called from DomaindocTool and `cns/api/actions.py`.
- `lora_service.py` — User-model ("LoRA" is the legacy name) manual refinement service mirroring `portrait_service.py`: `read_lora()`, `refine_lora()` → `accept_lora()` / `decline_lora()` under the standard preview contract. `refine_lora()` deterministically validates section anchors (`system_prompt_parser.validate_section_anchors`) after the critic loop and before the preview is stored — an invalid anchor raises `ValueError` naming the valid set (caller-facing 400 via the handler; it also gates the critic-exhaustion circuit breaker: an invalid anchor is never presentable). The refinement user message injects the valid-section list, and the `lora_refinement_system.txt` example's section anchors are `{example_section_a/b}` placeholders filled from the assessable taxonomy at load — generated, never hand-written. Unlike synthesis, critic exhaustion still presents the last candidate to the user (user-initiated, user decides). Acceptance persists via `FeedbackTracker.set_synthesis_output()` and invalidates `LoraTrinket`. Reuses the `user_model_critic_*` prompts and section vocabulary from `system_prompt_parser`.
- `pollers/` — Segment-lifecycle-bound polling services; see the two files below (no separate map; the directory covers the coverage gate via its two members).
- `pollers/segment_poller.py` — `SegmentPoller` ABC: per-user daemon threads start on the first `ComposeSystemPromptEvent` (if `_try_load_config()` returns config) and stop on `SegmentCollapsedEvent` (5s join). Subclasses set `poll_interval_seconds` / `target_trinket` / `poller_name` and implement `_try_load_config()` (runs on the event-bus thread, user context available; returning None is a normal "not configured") and `_poll_once(config)` (runs on the copied-context daemon thread; None means transient failure, cycle skipped). Poll results publish `UpdateTrinketEvent` to `target_trinket`.
- `pollers/inbox_poller.py` — `InboxPollerService(SegmentPoller)`: IMAP unread-header poller every 180s → `EmailTrinket`, capped at `MAX_UNREAD_EMAILS = 20`, readonly + `BODY.PEEK` so flags are never set; headers only (From/Subject/Date/UID) for token economy. Loads `email_tool` config through `utils.tool_config_store.load_user_tool_config(..., hydrate_secrets=True)` so split secret fields exist only server-side; infrastructure failures propagate out of `_try_load_config()`, only "no config configured" returns None.

## Wiring

Memory surfacing (inside `orchestrator.process_message()`, via `_surface_memories()`): `subcortical.generate()` → LLM-guided retention applied to the previous turn's cache (`_apply_retention()`, matched by 8-char ID prefix) → pinned cap (`MAX_PINNED_MEMORIES=6`) → sliding fresh budget (`max(MIN_FRESH_MEMORIES=2, MAX_SURFACED_MEMORIES - pinned)`) → `memory_relevance_service` embedding search (query-expansion + recent-assistant-text, encoded in parallel by `_compute_embeddings_parallel()` under the provider's `max_encode_seconds` bound — a timeout raises `TimeoutError` and fails the turn; the latter via `_merge_assistant_memories()` gated by `ASSISTANT_SIMILARITY_THRESHOLD` and capped at `MAX_ASSISTANT_MEMORIES`, merged and deduped by ID) → hard cap to 8 (pinned-first, then fresh by score) → `UpdateTrinketEvent` → `ProactiveMemoryTrinket`, whose cached memories become next turn's retention input. The cap bounds that cache, so subcortical retention never sees more than 8 passages.

User model pipeline (triggered in the collapse chain by `_process_feedback_loop()`): `assessment_extractor.extract_signals()` → `FeedbackRepository.save_signals()` → on the 7-use-day threshold, `user_model_synthesizer.synthesize()` (critic loop) → `FeedbackTracker.mark_synthesized()` → LoRA trinket cache invalidation. `system_prompt_parser` supplies the anonymized prompt and section vocabulary to both steps. The Persona pass (`persona_service.evaluate_segment()` → cadence-gated `refine_automatically_if_due()`) runs on the same collapse chain as a parallel, independent system with its own repository and trinket — it neither feeds nor reads the user model.

Collapse ordering constraint: the sentinel collapse and `SegmentCollapsedEvent` must precede downstream processing — pollers stop and live-compaction artifacts clear on `SegmentCollapsedEvent`, and `_trigger_downstream_processing()` needs the collapsed sentinel id. `_process_persona` runs *earlier* than the tail — before the sentinel save — so its failures count toward the `MAX_COLLAPSE_ATTEMPTS` budget (see its Files bullet). `_trigger_downstream_processing` → `_process_feedback_loop` → `_process_portrait_synthesis` → `ManifestUpdatedEvent` is the tail order; `ManifestUpdatedEvent` last, so manifest cache invalidation reflects the completed collapse.

Live compaction loop: `orchestrator` checks `_last_turn_usage` against `config.api.compaction_trigger_tokens` → `LiveContextCompactionService.schedule()` (lock-guarded, single `ThreadPoolExecutor` worker) → `compact_once()` (`model_config="batch"`) replaces the Valkey artifact → next turn's `format_messages_for_api()` filters covered messages. Segment collapse invalidates the token baseline; a new segment starts compaction counting fresh.

Segment display formatting (cross-directory edge): `cns/core/message_formatter.py` calls `format_segment_for_display()` and `format_precis_for_display()` from `segment_helpers.py` at call time (deferred import breaking the circular dependency), routing on the ephemeral `display_mode` (`extended`/`precis`) metadata and wrapping the output in the synthetic `continuum_tool` tool_call/tool pair that carries collapsed-segment context into the LLM request. The display format is a two-file contract — changes to it are coordinated with `cns/core/message_formatter.py`; the owning statement lives in `cns/core/AGENTS.md` (Wiring).
