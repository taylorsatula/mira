# cns/services/ — Stateless service layer: orchestration, processing, user model pipeline, and persona pipeline

## Rules

- No direct DB access. Services receive repositories via constructor injection and call repository methods only. SQL belongs in `cns/infrastructure/`.
- Prompts load from `config/prompts/` as `.txt` files in `__init__` or `_load_prompts()`. Never inline prompt strings as constants.
- `preprocess_content_blocks()` (from `cns.core.message`) is the canonical way to handle multimodal content (images, documents, tool results) before formatting for LLM input. Import it; don't re-implement truncation or media-block stripping.
- Non-critical fire-and-forget services (`peanutgallery_service`, feedback loops) swallow exceptions after logging. Critical-path services (`orchestrator`, `summary_generator`, `segment_collapse_handler`) let exceptions propagate.
- Background collapse is **not** a fail-loud path: the model is off the call stack, so an exception discards data instead of prompting a clarifying question. `segment_collapse_handler._process_pending_manual_memories()` resolves the user's timezone once per collapse via `_resolve_pending_memory_timezone()` (`memory_tool` queues `happens_at`/`expires_at` as naive local wall times, so the system default of UTC is wrong for every non-UTC user) and `_parse_pending_temporal_field()` stores the memory text with the field dropped and a diagnosable warning when a value will not parse. Never add a raise there and never mutate the memory text to compensate.

## Files

- `orchestrator.py` — Owns the message→LLM→response cycle: memory surfacing, system prompt composition, tool execution loop, live-compaction scheduling, provider-overflow retry fallback, halt handling, and provider-step-ordered persistence of assistant text, thinking, and tool results. Proactive compaction checks estimate the current composed request directly; they never reuse a prior turn's provider-reported count and never slice the active request. `ContextOverflowError` triggers one deep request shrink retry, then persists `collapse the segment, please. incremental compaction failed` with `model_error_reason="incremental_compaction_failed"` on the second overflow. Tool results are truncated at storage time via `_truncate_tool_result()` (`TOOL_RESULT_MAX_CHARS = 31999`) — JSON arrays are sliced to N complete elements, other formats get raw character truncation. Singleton via `get_orchestrator()`. Exports `TurnMetadata`, `LLMKwargs`, `ToolInteraction`, `AssistantStep`, `TurnAccumulator`, and `tool_stream_frame()`.
- `live_context_compaction_service.py` — Background active-chat compactor, Valkey artifact store, and request-scoped live-compaction filter. `LiveContextCompactionStore` manages the single per-user Valkey artifact (`live_context_compaction:{user_id}`) plus non-blocking per-user lock; segment collapse clears it through the stateful trinket. `LiveContextCompactionService` selects DB-backed ranges while preserving the last N user-started turns (config: `compaction_raw_user_turns_to_preserve`), formats XML role-tag history via `format_messages_for_live_compaction()`, calls the LLM with `model_config="primary"`, and replaces the single Valkey brief. Repeated compactions pass the prior brief as an assistant message and the new raw slice as a user message. Also owns `format_messages_for_api()` and `get_visible_messages()` which read the current Valkey artifact and omit only ordinary messages in `(covered_start, covered_end]` before calling `cns.core.message_formatter.format_messages_for_api()`. Never mutates `Continuum.messages`. Exports `filter_messages_for_live_context()`, `TOOL_RESULT_TRUNCATION_LIMIT`, `LiveContextCompactionArtifact`, and `LiveContextCompactionStore`. Compaction starts when the current request estimate reaches `config.api.compaction_trigger_tokens`.
- `tool_result_summarizer.py` — Post-commit hot-cache tool-result compactor. Oversized string results are LLM-compacted in Valkey while PostgreSQL keeps the original. `message_formatter.py` adds an ephemeral `continuum_tool.get_tool_result` breadcrumb beside compacted content. Uses `ToolResultHistoryCommittedEvent`, conditional cache patches, and `AsyncWorkBarrier`; restored exact results carry `tool_result_retrieved=True` and are never compacted again.
- `async_work_barrier.py` — Per-user latch for bounded cross-turn background work. Chat entry points wait before loading the hot continuum; completion callbacks are idempotent.
- `tool_loop.py` — Orchestrator-owned local tool execution helper. Runs sequential/parallel tool batches with contextvar propagation, emits `clients.llm.events` tool events, and owns circuit-breaker loop detection.
- `subcortical.py` — Pre-LLM processing step. `generate()` returns `SubcorticalResult` (never None — raises on failure). Produces query expansion, named entity extraction, retention pin evaluation, and complexity assessment via `<query_expansion>`, `<entities>`, `<complexity>`, `<passage>` tags. Uses `model_config="fast"`.
- `summary_generator.py` — Segment summary generation with thinking enabled and hierarchical chunking for oversized segments. Returns `SummaryResult(synopsis, precis, display_title, complexity)`. Uses `model_config="primary"`. Imports `preprocess_content_blocks` from `cns.core.message`.
- `segment_collapse_handler.py` — Owns the `SegmentTimeoutEvent` response: sentinel lookup → summary → embedding → collapse → lt_memory extraction → feedback/user-model loop → persona pass (when enabled) → portrait gate. `collapse_segment(event)` raises on failure; `handle_timeout` wraps it and swallows, counting failures toward the `MAX_COLLAPSE_ATTEMPTS` tombstone — the Persona pass deliberately does not catch inside collapse (a persistent Persona breakage surfaces via the tombstone budget rather than silently stopping revision history). Singleton via `get_segment_collapse_handler()`.
- `segment_helpers.py` — Pure utility functions for sentinel creation, collapse, display formatting, and marker creation. Exports `format_segment_for_display()` (extended summaries) and `format_precis_for_display()` (2-sentence precis). Canonical place for sentinel operations — never construct or parse sentinel Messages manually.
- `segment_timeout_service.py` — Scheduled admin-level job (every 5 min) that queries across all users for active segments (excludes paused) past timeout threshold and publishes `SegmentTimeoutEvent`. Returns `TimeoutCheckResult` TypedDict. Paused segments are invisible to this service — they never time out until the user resumes them (auto-resume on next message or explicit unpause).
- `assessment_extractor.py` — User model pipeline step 1. Evaluates conversation against anonymized system prompt sections, producing `AssessmentSignal` objects (`alignment`/`misalignment`/`contextual_pass`). Uses `model_config="assessment"`. Imports `_MEDIA_BLOCK_TYPES` from `cns.core.message` for conversation formatting.
- `user_model_synthesizer.py` — User model pipeline step 2. Synthesizes section-anchored observations from assessment signals with a critic validation loop (up to 3 attempts). Exports `UserObservation`, `CriticResult`, `SynthesisResult`. Uses `model_config="primary"` for synthesis and the critic.
- `system_prompt_parser.py` — Pure utility: extracts section IDs, anonymizes system prompt XML, formats section lists. Used by `assessment_extractor` and `user_model_synthesizer`. No LLM calls.
- `peanutgallery_model.py` — Single-stage `model_config="primary"` observer for metacognitive guidance. Returns `PeanutGalleryResult` with action `noop`/`concern`/`coaching` plus `critical` severity for user-facing repair authorization. Parses `<mira:peanutgallery>` attributes order-independently so prompt examples can evolve without breaking severity extraction. Builds an execution-trace ledger from recent commitments/tool activity and judges only current-session evidence. Imports `preprocess_content_blocks` from `cns.core.message` for multimodal formatting.
- `peanutgallery_service.py` — Fire-and-forget async wrapper around `PeanutGalleryModel`. Subscribes to `TurnCompletedEvent`, snapshots `event.continuum.messages` before dispatch, runs every N turns via `ThreadPoolExecutor` with `contextvars.copy_context()`, and injects directives into `PeanutGalleryTrinket`, including the `critical` flag for user-facing repairs. Swallows exceptions.
- `memory_relevance_service.py` — Thin wrapper around `lt_memory.ProactiveService`. Validates 768d embedding, delegates search. Returns `list[MemoryDict]`.
- `portrait_service.py` — Synthesizes a prose user portrait (150–250 words) from collapsed segment summaries. Read-only at turn time via `read_portrait(user_id)`; synthesis triggered by segment collapse chain, gated by use-day modular arithmetic. Uses `model_config="primary"`. Stores result on `users.portrait`.
- `persona_service.py` — Persona pipeline (second system beside the user model). `evaluate_segment()` scores a collapsed segment against the behavioral contract and stores `PersonaSignal`s; `refine_automatically_if_due()` appends a revision on the use-day cadence via a critic-validated candidate; `create_preview()`/`accept_preview()`/`decline_preview()` implement the propose→preview→approve flow (candidate held in Valkey under an opaque `preview_id`, never round-tripped through the client); `rollback()` re-appends a historical revision so `persona_revisions` stays append-only. Persists through `cns.infrastructure.persona_repository.PersonaRepository`; directives reach prompts through `PersonaTrinket` (`persona_directives`). Every LLM call uses `model_config="primary"`. Gated by `config.system.persona_enabled`.
- `manifest_query_service.py` — Segment data retrieval for manifest display. Valkey-cached with event-driven invalidation on `ManifestUpdatedEvent`. Singleton via `initialize_manifest_query_service()` / `get_manifest_query_service()` split. Exports `ManifestSegment` TypedDict.
- `domaindoc_summary_service.py` — One-sentence section summaries for DomainDoc via `model_config="fast"`. Module-level singletons with lazy init.
- `pollers/segment_poller.py` — `SegmentPoller` ABC: generic base for services that poll external sources during active conversation segments. Per-user daemon threads start on `ComposeSystemPromptEvent`, stop on `SegmentCollapsedEvent`. Subclasses implement `_try_load_config()` and `_poll_once(config)`.
- `pollers/inbox_poller.py` — `InboxPollerService(SegmentPoller)`: IMAP subclass. Polls unread email headers every 3 minutes, publishes to `EmailTrinket` via `UpdateTrinketEvent`. Lightweight IMAP (readonly, PEEK, headers only). Loads email tool config through `utils.tool_config_store.load_user_tool_config(..., hydrate_secrets=True)` so split secret fields are available only server-side.

## Wiring

Memory surfacing pipeline (inside `orchestrator.process_message()`): `subcortical.generate()` (pressure warning at 6 surfaced memories, critical at 8) → pinned cap (`max_pinned_memories=6`) → fresh budget (`max(min_fresh=2, max_surfaced - pinned)`) → `memory_relevance_service` embedding search → merge → **hard cap to `max_surfaced_memories=8`** (pinned-first then fresh-by-score) → `UpdateTrinketEvent` to `ProactiveMemoryTrinket`. Linked memories capped at `max_linked_per_primary=2` and rendered as `<context>` annotations, globally deduped across the surfaced-memory block. The cap also bounds next-turn's retention cache, so subcortical retention only ever sees ≤8 passages.

User model pipeline (triggered in segment collapse chain): `assessment_extractor.extract_signals()` produces `list[AssessmentSignal]` → `user_model_synthesizer.synthesize()` consumes signals → `system_prompt_parser` utilities provide anonymized prompt and section metadata to both steps. Persona pipeline runs on the same collapse chain as a parallel, independent pass (`persona_service.evaluate_segment()` → cadence-gated `refine_automatically_if_due()`), with its own signal/revision tables and trinket — it neither feeds nor reads the user model.
