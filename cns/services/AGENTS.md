# cns/services/ — the turn engine, the segment lifecycle, and the derived model text each writes: what runs inside a turn, what runs when a segment closes, and what a section save regenerates

## Files

- `__init__.py` — docstring only plus an unused `ContinuumOrchestrator` re-export.
- `orchestrator.py` — the turn engine: prompt composition, streaming, the tool loop, one persisted message per provider step. Open it before changing how a user message becomes a stored turn.
- `tool_loop.py` — local tool execution inside that loop, with the repeat-failure breaker. Open it before changing tool ordering, cancellation, or what a halted tool chain tells the model.
- `subcortical.py` — fast-route query expansion, memory retention, entity extraction, effort assessment. Open it before changing what the retrieval query is or how thinking effort is chosen.
- `memory_relevance_service.py` — the one wrapper over lt_memory's proactive search. Open it when a surfacing call's inputs disagree with what the retrieval layer requires.
- `manifest_query_service.py` — manifest rows from segment sentinels, Valkey-cached. Open it when the segment list is stale or a segment's displayed status looks wrong.
- `live_context_compaction_service.py` — the active segment's rolling compaction report and the request shaping that uses it. Open it before changing what the provider sees once a segment outgrows its window.
- `segment_collapse_handler.py` — the collapse pipeline: claim, summary, downstream stages, tombstone, deferred manual collapse. Open it before changing anything a closing segment triggers.
- `segment_timeout_service.py` — the sweep that decides which segments have gone quiet. Open it before changing the inactivity rule, its per-hour overrides, or the job that runs it.
- `segment_helpers.py` — sentinel construction and the segment display formatters; the writer of the segment metadata vocabulary. Open it before adding a metadata key or changing how a summary renders.
- `summary_generator.py` — segment synopsis, precis, display title, complexity, and the chunked fallback. Open it when a summary field is missing or an oversized segment fails to summarize.
- `assessment_extractor.py` — section-anchored behavioral signals for one collapsed segment. Open it when the user-model pipeline records nothing for a segment.
- `user_model_synthesizer.py` — signals into a user model, behind the anchor check and the critic loop. Open it before changing how a user model is produced, or when synthesis aborts.
- `persona_service.py` — Persona evaluation, automatic refinement, and the manual revision flows. Open it before changing MIRA's own directives or their revision history.
- `lora_service.py` — user-initiated refinement of the stored user model, with its preview flow. Open it when a manual model edit is requested or a preview has expired.
- `portrait_service.py` — the prose portrait: use-day-gated synthesis on collapse, plus preview-based refinement. Open it when the `{user_context}` placeholder is empty or a portrait edit is requested.
- `system_prompt_parser.py` — the section vocabulary every anchor check derives from. Open it before adding a system-prompt section that other code must recognize.
- `peanutgallery_service.py` — the observer's trigger and its HUD injection. Open it before changing when guidance appears or which observer actions reach the trinket.
- `peanutgallery_model.py` — the observer's single fast-route call and its parse. Open it before changing what an observation is made of or how a verdict is read.
- `background_digest.py` — dead: no module imports it, so its import-time contributor registration never runs. Kept as a worked contributor example for a planned wake digest; do not build on it as exercised.
- `domaindoc_summary_service.py` — one-sentence DomainDoc section summaries for the section index. Open it when that index shows a stale or missing summary or a section save produced none.
- `pollers/` — segment-lifecycle-bound pollers (base class plus the inbox poller); its own map.

## Wiring

- Turn entry: the transports in `cns/api` (`chat.py`, `websocket_chat.py`) call `orchestrator.process_message` after `continuum_repository.increment_segment_turn` stamps `segment_turn_number` and `last_turn_at`. That stamp is the collapse re-read guard's input — a transport that skips it makes its interleaving turn invisible to collapse. Counterpart: `cns/api/AGENTS.md`.
- Compose round-trip: `orchestrator._compose_llm_messages` publishes `ComposeSystemPromptEvent` → the composer in `working_memory/core.py` → `SystemPromptComposedEvent` → `orchestrator._handle_system_prompt_composed` fills the four request slots. The publish happens inside `working_memory.core._compose_lock`; outside it the read races another compose and the turn ships a prompt belonging to a different turn. Counterparts: `working_memory/AGENTS.md`, `cns/services/pollers/AGENTS.md`.
- Memory surfacing: `subcortical.generate` (fast route) → `orchestrator._compute_embeddings_parallel` → `memory_relevance_service` → `lt_memory/proactive.py:search_with_embedding`, with every cap and threshold imported from `lt_memory.proactive` rather than restated here; the surfaced list then leaves the turn as `UpdateTrinketEvent.create(target_trinket="ProactiveMemoryTrinket", context={'memories': ...})`, routed by `working_memory/core._handle_update_trinket`. Rename the target trinket or the context key and the update drops with one warning, so the prompt slot silently never refreshes. Counterparts: `lt_memory/AGENTS.md`, `working_memory/trinkets/AGENTS.md`.
- Portrait read path: `portrait_service.read_portrait` fills `{user_context}` during `working_memory/core.py` compose, and a stored write calls back into `working_memory.invalidate_portrait`, so the return contract and the invalidation name each reach the other directory. `read_portrait` returns `""` on a failed read by design, which makes a broken read indistinguishable from "no portrait yet". Counterpart: `working_memory/AGENTS.md`.
- Signal type: `AssessmentSignal` is defined in `assessment_extractor` and imported upward by `cns/infrastructure/feedback_repository.py` — the package's only infrastructure→services import — so a field it stops declaring is a field the repository keeps persisting as absent. Counterpart: `cns/infrastructure/AGENTS.md`.
- Prompt load sites: this directory's loads pair a template with the call it feeds. `segment_collapse_handler` loads `pending_memory_entities_*`, generates the format example, and parses the reply back by the pending_id echo; the assessment, persona, and summary loads all happen before the call they feed, so a load moved after it sends that request with no system prompt. A template's output shape and its parser move in one commit. Counterpart: `config/prompts/AGENTS.md`.
- Section summaries: `domaindoc_summary_service.update_section_summary` is reached only from `tools/implementations/domaindoc_tool.py` and the web-UI paths in `cns/api/actions.py` (`rg 'update_section_summary'`), and it swallows every failure by design so the summary never blocks the section save that triggered it — a broken contract there shows up only as a section saved without a summary, never as an error. Counterparts: `tools/implementations/AGENTS.md`, `cns/api/AGENTS.md`.
- Collapse claim: `segment_collapse_handler._claim_collapse` is a single guarded UPDATE issued against `continuum_repository.get_user_db_client`, bounded by the repository's `COLLAPSE_CLAIM_STALE_MINUTES`. Counterpart: `cns/infrastructure/AGENTS.md`.
- Collapse fan-out: `SegmentCollapsedEvent` must fire on the success path and the tombstone path alike — its subscribers are the poller stop, `orchestrator._invalidate_on_segment_collapse`, the stateful-trinket flush, the userdata cleanup, and the pinned-tool clear (`rg 'SegmentCollapsedEvent'`) — while `ManifestUpdatedEvent` reaches only `manifest_query_service`. Counterparts: `cns/core/AGENTS.md`, `working_memory/trinkets/AGENTS.md`, `tools/AGENTS.md`.
- Extraction seam: the collapse handler registers `lt_memory_factory.on_memories_stored` in its constructor, and that callback spawns the integration curator through `agents/spawn.py:spawn_subagent`. lt_memory never imports `agents/`; a refused spawn (at cap or already in flight) is skip-with-log because un-tended memories stay eligible for the floor re-sample. Counterparts: `lt_memory/processing/AGENTS.md`, `agents/AGENTS.md`, `agents/implementations/AGENTS.md`.
- Timeout job: `segment_timeout_service.register_timeout_job` is reached through `utils/scheduled_tasks.py:register_segment_timeout_job`, and `main.py`'s lifespan runs one `check_timeouts()` sweep before the server binds, so a raise there refuses startup. Counterpart: `utils/AGENTS.md`.
- Operator surfaces: `cns/api/actions.py` either calls `queue_manual_collapse` or `collapse_segment` directly, drives `refine_lora`, `PersonaService.create_preview` and `refine_portrait`, and reads Persona history. Counterpart: `cns/api/AGENTS.md`.
- Tool results: `tool_loop.ToolLoopExecutor._execute_tool` decides how every `tool_repo.invoke_tool` return value becomes provider content, so a new result shape is invisible here until it is handled. Counterpart: `tools/implementations/AGENTS.md`.
- Display and markers: `segment_helpers` reaches `cns/core` through its whole surface — `format_segment_for_display` and `format_precis_for_display` rendered by `cns/core/message_formatter.py`, the tier choosing between them set in `cns/core/segment_cache_loader.py`, and `create_collapse_marker` plus `create_session_boundary_marker` imported by that same loader to insert into the message stream. A change to a marker builder is therefore also a `cns/core` change. Counterpart: `cns/core/AGENTS.md`.

## Rules

- Adding a system-prompt section that an anchor check must accept is one vocabulary edit: `get_assessable_section_ids` in `system_prompt_parser` is the source both for `validate_section_anchors` and for the generated example anchors (`{example_section_a}`/`{example_section_b}`, filled in `lora_service._load_prompts` and `user_model_synthesizer._load_prompts`). Hand-write one of those examples instead and the model imitates a section the checker rejects, so every synthesis spends its retry budget and then fails; both fills raise at prompt load when fewer than two assessable sections exist.
- The user's trinket hash carries two directive fields: `behavioral_directives` belongs to LoraTrinket, `persona_directives` to PersonaTrinket. Invalidate the one the edit changed — user-model synthesis and check-in handling clear `behavioral_directives` (`segment_collapse_handler._invalidate_lora_trinket_cache`, `orchestrator._process_checkin_response`), Persona accept and rollback clear `persona_directives` (`persona_service._invalidate_cache`). Swapped, the stale section stays cached and the fresh one is dropped.
- The three preview flows share one shape — Valkey key `{prefix}:{user_id}:{uuid4}`, 600-second TTL, single-consume `GETDEL`, decline a no-op on absence — and differ only in what they store: `portrait_service` and `lora_service` store text, `persona_service` stores a `PersonaPreview` whose `parent_revision_id` makes accept a compare-and-set. A new preview flow that echoes stored text back to the client for confirmation defeats the reason the shape exists.
- The sentinel metadata vocabulary is written here and read across directories: `segment_helpers` plus the claim and flags in `segment_collapse_handler` write it, while `segment_timeout_service` (anchor), `manifest_query_service` (display), `cns/core/segment_cache_loader.py` (tier selection), `cns/core/message_formatter.py` (render), `cns/api/actions.py` (display title on the collapse response) and `tools/implementations/continuum_tool.py` (SQL filtering on `precis`, Python reads of `summary`, `segment_end_time`, `tools_used`, `display_title`) read it. A new key lands with its writer and every reader in one commit, or the readers fall back to defaults without an error — renaming `precis` or `segment_end_time` empties the agent-facing continuum search silently.
- Services the factory wires into the orchestrator are constructed only by `cns/integration/factory.py:create_cns_orchestrator`, and their getters (`get_orchestrator`, `get_manifest_query_service`) raise until it has run; the power-on self-test re-runs that construction and asserts `get_orchestrator() is orchestrator`. A singleton built anywhere else never replaces the one the API layer calls, so code verified against a hand-built instance never ships. Two deliberate exceptions: `SegmentTimeoutService` is built lazily by its own module-level `get_timeout_service` on first call — `main.py`'s pre-bind sweep is that call — and `PersonaService` is stateless over the persona repository, constructed per consumer.
- `MAX_LOCAL_TOOL_CALLS_PER_TURN` is not a local knob. The HTTP chat lock TTL and the WebSocket and MCP timeout rationales size themselves from it, so changing it without re-deriving those leaves their arithmetic silently wrong.

Elsewhere: this map owns what runs inside a turn, around a collapse, and beside a section save, not the events those stages publish, the rows they write, or the prompts they send. Which model a route name resolves to, and how a stalled provider surfaces, is `clients/llm/AGENTS.md`; the value behind each gate — the compaction trigger, the timeout threshold, the use-day cadences — is a config row owned by `config/AGENTS.md`; why a rule here reads as it does is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## Collapse: the timeout sweep to the downstream stages

One case end to end, because no single file shows it: a segment goes quiet and everything that follows depends on the order below.

1. Every five minutes `segment_timeout_service.check_timeouts` walks every user's active sentinels under an admin session. For each, `_segment_activity_anchor` returns the latest of the last message carrying that segment's own `segment_id`, the sentinel's `last_turn_at`, and its creation time; the inactivity is compared against `segment_timeout` with local-hour overrides.
2. A held per-user request lock defers the segment for that cycle only — no event, no attempt, no claim. Turn rows commit at turn end, so an in-flight turn is invisible to the clock; the deferral is what keeps it from being collapsed mid-flight, and the turn's final committed message re-anchors the clock.
3. A segment past the threshold publishes `SegmentTimeoutEvent`. The two subscribers have deliberately different exception contracts: `handle_timeout` catches everything, because a bus subscriber must never unwind dispatch, while `cns/api/actions.py` calls `collapse_segment` directly and maps its exceptions to HTTP.
4. `collapse_segment` clears then sets the user contextvar, finds the sentinel, and reads the attempt budget. At `MAX_COLLAPSE_ATTEMPTS` it takes the same claim as any other path, writes a zero-vector tombstone with `processing_failed=True`, publishes both events, drains the pending queue best-effort, and returns.
5. Below the cap it loads the segment's messages before claiming, so a still-uncommitted turn costs a cheap "not yet" instead of the claim. An empty segment is not a retryable shape — the sentinel persists together with its first messages, so zero messages means a lost atomic save — and it counts the attempt without claiming, so a late message heals the segment while an orphan still reaches the breaker.
6. `_claim_collapse` decides the winner among a scheduled sweep, a manual collapse, and a racing tombstone. While claimed, the summary runs with the previous five collapsed summaries as continuity, its embedding is generated, and the Persona pass runs when enabled — before the save, because a Persona failure must reach the attempt budget instead of stranding a collapsed segment with its evidence lost.
7. The pre-save re-read aborts if `last_turn_at` moved or the status left active/paused/collapsing: the segment stays active, this attempt's summary work is discarded, and the next sweep retries. Otherwise the collapsed sentinel is saved and `SegmentCollapsedEvent` publishes.
8. Downstream never unwinds that save: pending-memory drain, extraction submission, feedback loop, portrait synthesis, each tolerate-and-log, with `downstream_failed` recorded on the sentinel and the manifest publish in `finally`. Extraction retries belong to the `extract_unprocessed_segments` sweep; a second submission here would extract the same segment twice.
9. A manual collapse requested while the turn lock is held is deferred instead: `queue_manual_collapse` writes one Valkey flag, and `_handle_turn_completed` consumes it at the turn's `TurnCompletedEvent` and runs the collapse on its own copied-context thread, so the completing turn is part of the segment being collapsed.

Ordering invariants: contextvar cleared before it is set; claim after the cheap emptiness check and before the expensive work; drain before extraction; Persona before the save and everything else after it; manifest publish unconditional. Reorder any one and the failure is either a stranded memory the user was told was saved, or a durable collapse unwound by a stage that ran beside it.
