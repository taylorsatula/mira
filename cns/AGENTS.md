# cns/ — conversation orchestration: the layering contract over five subsystems — transport `api/`, domain `core/`, persistence `infrastructure/`, composition `integration/`, turn services `services/`

Elsewhere: the turn spine (entry → compose round-trip → tool loop → `UnitOfWork.commit()` → post-commit events → subscribers) — root `AGENTS.md` · per-file contracts, subsystem internals, and the four lifecycle deep-dives (the per-user turn lock, session-load→provider request, sentinel/epoch lifecycle, collapse-to-tombstone) — `cns/api/AGENTS.md`, `cns/core/AGENTS.md`, `cns/infrastructure/AGENTS.md`, `cns/services/AGENTS.md`, `cns/services/pollers/AGENTS.md` · bus dispatch semantics (class-name dict lookup, at-most-once, synchronous inline, fail-fast subscribe) — `cns/integration/AGENTS.md` · event taxonomy and `create()` shapes — `cns/core/AGENTS.md` (`cns/core/events.py`) · contextvar/RLS/copy-context/timezone doctrine — root `AGENTS.md`, `utils/AGENTS.md` · LLM route names, lifecycle and stall policy — `clients/llm/AGENTS.md` · design history — `git log`.

## Rules

- Import direction is the layering contract (module-level edges; re-derive with `rg 'from cns\.'` per subsystem): api → core/infrastructure/services · services → core/infrastructure plus the `EventBus` class from integration, never `cns.integration.factory` (a services import of the factory inverts the composition root — the factory constructs services, never the reverse) · infrastructure → core, one sanctioned upward type import owned by `cns/infrastructure/AGENTS.md` · core → siblings only in `cns/core/segment_cache_loader.py`; the core↔services boot cycle and its mechanism are owned by `cns/core/AGENTS.md` · integration, the composition root, → core/infrastructure/services plus `working_memory`/`tools`/`clients`/`config`/`utils`/`lt_memory` (`utils.tag_parser` at module level; `lt_memory.factory` at call sites — boot fails without the lt_memory singleton, `cns/integration/AGENTS.md`). Consequence: the turn transports import `cns.services.orchestrator` and `cns.infrastructure` at module level (`cns/api/chat.py`, `cns/api/websocket_chat.py`), so importing `cns.api` from services or infrastructure is a boot-time ImportError cycle; from core it drags the transport layer into every `cns.core` import — `lt_memory` imports `cns.core.message` without mounting routes by design.
- `cns/api` is a leaf: no file in `cns/` imports it; outside `cns/` only `main.py` (router mounts, shutdown's `close_all_connections`, the `cns/api/base.py` envelope) and `auth/api.py` (envelope only — `cns/api/base.py` imports no cns module) reach it. Routes hold no bus reference (`rg 'EventBus|event_bus' cns/api` → nothing): the one process bus lives on the orchestrator (`cns/integration/AGENTS.md`); a route constructing its own `EventBus()` publishes to zero subscribers — silent no-delivery. Event work belongs to the orchestrator and the collapse handler (`cns/services/AGENTS.md`).
- Add-one, a new domain event — three subsystems, one commit: (1) class in `cns/core/events.py` under an existing category base, frozen dataclass + `create()` factory; the two `user_id` shapes (contextvar default; explicit parameter for background publishers) are owned by `cns/core/AGENTS.md`; the module docstring is the taxonomy law — a one-off event is argued, not defaulted. Skip: a name outside the live `ContinuumEvent.__subclasses__()` walk raises ValueError at boot (`cns/integration/event_bus.py`). (2) Publisher on the turn or collapse path; events observing durable state ride `UnitOfWork.add_post_commit_callback` (owned by `cns/infrastructure/AGENTS.md`) — publish at build time and subscribers see a turn whose commit can still fail. (3) Subscriber registration during `create_orchestrator()` in `cns/integration/factory.py` (roster owned by `cns/integration/AGENTS.md`). Skip (2) or (3): `publish()` to zero subscribers is a DEBUG-only no-op (`cns/integration/event_bus.py:publish`) — the publisher is stranded with no error anywhere.

## Files

- `__init__.py` — empty; no re-exports, every consumer names a submodule (`rg 'from cns\.'`). Gotcha: keep it empty — every `from cns.…` import executes this file before the target module, so an import added here (transport included) mounts on every consumer: `lt_memory` (`Message`) and `agents` (events) import cns symbols on their own load paths.
- `api/` — FastAPI routes, the WS/HTTP turn protocol server side, the per-user turn lock: `cns/api/AGENTS.md`.
- `core/` — `Continuum` aggregate, `Message`, the event taxonomy, session-cache assembly, provider-neutral request formatting: `cns/core/AGENTS.md`.
- `infrastructure/` — repositories, `UnitOfWork`, the hot Valkey cache, sentinel lifecycle: `cns/infrastructure/AGENTS.md`.
- `integration/` — the event bus and the boot-time factory composing the orchestrator's dependency graph: `cns/integration/AGENTS.md`.
- `services/` — turn orchestration, the tool loop, segment collapse, memory surfacing, the user-model/Persona/portrait pipelines: `cns/services/AGENTS.md`.

## Wiring

- Package boundary (`rg 'from cns\.'` outside `cns/` — the grep is the consumer set): `main.py` mounts the routers and builds the graph (root `AGENTS.md`) · signup continuum + welcome rows ↔ `auth/AGENTS.md` (edge owned by `cns/infrastructure/AGENTS.md`); response envelope ↔ `auth/api.py` (owned by `cns/api/AGENTS.md`) · events + `EventBus` class + trinket/service getters ↔ `agents/AGENTS.md`, `working_memory/AGENTS.md` · `get_user_db_client`, events, `update_section_summary` ↔ `tools/implementations/AGENTS.md` · `Message` and the extraction seam ↔ `lt_memory/AGENTS.md`, `lt_memory/processing/AGENTS.md` · POST dependency check, timeout-job registration, the cleanup handler's bus ↔ `utils/AGENTS.md`.
