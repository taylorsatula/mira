# cns/ — conversation orchestration: the package boundary and the import-direction contract over its five subsystems

## Files

- `__init__.py` — package marker: a docstring, no imports, no re-exports. Open it before deciding whether something belongs at package level; nothing does.
- `api/` — the HTTP and WebSocket request boundary, and the server side of the turn protocol; its own map.
- `core/` — the aggregate, message and event types a turn is carried in; its own map.
- `infrastructure/` — durable conversation persistence and the hot Valkey cache; its own map.
- `integration/` — the process's one event bus and the boot-time composition root; its own map.
- `services/` — the turn engine and the segment lifecycle; its own map.

## Wiring

- Layering: `api/` → `core/`, `infrastructure/`, `services/` · `services/` → `core/`, `infrastructure/`, and the `EventBus` class out of `integration/` alone, never `cns.integration.factory`: the factory constructs the services, so a services import of it makes each depend on the other · `infrastructure/` → `core/`, plus two upward imports from `services/`: one type (`AssessmentSignal`, module-level in `feedback_repository.py`) and one function (`create_segment_boundary_sentinel`, function-local inside a `continuum_repository.py` method, whose placement keeps `cns.services` off infrastructure's import chain) · `core/` → `services/` and `infrastructure/`, confined to two files · `integration/` → `core/`, `infrastructure/`, `services/`, plus `working_memory/`, `tools/`, `clients/`, `config/`, `utils/` and `lt_memory/`. The projection is `rg 'from (cns|\.+)\.?(core|infrastructure|services|integration|api)\b' cns/<dir>` and running it is the check before adding an import across one of these lines; the absolute form alone is not enough, because `cns/integration/` reaches `core/` and `infrastructure/` only relatively and reads clean under it. Reaching outside `cns/` is not itself a layering violation — every subsystem does it, `integration/` most of all because it is the composition root — so a new outside import is governed by the edge its subsystem's map states, not by this bullet. The cost of getting a line wrong surfaces at boot, not in review: `cns.api` itself imports `services.orchestrator` and `infrastructure` at module level, so either one importing it back closes an ImportError cycle, and importing it from `core/` runs the transport layer for every consumer of `cns.core` — `lt_memory` imports `cns.core.message` on its own boot path and mounts no routes by design. The `core/` → `services/` edge is the one a reader gets wrong: it has one module-level site and one function-local site, and the placement of the second is deliberate; owner: `cns/core/AGENTS.md`.
- Package boundary: callers outside this tree are a projection — `rg 'from cns\.' main.py auth agents working_memory tools lt_memory utils clients` — and the counterparts whose map carries the reciprocal statement are: router mounts and graph construction in `main.py`, plus the pre-server self-test's identical `create_cns_orchestrator` call in `utils/power_on_self_test.py` (counterpart: root `AGENTS.md`), signup continuum rows and the `cns/api/base.py` response envelope (counterpart: `cns/api/AGENTS.md`, which owns the `auth/api.py` import), `get_continuum_repository` and `update_section_summary` (counterpart: `tools/implementations/AGENTS.md`), and the event classes in `cns/core/events.py` (counterpart: `working_memory/AGENTS.md`). The remaining outside reach — `agents/` importing `EventBus`, `lt_memory`'s extraction path importing `cns.core.message`, `utils/scheduled_tasks.py` importing `register_timeout_job` — is owned by the map of the subsystem that publishes the seam (`cns/integration/AGENTS.md`, `cns/core/AGENTS.md`, `cns/services/AGENTS.md`); this bullet does not restate those.
- One bus: the process's single `EventBus` instance belongs to the orchestrator and is constructed in `cns/integration/factory.py:_get_event_bus`, the only site holding the `EventBus()` literal. `create_orchestrator` is what orders that call: every subscription in the process registers during it, including the ones the constructors it invokes make for themselves. Counterpart: `cns/integration/AGENTS.md`.

## Rules

- Adding a domain event is three subsystems in one commit, and each skipped step fails differently. (1) The event class in `cns/core/events.py`, under one of the four category bases — a renamed or unregistered class raises `ValueError` at `EventBus.subscribe`, so boot fails loudly. (2) A publisher on the turn or the collapse path, with events that observe durable state riding `UnitOfWork.add_post_commit_callback` rather than publishing at build time — publish early and subscribers see a turn whose commit can still fail. (3) Subscriber registration during `create_orchestrator()` — skip this or step 2 and `EventBus.publish` finds no subscriber, logs at DEBUG, and returns, so the publisher is stranded with nothing in the log above DEBUG and no error anywhere.
- A route never holds a bus. The bus is reachable in `services/` by class import (`rg 'EventBus' cns/services`) and in `api/` by nothing: a route constructing its own `EventBus()` publishes into an empty subscriber map, which is the DEBUG-only no-delivery path above, so event work belongs to the orchestrator and the collapse handler.

Elsewhere: this map does not own any subsystem's internals — what a route validates, what an event carries, how a turn is persisted, the order the graph is built in, and what runs inside a turn are each the subdirectory map's. Design history is `git log`; signatures and per-method contracts are each file's docstring; the projection greps above replace any roster of callers. Every other destination this directory reaches is an edge — see `## Wiring` above.
