## Rules

- Never override `run()`. Every termination — success, wall or per-iteration timeout, iteration cap, injection rejection, sentry skip, exception — flows through `_exit()`, which writes the dedup row and fires `on_completion()`. A custom loop that exits any other way leaves either no `sidebar_activity` record (the dispatcher re-dispatches the item forever) or a tool-written record with no completion event (the target trinket never updates).
- `_exit(status, summary, activity_status='failed')` writes two different values: `status` to the trace and `on_completion()` (what the trinket sees), `activity_status` to the `sidebar_activity` dedup row. `complete_task` results route the tool's own reported status through (`complete_result.get('status', 'handled')` in `_run_iteration`) — skip that and the 'failed' default re-UPSERTs over the tool's terminal row and the item re-dispatches; the tool's `escalation_reason` survives because `_write_activity_record`'s UPDATE set doesn't touch it. Terminal, never re-dispatched: `_TERMINAL_STATUSES` in `agents/sidebar.py` — `handled`/`escalated`/`resolved`/`dismissed`. `failed` is the only retryable status, and it is what an injection rejection leaves (`_exit('rejected', …)` keeps the default), while a sentry skip writes terminal `dismissed`. A `_build_completion_context` that maps only success/failed/timeout renders `skipped`/`rejected` as failures.
- The base enriches every `sidebar_tool` call with `thread_id` (= `work_item.item_id`), `complete_task` additionally with `interface_name`/`agent_id`/`run_count` (`_execute_tool_calls`); those four are system-injected, never LLM-fillable schema parameters — a model-supplied `thread_id` UPSERTs the dedup row under a model-chosen key and orphans the dispatcher's.
- Wall-clock budgets resolve in `SidebarAgent.__init__` from `config.sidebar_dispatcher`: shared `agent_timeout_seconds` (default 120), per-agent `agent_timeout_overrides` keyed `type(self).__name__.removesuffix("Agent").lower()`, per-iteration `agent_iteration_timeout_seconds`. A `timeout_seconds` class attribute is silently overwritten at construction; a mistyped override key falls back to the shared default — long-running agents set their budget in `agent_timeout_overrides` or die at 120s. `run_blocking()` is bounded instead by `blocking_agent_timeout_seconds`, passed through `run()`'s `timeout_seconds` parameter.
- The two gates hold opposite failure policies. Injection gate — fail-closed, on by default (`sanitize_untrusted_input=True`): `_run_injection_gate` screens only `context['raw_content']` (truncated to 8000 chars first), writes `sanitized_content` back; a rejection exits `'rejected'`, a screen outage exits `'failed'` — content never reaches the loop unscreened, and `build_initial_message()` must read the sanitized key, not the raw one. Opting out is a producer-trust claim (`agents/implementations/AGENTS.md`). Sentry gate — fails open (`parse_sentry_response` and `_run_sentry` proceed on parse failure or LLM error): a cost optimization, never a security boundary; its skip writes terminal `dismissed`, so a skipped item is never re-dispatched.
- Overwatch (`overwatch_model_config_name` set) spawns a daemon thread with copied context per non-terminal iteration; the per-request `overwatch_max_tokens` (default 80) is the only thing holding the observer to one summary line — its route's row ceiling is 4096 (`fast`) / 16000 (`batch`/`primary`). Observer failures swallow at debug — the observer body (LLM call and `on_overwatch_update`) runs on its own daemon thread, so a raising observer ends only that thread, never the agent run; without the swallow, threading's excepthook prints an unhandled traceback each failed iteration. Blocking runs publish none (an `in_progress` entry with no terminal event strands the trinket's state machine).
- Dispatcher dedup: the per-user `sidebar_activity` row is keyed UNIQUE(`interface_name`, `thread_id`), but the in-flight registry is process-global across every spawn site, keyed `{interface_name}:{item_id}` and lock-guarded in `agents/spawn.py` — two users producing the same key collide and the later spawn is silently refused while the first runs; item-id key shapes that embed user identity are the trigger-side half (`agents/HOW_TO_BUILD_AN_AGENT.md`). Retry is `_dispatch_decision`'s exact test — `status == 'failed' AND run_count <= agent_class.max_retries` (base default 0: fire-and-forget) — and rides rediscovery; `prior_run` in context carries ONLY `status` and `run_count` (`_get_prior_run` selects those two), so a `build_recovery_context()` indexing anything else raises KeyError inside `run()` and consumes the retry.
- Blocking mode is opt-in (`blocking_supported`): `run_blocking()` executes the full loop on the caller's thread — no context copy; the caller's contextvar is the user — publishes no trinket events at all (the `_blocking` guards in `on_completion` and `_fire_overwatch` are the single suppression points), still lands the dedup row via `_exit`, and returns the completion record: a failing run is a returned `{'status','summary'}`, never a raise (raises only mean the class opted out or the exit contract broke). A caller testing only for exceptions reads failures as successes. Blocking runs take no in-flight slot — they spawn no thread, and the caller's turn plus `blocking_agent_timeout_seconds` bound them; `agents/spawn.py`'s docstring states this in the seam's contract.
- The spawn seam (`agents/spawn.py:spawn_subagent`) is the only code that starts an agent thread, and `config.sidebar_dispatcher.max_concurrent_agents` is the process-global cap for every spawn site — dispatcher poll, `subagent_tool` activate, collapse-handler curator. The cap check, duplicate-key guard, and insert are atomic under one lock (three concurrent writer contexts: APScheduler poll thread, the tool loop's parallel executor, the turn thread); the liveness prune runs under the same lock. At-cap refusal is per caller: the tool returns the truthful `capacity_result()` envelope, the dispatcher leaves the item unmarked so the next poll rediscovers it, the collapse handler skips with a log (the memory floor trigger re-samples untended memories). A thread crash publishes terminal `failed`/`ThreadCrash` to the unified results trinket for every type with an error TTL (heartbeat logs only).

## Files

- `__init__.py` — empty package marker; import `agents.base` / `agents.sidebar` / `agents.specs` / `agents.spawn` directly.
- `base.py` — the `SidebarAgent` ABC (gates, loop, exit, trace) plus module helpers. Entry: `run`/`run_blocking`/`_exit`, `_execute_tool_calls` (complete_task interception), `_run_injection_gate`, `_run_sentry`, `_fire_overwatch`, `_build_system_prompt` (the `rule_prompt` consumption point), `load_agent_prompt`, `ensure_activity_schema`, `_publish_trinket_refresh`, `_write_activity_record`. Gotcha: `_get_tool_schemas` drops an unavailable tool name silently at debug — a typo in `available_tools` never errors; the LLM just never sees the tool.
- `sidebar.py` — `WorkItem`, the `SidebarTrigger` protocol, and `SidebarDispatcher`: dedup/retry machine, eligibility union, per-trigger-per-user dispatch cap (`MAX_ITEMS_PER_USER_PER_POLL` — the counter resets inside the trigger loop), 30-day retention cleanup. Entry: `poll`, `_poll_user`, `_dispatch_decision`, `_get_eligible_users`, `_spawn_agent` (delegates to the seam), `_maybe_cleanup`. Gotcha: `on_dispatched` is called unconditionally after a successful spawn, inside the per-user trigger loop — any raise there aborts that user's remaining triggers for the tick (caught per-user in `poll()`; the live missing-method instance is `agents/triggers/AGENTS.md`'s).
- `specs.py` — `SubagentSpec` + `SUBAGENT_SPECS`: one policy row per subagent type (phoneafriend, forage, whilethecatsaway, memory_curator, heartbeat) — the tool's enum, the unified trinket's lifecycle, the seam's pending/crash policy, and continue/dismiss behavior all read from it; `load_agent_class` is the lazy import path, `spec_for_agent_class` resolves trigger-held classes. Import-light: agent classes are lazy import strings here. The dispatch protocol (activate on every invocable class, continue_task on continuable ones, the None claim semantic) is documented in this module's docstring.
- `spawn.py` — the single spawn seam: `spawn_subagent` (thread + copied context, process-global in-flight registry, cap check + duplicate guard + insert + thread start atomic under one lock), `is_in_flight`/`in_flight_count`, `publish_result` (the single producer-side publisher to the unified results trinket — seam pending/crash, agent refine auto-dismiss, tool dismiss), `capacity_result` (the shared at-cap envelope). Blocking runs never enter this module's registry. Gotcha: the start must sit inside the lock — `is_alive()` is False before it, so an outside-lock start leaves a window where the liveness prune evicts the registered entry and defeats cap and dedup.
- `HOW_TO_BUILD_AN_AGENT.md` — the add-an-agent walkthrough: step recipe (class → rubric → schema restriction → completion → trigger → config → maps → retries → sentry), tool-restriction limits, key-shape and pre-fetch doctrine, security checklist, offline verification floor, upstream-PR policy. Trust: a base-class or dispatcher contract change updates it in the same commit.
- `implementations/` — the concrete agents and the Mode Contract — `agents/implementations/AGENTS.md`.
- `triggers/` — work-item discovery, the trigger registry, the rule filter — `agents/triggers/AGENTS.md`.

## Wiring

- Construction and tick: `main.py` → `utils/scheduled_tasks.py:register_sidebar_dispatcher_job` → `utils/sidebar_jobs.py:register_sidebar_jobs` constructs `SidebarDispatcher(tool_repo, event_bus)` from `config.sidebar_dispatcher` (the concurrent-agent cap lives in `agents/spawn.py`), registers `agents/triggers/registry.py:TRIGGER_CLASSES` instances, and schedules `dispatcher.poll` as job `sidebar_dispatcher_poll` every `poll_interval_minutes`. Counterparts: `utils/AGENTS.md` (fixed registration order), `agents/triggers/AGENTS.md` (registry, dispatch order, gates), `config/AGENTS.md`.
- Spawn paths — every path ends at the same `run` → `_exit` → dedup-row chain; WorkItem construction sites: `rg 'WorkItem('`. All spawns go through `agents/spawn.py:spawn_subagent` — the dispatcher's `_spawn_agent` (keeps its `on_dispatched` contract; an item over cap is left unmarked and rediscovered next poll), `subagent_tool`'s activate path (via each agent class's dispatch classmethods — `agents/implementations/AGENTS.md`), and the collapse hook `cns/services/segment_collapse_handler.py:_spawn_integration_curator` (best-effort — never fails the collapse). Blocking runs (`run_blocking`: the phoneafriend consult, blocking forage) bypass the seam and take no slot. Per-site contracts: `agents/implementations/AGENTS.md`; the dispatching tool: `tools/implementations/AGENTS.md`.
- Second writers and readers of the dedup surface (DDL owned by `utils/AGENTS.md`, `utils/userdata_manager.py`; the table is also created at every user-DB open, so dedup works before any agent runs; consumers needing it call `ensure_activity_schema`, grep `rg 'ensure_activity_schema'`): `sidebar_tool.complete_task` writes the terminal row first — `tools/implementations/AGENTS.md` · `subagent_tool` dismiss/resolve from the main conversation (module-level `ensure_activity_schema` import; refreshes via `_publish_trinket_refresh`) — `tools/implementations/AGENTS.md` · the rules-API conflicts read — `cns/api/AGENTS.md`.
- Eligibility: `_get_eligible_users` (admin session, BYPASSRLS) = users active within 2 days ∪ `heartbeat_armed_users`; the armed table is `tools/implementations/heartbeat_tool.py`'s presence surface (`upsert_armed_user`/`remove_armed_user`) — an armed-but-dormant user stays pollable, and any future trigger needing dormant users must ride that table or its users are never polled. Counterparts: `tools/implementations/AGENTS.md`, `agents/triggers/AGENTS.md`.
- Completion publish: `on_completion()` → `UpdateTrinketEvent.create(continuum_id='sidebar', target_trinket, context)` (user_id from the contextvar; synchronous bus — the trinket handler runs on the agent's own thread) → `working_memory/core.py:_handle_update_trinket` routes by name; an unregistered target trinket is dropped with a warning. Trinkets render by re-reading `sidebar_activity` — the event is a re-render signal, not the data path; state machines: `working_memory/trinkets/AGENTS.md`; taxonomy: `cns/core/events.py`.
- LLM and tool plumbing: `_resolve_llm` → `utils.user_context.get_model_config(model_config_name)` (five-route, no-fallback contract: `utils/AGENTS.md`) + `clients/llm_provider.py:get_llm_provider()`; per-iteration message assembly through `clients/llm/tool_messages.py` (`append_tool_result_messages`); tool resolution and per-user DI through `tools/repo.py:ToolRepository.get_tool` — `tools/AGENTS.md`.
- Prompt seam: rubrics are files under `config/prompts/agents/` loaded through `load_agent_prompt` → `load_prompt("agents/<name>")` — a missing rubric fails at the first `get_agent_prompt()` call, not at import, so `py_compile`-clean code can still carry a dead agent. Inventory: `config/prompts/AGENTS.md`.
