# agents/ — the runtime that carries one discovered work item from spawn to a dedup row

## Files

- `__init__.py` — package marker; re-exports nothing, so importing `agents` pulls no agent, tool, or client module.
- `base.py` — the base loop every agent runs inside. Open it before changing when a run starts, gates, or ends, or before adding a per-iteration hook.
- `sidebar.py` — the poll that decides what runs, and the `WorkItem` contract a trigger hands it. Open it before changing which items get dispatched, skipped, or retried.
- `spawn.py` — the one seam that starts an agent thread, and the process-global in-flight registry behind it. Open it before writing code that starts an agent or reports a refused spawn.
- `specs.py` — one policy row per subagent type, and the lazy class import every dispatcher reads. Open it before adding a subagent type or changing what a type's results entry does.
- `HOW_TO_BUILD_AN_AGENT.md` — the add-an-agent walkthrough: step recipe, tool-restriction limits, security checklist, offline verification floor. Open it before building, wiring, or restricting an agent.
- `implementations/` — the concrete agents and the Mode Contract; its own map.
- `triggers/` — work-item discovery, the trigger registry, the rule filter; its own map.

## Wiring

- Tick: `utils/scheduled_tasks.py:register_sidebar_dispatcher_job` → `utils/sidebar_jobs.py:register_sidebar_jobs` → `SidebarDispatcher.poll`. The dispatcher is constructed once with the `TRIGGER_CLASSES` instances and a single scheduled job drives every tick; a trigger class that never reaches that registry is never polled. Counterparts: `utils/AGENTS.md`, `agents/triggers/AGENTS.md`.
- Spawn: every site ends at `spawn.py:spawn_subagent` — the dispatcher's `_spawn_agent`, `subagent_tool`'s activate through the agent class's own classmethods, and `cns/services/segment_collapse_handler.py:_spawn_integration_curator`. The seam returns a bool and the caller owns the refusal, differently at each site: the dispatcher leaves the item unmarked so the next poll rediscovers it, the tool answers with `capacity_result()`, and the collapse hook logs while the collapse stands. Counterparts: `tools/implementations/AGENTS.md`, `cns/services/AGENTS.md`.
- Completion publish: `_exit` writes the `sidebar_activity` row, then `on_completion()` publishes `UpdateTrinketEvent` → `working_memory/core.py:_handle_update_trinket`. The row write has to stay ahead of the publish: the event is a re-render signal, so a trinket that reads the row behind a publish that overtook it renders the previous state. Counterpart: `working_memory/trinkets/AGENTS.md`.
- Dedup surface: four write sites share `sidebar_activity` — this directory's `_write_activity_record`, `sidebar_tool`'s `complete_task`, and `subagent_tool`'s dismiss and resolve; the DDL is `utils/userdata_manager.py`'s and each writer calls `ensure_activity_schema` first. `sidebar.py:_maybe_cleanup` deletes from both tables, reaching `scratchpad` rows through the `thread_id`/`updated_at` join it uses to expire `sidebar_activity`, so a shape change to either table reaches the retention sweep as well as the readers. Counterparts: `tools/implementations/AGENTS.md`, `utils/AGENTS.md`.
- Import direction: `subagent_tool` imports `agents.base.ensure_activity_schema` at module level and `_publish_trinket_refresh` at call time, and `cns/api/trigger_rules.py` and `working_memory/trinkets/asyncactivity_trinket.py` import `ensure_activity_schema` too — so `base.py` stays free of heavy module-level imports, which would drag the LLM client chain into `tools/` import time. Counterpart: `tools/implementations/AGENTS.md`.
- Spec table read times: `subagent_tool` builds its model-facing `agent_type` enum from the invocable `SUBAGENT_SPECS` rows at import, so a row added after that import stays invisible to the model's schema for the life of the process, while `subagent_results_trinket` reads per-type `result_ttl_turns`/`error_ttl_turns` on each render and picks up a change at once. Counterparts: `tools/implementations/AGENTS.md`, `working_memory/trinkets/AGENTS.md`.
- Rubric load: `load_agent_prompt` → `config/prompts/loader.py:load_prompt`. A missing rubric file fails at the first `get_agent_prompt()` call rather than at import, so a module that compiles cleanly can still carry an agent that cannot run. Counterpart: `config/prompts/AGENTS.md`.
- Gated base prompt: `BaseAgent.inherit_base_prompt` defaults to `True`, so `_build_system_prompt` prepends `config/prompts/agents/base_system.txt` to the rubric; every implementation sets it `False`, so that file currently reaches no live prompt. Flipping the default re-activates a rubric file nothing else is watching. Counterpart: `config/prompts/AGENTS.md`.

## Rules

- Never override `run()`. Every termination — success, both timeouts, iteration cap, injection rejection, sentry skip, exception — goes through `_exit`, and `_exit` is the only thing that concludes a run — it writes the terminal row and fires `on_completion()`. A loop that ends any other way leaves no dedup row, so the dispatcher re-dispatches that item on every poll forever, or leaves a tool-written row with no completion event, so the trinket keeps rendering the state from before the run.
- `_exit(status, summary, activity_status='failed')` carries two values that are not interchangeable: `status` reaches the trace and `on_completion()`, `activity_status` reaches the dedup row. An exit path that stops passing the pair through is the failure this prevents — `complete_task` reports its own status and `_run_iteration` routes it into `activity_status`, so leaving the `'failed'` default UPSERTs over a terminal row and the item comes back on the next poll.
- The two gates keep their polarity. `_run_injection_gate` fails closed and `_run_sentry` fails open, because the sentry is a cost filter and never a security boundary — it cannot stand in for the screen. An agent setting `sanitize_untrusted_input = False` is making a claim about the producer that fills `context['raw_content']`, and when the claim is wrong external text reaches the loop unscreened; the producer-trust rule and the current opt-outs are `agents/implementations/AGENTS.md`'s.
- A new subagent type is four edits that must land together: the agent class, its rubric file, the `SUBAGENT_SPECS` row, and — when the dispatcher drives it — the trigger registration in `agents/triggers/registry.py:TRIGGER_CLASSES`. Each skipped step fails its own way: a class with no spec row raises `KeyError` in `spec_for_agent_class` at spawn, a row left `invocable=False` never reaches `subagent_tool`'s enum, a row left at `error_ttl_turns=None` never renders a failed entry in the results trinket, and a trigger class that never reaches the registry is never polled. The long form is `agents/HOW_TO_BUILD_AN_AGENT.md`.
- Every agent thread starts at `spawn.py:spawn_subagent`. A hand-rolled `threading.Thread` skips the `max_concurrent_agents` cap and the duplicate-key guard, and without `copy_context()` it loses `app.current_user_id`, so every RLS-scoped query inside the agent returns zero rows and raises nothing.

Elsewhere: this directory owns a work item's runtime, not the discovery that creates it or the work an agent does with it. The item-id key shapes triggers must mint, the opt-in double gate, and the pre-fetch cost shape are `agents/HOW_TO_BUILD_AN_AGENT.md`'s, as is the verification floor that proves an agent ran rather than merely imported; why a bullet on this page reads as it does is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## One item through the dedup contract

The path that decides most of the Rules above: an item is dispatched, times out, and ends.

1. `poll` sets the user contextvar and `_poll_user` walks the triggers. A trigger returns the item; `_get_prior_run` finds no row, so `_dispatch_decision` says dispatch and `context['run_count']` starts at 1.
2. `_spawn_agent` resolves the spec row from the trigger's `agent_class` and calls `spawn_subagent`, which starts the thread under a copy of the context and publishes the `pending` entry if the spec asks for one.
3. The run hits its wall-clock bound, so `_exit('timeout', …)` writes the row with the default `activity_status='failed'` while publishing `status='timeout'`. The trinket shows a timeout; the dedup row says failed.
4. On the next tick `_dispatch_decision` reads `failed` with `run_count` 1 against the class's `max_retries` and answers skip, because `max_retries` defaults to `0` and no shipped class raises it — a timeout ends the item rather than retrying it. A class that did raise it would get the retry branch: `_poll_user` sets `run_count` 2 and `prior_run`, and the new run calls `build_recovery_context(prior_run)`, whose dict holds only `status` and `run_count` because `_get_prior_run` selected only those two; indexing anything else raises `KeyError` inside `run()` and consumes the retry it was meant to guide.
5. A run that completes instead goes through `complete_task`, whose own status rides to `_exit` as `activity_status`. The row becomes `handled`, which `_TERMINAL_STATUSES` skips on every later poll. Terminality is per `item_id`, not per real-world task: a trigger that mints a new id re-surfaces the same work at once, which the floor trigger's `floor_{user_id}_{activity_days}` key does on the next activity cycle; retention cleanup is what frees the id itself.
