Elsewhere: the trigger add-one walkthrough (protocol shape, `item_id` keying doctrine, opt-in double gate, pre-fetch cost shape, physical-resource dedup) — `agents/HOW_TO_BUILD_AN_AGENT.md` · dispatcher mechanics (`WorkItem`, the `SidebarTrigger` protocol, dedup/decision machine, eligibility union, per-user poll cap) — `agents/AGENTS.md` (`agents/sidebar.py`) · agent sides: the HeartbeatAgent gate, the curator Mode Contract and `FloorContext` — `agents/implementations/AGENTS.md` · the briefs store (DDL, state machine, report outcomes, presence writes) — `tools/implementations/AGENTS.md` (`heartbeat_tool.py`) · rules-API endpoints and write-time validation — `cns/api/AGENTS.md` (`cns/api/trigger_rules.py`) · `trigger_rules` DDL — `utils/AGENTS.md` (`userdata_manager.py:_init_trigger_rules_schema`) · config blocks `heartbeat`, `memory_curator`, `sidebar_dispatcher` — `config/AGENTS.md` · the deployer shim contract (`arm_low_power`, log-and-continue) — `utils/AGENTS.md` (`device_binding.py`) · signatures — the files.

## Rules

- A trigger class reaches the system only through `registry.py:TRIGGER_CLASSES` — `utils/sidebar_jobs.py:register_sidebar_jobs` instantiates and registers every list member (list order = dispatch order), and `cns/api/trigger_rules.py:registered_trigger_specs` derives the rule-addressable trigger/field set from the same list at request time. A class missing from the list never dispatches AND its `trigger_id` is rejected by the rules API; a duplicate `trigger_id` or `interface_name` fails at import (`_validate_registry`). Registration anywhere else is dead code; the `__init__.py` re-export is the walkthrough's registration step, not a wiring edge.
- Module level of a trigger file imports only `WorkItem` and `rule_filter`; everything else — agent class, config, DB managers, timezone utils, `heartbeat_tool` — resolves inside the method or the `agent_class` property. `registry.py` imports both trigger modules at module level and `register_sidebar_jobs` walks that chain at boot, so a module-level agent import drags the agent module's own chain (its tool module, the tools package) into scheduler registration — exactly what the lazy properties exist to prevent. Heavy clients construct once in `__init__` (`MemoryFloorTrigger`'s `LTMemoryDB`), never per poll.
- Every `check_for_new_items` ends `return apply_trigger_rules(user_id, self.trigger_id, items)` — skipping it silently ignores the user's rules. The filter is opt-in per trigger (no enabled rows → every item passes) and exclusive per item (rows present → only a regex-matching item survives; drops are logged, not errors): a stored rule whose `field` names a dead or renamed context key silently drops every discovered item for rule-having users. An uncompilable stored `pattern` raises `re.error` out of discovery by design — the API validates patterns at write time, so an uncompilable row is corrupted state, not user error.
- A work-item context key is a three-way same-commit contract: the trigger builds it, `FILTERABLE_FIELDS` declares the scalar string keys the rules API accepts (read off the class with `getattr(cls, "FILTERABLE_FIELDS", ())` in `registry.py:registered_trigger_specs` — a missing attribute registers as zero fields, no error, and an empty tuple like heartbeat's makes the trigger wholly rule-unaddressable), and the consuming agent renders/stamps it (`FloorContext` in `agents/implementations/memory_curator_agent.py`, the `briefs` keys in `agents/implementations/heartbeat_agent.py:build_initial_message`). Miss one on a rename: the agent renders nothing, rules match a dead field, or the API validates a field no item carries. Non-string context values (`memories`) never match — lists stay undeclared.
- The floor's use-day gate is the inline per-user modular check — `get_user_cumulative_activity_days() % config.memory_curator.floor_use_days` inside `check_for_new_items` — the sanctioned per-user spelling of `scheduled_tasks.get_users_due_for_job`'s MOD condition: the dispatcher already iterates users, so the stateless all-users function would re-query the table every poll. Do not converge it to `get_users_due_for_job`, and never add a last-ran column (the drift defect `utils/AGENTS.md` names).
- The dispatch stamp is twin code across the trigger and the agent's failure accounting: `heartbeat_trigger.check_for_new_items` writes `last_wake_at = <dispatch_stamp>` on every dispatched brief and carries `dispatch_stamp` in each brief's context entry; `agents/implementations/heartbeat_agent.py:on_completion` reads `state = 'armed' AND last_wake_at = dispatch_stamp` as carried-but-never-reported, and every `heartbeat_tool` report outcome overwrites `last_wake_at` (comparison side owned by `agents/implementations/AGENTS.md`). Change the stamp write, the context key, or the comparison in one commit — drift any of the three and unreported briefs wedge armed behind their terminal dispatch-window record (the sweep is their only exit).

## Files

- `__init__.py` — re-exports both trigger classes; no in-repo importer of the package root — consumers import `agents.triggers.registry` / `.heartbeat_trigger` / `.rule_filter` directly (grep `rg 'agents\.triggers'`). A new class still joins the re-export per the walkthrough's registration step.
- `heartbeat_trigger.py` — due-brief discovery for the HeartbeatAgent (all of a user's due briefs batched into one work item) plus the device-power publisher. Entry: `HeartbeatTrigger.check_for_new_items`, `publish_device_wake_aggregate`, `register_device_wake_job`, the lazy `agent_class`. Gotcha: the class defines no `on_dispatched`, and `agents/sidebar.py:SidebarDispatcher._poll_user` calls it unconditionally after spawn — every heartbeat dispatch raises `AttributeError`, caught and logged as a per-user poll error after the spawn (the agent run survives; heartbeat is last in `TRIGGER_CLASSES`, so no later trigger is skipped today — reorder the list and the abort eats one).
- `memory_floor_trigger.py` — floor-mode curation discovery: bounded SQL sample of low-value un-tended memories, pre-fetched with texts and scores so the agent judges without a search round-trip. Entry: `check_for_new_items`, `on_dispatched` (no-op), the lazy `agent_class`. Gotcha: `item_id` `floor_{user_id}_{activity_days}` is per activity-day cycle and `max_retries` is the base 0 — a failed run is never re-dispatched; the re-sample IS the retry (the agent stamps `last_tended_at` only on success, and eligibility's NULL+age branch — `lt_memory/db_access.py:get_floor_candidates` — keeps un-stamped memories coming back).
- `registry.py` — the single trigger registry both dispatch and the rules API consume. Entry: `TRIGGER_CLASSES`, `registered_trigger_specs`, `TriggerSpec`. Gotcha: `getattr(cls, "FILTERABLE_FIELDS", ())` — a trigger class without the attribute registers with zero rule-addressable fields, no error; duplicates fail at import (`_validate_registry`).
- `rule_filter.py` — the dispatch-time reader of per-user `trigger_rules` rows (writer: `cns/api/trigger_rules.py`). Entry: `apply_trigger_rules`. Gotcha: `scope` is stored and echoed by the API but matched by nothing — no registered trigger has a scoped surface.

## Wiring

- Registration: `main.py` → `utils/scheduled_tasks.py:register_sidebar_dispatcher_job` → `utils/sidebar_jobs.py:register_sidebar_jobs` → `TRIGGER_CLASSES` loop (heartbeat skipped when `config.heartbeat.enabled` is false — registration half of the double gate) → `dispatcher.register_trigger` → `sidebar_dispatcher_poll` job → `register_device_wake_job` → `heartbeat_device_wake_aggregate` job. The wake job carries its own `config.heartbeat.enabled` gate and borrows the poll's cadence (`sidebar_dispatcher.poll_interval_minutes * 60` — one knob); it registers only when the dispatcher registers, so `sidebar_dispatcher.enabled = false` stops wake publishing too. Counterparts: `utils/AGENTS.md` (`scheduled_tasks.py` fixed registration order; `sidebar_jobs.py`), `agents/AGENTS.md` (dispatcher), `config/AGENTS.md` (the gates).
- Rules protocol (two endpoints): `cns/api/trigger_rules.py` writes `trigger_rules` rows — trigger_id/field validated against `registered_trigger_specs()`, patterns compiled at write — → `rule_filter.apply_trigger_rules` at dispatch → matched-rule `prompt` rides `context['rule_prompt']` → `agents/base.py:SidebarAgent._build_system_prompt` (the single consumption point: every agent honors rule prompts, no per-agent wiring). Counterpart: `cns/api/AGENTS.md`.
- Floor sampling loop: `check_for_new_items` → `lt_memory/db_access.py:LTMemoryDB.get_floor_candidates` (importance + staleness, random sample, RLS-scoped) → `get_memories_by_ids` (pre-fetch) → `FloorContext` → agent → `update_last_tended` (agent-owned) → the NULL+age eligibility branch closes the loop. Params from `config.memory_curator.floor_*`. Counterparts: `lt_memory/AGENTS.md` (query semantics), `config/AGENTS.md`.
- Briefs and presence: the trigger imports `tools/implementations/heartbeat_tool.py:ensure_briefs_table` at poll time (DDL owned there; brief state in per-user SQLite, `encrypted__` columns arriving decrypted); `heartbeat_armed_users` rows are written by `heartbeat_tool` (`upsert_armed_user`/`remove_armed_user`/`refresh_armed_marker`) and read twice — the dispatcher's eligibility union (`agents/sidebar.py:_get_eligible_users`: armed users stay pollable while dormant) and `publish_device_wake_aggregate` (min `earliest_wake_at`, one admin-session query). Counterpart: `tools/implementations/AGENTS.md`.
- Device binding: `publish_device_wake_aggregate` → `utils/device_binding.py:notify_heartbeat_sleep` — sole caller; empty table publishes nothing; `notify` never raises (a shim failure leaves the device at full power, the unbound behavior). Counterpart: `utils/AGENTS.md` (its `device_binding.py` card names this directory as sole publisher).
- Agent handoffs (lazy `agent_class`): `HeartbeatAgent` (`agents/implementations/heartbeat_agent.py`) — context `briefs` with full decrypted payloads + `dispatch_stamp` per brief; `MemoryCuratorAgent` (`agents/implementations/memory_curator_agent.py`) — context `FloorContext`. Counterpart: `agents/implementations/AGENTS.md`.
- `interface_name` (`"heartbeat"`, `"memory_curator_floor"`) keys the dispatcher's dedup surface (`sidebar_activity`) and the activity-trinket grouping. Counterparts: `agents/AGENTS.md`, `working_memory/trinkets/AGENTS.md`.
- Directory consumers: `rg 'agents\.triggers'` → `utils/sidebar_jobs.py` (registry + wake job) and `cns/api/trigger_rules.py` (specs); nothing else imports the package.

## The wake cycle, poll to re-arm

1. Registration instantiates `TRIGGER_CLASSES` on the dispatcher, skipping `HeartbeatTrigger` when `config.heartbeat.enabled` is false; the poll half of that double gate re-checks the flag inside `check_for_new_items`. Only the disable direction is honored without restart — an enable flip waits for restart (the unregistered class never joins the dispatcher), and no in-process path writes the flag (`config` is an import-time singleton).
2. A poll tick: the dispatcher sets the user contextvar from eligibility — 2-day-active users plus every user present in `heartbeat_armed_users` — so armed users stay pollable while dormant (union owned by `agents/AGENTS.md`).
3. Discovery re-checks the flag, runs `ensure_briefs_table`, selects `state = 'armed'` ordered by `next_wake_at`, and keeps rows whose parsed wake time is due. An unparseable `next_wake_at` logs a warning and skips that brief — a corrupt row never fails the poll.
4. All due briefs become ONE work item: `brf_{user_id}_{minute_key}`, minute_key the earliest due brief's `next_wake_at` string-truncated to the minute. Batching exists because briefs cluster (a morning's re-arms) and one agent run beats N; a re-arm stamps a new `next_wake_at`, so the next due window is a genuinely new item — the same window never double-dispatches.
5. Before returning, the trigger stamps every dispatched brief's `last_wake_at` with `format_utc_iso(now)` and carries that same `dispatch_stamp` in each brief's context entry. The context carries full decrypted payloads (mission, condition_check, bail_if, prior `last_result`) — the agent acts on what is handed, never reconstructs intent from archaeology.
6. Dispatch: `apply_trigger_rules`, then the dispatcher's dedup (`agents/AGENTS.md`). Every run that enters `agents/base.py:SidebarAgent.run` exits through `_exit`, which writes the `sidebar_activity` row before `on_completion` — so a window has a prior record from its first run onward; `max_retries = 0` (base default) means a failed window is never re-dispatched.
7. Every `heartbeat_tool` report outcome (fired/false/bailed) overwrites `last_wake_at`; `on_completion` — every terminal status, owned by `agents/implementations/AGENTS.md` — hands briefs still `armed` with `last_wake_at` equal to the stamp to `apply_run_failure` — backoff re-arm (`interval × 2^failures`, clamped by `max_interval_seconds`) writes a NEW `next_wake_at` (a new window), or `failed_permanently` at `max_failures` (a deliberate exemption from the infrastructure-failure exclusion — `config/config.py:HeartbeatConfig.max_failures` documents the underivable-distinction reasoning).
8. Each state transition recomputes `heartbeat_armed_users` (`refresh_armed_marker`); the wake job reads `min(earliest_wake_at)` across users and hands it to `notify_heartbeat_sleep` — an empty table or unbound config publishes nothing and the device stays at full power, which is the unbound behavior.

Ordering invariants: the stamp precedes the return — stamp after, and the agent's comparison reads pre-dispatch values; the report-overwrite is what makes stamp-equality mean "unreported" — a new report outcome that skips the overwrite counts a reported brief as a straggler; the `on_completion` sweep is the only unwedge path for an under-reported brief, which is why it runs on failed and timeout statuses, not just success.
