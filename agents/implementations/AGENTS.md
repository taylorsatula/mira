# agents/implementations/ — the concrete sidebar agent classes: what each does when it runs and what it must be handed

## Files

- `__init__.py` — package marker only; it re-exports nothing and imports no agent class. Nothing to open.
- `forage_agent.py` — background research on `batch`, and the only type whose `continue` refines a finished result. Open it before changing how a completed briefing is reused, capped, or dismissed.
- `heartbeat_agent.py` — the brief gate, and the one place an under-reported run is accounted for. Open it before changing what happens to a brief whose run died before reporting.
- `memory_curator_agent.py` — the two-mode memory-graph curator and its work-item context shapes. Open it before changing a shape a trigger or the collapse handler fills.
- `phoneafriend_agent.py` — the outside-model consult and its segment-scoped thread store. Open it before changing how a consult thread is keyed, resumed, or expired.
- `talktoanyone_agent.py` — the persona consult: the caller supplies a persona description and a question in `subject`, and the model answers fully in character. Same blocking `other`-route mechanics and thread store as the phone-a-friend consult, separate `talktoanyone:` key prefix and interface. Open it before changing how a persona consult is framed, resumed, or expired.
- `whilethecatsaway_agent.py` — fire-and-forget curiosity research. Open it before changing what a background discovery is allowed to write into memory.

## Wiring

- Model-invoked dispatch: `tools/implementations/subagent_tool.py` → the target class's `activate`/`continue_task`, reached through `agents.specs.load_agent_class`. `continue_task` returns None when the task_id is not that type's surface, which is what lets the tool try each continuable type in turn and fall through to its generic not-found envelope; a class that raises on a foreign id ends the trial there instead, and the caller gets an error where it should have got that envelope. Counterpart: `tools/implementations/AGENTS.md`.
- Curator spawn at collapse: `cns/services/segment_collapse_handler.py:_spawn_integration_curator` → `MemoryCuratorAgent` in integration mode, gated on `config.memory_curator.enabled` and best-effort — a spawn failure or an at-cap refusal never fails the collapse. Producers fill the shape exactly, `candidate_hints` keyed by the new memory's full UUID string; a short-id key renders every hint as "(none)" and raises nothing. The two sources carry distinct item_ids on purpose — `integrate_{seg_id}_{user_id}:extraction` through the `on_memories_stored` callback, `:drain` through the manual-memory drain, differing only by that `:{source}` suffix — because one shared id makes the two runs race a single `UNIQUE(interface_name, thread_id)` row. Counterpart: `cns/services/AGENTS.md`.
- Dispatcher spawn: `agents/triggers/heartbeat_trigger.py` → `HeartbeatAgent`, and `agents/triggers/memory_floor_trigger.py` → `MemoryCuratorAgent` in floor mode. The heartbeat trigger writes `last_wake_at` on every brief it hands over and carries that value as `dispatch_stamp`; a report overwrites it a moment later, and `on_completion` reads `state='armed'` with a still-equal stamp as never-reported. A producer that stops carrying the stamp makes every brief unaccountable, so the accounting skips all of them and they stay armed behind the window's terminal row. The accounting reads `briefs` itself rather than through `heartbeat_tool` — `on_completion` runs `SELECT last_wake_at, state FROM briefs WHERE id = :id` against the per-user SQLite table whose DDL is `tools/implementations/heartbeat_tool.py:BRIEFS_DDL`, so a renamed `last_wake_at` or `state` breaks this query while the tool's own code keeps working. Each unaccountable brief then goes to `heartbeat_tool.apply_run_failure`, the terminator of the state machine: backoff re-arms it at `interval_seconds * 2^consecutive_failures`, and at `config.heartbeat.max_failures` it goes `failed_permanently` with an exit note instead. Counterparts: `agents/triggers/AGENTS.md`, `tools/implementations/AGENTS.md`.
- Tended stamp: `MemoryCuratorAgent.on_completion` → `lt_memory.db_access.LTMemoryDB.update_last_tended`, called through `_tended_uuids_for_status` only on `status == 'success'`. That stamp is what `get_floor_candidates` samples against: a stamp on a failed run hides every memory it names from the floor's resample, while a stamp that fails only logs and lets them re-surface through the NULL-and-old-enough branch. Counterpart: `lt_memory/AGENTS.md`.
- Completion publishing: `_get_completion_trinket` names `SubagentResultsTrinket` by class-name string for `working_memory/core.py:_handle_update_trinket` to resolve, so a renamed class drops the refresh with a warning and the completion never reaches the sidebar. `forage_agent.continue_task` reads `active_results` through a direct handle guarded by a None check, so a renamed member degrades to a not-dispatched answer rather than raising. Counterpart: `working_memory/trinkets/AGENTS.md`.
- Tool surfaces: `HEARTBEAT_AGENT_SCHEMA` and `CURATOR_MEMORY_SCHEMA` are imported from their tool modules at module level and handed to the loop through `tool_schema_overrides`. Counterpart: `tools/implementations/AGENTS.md`.

## Rules

- Import agent classes lazily on every dispatch path: `agents.specs.SUBAGENT_SPECS` stores each class as an `agent_class_path` string and `load_agent_class` imports it inside the call. The weight of a module-level agent import is its tool module's chain, and that varies by agent: `memory_curator_agent.py`'s `CURATOR_MEMORY_SCHEMA` pulls `memory_tool`, and behind it the embeddings provider, Valkey, and LT_Memory clients, while `heartbeat_agent.py`'s `HEARTBEAT_AGENT_SCHEMA` pulls `heartbeat_tool`, whose own chain is `tools.repo`, `tools.registry`, and `utils.timezone_utils`. A module-level agent import from a registration path such as `utils/sidebar_jobs.py` drags that agent's chain into startup, and reaching one agent's constant from another module loads both.
- `sanitize_untrusted_input` is a producer-trust claim, not a style setting. The base gate is on by default and screens only `context['raw_content']`; `HeartbeatAgent` and `MemoryCuratorAgent` set it False because their producers are trusted (briefs are user- or MIRA-authored; curator inputs are store-sampled memory text plus discovery-computed hints). When a producer set gains a field sourced from outside the system, that agent re-enables the gate — opting out there bypasses the injection screen for text the model then acts on.
- `CURATOR_MEMORY_SCHEMA` is a deepcopy of `MemoryTool.tool_schema` whose operation enum and description are then replaced wholesale with the fixed literal `_CURATOR_OPERATIONS` in the tool's own module, so a new `memory_tool` operation is invisible to the curator — its enum never grows — until the operation is added to that list; add it there when the curator should have it, and never widen the surface by dropping the override.

Elsewhere: this map owns what each concrete class does when it runs, not the loop that runs it, the policy that decides whether it may run, or what its tools do. The loop, gates, budgets, dedup, and spawn seam are `agents/AGENTS.md`; the per-type policy table and the dispatch protocol are `agents/specs.py`; the add-an-agent recipe and verification floor are `agents/HOW_TO_BUILD_AN_AGENT.md`; why any of it was built this way is in `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above. A class rename also has to reach the offline probes under the gitignored `scratch/` tree, which a plain `rg 'ForageAgent'` skips.
