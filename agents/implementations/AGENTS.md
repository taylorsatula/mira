## Rules

- **Mode Contract** — a multi-mode agent keys dispatch on `work_item.context['mode']` and declares its context shapes as the TypedDicts beside the class (`CandidateRef`/`NewMemory`/`IntegrationContext`, `FloorMemory`/`FloorContext` in `memory_curator_agent.py`); producers populate exactly those shapes, and `get_agent_prompt`/`build_initial_message` raise `ValueError` on any other mode — the base `run()` converts that to a `'failed'` exit, so a mis-keyed producer fails loud instead of running the wrong rubric. Identity asymmetry inside the shapes is load-bearing: `CandidateRef.memory_id` is a SHORT id (discovery pointer, resolvable by `memory_tool` only when unambiguous — on collision recover the full UUID by text search), while `NewMemory.memory_id`/`FloorMemory.memory_id` are FULL UUID strings (tool-call identity and `on_completion`'s stamp identity — short IDs cannot serve `update_last_tended`). A producer writing short ids into the tended lists breaks the stamp: parse warn+skip → the memory is never marked tended → the floor trigger re-samples it forever.
- Link typing: the curator judges every link type it writes — discovery arrives typeless (`CandidateRef.bond` always `""` from `lt_memory/linking.py:find_candidate_hints`; extraction bonds merged spawn-side, owned by `lt_memory/processing/AGENTS.md`) — but it is not the sole typer: the pending-manual drain writes programmatic `supersedes` links (`cns/services/segment_collapse_handler.py`), and `link_memories` rides the full `memory_tool` schema on the main conversation and the un-narrowed forage/whilethecatsaway rosters. Audit link-type provenance with `rg 'create_links'` (caller inventory owned by `lt_memory/AGENTS.md`); assuming curator exclusivity misses the drain and the un-narrowed surfaces.
- `tool_schema_overrides` replaces the whole schema dict handed to the LLM (`agents/base.py:_get_tool_schemas`) and consumes exported constants, never hand copies: `HeartbeatAgent` → `HEARTBEAT_AGENT_SCHEMA` (a standalone report-only surface), `MemoryCuratorAgent` → `CURATOR_MEMORY_SCHEMA` (a deepcopy of `MemoryTool.tool_schema` with the operation enum narrowed by `_CURATOR_OPERATIONS` — new `memory_tool` operations flow into the copy but stay unreachable unless listed). Dropping the override hands the curator `create_memory` (manufactured silt) and the heartbeat gate `schedule`/`cancel` (a gate able to erase its own wake schedule); a schema copied into the agent file drifts silently on the tool's next edit.
- Heartbeat failure accounting is the only re-arm path for briefs whose run died: the trigger stamps every dispatched brief's `last_wake_at` with the dispatch time and carries `dispatch_stamp` in context; every report overwrites `last_wake_at`; `HeartbeatAgent.on_completion` (every terminal status) re-queries the carried briefs and treats `state='armed' AND last_wake_at=stamp` as never-reported, advancing the failure state machine via `apply_run_failure` (`tools/implementations/heartbeat_tool.py`). `max_retries=0` is the matching half — a dispatcher retry would re-run the stale due-window payload after the per-brief accounting already re-armed. Drop the accounting and an under-reported run's briefs stay armed forever behind the window's terminal activity row.
- `MemoryCuratorAgent.on_completion` stamps `last_tended_at` only on `status='success'` (`_tended_uuids_for_status` → `lt_memory/db_access.py:update_last_tended`): the stamp is the floor trigger's exclusion signal (`get_floor_candidates` samples tended-before-cutoff and never-tended rows aging in via the NULL+age branch). Stamp on failure and every failed run hides its memories from floor eligibility; skip the stamp and tended memories flood the floor again. The stamp is tolerate-and-log — it must never mask a successful curation run.
- Agent modules import their schema constants at module level — `memory_curator_agent.py` thereby pulls `memory_tool`, and with it the embeddings/Valkey/LT_Memory clients; `heartbeat_agent.py` pulls `heartbeat_tool`'s module — so every dispatch-path consumer imports agent classes lazily: the triggers' `agent_class` property, the tool spawn functions, `_spawn_integration_curator`. A module-level agent import from a registration path (`utils/sidebar_jobs.py`) drags the heavy chain into startup.
- `sanitize_untrusted_input = False` (`HeartbeatAgent`, `MemoryCuratorAgent`) is a producer-trust claim, not a style: briefs are user/MIRA-authored, curator inputs are store-sampled memory text and discovery-computed hints. The base default True screens only `context['raw_content']` (mechanism owned by `agents/AGENTS.md`). An agent whose producer set ever gains an externally sourced field re-enables the gate — opting out there bypasses the injection screen for content the model acts on.

## Files

- `__init__.py` — empty, no re-exports; agents are imported by module path at their spawn sites; no agent registry exists here (the trigger registry is `agents/triggers/registry.py:TRIGGER_CLASSES`).
- `forage_agent.py` — speculative research agent on `batch`; the roster's only blocking-capable agent and sole `run_blocking` target; rubric `config/prompts/agents/forage_system.txt`. Owns the refinement branch (`previous_result` in context), the `_iteration_status` progress bar (`_PROGRESS_BAR_WIDTH`), and the roster's only overwatch publish (`on_overwatch_update` → `ForageTrinket` `in_progress` entries). Entry: `build_initial_message`, `_iteration_status`, `on_overwatch_update`. Gotcha: `max_iterations = 20` is the background cap, calibrated to the 600s `agent_timeout_overrides['forage']`; `forage_tool`'s blocking path rewrites the instance's cap to `config.forage_tool.max_iterations` before `run_blocking`, and the bar and grace turn rescale with it.
- `heartbeat_agent.py` — the brief gate on `fast`: evaluates every carried brief (bail_if first, then condition_check) and reports through the report-only schema; `max_iterations = 8`; rubric `config/prompts/agents/heartbeat_agent_system.txt`. Entry: `build_initial_message` (renders the batched briefs list), `on_completion` (failure accounting). Gotcha: the rubric's DISPATCH step names "the specialized agent named in the work item's dispatch instructions" — no producer writes that key (trigger context is the briefs list only) and `available_tools` offers no dispatch tool, so a mission needing real work has no dispatch path; a `fired` report is the agent's own say-so.
- `memory_curator_agent.py` — the two-mode curator on `batch` (integration: tend each new memory — link/merge/stand-alone; floor: triage the low-value sample — archive/salvage); rubrics `config/prompts/agents/memory_curator_integration.txt` and `memory_curator_floor.txt`. Owns the Mode Contract TypedDicts, the mode-dispatched prompt/message builders, the success-only `last_tended` stamp, and `_short` (renders via `format_memory_id`, `utils/tag_parser.py`). Entry: `CandidateRef`, `IntegrationContext`, `FloorContext`, `get_agent_prompt`, `_build_integration_message`, `_build_floor_message`, `on_completion`. Gotcha: `candidate_hints` keys are full-UUID strings — `_build_integration_message` reads `hints.get(full_id)`, so a spawn site keying by short id renders "(none)" for every memory with no error.
- `whilethecatsaway_agent.py` — curiosity research on `batch`, fire-and-forget only (no blocking; no refine/dismiss path — results auto-expire after 8 turns, owned by `working_memory/trinkets/AGENTS.md`); rubric `config/prompts/agents/whilethecatsaway_system.txt`. Entry: `build_initial_message` (topic/context), `_build_completion_context`. Gotcha: full `memory_tool` surface — `create_memory` included, so findings queue into the pending-memories chain (owned by `tools/implementations/AGENTS.md`); `ForageAgent` carries the same un-narrowed surface.

## Wiring

- Spawn edges (this directory is the dispatch target; spawn mechanics owned by `agents/AGENTS.md`): `tools/implementations/forage_tool.py` → `ForageAgent` (background thread + the inline blocking path) and `tools/implementations/whilethecatsaway_tool.py` → `WhileTheCatsAwayAgent` (thread; a thread crash publishes `failed`/`ThreadCrash`) — counterparts `tools/implementations/AGENTS.md` · `agents/triggers/heartbeat_trigger.py` → `HeartbeatAgent` (batched due-window item `brf_{user_id}_{minute}`; stamps `last_wake_at`) and `agents/triggers/memory_floor_trigger.py` → `MemoryCuratorAgent` floor (`floor_{user_id}_{activity_days}`, use-day gated) — counterpart `agents/triggers/AGENTS.md` · `cns/services/segment_collapse_handler.py:_spawn_integration_curator` → `MemoryCuratorAgent` integration — two sources with distinct item_ids `integrate_{segment}_{user_id}:{source}`: `source="extraction"` via the `on_memories_stored` factory callback and `source="drain"` via `_tend_manual_memories`; gated on `config.memory_curator.enabled` (the same flag gates the floor trigger); best-effort — a spawn failure never fails the collapse — counterparts `cns/services/AGENTS.md`, seam `lt_memory/AGENTS.md`, hint assembly `lt_memory/processing/AGENTS.md`.
- Schema constants consumed at module level: `HEARTBEAT_AGENT_SCHEMA` (`tools/implementations/heartbeat_tool.py`), `CURATOR_MEMORY_SCHEMA` (`tools/implementations/memory_tool.py`) — op sets and state machines owned by `tools/implementations/AGENTS.md`.
- Completion publishing (`UpdateTrinketEvent`, `continuum_id='sidebar'`): `ForageTrinket` (terminal states + per-iteration `in_progress`), `WhileTheCatsAwayTrinket`, `MemoryCuratorTrinket` — state machines owned by `working_memory/trinkets/AGENTS.md`. `HeartbeatAgent` overrides no `_get_completion_trinket` and publishes to the default `AsyncActivityTrinket` — the rendered line is the `sidebar_activity` row's summary; the event context is a re-render signal only.
- Config couplings: `config.sidebar_dispatcher.agent_timeout_overrides` keys are class names minus `Agent`, lowercased (`forage`, `memorycurator`, `whilethecatsaway`; heartbeat unlisted → default `agent_timeout_seconds`); `config.memory_curator.enabled` gates both curator modes; `config.heartbeat.max_failures`/`max_interval_seconds` bound `apply_run_failure`'s backoff.
- Full consumer set: `rg --no-ignore 'ForageAgent|HeartbeatAgent|MemoryCuratorAgent|WhileTheCatsAwayAgent'` → the five spawn sites above, the roster definitions and base-class comments, in-tree docstring/description mentions (config field docs, tool and trinket docstrings), the maps, and offline `scratch/` probes (gitignored — plain `rg` misses them) — a class rename triages every class.
