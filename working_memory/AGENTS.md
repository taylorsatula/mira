## Rules

- `_compose_lock` (module-level in `core.py`) is shared cross-directory and must stay an `RLock`: `cns/services/orchestrator.py:_compose_llm_messages` imports it and holds it across the publish→composed round-trip, and the synchronous bus re-enters it on the same thread at `_handle_compose_prompt` → per-trinket `UpdateTrinketEvent` broadcast → `_handle_update_trinket` → `handle_update_request` → `TrinketContentEvent` → `_handle_trinket_content` — three lock-taking handlers on the re-entrant chain. A plain `Lock` deadlocks every compose at `_handle_compose_prompt`, before the broadcast reaches any trinket; relocating the lock breaks `from working_memory.core import _compose_lock` at the orchestrator.
- `SystemPromptComposer` carries no user dimension — one unscoped `_sections` dict on a process-global instance. User isolation rests entirely on `_compose_lock` serializing whole composes, plus per-user keys on the coordinator's fields (`_current_continuum_ids[user_id]`, `_portrait_cache[user_id]`) and on trinket state (singleton doctrine owned by root). A per-user value stored unkeyed, or compose work started outside the lock, cross-wires two users' prompts.
- Two producer paths, different semantics: `publish_trinket_update()` is gated on `_current_continuum_ids[user_id]`, set only by the user's first `_handle_compose_prompt` — before that it is a logged no-op (`"No active continuum context for trinket update"`) and the requested refresh silently never lands; live callers: `rg 'publish_trinket_update'`. Publishing `UpdateTrinketEvent.create(...)` straight to the bus bypasses the gate and always reaches the router.
- Trinket failure never fails the turn: `_handle_update_trinket` catch-alls around `handle_update_request`, logs, and continues the broadcast loop — the failed trinket's section is absent from that compose and its Valkey field keeps the previous value. Failure classification is a substring test on the exception type name (`Database`/`Valkey`/`Connection` → `error_category: infrastructure`, else `logic`): an infra exception class lacking those tokens misfiles, and an exception swallowed inside the trinket never reaches this boundary at all (trinket-side duty owned by `working_memory/trinkets/AGENTS.md`).
- Collapse flush clears three stores in a fixed order per StatefulTrinket — `_clear_all_state()` (in-memory items) → `clear_user_turn(user_id)` (turn counter) → `_clear_from_valkey()` (API-visible field) — then `invalidate_portrait(user_id)`. A skipped step leaves that store stale: in-memory state surviving into the next segment renders prior-segment data post-collapse; a surviving Valkey field serves pre-collapse content to API reads; a surviving counter does no segment-level harm — `TurnCompletedEvent.turn_number` counts the continuum's user messages (segments share the sequence) and `_on_turn_completed` overwrites the counter before `_expire_items()` runs — the discontinuity is cross-continuum: turn numbers restart at 1, so a counter surviving a continuum switch (no flush fires there) over-extends `display_until_turn` windows. Trinkets never subscribe to `SegmentCollapsedEvent` themselves (child-map Rule).

## Files

- `__init__.py` — re-export of `WorkingMemory` only; sole runtime consumer `cns/integration/factory.py` (`from working_memory import WorkingMemory`). Everything else imports `working_memory.core` by path.
- `types.py` — TypedDicts for the dict shapes crossing composer and core (`ComposedPrompt`, `TrinketState`, `TrinketStatesMeta`, `AllTrinketStates`); no consumer outside this package.
- `composer.py` — placement and assembly of the composed prompt: `SECTION_LAYOUT` (each slot → exactly one of `system`/`post_history`/`notification`; `cache_policy` splits `system` into cached/non-cached, consulted only after the other two placements have routed), `set_base_prompt` (appends the `═`×60 delimiter + scaffolding note; `cache_policy=True` hardwired — the cache-eligible prefix starts here), `compose()` → `ComposedPrompt`, `_build_notification_center` (wraps parts in `<mira:hud>`). Entry: `SystemPromptComposer.compose`, `add_section`, `set_base_prompt`, `SECTION_LAYOUT`. Gotcha: `tool_availability` is a reserved dead slot — no trinket provides it; the silent miss is deliberate, do not build on it.
- `core.py` — the `WorkingMemory` coordinator: four event subscriptions in `__init__`, `_handle_compose_prompt` (per-user continuum id, base-prompt personalization, the broadcast, `SystemPromptComposedEvent`), `_handle_update_trinket` (router + isolation boundary), `_handle_trinket_content`, `_flush_stateful_trinkets`, `publish_trinket_update`, `invalidate_trinket`/`invalidate_portrait`, `get_trinket`, and the Valkey read side `get_trinket_state`/`get_all_trinket_states`. Gotcha: `get_all_trinket_states` reaches `valkey._client.hkeys` directly — a private attribute with no public wrapper on `clients/valkey_client.py`; a client refactor breaks the working-memory API read with an `AttributeError` at request time, not at boot.
- `skills/` — MIRA's global model-facing skills, one `<name>/SKILL.md` each (flat `name`/`description` frontmatter + markdown body; discover the roster by listing the directory, never from memory). Read-only repo content: `utils/skill_files.py:delete_user_skill` raises `GlobalSkillReadOnlyError` for anything here, and user-authored skills live under `data/users/{user_id}/skills/`, never in this tree. Served into the prompt through the skills trinkets (`working_memory/trinkets/AGENTS.md`); boot-snapshot freshness owned by `utils/AGENTS.md`. `bash_tool`'s refusal path routes precise-edit work to `precise-file-editing` here (`tools/implementations/AGENTS.md`).
- `trinkets/` — trinket implementations and the base classes; own map: `working_memory/trinkets/AGENTS.md`.

## Wiring

- Construction: `cns/integration/factory.py:_get_working_memory()` is the sole constructor of `WorkingMemory(event_bus)` — the four subscriptions happen in `__init__` — and fires `utils.skill_files.load_global_catalog()` (the skills boot snapshot) immediately after trinket construction. Counterpart: `cns/integration/AGENTS.md`; trinket construction order and config gates owned by `working_memory/trinkets/AGENTS.md`.
- Compose round-trip: `cns/services/orchestrator.py:_compose_llm_messages` publishes `ComposeSystemPromptEvent` (base prompt = `config.system_prompt`, passed in by the API layer) and consumes the reply `SystemPromptComposedEvent` in `_handle_system_prompt_composed` — sole subscriber; fields still `None` after the publish → `RuntimeError`, the turn fails rather than running on an empty prompt. The traced walkthrough is owned by `working_memory/trinkets/AGENTS.md` ("The compose round-trip"). Counterpart: `cns/services/AGENTS.md`.
- Session-start signal: `ComposeSystemPromptEvent` also drives poller lifecycle — `cns/services/pollers/segment_poller.py` starts a per-user polling thread on the user's first compose and stops it on `SegmentCollapsedEvent`; the inbox poller is the live subclass. Counterpart: `cns/services/pollers/AGENTS.md`.
- Read side: `get_trinket_state(section)`/`get_all_trinket_states()` ← `cns/api/data.py:_get_working_memory` (the `section` param filters; a `None` state raises the API's `NotFoundError`, so corrupt JSON in a hash field — logged warning — reads as not-found). Counterpart: `cns/api/AGENTS.md`.
- Direct-handle edges (renaming a member breaks its caller silently — None/hasattr guards degrade to empty; consumer inventory owned by `working_memory/trinkets/AGENTS.md`): `get_trinket` — `rg 'get_trinket\('` (the orchestrator's retention read on `ProactiveMemoryTrinket`, `subagent_tool` and `ForageAgent.continue_task` on `SubagentResultsTrinket`) · `invalidate_trinket("LoraTrinket", user_id)` ← `cns/services/lora_service.py:_invalidate_lora_cache` — the method requires an ambient user context (`get_current_user_id()` raises when none is set, before any swap), swaps the contextvar to the passed `user_id` only for the Valkey clear, and restores the ambient user after: a no-context caller fails loud, never leaks the target user onto the contextvar · `invalidate_portrait(user_id)` ← `cns/services/portrait_service.py:_invalidate_portrait_cache`, plus the collapse flush · `event_bus` ← `tools/repo.py:ToolRepository.__init__` — subscribes `_clear_pinned_tools_on_segment_collapse` to `SegmentCollapsedEvent` through `getattr(working_memory, "event_bus", None)`; the None guard makes a member rename silently drop the collapse-time pinned-tool teardown — counterparts `tools/AGENTS.md`, `cns/integration/AGENTS.md`.
- Personalization inputs: `read_portrait` (`cns/services/portrait_service.py`; returns `""` on any failure — the portrait is optional content and a degraded read is the pre-portrait state) fills `_portrait_cache` at the user's first compose; `get_user_preferences()`/`get_model_config("primary")` resolve per root doctrine (`utils/AGENTS.md`). The five placeholder strings are twin with `config/system_prompt.txt`, contract owned by `config/AGENTS.md`: rename either side alone and the literal `{placeholder}` reaches the model every turn, no error anywhere.
- Update routing: producers publish `UpdateTrinketEvent` with `target_trinket` = registered class name; `_handle_update_trinket` drops an unregistered name with a warning and no re-render — the section serves the previous compose's content. Producer set: `rg 'target_trinket'` (inventory owned by `working_memory/trinkets/AGENTS.md`).
- Valkey surface `trinkets:{user_id}` (field = slot name; `TRINKET_KEY_PREFIX` from `working_memory/trinkets/base.py`): write side, field format, and the post-mutation field invalidators (`rg 'TRINKET_KEY_PREFIX'`) are owned by `working_memory/trinkets/AGENTS.md`; the read methods in `core.py` are the in-process consumers. Retry wrappers: `clients/valkey_client.py` (`hset_with_retry`/`hget_with_retry`/`hdel_with_retry`).
