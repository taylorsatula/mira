# working_memory/ — system-prompt composition from trinket sections

## Files

- `__init__.py` — package re-export. Open it before moving or renaming `WorkingMemory`.
- `types.py` — the `TypedDict`s for the composed-prompt dict and the two working-memory API read responses. Open it before adding a field to a composed prompt or to a working-memory API response.
- `composer.py` — section placement and prompt assembly. Open it before adding a prompt slot or changing where a section lands.
- `core.py` — the event-driven compose coordinator. Open it before changing when a prompt is composed or how a trinket is reached.
- `skills/` — MIRA's global model-facing skills, one `<name>/SKILL.md` each, served into the prompt through the skills trinkets. Open it before editing a shipped skill, never for user-authored ones; list the directory for the roster.
- `trinkets/` — trinket implementations and the base classes; its own map.

## Wiring

- Construction: `cns/integration/factory.py:_get_working_memory` is the sole constructor of `WorkingMemory(event_bus)`; every bus subscription is taken in `__init__`. A second construction site would subscribe a competing handler to every compose event. Counterpart: `cns/integration/AGENTS.md`; trinket construction order and its config gates belong to `working_memory/trinkets/AGENTS.md`.
- Compose round-trip: `cns/services/orchestrator.py:_compose_llm_messages` takes `_compose_lock`, publishes `ComposeSystemPromptEvent` carrying the API-supplied base prompt, and reads the reply out of `SystemPromptComposedEvent` in `_handle_system_prompt_composed`. A `_cached_content` still `None` after the publish raises `RuntimeError`, so the turn fails rather than running on an empty prompt; the check is `is None`, not falsy, because the other three fields may legitimately be empty. Counterpart: `cns/services/AGENTS.md`; the per-trinket trace is owned by `working_memory/trinkets/AGENTS.md`.
- Prompt personalization: the five placeholder literals `core.py` substitutes (`{first_name}`, `{user_context}`, `{relative time since account creation}`, `{model_id}`, `{model_name}`) are twins of the text in `config/system_prompt.txt`. Rename one side alone and the literal brace string reaches the model every turn with no error anywhere. Counterpart: `config/AGENTS.md`.
- Session-start signal: the same `ComposeSystemPromptEvent` drives poller lifecycle — `cns/services/pollers/segment_poller.py` starts a per-user polling thread on the user's first compose and stops it on `SegmentCollapsedEvent`. That poll thread's own `UpdateTrinketEvent` publishes re-enter `_handle_update_trinket`, which takes the same lock, so a poll publish and a compose serialize against each other rather than interleaving. Counterpart: `cns/services/pollers/AGENTS.md`.
- Read side: `cns/api/data.py:_get_working_memory` calls `get_trinket_state(section)` when the `section` query param is set and `get_all_trinket_states()` otherwise; a `None` state becomes the API's `NotFoundError`, which is also how a hash field holding invalid JSON reads. Counterpart: `cns/api/AGENTS.md`.
- Direct handles: `get_trinket` (the orchestrator's retention read, `subagent_tool`, `ForageAgent.continue_task`), `publish_trinket_update` from `tools/implementations/invoke_skill_tool.py`, `invalidate_trinket("LoraTrinket", user_id)` from `cns/services/lora_service.py`, and the `event_bus` attribute that `tools/repo.py` reads through a `None` guard to subscribe its own collapse handler. The guards degrade to empty or to a skipped subscription rather than raising, so a renamed member breaks its caller silently. Consumer inventory: `rg 'get_trinket\('`; counterparts `cns/integration/AGENTS.md`, `tools/implementations/AGENTS.md`, `agents/implementations/AGENTS.md`.
- Portrait: `_handle_compose_prompt` reads `portrait_service.read_portrait` on the first compose for a user, under `_compose_lock`, and `_portrait_cache[user_id]` keeps that database read off the process-wide lock thereafter; `invalidate_portrait(user_id)` is the only correct way to make a re-synthesized portrait visible, and `cns/services/portrait_service.py` owns the synthesis side. Counterpart: `cns/services/AGENTS.md`.
- Skills: each `skills/` subdirectory holds one `SKILL.md`, read into the global catalog by `utils/skill_files.py` (`GLOBAL_SKILLS_DIR` points at this directory) once at boot; the catalog is served from that snapshot for process life, so an edit here takes effect only after a restart and a live test of a just-edited skill sees the old text with no error. Counterparts: `utils/AGENTS.md`, `working_memory/trinkets/AGENTS.md`.
- Update routing: producers publish `UpdateTrinketEvent` with `target_trinket` set to a registered class name; `_handle_update_trinket` drops an unregistered name with a warning; that section is then missing from the compose, while its `trinkets:{user_id}` field keeps the last value a successful render wrote. Producer set: `rg 'target_trinket'`; inventory owned by `working_memory/trinkets/AGENTS.md`.
- Cache surface `trinkets:{user_id}` (field = slot name, `TRINKET_KEY_PREFIX` from `working_memory/trinkets/base.py`): the write side, field format, and post-mutation invalidators are owned by `working_memory/trinkets/AGENTS.md`; the read methods here are the in-process consumers.

## Rules

- `_compose_lock` is module-level in `core.py` and must stay an `RLock` at that path: `cns/services/orchestrator.py:_compose_llm_messages` imports it and holds it across the publish→composed round-trip, and the synchronous bus re-enters it on the same thread through `_handle_compose_prompt` → per-trinket `UpdateTrinketEvent` broadcast → `_handle_update_trinket` → `handle_update_request` → `TrinketContentEvent` → `_handle_trinket_content`, three lock-taking handlers deep. A plain `Lock` deadlocks every compose at the first nested handler; relocating the symbol breaks the orchestrator's import.
- User isolation here is positional, not structural: `SystemPromptComposer._sections` is a single unscoped dict on a process-global instance, and correctness rests on `_compose_lock` serializing whole composes plus per-user keys on the coordinator's own fields (`_current_continuum_ids[user_id]`, `_portrait_cache[user_id]`). A per-user value stored unkeyed, or compose work started outside the lock, cross-wires two users' prompts.
- Two update producers, two semantics: `publish_trinket_update()` is gated on `_current_continuum_ids[user_id]`, which only the user's first `_handle_compose_prompt` sets — before that it logs and returns, so the requested refresh silently never lands; publishing `UpdateTrinketEvent.create(...)` straight to the bus bypasses the gate and always reaches the router.
- Trinket failure never fails the turn: `_handle_update_trinket` catch-alls around `handle_update_request`, logs, and continues the broadcast, so the failed trinket's section is absent from that compose while its Valkey field keeps the old value. There the infrastructure/logic split is a substring test on the exception class name, so a real outage raised by a class whose name does not spell its failure type is filed as a logic bug.
- Collapse flush clears three stores per `StatefulTrinket` in a fixed order — `_clear_all_state()`, then `clear_user_turn(user_id)`, then `_clear_from_valkey()` — and then calls `invalidate_portrait(user_id)`. Skipping the in-memory step renders prior-segment items into the next segment; skipping the Valkey step leaves pre-collapse content served to API reads; a surviving turn counter does no segment-level harm because `TurnCompletedEvent.turn_number` counts the continuum's user messages and overwrites it before expiry runs, but it over-extends `display_until_turn` windows across a continuum switch, where no flush fires.
- `get_all_trinket_states` reaches `valkey._client.hkeys` directly: a private attribute with no public wrapper on the client. A refactor of `clients/valkey_client.py` breaks the working-memory API read with an `AttributeError` at request time, never at boot.

Elsewhere: this map routes composition and does not own trinket implementations, their base classes, the add-a-trinket recipe, or the per-trinket trace of the compose round-trip. The event classes (`ComposeSystemPromptEvent`, `UpdateTrinketEvent`, `TrinketContentEvent`, `SystemPromptComposedEvent`, `SegmentCollapsedEvent`) are defined in `cns/core/events.py`; bus mechanics (synchronous dispatch, subscribe by event class `__name__`) belong to root doctrine. The read-only guard that makes this tree refuse writes is `GlobalSkillReadOnlyError` in `utils/skill_files.py`, which also owns skill-file freshness; the route configs personalization resolves and the identity contextvar come from `utils/user_context.py`. Why a rule on this page reads as it does is in `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.
