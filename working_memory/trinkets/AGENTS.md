# working_memory/trinkets/ — Self-registering prompt-section components, each owning one `variable_name` slot in the composed system prompt

## Rules

- `variable_name` is dual-purpose: it names the `SECTION_LAYOUT` slot in `working_memory/composer.py` AND is the Valkey hash field under `trinkets:{user_id}` (`base.py:TRINKET_KEY_PREFIX`, `_persist_to_valkey()`). Because all trinkets share one hash per user, two trinkets must never declare the same `variable_name` — a collision silently overwrites the other's persisted content. `persona_trinket.py` (`persona_directives`) and `lora_trinket.py` (`behavioral_directives`) are the documented near-collision pair.
- State-mutating trinkets (`email`, `forage`, `memory_curator`, `whilethecatsaway`, `peanutgallery`) override `handle_update_request()` to consume event context FIRST, then call `super().handle_update_request(event)` to render. An event context missing the trinket's action key (`data`, `task_id`, or `action`) is a lifecycle refresh (compose broadcast or `StatefulTrinket._refresh_content()`), not new input — re-render from existing state, never treat it as data. Missing-`task_id` paths return `super().handle_update_request(event)` directly in `forage_trinket.py`, `memory_curator_trinket.py`, `whilethecatsaway_trinket.py`.
- `StatefulTrinket._expire_items()` returning `True` triggers `_refresh_content()` → `working_memory.publish_trinket_update(context={"action": "lifecycle_refresh"})` for a mid-turn re-render (`base.py:_on_turn_completed`). Returning `False` every turn is valid for poller-fed or store-fed trinkets — `email_trinket.py` and `live_context_compaction_trinket.py` do exactly that.
- Per-user state is a plain dict keyed by `get_current_user_id()` (`_user_results`, `_user_guidance`, `_inbox_snapshots`, `base.py:_turn_counts`). Trinket instances are process-global singletons registered once and shared across users — never store user state on instance attributes without the user-id key, and never assume a trinket serves one user.
- Escape every user- or agent-controlled string interpolated into prompt XML: `html.escape(value, quote=True)` for attribute values, `html.escape(value)` for body text — the reference idiom is `asyncactivity_trinket.py:_render_items()`. All result-feed trinkets (`forage`, `whilethecatsaway`, `memory_curator`, `reminder_manager`, `domaindoc`) follow this; new trinkets must too.
- Do not subscribe a trinket to events that mutate turn-scoped state on collapse; `StatefulTrinket` already subscribes `TurnCompletedEvent` in `base.py`, and segment collapse is handled centrally by `WorkingMemory._flush_stateful_trinkets()` calling `_clear_all_state()`.
- `HOW_TO_BUILD_A_TRINKET.md` is the authoring walkthrough and is kept aligned with `base.py`: it teaches the `variable_name` class attribute (never a `_get_variable_name()` method), the `EventAwareTrinket` vs `StatefulTrinket` choice, per-user-dict state, XML rendering with escaping, propagate-infrastructure-failures error handling, and the two-file registration (`cns/integration/factory.py` instantiation + `working_memory/composer.py:SECTION_LAYOUT` placement). Change a contract in `base.py` and this guide in the same commit.

## Files

- `base.py` — `EventAwareTrinket` (ABC: validates `variable_name`, self-registers via `working_memory.register_trinket()`, owns the render/persist/publish cycle in `handle_update_request()`) and `StatefulTrinket` (per-user turn counters via `current_turn` property, `_expire_items`/`_clear_all_state` contract, `_refresh_content()`). Owns Valkey persistence (`TRINKET_KEY_PREFIX`, `_persist_to_valkey()`, `_clear_from_valkey()`). Infrastructure failures propagate out of `handle_update_request()` by design. `Consumers: working_memory/core.py` (registration + `_flush_stateful_trinkets()`).
- `email_trinket.py` — thin zero-I/O inbox HUD (`inbox_status`, `StatefulTrinket`). Stores poller snapshots from `UpdateTrinketEvent.context['data']`, renders a trusted `<inbox_status>` XML frame around ONE `utils/untrusted_content.wrap_untrusted` region holding a plain-text listing, one line per email (`_format_email_line`; header values whitespace-folded and capped at `_MAX_HEADER_CHARS` = 120). Headers render into the primary system prompt — attacker-controlled content crosses the one sanctioned boundary once per render, never per field (per-field wrapping repeated the directive up to 3× per email). `_expire_items()` always `False` — poller refreshes state. `Consumers: cns/services/pollers/inbox_poller.py` (publishes `{'data': [...]}` snapshots).
- `asyncactivity_trinket.py` — sidebar agent activity feed (`async_activity`, plain `EventAwareTrinket`). Reads `sidebar_activity` SQLite table per render via `UserDataManager`; items persist until dismissed (no turn expiry, no collapse state). `html.escape`s interface/summary/reason text. `Consumers: agents/base.py` (`ensure_activity_schema`).
- `skills_catalog_trinket.py` — available-skills catalog (`skills_catalog`, plain `EventAwareTrinket`, `cache_policy=True`). Renders the merged catalog from `utils.skill_files.catalog_for()` — the boot-cached global skills (stable for process life) plus the user's own (live re-scan per render, with the empty-directory negative cache owned by `utils/AGENTS.md`) — one `<skill name=… description=…/>` line per skill plus the fixed instruction line directing the model to call `invoke_skill_tool` with the exact name; empty merged catalog → `""` (no dangling instruction). `Consumers: tools/implementations/invoke_skill_tool.py` (loads the bodies this catalog advertises).
- `active_skills_trinket.py` — activated skill bodies (`active_skills`, `StatefulTrinket`, `cache_policy=False` so a mid-conversation activation never busts the cached prefix). `handle_update_request()` on `action == 'activate'` stores a body snapshot per user (user→name→body) then delegates — the snapshot, not a re-read, is what renders, so mid-segment file edits cannot drift the section. `_expire_items()` always `False` (no TTL); `_clear_all_state()` flushes on segment collapse; re-activation overwrites. `html.escape`s name and body. `Consumers: tools/implementations/invoke_skill_tool.py` (publishes `{'action': 'activate', 'name', 'body'}`).
- `domaindoc_trinket.py` — domain knowledge injection (`domaindoc`, `cache_policy=True`). Owns the section-tree renderer: one walk of the section tree produces three buffers (`_format_sections()` → states / unconditional TOC index / content), two nesting levels, pinned-override, collapsed-parent-hides-descendants. Renders personal docs plus accepted cross-user shares via `utils.domaindoc_shares.get_accepted_shares()`, reading the owner's `UserDataManager` with `shared_by` attribute. `Consumers: tools/implementations/` (domaindoc section-management tools operate on the same state).
- `forage_trinket.py` — background forage results (`forage_results`, `StatefulTrinket`). Owns the task-status state machine (`pending → in_progress → success | timeout | failed`, plus `dismissed`); `in_progress` summaries stack per-iteration so the primary LLM sees the full research arc; terminal states never downgraded by a late `in_progress`; the timeout render (`_format_error`) shows the producer's actual fields — `iterations` count and `error` summary (`forage_agent._build_completion_context` never sends `elapsed`/`iteration`), so never render those. Errors/timeout expire after `ERROR_TTL_TURNS = 5`, successes persist until dismiss or collapse. `Consumers: tools/implementations/forage_tool.py` (`dismiss_task_id`) and the forage agent's overwatch loop (status events).
- `whilethecatsaway_trinket.py` — curiosity-research results (`whilethecatsaway_results`, `StatefulTrinket`). Same task-status state machine but ALL results auto-expire after `RESULT_TTL_TURNS = 8`; no dismiss path. `Consumers: agents/implementations/whilethecatsaway_agent.py` (status events).
- `memory_curator_trinket.py` — memory-curation results (`memory_curation`, `StatefulTrinket`). Same state machine, keyed by curation-run `task_id`; successes persist until segment collapse, timeout/failed expire after `ERROR_TTL_TURNS = 5`. Unknown statuses are ignored (early return without render). `Consumers: cns/services/orchestrator.py` / MemoryCuratorAgent runs.
- `live_context_compaction_trinket.py` — conversation-prefix continuation brief (`context_compaction`, `StatefulTrinket`). Zero summarization logic: renders `LiveContextCompactionStore.get()` only when the artifact's `continuum_id` matches the event's; `_clear_all_state()` deletes the Valkey artifact on collapse. `_expire_items()` always `False`. `Consumers: cns/services/live_context_compaction_service.py` (writes the artifact).
- `persona_trinket.py` — current immutable Persona revision's directives (`persona_directives`, `cache_policy=True`), rendered via `PersonaRepository.get_current_revision()`. Shares the `trinkets:{user_id}` Valkey hash with `lora_trinket` — slot names must never collide.
- `lora_trinket.py` — user-model observations from the feedback-synthesis pipeline (`behavioral_directives`, `cache_policy=True`). Parses `<mira:observation>`/`<mira:topic>` XML out of `FeedbackTracker.get_lora_content()` with regex, strips `<changelog>` blocks, and when `needs_checkin` renders the `<behavioral_checkin>` contract (verbatim blockquote + matching `<mira:checkin_response>` tag).
- `peanutgallery_trinket.py` — metacognitive observer guidance (`peanutgallery_guidance`, `StatefulTrinket`). `PeanutGalleryService` injects entries via `handle_update_request()` `action == 'add_guidance'`; renders three separate sections (standard = silent repair, initiative = bounded stewardship, critical = fourth-wall-breaking directive) so criticality gates explicit self-acknowledgment. Default TTL 2 turns. `Consumers: cns/services/peanutgallery_service.py`.
- `proactive_memory_trinket.py` — surfaced long-term memories (`relevant_memories`, plain `EventAwareTrinket`). Caches the previous turn's memories per user; `get_cached_memories()` feeds orchestrator retention evaluation. Owns cross-primary linked-memory dedup (`_format_linked_context()` seeds `seen_linked_ids` with primary IDs so no memory renders twice). `Consumers: cns/services/orchestrator.py` (`get_cached_memories`).
- `manifest_trinket.py` — conversation segment manifest (`conversation_manifest`, plain `EventAwareTrinket`). Formats `ManifestQueryService.get_segments()` into `<conversation_manifest>` XML grouped by user-timezone relative date; legitimately returns `""` when no segments exist (no history yet — not a failure). `Consumers: cns/services/manifest_query_service.py`.
- `reminder_manager.py` — active reminders (`active_reminders`, plain `EventAwareTrinket`). Fetches overdue/today sets for user and internal categories by invoking `ReminderTool.run()` directly (the only trinket that executes a tool), formatted via the `_CategoryConfig` dataclass matrix. Empty result is legitimately empty, not failure. `Consumers: tools/implementations/reminder_tool.py`.
- `location_trinket.py` — location/weather context (`location_context`, `cache_policy=True`). Reads the `location:{user_id}` Valkey key populated by the POST /location endpoint on frontend page load; renders forecast, sunrise/sunset, UV warning, and recent-daily weather. `Consumers: cns/api/location.py` (writes the cache key).
- `time_manager.py` — current local datetime (`datetime_section`, plain `EventAwareTrinket`). Stateless; renders a fresh `<current_datetime>` line each compose using `get_user_preferences().timezone`.
- `__init__.py` — docstring only, no re-exports; trinkets are instantiated by the CNS factory (`cns/integration/factory.py` — three construction sites; see the Wiring entry). whose constructions self-register via `working_memory.register_trinket()`.
- `HOW_TO_BUILD_A_TRINKET.md` — tutorial for building trinkets; CURRENT. Owns the step-by-step walkthrough (base-class choice, patterns 0-10, a complete result-feed example, the two-file registration, live verification, and a symptom→cause→fix table). Doctrine and per-trinket behavior stay in this map; the guide cites them rather than restating them.

## Wiring

Composition flow (owned by `working_memory/core.py` and `working_memory/composer.py`; cited, not repeated): `ComposeSystemPromptEvent` broadcast → each trinket's `handle_update_request()` → `generate_content()` → `_persist_to_valkey()` → `TrinketContentEvent` → composer routes by `variable_name`.

Result-feed update flow (local ordering invariant for `forage` / `memory_curator` / `whilethecatsaway`): producer publishes `UpdateTrinketEvent` with `task_id` + `status` → trinket mutates `_user_results[task_id]` → `super().handle_update_request()` renders and publishes. If the trinket rendered BEFORE mutating state, the prompt would lag one cycle behind the agent's result; if it skipped `super()`, nothing would publish.

Expiry flow (owned by `base.py`): `TurnCompletedEvent` → `_on_turn_completed()` sets `current_turn` → `_expire_items()` → on `True`, `_refresh_content()` republishes with `{"action": "lifecycle_refresh"}` → the trinket's own `handle_update_request()` sees no action key and re-renders.

Construction point (owned by `cns/integration/factory.py` — the only file in the repo that constructs trinkets): every trinket is instantiated manually, at exactly three sites. `_get_working_memory()` builds thirteen standard trinkets (twelve unconditional plus `PersonaTrinket` when `config.system.persona_enabled`; registration order is deliberate; keep manual). `_initialize_peanutgallery_service()` builds `PeanutGalleryTrinket` with `default_ttl=PG_GUIDANCE_TTL_TURNS`, gated by `config.system.peanutgallery_enabled`. `_initialize_inbox_poller()` builds `EmailTrinket` unconditionally — the poller service no-ops without credentials, but the trinket itself is always constructed. Deleting an instantiation silently removes that trinket's section content from the composed prompt (it never publishes `TrinketContentEvent`, so `composer.add_section()` is never called for its `variable_name`); reordering instantiations changes nothing in the prompt — slot order is owned by `working_memory/composer.py:SECTION_LAYOUT`, per `working_memory/AGENTS.md`. Each constructor's `base.py` registration is the only wiring — no trinket auto-registers.

## Result-feed state machine

Three trinkets share one state machine over `_user_results[user_id][task_id]` entries (`type`, `data`, `received_turn`, optional `display_until_turn`). The deltas are the policy knobs:

| Concern | forage | whilethecatsaway | memory_curator |
|---|---|---|---|
| Success | persists until `dismissed` or collapse | auto-expires `RESULT_TTL_TURNS = 8` | persists until collapse or next run |
| timeout/failed | expire `ERROR_TTL_TURNS = 5` | expire `RESULT_TTL_TURNS = 8` | expire `ERROR_TTL_TURNS = 5` |
| `in_progress` | yes — stacks per-iteration summaries; late in_progress never downgrades a terminal state | no | no |
| `dismissed` status | yes (from `forage_tool`) | no | no |
| unknown status | falls through without state update | falls through without state update | early-returns without rendering |

Shared invariants: an event without `task_id` is a lifecycle refresh (render only, no state change); `display_until_turn` is compared against `self.current_turn` with strict `>` in `_expire_items()` but `<=` in `generate_content()`, so an item expires exactly at the turn boundary in both paths; `_expire_items()` must return `bool(expired)` so `base.py` can decide whether a mid-turn re-render is needed.

A fourth variant exists: `peanutgallery_trinket.py` runs the same task-id/turn-TTL shape but is keyed by generated guidance `id` (`add_guidance` action, `expires_at_turn = current_turn + ttl`) rather than producer task IDs, and has no task-status lifecycle.

When adding a fifth result-feed trinket, reuse this shape (per-user dict → `active_results` lazy-init property → status dispatch in `handle_update_request()` → `_expire_items()` on `display_until_turn`) instead of inventing a parallel mechanism; differing only in the policy knobs above is the established pattern.
