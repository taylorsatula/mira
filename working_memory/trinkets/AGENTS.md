# working_memory/trinkets/ — one prompt-slot implementation per trinket module, each self-registering when constructed, all on the two bases in `base.py`

## Files

- `__init__.py` — package marker, docstring only; no re-exports, so every consumer imports a trinket module by path.
- `base.py` — both base classes, the constructor that registers a trinket, and the persist-then-publish cycle each render runs. Open it before adding a trinket or changing what a publish writes.
- `lora_trinket.py` — the user model, plus the check-in guidance that opens the `<mira:checkin_response>` loop. Open it when the model's picture of the user reads wrong or a debrief goes unanswered.
- `persona_trinket.py` — the current Persona revision's directives in their own slot. Open it before changing how Persona text reaches the prompt.
- `skills_catalog_trinket.py` — the merged skill catalog, names and descriptions only, plus the instruction naming `invoke_skill_tool`. Open it when the model cannot find a skill it should have.
- `active_skills_trinket.py` — bodies of the skills invoked this segment, in the non-cached half of the system prompt. Open it before changing how a skill body reaches the prompt.
- `location_trinket.py` — location, sun times, UV index and a two-hour forecast read from Valkey. Open it when local weather or location context is stale or absent.
- `manifest_trinket.py` — the conversation segment manifest, bucketed by day in the user's timezone. Open it when history renders under the wrong day or the wrong clock.
- `domaindoc_trinket.py` — enabled domaindocs as section trees with expand/collapse state, personal and accepted shares. Open it before changing how a document's sections or depth render.
- `time_manager.py` — the current wall clock in the user's timezone, which is the model's only "now". Open it when relative times come out wrong or the date is missing.
- `asyncactivity_trinket.py` — the sidebar-agent activity feed re-read from the per-user SQLite table on every render. Open it when activity lines are missing, duplicated, or stuck.
- `reminder_manager.py` — active reminders in user and internal categories, fetched by running `ReminderTool` directly. Open it when a reminder is due and the model does not raise it.
- `email_trinket.py` — unread inbox headers from the poller's last snapshot. Open it before changing what the model sees about email.
- `subagent_results_trinket.py` — every model-visible subagent result in one section, with per-agent-type lifecycle policy. Open it before changing when a result appears, expires, or disappears.
- `proactive_memory_trinket.py` — the memories surfaced for this turn, and the cache the orchestrator's retention check reads. Open it when surfaced memories render stale, duplicated, or not at all.
- `peanutgallery_trinket.py` — metacognitive guidance with a turn-counted expiry, including the critical section that authorizes visible self-correction. Open it when guidance never expires or the model ignores it.
- `HOW_TO_BUILD_A_TRINKET.md` — the authoring walkthrough, base-class choice through verification. Open it before writing a new trinket.

## Wiring

- Construction: `cns/integration/factory.py:_get_working_memory()` constructs eleven trinkets unconditionally, with `PersonaTrinket` beside them behind `config.system.persona_enabled`. Two construct elsewhere: `PeanutGalleryTrinket` in `_initialize_peanutgallery_service` behind `config.system.peanutgallery_enabled`, `EmailTrinket` in `_initialize_inbox_poller` unconditionally. Construction is what registers, so a closed gate makes the trinket absent from every compose and its direct-handle consumer sees `None`. Counterpart: `cns/integration/AGENTS.md`.
- Placement: `working_memory/composer.py:SECTION_LAYOUT` decides each slot's placement — cached or non-cached system, post-history, notification. A slot missing from every list still renders, appended at the end of the system prompt with a `logger.warning`, so a layout edit that forgets a slot puts content in the wrong place and raises nothing. Counterpart: `working_memory/AGENTS.md`.
- Producer edges: two independent contracts, and both fail silently. First, an `UpdateTrinketEvent` names its target by trinket class name, and `working_memory/core.py:_handle_update_trinket` drops a name no trinket registered under with a warning, so a producer left naming a renamed class writes a refresh that never lands. Second, the payload keys each trinket indexes out of `event.context`: `active_skills_trinket.handle_update_request` reads `action`/`name`/`body` (written by `tools/implementations/invoke_skill_tool.py`), and `subagent_results_trinket.handle_update_request` reads `task_id`/`status`/`agent_type` (written by `agents/spawn.py`, `agents/base.py`, `agents/implementations/forage_agent.py`), logging `update dropped` for an `agent_type` it has no branch for. A renamed key yields an absent section, not a visibly wrong one. Live producer set: `rg 'target_trinket'`. Counterparts: `agents/AGENTS.md`, `tools/implementations/AGENTS.md`, `cns/services/AGENTS.md`.
- Poller edge: `cns/services/pollers/inbox_poller.py:InboxPollerService` is the one producer here whose publish originates on a thread this directory never sees — `SegmentPoller._poll_loop` publishes `UpdateTrinketEvent.create(target_trinket='EmailTrinket', context={'data': [...]})` directly to the bus, so the `publish_trinket_update` continuum guard does not apply and a cycle can land before any compose of the segment has run. `email_trinket.handle_update_request` takes the snapshot out of `context['data']` and `_format_email_line` reads `uid`, `from_addr`, `subject`, `date` from each row, so a key renamed on either side renders an empty field rather than raising. `EmailTrinket` must be constructed — and so registered under its class `__name__` — before the poller's first cycle publishes; a class rename on either side drops every publish behind one `No trinket registered with name` warning and the inbox slot never renders again for any user. Counterpart: `cns/services/pollers/AGENTS.md`.
- Direct-handle consumers read trinket members and guard with `hasattr` or a None check, so a rename degrades to an empty result rather than raising: `active_results` (from `tools/implementations/subagent_tool.py` and `agents/implementations/forage_agent.py`), `get_cached_memories()` (from `cns/services/orchestrator.py`), `invalidate_trinket("LoraTrinket", ...)` (from `cns/services/lora_service.py`). Counterparts: `tools/implementations/AGENTS.md`, `agents/implementations/AGENTS.md`.
- Valkey surface: `working_memory/trinkets/base.py:TRINKET_KEY_PREFIX` names one hash per user whose fields are slot names — plus, for one upgrade window, retired slot names (`forage_results`, `whilethecatsaway_results`, `memory_curation`), which `subagent_results_trinket._persist_to_valkey` sweeps once per user. Services outside this directory delete a field by name after mutating the store behind it, so a slot rename leaves those deletions pointing at a field nothing writes. Live set: `rg 'TRINKET_KEY_PREFIX'`. Counterparts: `cns/services/AGENTS.md`, `cns/api/AGENTS.md`, `utils/AGENTS.md`.
- Location cache: `cns/api/location.py:LocationHandler.process_request` writes `location:{user_id}` — geocode plus forecast under `LOCATION_CACHE_TTL_SECONDS` — and `location_trinket.py` reads the JSON keys `location_name`, `forecast`, `sunrise`, `sunset`, `uv_index`, `recent_weather` straight out of it with no fetch of its own. A key rename blanks a field of this section and a TTL drift leaves it stale, neither raising. Counterpart: `cns/api/AGENTS.md`.
- Reminder projection: `reminder_manager.py:_format_reminder_xml` renders the rows `tools/implementations/reminder_tool.py:ReminderTool.run(operation="get_reminders")` returns, keyed by that tool's decrypted field names (`encrypted__title`, `encrypted__description`, `reminder_date`, `id`, `completed`). The projection and this renderer move together. Counterpart: `tools/implementations/AGENTS.md`.
- Read-side sources: `lora_trinket.py` renders `cns/infrastructure/feedback_tracker.py:FeedbackTracker.get_lora_content`'s `synthesis_xml` and `needs_checkin`, and `persona_trinket.py` renders `cns/infrastructure/persona_repository.py:PersonaRepository.get_current_revision().directives`. Change either return shape alone and a prompt section empties with the other side intact. Counterpart: `cns/infrastructure/AGENTS.md`.
- Twin edges: the domaindoc section model — depths 0 through 2, pinned always expanded, a collapsed parent hiding every descendant — also governs `tools/implementations/domaindoc_tool.py` and `cns/api/actions.py:DomainKnowledgeDomainHandler`, so a change to depth accounting or collapse semantics is a change to all three; the owning maps are `tools/implementations/AGENTS.md` and `cns/api/AGENTS.md`. The check-in loop spans `lora_trinket.py`'s `<mira:checkin_response>` instruction, the tag regex in `utils/tag_parser.py:TagParser.parse_response` that produces the `checkin_response` field, and `cns/services/orchestrator.py:_process_checkin_response` that consumes it; wording drift on any of the three breaks the loop with no error on any side. Counterparts: `utils/AGENTS.md`, `cns/services/AGENTS.md`.

## Rules

- A `variable_name` keys two registries at once: the placement list in `working_memory/composer.py:SECTION_LAYOUT` and the field this trinket writes in the `trinkets:{user_id}` hash (`working_memory/trinkets/base.py:_persist_to_valkey`). It must be unique across every trinket, because a duplicate makes the later publisher win both the composer's section dict and the hash field — the other trinket's section then vanishes from the prompt with nothing logged. `persona_directives` exists as a separate slot from `behavioral_directives` for exactly this reason: one hash, two fields, two subjects.
- Add-one recipe — this directory is the extension point, and all four steps are required:
  1. A new module subclassing a base from `base.py`, with `variable_name` as a class attribute. Falsy raises `TypeError` at construction; no `_get_variable_name()` hook exists, so defining one leaves the attribute unset.
  2. Pick the base by state model: turn-scoped in-memory state takes `StatefulTrinket` and implements `_expire_items()` plus `_clear_all_state()`; a stateless render, or state that lives in a store, takes `EventAwareTrinket`. A plain base holding turn-scoped state keeps rendering the previous segment's data after collapse.
  3. Construct it in `cns/integration/factory.py:_get_working_memory()`. Construction is registration and there is no discovery pass, so a trinket that is never constructed is silently absent from every compose, in every deployment.
  4. Add the slot to exactly one `SECTION_LAYOUT` list in `working_memory/composer.py`. Skip this and the content still renders, appended at the end of the system prompt behind a `logger.warning`: visible, in the wrong place, no failure.
- `cache_policy` is consulted only for system-placement slots — `working_memory/composer.py:_route_section` tests the post-history and notification placements before it ever reads the flag. Setting it True on a HUD or post-history trinket changes nothing (`domaindoc_trinket.py` carries such a setting today), and an author who believes that slot is cached will make cache-invalidating edits without knowing their cost. On a system slot the flag is load-bearing in both directions: True on a volatile slot busts the cache-eligible prefix on every change, False on a stable one re-pays its tokens every turn.
- Escaping has exactly two tiers, and a section picks one. Text that originates outside the system crosses `utils.untrusted_content.wrap_untrusted` once per section, around the whole external listing — `email_trinket.py:generate_content` is the shape; per-field wrapping repeats the treat-as-data directive once per row per turn. Every other interpolation takes `html.escape` at the point of interpolation — text positions plain, attribute positions with `quote=True`. Two first-party sites render unescaped on purpose, and both are the slot's own subject matter rather than an ingredient of it: `lora_trinket.py:_format_user_model`'s observation text (second-order synthesis already downstream of the ingestion boundary) and `persona_trinket.py:generate_content`'s directives (the current Persona revision, which is what that slot is for). Two user-authored sites are unescaped today and are defects, not precedents: `manifest_trinket.py:generate_content`'s `display_title`, which is user message content from `cns/services/manifest_query_service.py`, and `peanutgallery_trinket.py:generate_content`'s guidance text. Escape those rather than extending the exemption; copying either onto raw external or user text is an injection.

Elsewhere: this map does not own how the prompt is assembled or when a section lands — the content a section renders belongs to its file's docstring, and the compose, routing and flush machinery belongs to the working-memory map cited under `## Wiring`. How a trinket is built, pattern by pattern, is `HOW_TO_BUILD_A_TRINKET.md`; why a rule reads the way it does is `git log`. Every other destination this directory reaches is an edge — see `## Wiring` above.

## One trinket through one turn

The case that decides most of the Rules above: a stateful trinket receives producer input mid-conversation, then survives a segment collapse.

1. A producer publishes `UpdateTrinketEvent` naming this trinket. `working_memory/core.py:_handle_update_trinket` takes `_compose_lock`, looks the name up, and calls `handle_update_request`, which runs to completion because the bus is synchronous.
2. The trinket's override stores the producer's payload first and only then calls `super()`. Reversing that order renders before mutating and leaves the section one producer cycle behind. The override tells producer input from a lifecycle refresh by the producer's own marker in `context` — a compose broadcast arrives with `context` empty, so an override that cannot tell the two apart wipes the producer's state at every compose.
3. The base renders and, for non-empty content, persists the Valkey field and publishes `TrinketContentEvent`; `_handle_trinket_content` re-enters the same lock and adds the section to the composer. A publish that lands between composes therefore changes the stored field immediately while the prompt changes only at the next compose.
4. A producer that publishes before this user's first compose sees a logged no-op from `publish_trinket_update`, which requires `_current_continuum_ids` to be set. That is why the orchestrator publishes its first-turn memories straight to the bus instead of through that helper.
5. Each `TurnCompletedEvent` advances this user's counter and runs `_expire_items()`; a True return re-renders through the same publish chain, mid-life.
6. On collapse, `WorkingMemory._flush_stateful_trinkets` runs `_clear_all_state()`, then drops the turn counter, then deletes the Valkey field, per stateful trinket. State, counter, and stored field therefore start clean on the next compose for that user — a flush that skips any one of the three leaves a section that no longer matches its state.
