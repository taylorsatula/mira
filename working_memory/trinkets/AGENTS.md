# working_memory/trinkets/ — trinket implementations: one `variable_name` slot each in the composed system prompt

Elsewhere: compose orchestration, the `WorkingMemory` handlers, portrait caching — `working_memory/AGENTS.md` (`core.py`, `composer.py`) · event definitions (`ComposeSystemPromptEvent`/`UpdateTrinketEvent`/`TrinketContentEvent`/`TurnCompletedEvent`) — `cns/core/events.py` · trinket construction site and config gates — `cns/integration/factory.py` (`cns/integration/AGENTS.md`) · producer-side contracts (agent completion publishes, spawn, blocking suppression) — `agents/AGENTS.md`, `agents/implementations/AGENTS.md`, `tools/implementations/AGENTS.md` · poller lifecycle — `cns/services/pollers/AGENTS.md` · `wrap_untrusted` mechanics — `utils/AGENTS.md` (`untrusted_content.py`) · skills store freshness — `utils/AGENTS.md` (`skill_files.py`) · the full authoring walkthrough (patterns, complete example, verification tiers) — `HOW_TO_BUILD_A_TRINKET.md` · how a pattern was learned — `git log`.

## Rules

- One slot string, two registries: `variable_name` keys the placement list in `working_memory/composer.py:SECTION_LAYOUT` and the field this trinket writes in the `trinkets:{user_id}` Valkey hash (`base.py:_persist_to_valkey`/`_clear_from_valkey`) — globally unique across all trinkets. A duplicate makes the later publisher win both the composer's section dict and the hash field; the other trinket's section silently vanishes. Live hazard `persona_trinket.py` guards against: `persona_directives` vs LoraTrinket's `behavioral_directives`.
- Add-one recipe (this directory is the extension point; the pattern-level walkthrough is `HOW_TO_BUILD_A_TRINKET.md`):
  1. New module subclassing a base from `base.py`, `variable_name` as a class attribute — falsy raises `TypeError` in `base.py:__init__`. No `_get_variable_name()` exists; defining one silently leaves the attribute unset.
  2. Base by state model: turn-scoped in-memory state → `StatefulTrinket` (implement `_expire_items()` + `_clear_all_state()`); stateless render or state that lives in a store → `EventAwareTrinket`. A plain base holding turn-scoped state renders prior-segment data after collapse.
  3. Construct in `cns/integration/factory.py:_get_working_memory()` — construction self-registers via `working_memory.register_trinket()`; no auto-discovery, so a trinket never constructed is silently absent from every compose. Two construct under config gates: `PersonaTrinket` (`config.system.persona_enabled`, inside the main block) and `PeanutGalleryTrinket` (`_initialize_peanutgallery_service`, `config.system.peanutgallery_enabled`). `EmailTrinket` constructs unconditionally in `_initialize_inbox_poller` — the no-credentials case no-ops the poller service at runtime, never the construction, so the trinket is never absent.
  4. Add the slot to exactly one `SECTION_LAYOUT` list in `working_memory/composer.py`. Skipped: content still renders, appended at the end of `system` with `logger.warning` — content in the wrong place, no crash.
  5. Verify live per the guide's tier-2 list: boot, one turn, read the section back with `working_memory.get_trinket_state()`. A section that never survives a Valkey round-trip is unverified.
- Never subscribe to `SegmentCollapsedEvent` or `TurnCompletedEvent` from a trinket. Collapse flush is centralized in `working_memory/core.py:_flush_stateful_trinkets()` (per stateful trinket: `_clear_all_state()` → `clear_user_turn()` → `_clear_from_valkey()`); turn advance is `base.py:StatefulTrinket._on_turn_completed` (per-user counter, then `_expire_items()`; a True return fires `_refresh_content()`). A self-subscription duplicates the flush against a counter the base already maintains — state and turn bookkeeping desynchronize.
- `generate_content()` failures raise. `working_memory/core.py:_handle_update_trinket` is the sole isolation boundary — per-trinket isolation plus the infrastructure/logic classification (`Database`/`Valkey`/`Connection` in the exception type name → infrastructure). A catch-and-return-`""` inside the trinket masks an outage as "no content" and the classification never fires. Narrow `except` around one formatting call is the sanctioned degradation (`manifest_trinket.py:_format_time_range` → `"[Unknown]"`, row kept).
- `handle_update_request` overrides mutate state before `super()` — render-before-mutate leaves the section one producer cycle behind. And the compose broadcast arrives with an empty `context` at every trinket: an override keys on the producer's marker (`action`/`data`/`task_id`) to tell producer input from lifecycle refresh, or every compose wipes the state the producer wrote. Shape across `active_skills_trinket.py`, `email_trinket.py`, `subagent_results_trinket.py`, `peanutgallery_trinket.py`.
- `cache_policy` marks provider prompt-cache eligibility for `PLACEMENT_SYSTEM` slots only — `working_memory/composer.py:_route_section` consults it after notification/post_history have already routed, so it is a silent no-op on a HUD trinket. Setters: `rg 'cache_policy = True'` (five today — four system-placement; `domaindoc`'s is a silent no-op: its `post_history` placement routes before the cache branch ever consults it). True on a volatile system slot busts the cache-eligible prefix on every change; False on a stable one re-pays its tokens every turn.
- Escaping tiers: external-source text crosses `utils.untrusted_content.wrap_untrusted` once per section, around the whole external listing (`email_trinket.py:generate_content` is the shape — per-field wrapping repeats the treat-as-data directive every turn); every other user-controlled interpolation takes `html.escape` at the interpolation point. Exception: `lora_trinket.py:_format_user_model` renders observations unescaped — internal second-order synthesis, already downstream of the ingestion boundary; copying that exception for raw external or user text is an injection. Boundary doctrine owned by root and `utils/AGENTS.md`.

## Files

- `__init__.py` — docstring only, no re-exports; every consumer imports trinket modules by path.
- `base.py` — both base classes and the persist/publish cycle: `EventAwareTrinket` (validates `variable_name`, self-registers, `handle_update_request`: generate → persist-or-clear → publish `TrinketContentEvent`), `StatefulTrinket` (per-user `current_turn`, `TurnCompletedEvent` subscription, abstract `_expire_items()`/`_clear_all_state()`, `_refresh_content()`). Entry: `TRINKET_KEY_PREFIX` (the `"trinkets"` hash prefix six modules outside this directory import), `_persist_to_valkey`, `_clear_from_valkey`. Gotcha: `_refresh_content()` → `working_memory.publish_trinket_update` is a logged no-op until the user's first compose sets `_current_continuum_ids` in `working_memory/core.py` — an expiry-driven refresh before any compose silently never lands.
- `active_skills_trinket.py` — bodies of skills the model invoked, in the non-cached system prompt (slot `active_skills`). Entry: `handle_update_request` (stores the activation snapshot, then renders). Body snapshotted at activation — a later skill file edit/delete mid-segment cannot change or blank the section; no TTL, no deactivate, only collapse clears.
- `asyncactivity_trinket.py` — sidebar-agent activity feed from the SQLite `sidebar_activity` table (slot `async_activity`), grouped per `interface_name` (producers and the dedup pairing owned by `agents/triggers/AGENTS.md`), `escalated`/`conflict` rows prefixed. Entry: `generate_content`, `_render_items`, `_format_age`. State lives in SQLite and is re-read every render — collapse clears nothing; rows leave via `dismissed`/`resolved` status writes. phoneafriend rows are excluded from the render — `SidebarAgent._exit` lands the full consult response in `summary`, which would echo every consult's answer as a feed line; the response belongs to the `subagent_tool` result.
- `domaindoc_trinket.py` — enabled domaindocs as section trees: states/index/content from one tree walk (index unconditional — the TOC for collapsed sections), personal plus accepted shares, `LARGE_SECTION_CHARS` marker. Entry: `generate_content`, `_format_sections`, `_load_shared_docs`. Gotcha: rows come from `db.fetchall()` + `db._decrypt_dict()` — only `db.select()` decrypts automatically, so the manual decrypt is load-bearing here; dropping it puts Fernet ciphertext into the prompt with no fetch-time warning.
- `email_trinket.py` — unread inbox listing in the HUD from poller snapshots (slot `inbox_status`). Entry: `handle_update_request` (snapshot store), `_format_email_line`, `_header_value` (whitespace-folded, 120-char cap). One `wrap_untrusted` region around the whole listing — the only external-source trinket.
- `subagent_results_trinket.py` — every model-visible subagent result in one section (slot `subagent_results`), keyed `task_id`, carrying `agent_type`; per-type lifecycle read from `agents/specs.py:SUBAGENT_SPECS`: forage `pending` → `in_progress` (stacked per-iteration summaries, terminal-state guard against late overwatch downgrades) → `success` (persists until dismissed) | `timeout`/`failed` (error TTL 5); whilethecatsaway every status auto-expires (result TTL 8 for pending/success, error TTL for timeout/failed); memory_curator `success` persists (the next run's stable task_id replaces it), `timeout`/failed (error TTL 5), unknown statuses drop without re-render; `dismissed` removes for any dismissable type, and `pending` creates only when absent (a late pending never overwrites the agent's own first update — the seam publishes after the thread starts). phoneafriend never appears (blocking suppression, `agents/base.py`). Entry: `handle_update_request` (per-type dispatch), `active_results` (the public surface `subagent_tool`'s dismiss/continue and `ForageAgent.continue_task`'s refine gating read), `_expire_items`, `_persist_to_valkey` (deletes the three legacy slot fields on the trinket's first persist per user — the old trinkets are unregistered, so nothing else would ever clean those Valkey hash fields).
- `location_trinket.py` — location/sunrise/UV/forecast from the Valkey `location:{user_id}` key (slot `location_context`, cached). Entry: `generate_content`. Gotcha: UV label bug — any `uv_index` below 11 renders "(Very High)", including low values; fix before relying on the label.
- `lora_trinket.py` — user-model observations plus behavioral check-in guidance from `FeedbackTracker.get_lora_content` (slot `behavioral_directives`, cached). Entry: `_parse_user_model_xml` (attribute-keyed regex parse — order drift cannot drop entries; unparseable entry logs the consequence and is omitted, not silent), `_format_user_model`, `_format_checkin_guidance` (issues the `<mira:checkin_response>` protocol).
- `manifest_trinket.py` — conversation segment manifest grouped TODAY/YESTERDAY/date in the user's timezone (slot `conversation_manifest`). Entry: `generate_content`, `_group_segments_by_date`, `_format_time_range`. Gotcha: the broad `except` → `'UTC'`/`"[Unknown]"` fallbacks are sanctioned for display labels only — copying them into anything the model acts on converts a bad timestamp into a silently wrong one.
- `reminder_manager.py` — active reminders in user + internal categories, fetched by constructing `ReminderTool` and calling `run(operation="get_reminders", ...)` directly (slot `active_reminders`). Entry: `generate_content`, `_CategoryConfig` (the two category configs), `_format_category`. Reminder fields arrive decrypted under their `encrypted__`-prefixed storage names — the tool result's projection, owned by `tools/implementations/AGENTS.md`.
- `skills_catalog_trinket.py` — the merged skill catalog (global boot-snapshot + per-user), name + description only, plus the literal instruction naming `invoke_skill_tool` (slot `skills_catalog`, cached). Entry: `generate_content` via `utils.skill_files.catalog_for`. Bodies never render here — `invoke_skill_tool` loads them into `active_skills`.
- `time_manager.py` — the current user-local wall clock (slot `datetime_section`). The model's only clock; root's model-supplied-timestamp doctrine depends on it. Smallest trinket — the minimal shape.
- `peanutgallery_trinket.py` — metacognitive guidance entries with turn TTL, rendered in standard/initiative/critical sections (critical carries the 4th-wall-breaking directive authorizing visible self-correction). Entry: `add_guidance`/`get_active_guidance`, `handle_update_request` (`action == "add_guidance"`), `GuidanceEntry`. `default_ttl` arrives as a constructor arg from the factory (`PG_GUIDANCE_TTL_TURNS` in `cns/services/peanutgallery_service.py`) — the only trinket with a third constructor parameter.
- `persona_trinket.py` — the current Persona revision's directives (slot `persona_directives`, cached). Entry: `generate_content` via `PersonaRepository.get_current_revision`. Distinct slot from LoraTrinket's `behavioral_directives` — one Valkey hash, two fields, two subjects (user-model observations vs MIRA's prescriptive self-evaluation).
- `proactive_memory_trinket.py` — surfaced memories passed by the orchestrator each turn (slot `relevant_memories`), short-ID formatted, linked memories as deduped inline `Also:` context. Entry: `generate_content` (caches `context['memories']`), `get_cached_memories` (the orchestrator's retention-evaluation read), `_format_linked_context`. Gotcha: EventAware with an in-memory per-user cache that collapse does NOT flush — correct only because the orchestrator republishes every turn; a consumer reading the cache outside that cadence sees pre-collapse rows.
- `HOW_TO_BUILD_A_TRINKET.md` — the authoring walkthrough: base-class table, ten patterns (registration, producer wiring, state, caching, error policy, DB access, timezone, triggering), a complete result-feed example, common-issues table. Trust: verified against source; its former three stale spots (Pattern 5 escape claim, Pattern 6 setter count, Pattern 0 live-split list) were corrected with the unification.

## Wiring

- Construction: 12 trinkets instantiate in the main block of `cns/integration/factory.py:_get_working_memory()` (order deliberate, manual); `PersonaTrinket` in the same block gated `config.system.persona_enabled`; `EmailTrinket` in `_initialize_inbox_poller`; `PeanutGalleryTrinket` in `_initialize_peanutgallery_service` gated `config.system.peanutgallery_enabled`. Counterpart: `cns/integration/AGENTS.md`. Gate closed → trinket absent; direct-handle consumers guard with `get_trinket()` None checks.
- Placement: every slot maps to one placement in `working_memory/composer.py:SECTION_LAYOUT` — `system` (split cached/non-cached on `cache_policy`), `post_history` (domaindoc), `notification` (the `<mira:hud>` sliding assistant message). Counterpart: `working_memory/AGENTS.md`.
- Producer edges — each publishes `UpdateTrinketEvent` with `target_trinket` = registered class name (live set: `rg 'target_trinket'`); a name no trinket registered under is dropped with a warning and the refresh never happens: `cns/services/orchestrator.py:process_message` → ProactiveMemoryTrinket (surfaced memories, every turn) · `tools/implementations/invoke_skill_tool.py` → ActiveSkillsTrinket (activate, with body) · subagent chain — `agents/spawn.py:publish_result` is the single producer-side publisher (seam `pending` at spawn + `failed`/`ThreadCrash` on a crashed thread; `ForageAgent.continue_task`'s refine auto-dismiss; `subagent_tool`'s dismiss), `agents/implementations/forage_agent.py` (`in_progress` via overwatch; completion `success`/`timeout`/`failed` with `agent_type`+`subject`), `whilethecatsaway_agent.py` and `memory_curator_agent.py` completions — all → SubagentResultsTrinket · `agents/base.py` default completion + `_publish_trinket_refresh` → AsyncActivityTrinket · `cns/services/pollers/inbox_poller.py` (`SegmentPoller` subclass) → EmailTrinket · `cns/services/peanutgallery_service.py:_inject_guidance` → PeanutGalleryTrinket. Blocking agent runs publish nothing — the single suppression point is `agents/base.py`. Counterparts: `tools/implementations/AGENTS.md`, `agents/AGENTS.md`, `agents/implementations/AGENTS.md`, `cns/services/AGENTS.md`, `cns/services/pollers/AGENTS.md`.
- Direct-handle consumers — renaming these members breaks the caller silently (None/hasattr guards degrade to empty): `active_results` on SubagentResultsTrinket ← `tools/implementations/subagent_tool.py` (dismiss validation + continue type discrimination) and `agents/implementations/forage_agent.py:continue_task` (refine gating, via `tool_repo.working_memory`); `get_cached_memories()` on ProactiveMemoryTrinket ← `cns/services/orchestrator.py` (`_get_previous_memories`, retention evaluation); `WorkingMemory.invalidate_trinket('LoraTrinket')` ← `cns/services/lora_service.py`. Counterparts: `tools/implementations/AGENTS.md`, `agents/implementations/AGENTS.md`, `cns/services/AGENTS.md`.
- Valkey surface `trinkets:{user_id}` (field = slot name; JSON `content`/`cache_policy`/`updated_at`; `base.py:TRINKET_KEY_PREFIX`): written on every publish, deleted on empty content and on collapse flush. Read side: `working_memory/core.py:get_trinket_state`/`get_all_trinket_states` ← `cns/api/data.py`'s working-memory query action (`section` filter). Field invalidators after upstream mutation (live set: `rg 'TRINKET_KEY_PREFIX'`): `cns/services/persona_service.py` (`persona_directives`), `cns/services/segment_collapse_handler.py` + `cns/services/orchestrator.py` check-in path (`behavioral_directives`), `cns/api/actions.py` domaindoc/skills/lora handlers (`domaindoc`, `skills_catalog`, `behavioral_directives`), `utils/domaindoc_shares.py` (`domaindoc`). A slot rename is a cross-service break — every invalidator edits in the same commit. Counterparts: `working_memory/AGENTS.md`, `cns/services/AGENTS.md`, `cns/api/AGENTS.md`, `utils/AGENTS.md`.
- Store edges: `asyncactivity_trinket.py` → `sidebar_activity` via `agents/base.py:ensure_activity_schema` (DDL constants owned by `utils/AGENTS.md`; second-writer contract by `agents/AGENTS.md`) · `skills_catalog_trinket.py` → `utils/skill_files.py:catalog_for`, with `load_global_catalog()` boot-snapshotted in the factory right after trinket construction (freshness doctrines `utils/AGENTS.md`) · `lora_trinket.py` → `cns/infrastructure/feedback_tracker.py:get_lora_content` · `persona_trinket.py` → `cns/infrastructure/persona_repository.py:get_current_revision` · `manifest_trinket.py` → `cns/services/manifest_query_service.py:get_segments` · `location_trinket.py` → Valkey `location:{user_id}` written by `cns/api/location.py` · `reminder_manager.py` → `tools/implementations/reminder_tool.py` (constructed directly).
- Twin edges: the domaindoc depth contract (depths 0–2, any-depth parent resolution, pinned sections always expanded, collapsed parent hides all descendants) is twin code with `domaindoc_tool` and the API handler — owned by `tools/implementations/AGENTS.md`; this trinket renders it, change both sides in the same commit. The check-in protocol: `lora_trinket._format_checkin_guidance` instructs `<mira:checkin_response>` (blockquote + tag must match); `cns/services/orchestrator.py` extracts it → `FeedbackTracker.acknowledge_checkin` + `behavioral_directives` field invalidation — wording drift on either side breaks the loop silently.
- Counterparts: prompt-authored content rendered by the lora trinket ↔ `config/prompts/AGENTS.md`; surfaced memories arrive from `lt_memory` ↔ `lt_memory/AGENTS.md`.

## The compose round-trip

1. A turn's prompt build publishes `ComposeSystemPromptEvent` (trigger side owned by `cns/services/AGENTS.md`). `WorkingMemory._handle_compose_prompt` takes `_compose_lock`, records `_current_continuum_ids[user]`, personalizes the base prompt, clears sections, then broadcasts one `UpdateTrinketEvent` per registered trinket — `target_trinket` = class name, `context` empty.
2. The bus is synchronous: each broadcast runs that trinket's `handle_update_request` to completion before the loop continues. Overrides consume state first, then `super()`; `generate_content()` runs inside.
3. Non-empty content: `_persist_to_valkey` (the hash field — what API reads see), then `TrinketContentEvent` → `_handle_trinket_content` → `composer.add_section`. Both handlers re-enter `_compose_lock` on the same thread — the RLock exists for exactly this re-entrant chain and for mid-compose `publish_trinket_update` calls (a trinket refreshing during the broadcast re-enters through `_handle_update_trinket`). The orchestrator's ProactiveMemoryTrinket republish is not one: `process_message` publishes `UpdateTrinketEvent.create(...)` straight to the bus at memory surfacing, before the turn's first compose acquires the lock — bypassing `publish_trinket_update`'s first-compose no-op gate is what lets turn-1 surfaced memories render. Empty content: the field is deleted and nothing publishes — `compose()` never sees the slot.
4. After the loop, `composer.compose()` routes by `SECTION_LAYOUT` (cached/non-cached split on `cache_policy` for system slots; notification parts wrapped in `<mira:hud>`; post-history items become assistant messages) and `SystemPromptComposedEvent` carries the pieces to the orchestrator.
5. Stateful overlay: `TurnCompletedEvent` at turn end advances the per-user counter and runs `_expire_items()` — a True return fires `_refresh_content()`, a mid-life re-render through the same publish chain. `SegmentCollapsedEvent` runs `_flush_stateful_trinkets`: state → turn counter → Valkey field, per stateful trinket, then the portrait-cache invalidation (parent-owned).

Invariants: producer publishes between composes mutate trinket state and the Valkey field, but the composed prompt changes only at the next compose (the broadcast re-renders every trinket); a mid-session refresh before the user's first compose is a logged no-op (`_current_continuum_ids` unset); the flush order means the next compose for that user starts with state, counter, and field all clean.
